# /derive-styleguide — стиль владельца, извлечённый из улик

Слабая сессия не удержит стиль владельца в голове — через десять страниц её уносит. Лекарство —
никогда не «стараться сильнее»: извлеки стиль ОДИН РАЗ из собственного текста владельца, утверди
и переведи каждое машинно-проверяемое правило в строку линтера. «Модель забудет стайлгайд через
десять страниц — линтер не забудет никогда».

**Главное правило: выводи из ОБРАЗЦА, не из головы.** Каждое утверждение стайлгайда обязано
указывать на улику в тексте владельца. Стайлгайд, выдуманный из вкуса, — тот же фрод, что
выдуманное число.

## Шаг 1. Собери образец

Спроси владельца, какие артефакты эталонные (или возьми объявленные `canonArtifacts` из
`.kaif/kaif.json`). Предпочитай текст, который владелец НАПИСАЛ, тексту, который он лишь принял.
Образец тонкий (меньше нескольких страниц) — скажи об этом: тонкий образец даёт тонкий гайд, и
владелец должен знать, на каком объёме улик стоит каждое правило.

## Шаг 2. Извлеки — с цитатами

Пройди образец и извлеки, каждый пункт С ЦИТАТОЙ из текста владельца:

1. **Регистры** — какой голос какому содержанию служит (сухой кодекс-регистр для механик,
   повествовательный для лора — деление ВЛАДЕЛЬЦА, не учебника).
2. **Эталонные примеры** — 3–7 коротких цитат, которые И ЕСТЬ стиль: форма фразы, ритм, как
   вводятся термины, как подаются числа и таблицы.
3. **Словарь: одно понятие — одно слово.** Каждое понятие домена — термином ВЛАДЕЛЬЦА; каждый
   синоним, которым владелец НЕ пользуется, — в запретный список (дрейф синонимов — то, как
   гниют каноны).
4. **Конвенции оформления** — заголовки, регистр букв, пунктуация списков, форматы чисел, как
   свёрстаны формулы и стат-блоки.
5. **Анти-паттерны** — чего текст владельца не делает никогда (вода, хеджирование, маркетинговый
   тон…), каждый с уликой «в образце отсутствует / владелец снёс в коммите X».

## Шаг 3. Раздели правила: линтуемое и суждение

Пометь каждое извлечённое правило:
- **ЛИНТУЕМОЕ** — проверяется грепом/скриптом: запрещённые синонимы и маркеры воды, запрещённые
  конструкции, «формула без где-блока», регистровые слова не в том типе документа. Эти правила
  уходят строками в линтер канона (его исполняемый шаблон — в истоке `framework/tools/kaif-canon-lint.mjs`,
  в развёрнутых проектах `.kaif/tools/kaif-canon-lint.mjs`) — оформи машинной таблицей `паттерн → сообщение`.
- **СУЖДЕНИЕ** — тон, ритм, вкус: остаётся в гайде для проходов сильной моделью и вычитки
  владельца. Не выдавай суждение за застрахованное — прямо скажи, какие правила ничем не
  стерегутся.

## Шаг 4. Владелец утверждает — и гайд связывает

Оформи гайд документом рядом с каноном, которым он управляет (например `rules/STYLEGUIDE.md`),
с провенанс-пометками как любой ИИ-текст на территории владельца. Отдай владельцу с ОДНИМ
вопросом на каждую действительно неоднозначную развилку регистра (не викторина — работу сделал
ты, он ветирует). После утверждения: гайд обязателен для каждого будущего письма в этот канон, а
линтуемые правила в тот же день уходят в линтер (правило без стража — пожелание, а не правило).

## Заметки

- Перевыводи инкрементально: владелец написал новое, противоречащее гайду, — прав ВЛАДЕЛЕЦ;
  обнови гайд и его строки в линтере, но никогда не «исправляй» текст владельца.
- Режимы строгости: вывод/обновление гайда — работа сильной модели; ПРОГОН линтера — работа
  любой. В этом разделении и смысл.
