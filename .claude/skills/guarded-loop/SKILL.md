# /guarded-loop — автономный цикл, переживающий зависание

Обычные циклы (`/autoloop`, `/dayloop`, `/nightloop`) доверяют харнессу держать агента живым.
В поле это доверие иногда ломается: сеть лагает, API-вызов падает, чат виснет — и агент сам не
просыпается. Защищённый цикл добавляет к ТОЙ ЖЕ дисциплине цикла три гарантии: **внешний сторож**,
дёргающий агента каждые N минут, **heartbeat**, доказывающий реальный прогресс, и **политику
рестартов**, которая не сдаётся и не зацикливается. Всё про выбор и исполнение пунктов беклога —
канон `/autoloop`, без изменений.

## Шаг 0 — разбери просьбу, назови контракт

Два параметра, проговорённые ОДНОЙ строкой до старта:

- **Длительность** — явная («до 22:00», «3 часа») или дефолт: **1 час** для голого «защищённый
  цикл».
- **Интервал будильника** — явный («будильники каждые 20 минут») или дефолт: **10 минут**.

Пример: *«Защищённый цикл: до 22:00, пробуждения каждые 10 мин (дефолт). Стартую.»*

Контракт ЗАПИСЫВАЕТСЯ, а не только произносится (issue #30 поля: сессия сама вписала «до 23:50»
в свой пульс и всё равно закрылась на 25 минут раньше): первая строка пульса прогона —
`armed until <ISO>`, а `.kaif/guarded-loop.json` несёт `{ "until": "<ISO>" }` — записанная
строка не хранитель; хранитель — ПРОВЕРКА против неё (шаг 5). У истока `until` уже держит
сторож: `node tools/guarded-watchdog.mjs --arm` пишет `runEndsAt`, `--status` печатает его.

Длительность ограничивает РАБОТУ, а не закрытие (`AGENT_GUIDE.md` → «Работа до названного
времени»): работай в обычном темпе до самой границы — без раннего финиша из страха перед
сроком, — а наступление границы СТАРТУЕТ мягкое закрытие (шаг 5) и никогда не означает «всё
должно быть завершено до неё».

## Шаг 1 — взведи СТОРОЖА (внешнего, никогда не себя)

Процесс, исполняющий работу, не может быть единственным судьёй собственного здоровья — зависший
агент не выполнит свой же self-check. Два слоя:

1. **Сначала штатный планировщик харнесса** (scheduled wake-ups / cron-промпты / самобудильники
   твоей агентской системы) — взведён на интервал будильника. Это ШТАТНЫЙ путь.
2. **Страхующий слой — ЛОКАЛЬНЫЙ механизм ОС**, который агент строит один раз на проект
   (Планировщик задач Windows / cron / фоновый скрипт — добавь в стенд проекта и задокументируй):
   каждые N минут проверяет свежесть heartbeat-файла и при протухшем пульсе дёргает/перезапускает
   агента тем способом, который позволяет харнесс проекта (перезапуск CLI, уведомление владельцу
   как последняя ступень). KAIF предписывает КОНТРАКТ ниже; сам скрипт — инструмент проекта, не
   фреймворка.

Контракт сторожа (каждая строка оплачена реальным прогоном):
- **single-instance guard** — lock/pid-файл: два сторожа не устраивают двойных рестартов;
- **дебаунс** — действие только после M протухших проверок ПОДРЯД (долгая сборка законно
  молчит пульсом; M — из ИЗМЕРЕННОГО самого долгого шага проекта, не с потолка);
- **снять взвод в конце прогона** (Шаг 5) — сторож, оставленный после прогона, — мина.

## Шаг 2 — HEARTBEAT: пульс = завершённая работа, никогда не таймер

Дописывай строку в **`.kaif/heartbeat.log`** в КОНЦЕ каждой завершённой итерации/шага:

```
<ISO-время> | <пункт беклога> | <статус: done/progress/blocked> | next: <следующее действие>
```

Пульс пишется ТОЛЬКО по факту завершённого шага. Heartbeat от таймера («ещё жив» по расписанию)
обнуляет весь механизм — сторож будет радостно смотреть на тикающего зависшего агента — и это
фрод, на который охотится `/fable-judge`. Последняя строка заодно — микро-контекст восстановления.
Файл — runtime-состояние, не история: он в `.gitignore` (ignore-first-список машинерии кроет его
с 2.1) — пульс никогда не коммитится.

## Шаг 3 — сам цикл

Исполняй пункты беклога ровно по `/autoloop`: тот же выбор пунктов, исполнение по fable-циклу,
обязательный judge-проход на пункт, набросы владельца — в беклог, ТЯЖЁЛЫЙ неспланированный
пункт → сначала `/plan-epic`. Контекст/лимиты — забота харнесса, не стоп-условие. Правило
освежения едет на пробуждениях (`AGENT_GUIDE.md` → «Освежение контекста»): пробуждение спустя
час с последнего освежения — или впереди ТЯЖЁЛЫЙ пункт — начинается с перечитывания ядра и
обновления свидетельства.

## Шаг 4 — пробуждение: политика рестартов

Разбужен сторожем, пульс протух:

1. Скажи это вслух: *«разбужен сторожем — пульс протух с <T>»* (честность прежде всего; строка —
   криминалистика для следующей сессии).
2. Восстановись штатным входом: **`/resume`** — `STATUS.md` плюс последняя строка heartbeat И
   ЕСТЬ контекст восстановления; продолжи прерванный пункт или возьми следующий.
3. **Cooldown** между сторожевыми рестартами (не долби лагающую сеть).
4. **Потолок эскалации:** после ~3 рестартов подряд БЕЗ продвижения (между ними нет новых строк
   пульса) — СТОП: зафиксируй состояние в `STATUS.md` (и документ в `bugs/`, если причина похожа
   на дефект), сними сторожа, оставь владельцу ясную записку. Вечный crash-цикл жжёт бюджет и
   маскирует настоящую проблему.

## Шаг 5 — конец прогона

До ЛЮБОЙ церемонии закрытия напечатай принудительный артефакт —
`BOUNDARY: now <ISO> · armed until <ISO> · pool <empty | N items>` — и закрытие начинается ТОЛЬКО
когда `now ≥ until`, либо при действительно пустом пуле, перечисленном вслух. Время церемоний
тратится ПОСЛЕ границы и никогда не резервируется до неё: бюджетирование церемоний назад от
границы — ровно та инверсия, что молча потеряла 25 из 60 заказанных минут в поле (issue #30), и
`/fable-judge` охотится на финальный пульс раньше `until` при непустом пуле (охота
«early-finish»). Затем, на границе длительности (или при пустом пуле): чисто добей текущий пункт
до логического среза — не спеша: граница стартовала закрытие, а не подгоняет его, — запиши
финальную строку пульса (`run complete`), **сними внешнего сторожа**, закройся по ситуации сессии:
полные неторопливые
церемонии `/end-chat-soft`, если сессия кончается, либо парковочная заметка (по-`/pause`), если
чат продолжается. Отчёт: пунктов сделано, рестартов пережито, что эскалировано — первой строкой
`DELIVERY: <метрика владельца> X → Y; moved by: … | blocker: …` (метрика из `MASTER_PLAN.md`;
нулевой сдвиг только с названным блокером — охота судьи «delivery-line»).

## Что навык ЗАПРЕЩАЕТ

- Полагаться только на собственную живость агента — исполнитель никогда не единственный судья
  своего здоровья.
- Кормить heartbeat таймером — пульс доказывает РАБОТУ (судья охотится на это).
- «Always restart» — без cooldown и потолка эскалации плохое состояние становится crash-штормом.
- Закрываться до взведённой границы при непустом пуле — сначала печатается строка `BOUNDARY:`, и
  решают часы, а не оценка агентом длительности церемоний.
- Оставлять сторожа взведённым после прогона; два сторожа без single-instance guard.
- Выдумывать пороги — дебаунс и таймауты берутся из измеренных длительностей проекта.
