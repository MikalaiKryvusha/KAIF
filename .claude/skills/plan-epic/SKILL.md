# /plan-epic — полная лестница планирования тяжёлой работы

Почти на всё в индустрии есть золотые стандарты, лучшие практики, научные работы — или хотя бы
задокументированные наработки практиков. Эпик, спланированный по памяти, плохо переизобретает
решённые задачи; эпик, расписанный весь заранее, к третьей фазе исполняет фикцию. Лестница чинит
оба провала: research даёт эпику доказательную базу, мета-план показывает владельцу всю форму один
раз, пофазные операционные планы удерживают теряющую контекст сессию на ПРАВИЛЬНОМ следующем шаге.

Канон: `AGENT_GUIDE.md` → «Дисциплина планирования — лестница задач».

## Шаг 0 — подтверди тяжесть

Прогони тест тяжести (≥2 из: ≥3 подсистемы/канон-документа · внешняя правда или индустриальный
стандарт · больше одной сессии · меняет состав поставки/контракты · решения владельца). НЕ
тяжёлая → переключайся на `/plan-task`: лестница на обычной задаче — церемония, перевешивающая
работу.

## Ступень 1 — research (первый артефакт эпика; до него ни кода, ни мета-плана)

Синтезируй ТРИ источника в один research-документ `researches/NN_<эпик>.md`:

1. **Гуглёж индустрии:** золотые стандарты, лучшие практики, научные работы, зрелый опенсорс по
   этому классу задач. У каждого утверждения — URL источника; выдуманных ссылок не бывает.
   Записывай и антипаттерны — знать, от чего индустрия отказалась, — половина ценности.
2. **Локальная разведка:** как реально стоят код/документы/данные проекта там, куда ляжет эпик
   (читать, не вспоминать); прошлые наработки в `researches/` и уроки в `EXPERIENCE.md`.
3. **Требования:** просьба владельца дословно, стыковка с `GOAL.md`/`MASTER_PLAN.md`, ограничения.

Финал документа: находки → следствия для ЭТОГО эпика → открытые развилки владельцу. Большой массив
источников можно извлекать субагентами — но только со схемой дословных цитат и механической
проверкой цитат (находка — не находка, пока не верифицирована; метод — EXP-0015).

## Ступень 2 — мета-план (один `plans/NN_EPIC_<имя>.md`)

- **Пиши его в файл с именем `NN_EPIC_<имя>.md`** — пометка и есть то, что делает эпик видимым в
  беклоге по одному имени файла, до того как его кто-то открыл (`plans/README.md` → «Именование»).
- Мета-план ОТКРЫВАЕТСЯ вектором цели эпика — *какую боль решаем и где хотим оказаться* — и
  критериями приёмки всего эпика (наблюдаемые, где возможно — исчислимые), написанными по
  `REQUIREMENTS_FRAMEWORK.md`; вектор и критерии модифицируются по мере того, как учат фазы, —
  правка вектора — это правка, а не провал.
- Фазы с явным ПОРЯДКОМ и его обоснованием; зависимости между фазами.
- Гейты: что должно быть истинно для входа/закрытия фазы (сборка зелёная, стражи доказаны
  умеющими краснеть, судья пройден — по `TESTING_FRAMEWORK.md`).
- Развилки уровня видения → `/interview` (незаблокированные фазы идут параллельно);
  двусмысленность уровня задачи → один точечный вопрос в чате.
- Мета-план коммитится до исполнения чего-либо.

## Ступень 3 — операционный план ТОЛЬКО ближайшей фазы

Детализируй ТОЛЬКО предстоящую фазу (R&D · тестирование · макетирование · разработка · отладка ·
приёмка — что применимо): шаги с чекбоксами, верификация каждого шага, риски. Операционный план
наследует открывающий блок — вектор цели и критерии приёмки САМОЙ фазы первыми
(`REQUIREMENTS_FRAMEWORK.md`). **Фаза тестирования планируется ПО тестовым артефактам, которые
написали производящие фазы** — своды, кейсы, чек-листы, фикстуры, названные путями; фаза
тестирования, чьих артефактов ещё не существует, — это фаза, которая выдумает себе верификацию в
последний момент (`TESTING_FRAMEWORK.md` → «Работа производит и средство своей проверки»). Дальние фазы остаются скелетами в мета-плане. **Операционный план фазы N+1 пишется на закрытии фазы N** — со
всем, чему научила фаза N.

Файл ребёнка называется **`NN_epicMM_<фаза>_<имя>.md`**, где `MM` — номер родительского эпика:
ребёнок эпика называет родителя в собственном имени, и семья читается прямо из листинга
директории, без открытия хотя бы одного документа. (Этих детей пишет `/plan-task`.)

## Ступень 4 — трассировка и исполнение

- Каждый операционный шаг цитирует строку-якорь мета-плана (правило цитирования, чек-лист шаг 7);
  шаг без якоря — дрейф скоупа, пойманный до диффа. Трассировку несут имя и цитата вместе: имя
  ребёнка говорит, КАКОМУ эпику он служит, процитированный якорь — КАКУЮ его строку исполняет шаг.
- Каждая фаза исполняется по fable-циклу; `/fable-judge`-проход закрывает фазу ДО написания
  операционного плана следующей.
- Отмечай мета-план по закрытию фаз; на закрытии эпика — секция «Решения, принятые без владельца».

## Что навык ЗАПРЕЩАЕТ

- Начинать кодить, «пока research отлёживается» — research И ЕСТЬ первый артефакт эпика.
- Писать все операционные планы заранее — фаза N+1 планируется с уроками фазы N, не раньше.
- Считать гуглёж опциональным — «я знаю этот домен» — это память сессии, а память выдумывает.
- Растворять развилки владельца в дефолтах — развилки видения идут в `/interview`, видимо.
