# /plan-task — один операционный план для обычной задачи

Неспланированная задача исполняется импровизацией, а импровизация не переживает теряющую контекст
сессию. ОБЫЧНОЙ задаче положен ровно ОДИН артефакт: короткий операционный план, который свежая
сессия может исполнить и по которому судится работа. Без лестницы и фаз — это территория
`/plan-epic`, и тащить церемонию эпика на маленькую задачу так же неправильно, как пропустить
планирование на большой.

## Шаг 0 — тест тяжести (канон: AGENT_GUIDE.md → «Дисциплина планирования»)

Задача ТЯЖЁЛАЯ, если выполняются **≥2** из:

- трогает ≥3 подсистемы или канон-документа;
- опирается на внешнюю правду или индустриальный стандарт;
- не помещается в одну сессию;
- меняет состав поставки или публичные контракты;
- требует решений владельца.

ТЯЖЁЛАЯ → стоп, переключайся на **`/plan-epic`** (скажи об этом одной строкой в чате). Иначе — дальше.

## Шаг 1 — сбор (минуты, не часы)

- Исходный документ (`ideas/NN`, `bugs/NN` или просьба владельца дословно).
- Релевантный срез карты (`PROJECT_ARCHITECTURE_INTERNAL_MAP.md` — blast radius).
- Греп `EXPERIENCE.md` по тегам задачи — процитируй релевантные уроки или скажи «нет таких».
- Задача опирается на внешнюю правду — сначала разведдок (чек-лист, шаг 8); планировать по памяти
  значит выдумывать.

## Шаг 2 — написать план

Структура (по возможности — один экран):

```
## План: <цель одной строкой>
**Готово, когда:** <наблюдаемые критерии — что будет ВИДНО работающим, не «код написан»>
**Шаги:**
- [ ] <шаг — достаточно мелкий, чтобы проверяться сам по себе>
- [ ] ...
**Верификация:** <как наблюдается каждое утверждение: прогон, рендер, замер, страж>
**Риски:** <топ-1..3, у каждого — реакция на срабатывание (ранжирование Мерфи из PHILOSOPHY.md)>
```

Размещение: план совсем маленькой задачи живёт **секцией в её документе идеи/бага**; покрупнее —
своим `plans/NN_<имя>.md`. В обоих случаях план коммитится до начала работы
(`node tools/commit.mjs "<msg>"`).

## Шаг 3 — допуск, затем вперёд

- План задевает территорию владельца (бренд, UX, архитектура, канон)? Сначала подними развилку —
  один точечный вопрос в чате для двусмысленности уровня задачи, `/interview` для уровня видения.
- Иначе — исполняй сразу (fable-цикл, чек-лист шаг 6): план — стоячая авторизация на собственные
  обратимые шаги.

## Что навык ЗАПРЕЩАЕТ

- Планировать эпик плоским списком шагов (тест тяжести ловит дрейф скоупа на планировании, а не
  посреди исполнения).
- План без критериев «готово» и верификации — «шаги сделаны» ≠ «задача сделана»
  (`TESTING_FRAMEWORK.md`: сырому доверия нет).
- Пропустить план, потому что «задача понятна» — понятна ЭТОЙ сессии; план пишется для следующей.
