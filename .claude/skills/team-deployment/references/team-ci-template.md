# team-ci — CI-workflow, который едет с командой

> Шаблон навыка KAIF `team-deployment` (операция 3, шаг 6; приказ владельца в issue #29 истока:
> «CI должен поставляться вместе с деплойментом команды»). Скопируй fenced-блок ниже в
> `.github/workflows/team-ci.yml` проекта — по «да» владельца, как и каждый артефакт операции 3, —
> и заполни каждый плейсхолдер в `<угловых скобках>`.

## Констрейнты (назови их в § 5 конституции; держи здесь)

1. **Только дешёвые гейты** — юниты, линт, проверка типов. Без секретов, эмуляторов, живого
   стенда, устройства: тяжёлые динамические проверки остаются ЛОКАЛЬНО за замком стенда
   (конституция § 7).
2. **Команды ЧИТАЮТСЯ, никогда не угадываются** — бери их из скриптов `package.json` или из
   канона сборки проекта (`AGENT_GUIDE.md`). Неизвестная команда остаётся именованным
   плейсхолдером для владельца: job, гоняющий не ту команду, хуже отсутствующего (ложный зелёный).
3. **Красный блокирует мерж** — красный прогон ролевой ветки блокирует запрос на мерж так же, как
   отсутствующий вердикт судьи; Менеджер не мержит ничего красного (конституция § 5).
4. **Не-GitHub remote** — тот же job гоняется документированным локальным pre-push скриптом,
   названным в § 5 конституции; возможность деградирует изящно, никогда молча.
5. **Один job, не более трёх шагов-гейтов** — командный CI, разросшийся в пайплайн, принадлежит
   собственному CI-канону проекта, а не этому шаблону.

## Workflow

```yaml
name: team-ci
on:
  push:
    branches: ['main', '<project>-team-*']   # the role-branch pattern of the naming invariant (§ 1)
  pull_request:
    branches: ['main']
jobs:
  gates:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4            # <replace with the project's toolchain setup action>
        with: { node-version: '<major from .nvmrc / engines>', cache: npm }
      - run: npm ci                            # <the project's install command>
      - run: <unit-test command>               # gate 1 — from package.json / the build canon
      - run: <lint command>                    # gate 2
      - run: <typecheck command>               # gate 3 — drop the line if the stack has none
```

## Локальный pre-push (не-GitHub remote)

`<команда pre-push>` — те же три гейта в том же порядке, подключённые как хук `pre-push`
репозитория или как документированный скрипт проекта; § 5 конституции называет его, чтобы ни одно
место не могло заявить, что проверка к нему не относилась.
