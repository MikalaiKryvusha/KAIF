# /what-next — предложить следующие шаги наибольшей ценности

Иногда агент останавливается и ничего не предлагает. Этот навык — ответ одной командой на простой вопрос
владельца — **«что дальше?»** — план следующих шагов, ранжированный по ценности для видения владельца.

## Процедура

### Шаг 1. Сориентируйся (дёшево, без глубокого погружения)
Прочитай `GOAL.md` (видение), `MASTER_PLAN.md` (текущая фаза), `STATUS.md` (где мы), пройдись по
открытому беклогу: `bugs/`, `ideas/`, `plans/`, `homeworks/` без тега `DONE`, плюс неотвеченные
`interviews/`.

### Шаг 2. Ранжируй по ценности
Сначала — по знаменателю: сдвигает ли шаг компоненту вектора доставки (`DELIVERY: systems ·
complete · integrated · holes · contradictions · bugs` — `node dist/KAIF-CORE.mjs delivery` из
`SYSTEMS_REGISTRY.md`, `MASTER_PLAN.md` §8; реестра нет → составить его И ЕСТЬ первый шаг, а не
вопрос владельцу) или разблокирует ближайший прогон редкого ресурса (живой вечер
владельца, машину, устройство)? Только затем упорядочь остальное по **ценности для видения**
согласно `PHILOSOPHY.md`: Парето (немногое жизненно важное), матрица Эйзенхауэра (важно × срочно),
эффекты второго порядка (что разблокирует больше всего будущей работы). Новейшая боль — НЕ
приоритет сама по себе: свежий инцидент получает ранг по метрике, а не по дате (поле: 54 честных
зелёных сессии сдвинули продукт на 11 из 389). Отметь примерную трудоёмкость каждого.

### Шаг 3. Ответь в чате — ФИКСИРОВАННОЙ ФОРМОЙ (KAIF 2.6, тикет origin #53)
Правило «свежая боль — не заявка на приоритет» стояло здесь прозой, и полевой агент процитировал его и
нарушил тем же ответом. Проза не ранжирует; ранжирует форма. Ответ ОТКРЫВАЕТСЯ двумя строками,
прочитанными из документов, а не по памяти, затем таблица, затем две обязательные строки:

```
METRIC: <вектор DELIVERY — `node dist/KAIF-CORE.mjs delivery` (в поле: `node .kaif/kaif-core.mjs delivery`), с датой>
MAIN PHASE: <фаза, которую MASTER_PLAN.md помечает «ГЛАВНОЕ СЕЙЧАС»; пометки нет → первая незакрытая фаза, и скажи об этом>

| шаг | moves | closes | трудоёмкость |
|---|---|---|---|
| 1. <шаг> | <компонента метрики, которую сдвигает, или —> | <bugs/NN, plans/NN, которые закрывает, или пусто> | <чатов> |

Свежие слова владельца — не ранжированы метрикой (→ /fix-vision): <слова за 48 ч, ещё не вписанные в GOAL/MASTER_PLAN, или «нет»>
Техдолг: открытых багов N · красных M · разъехавшихся пар K
```
Правила таблицы: у каждой строки `moves` (или `—`) и `closes`; строка с `moves: —` и пустым `closes`
НИКОГДА не стоит выше строки, у которой есть хотя бы одно, — и строка 1 в частности сдвигает метрику или
закрывает что-то. Свежее слово владельца получает ранг по метрике, а не по дате: пока `/fix-vision` не
вписал его в GOAL/MASTER_PLAN, оно лежит на полке — видно, записано, НЕ ранжировано. Строка долга стоит
всегда (посчитай открытые баги, красные, разъехавшиеся пары реестра). Затем:
1. **ОДИН следующий шаг** — строка 1, и *почему именно он* (свяжи с GOAL/MASTER_PLAN).
2. **2–4 запасных** — остальные строки таблицы, по строке на каждый.
3. **Заблокировано на владельце** — открытые интервью/домашки, если есть.
Черновик — через линт ДО печати: `node .kaif/tools/kaif-ranking-lint.mjs check <черновик.md>` (в истоке —
`node framework/tools/kaif-ranking-lint.mjs check …`) — код 1 называет, чего нет (`METRIC:`, свежее слово в
строке 1, полка, строка долга); код 3 — ответа не увидел.

### Шаг 4. Предложи начать
Предложи немедленно взять верхний шаг; по подтверждению владельца (или в автономном цикле) — начинай.
Неспланированный шаг сначала планируется: `/plan-task` для обычного, `/plan-epic` — если тест
тяжести говорит «тяжёлый».

## Правила
- Никогда не отвечай «делать нечего»: пустой беклог означает — предложи `/check-backlog` или
  `/refresh-context`, работу над качеством/долгом или `/interview` для пополнения видения.
- Будь конкретен: шаги с именами и файлами, а не общие слова.
