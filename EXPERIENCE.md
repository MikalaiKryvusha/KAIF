# EXPERIENCE (ОПЫТ) — накопленный опыт ИИ-агента

> Растущий журнал уроков — **вынесенная память о том, *что работает, а что нет***, чтобы свежая сессия
> (или автономный цикл) без контекста не наступала повторно на те же грабли. **Свернись** сюда ПЕРЕД
> задачей, **допиши** ПОСЛЕ значимой попытки (успех **или** провал). Ищи грепом, не листай.
>
> **Теги стоят инлайн на каждой записи** (не в общем списке) — чтобы один греп находил опыты напрямую:
> `grep '#loop' EXPERIENCE.md` · `grep -i '#context\|#build' EXPERIENCE.md` · `grep '❌' -A4 EXPERIENCE.md`
> · `grep 'EXP-0002' EXPERIENCE.md`. Переиспользуй существующий тег, если подходит (грепни, чтобы увидеть).
>
> **Формат записи (коротко и греп-дружелюбно).** Новые — сверху. id `EXP-NNNN` · ISO-дата · маркер
> `✅`/`❌`/`❌→✅` · инлайн-`#теги` + поля **Repro:** (готовая команда/проверка, применяющая урок —
> слабая сессия исполнит команду, но не эссе; **с 2.1 ОБЯЗАТЕЛЬНА — урок без Repro-строки не
> принимается**; правда нет команды — назови, что НАБЛЮДАТЬ, но назови действием), **Trigger:**
> (для классовых уроков — точка решения, в которой урок применять: «пишешь X → прогони Y») и
> **Not for:** (граница применимости — где урок НЕ действует: документированный урок — тоже
> гипотеза, вне своего диапазона он убивает верные идеи).
> **Повторившийся урок — урок, проваленный как текст:** класс всплыл в НОВОМ коде после записи →
> урок обязан стать исполняемым (линтер, страж, гейт) со строкой `механизировано: <инструмент>`
> в самой записи. Два раза — механизм, третьего напоминания не бывает.
> Навык: `/experience`. Живой справочник — тегом `DONE` не помечается.
>
> **Теги — триггерные:** перед задачей грепни по её тегам и ПРОЦИТИРУЙ релевантные уроки в отчёте
> (id + строка) — или скажи «релевантных нет». Непроцитированный recall непроверяем; `/fable-judge`
> ищет эту строку.

## Записи

### EXP-0032 · 2026-08-07 · ❌→✅ · #grep #cyrillic #windows #verification #judge
**Ситуация:** судья фазы N2 получил ложные 23/27 на dogfooding-скане планов: git-bash `grep -i`
не кейс-фолдит кириллицу («Критерии приёмки» не матчится паттерном `критерии`), а байтовый класс
`[А-Яа-я]` ложно матчит пунктуацию («—», «ёлочки») — обе стороны отказа воспроизведены живьём.
**Что делали:** переисполнение Unicode-корректным node-сканом (свойства письменностей / точные
строки в нужном регистре) дало 27/27; находка судьи опровергнута его же переисполнением.
**Итог:** ✅ вердикт фазы честный; класс задокументирован.
**Урок:** на Windows git-bash `grep` по кириллице ненадёжен в ОБЕ стороны: `-i` не кейс-фолдит
не-ASCII (ложный красный), байтовые диапазоны матчат мусор (ложный зелёный/красный). Проверки
русского текста строй node-скриптом со свойствами Unicode (как EXP-0030) или грепом ТОЧНОЙ
строки без `-i` и без диапазонов (форма `[Кк]ритерии` — явные обе буквы — тоже легальна).
**Repro:** `printf 'Критерии\n' | grep -i 'критерии'` → пусто на git-bash (ложный красный);
`printf 'em—dash «x»\n' | grep -E '[А-Яа-я]'` → совпало (ложный позитив); node
`\p{Script=Cyrillic}`/`toLowerCase()` — корректен.
**Триггер:** пишешь bash-проверку/стража с кириллическим паттерном → либо точная строка с
явным регистром (`[Кк]…`), либо node-скан; `-i` и `[А-Яа-я]` — запрещённые формы.
**Not for:** ASCII-паттернов (там `grep -i` честен); GNU grep на Linux с UTF-8-локалью
(там кейс-фолд кириллицы работает — класс специфичен окружению Windows/git-bash).

**Урок:** канон-документ — не летопись и не конспект: (а) мета-комментарий о структуре текста

**Repro:** перед сдачей канон-текста — греп `чат 20|идея [0-9]|слово владельца|дополняет до|итого|тройка:|the triad:` по нему → каждое совпадение: механизм вместо этикетки, происхождение — в план.
**Триггер:** пишешь/правишь канон-документ (ключевые доки, payload-шаблоны) → прогони греп из
Repro до сдачи.
**Not for:** планов, закрытий, летописи, баг-доков — там происхождение и комментарий структуры
и есть содержание.

### EXP-0027 · 2026-08-07 · ❌→✅ · #windows #harness #browser #signals #timeouts
**Ситуация:** QA-прогон интерактивного контура (K5): (1) тест исхода «прерван человеком»
через `process.kill(pid, 'SIGINT')` УБИЛ сам прогон — на Windows libuv не эмулирует сигналы,
а завершает процесс; (2) проверка «мёртвый сервер» с фиксированной задержкой 1.2 с была
ложно-красной: Chrome переиспользует keep-alive-сокет убитого сервера и ждёт TCP-таймаут —
отказ fetch проявился только через ~2 с; (3) EPERM уборки временного профиля сразу после
SIGKILL браузера маскировал настоящую ошибку теста (throw в finally затирает исходный throw).
**Что делали:** (1) слушателей поднимаем `process.emit('SIGINT')` — ОС не участвует;
(2) проверка опрашивает DOM до дедлайна, как человек у экрана, и печатает фактическое время
проявления; (3) rmSync с maxRetries + пауза после kill; краш прогона больше не обнуляет счёт
зелёных (честный репорт).
**Итог:** ✅ QA-прогон 75/75; все три ловушки задокументированы в коде.
**Урок:** харнесс, тестирующий СМЕРТЬ процесса/сервера на Windows: сигналы себе не шли —
эмитируй слушателей; после внезапной смерти сервера жди отказ клиента ПОЛЛИНГОМ до дедлайна
(keep-alive живёт дольше процесса); уборку в finally делай нетеряющей — throw в finally
съедает настоящую причину падения.
**Repro:** тест исхода сигнала → `process.emit('<SIGNAL>')`; тест мёртвого сервера → kill →
цикл опроса состояния с дедлайном ≥ 20 с и печатью фактического времени; finally → только
терпимые операции (try/catch вокруг каждой).
**Триггер:** пишешь тест, где процесс/сервер умирает или получает сигнал, на Windows →
проверь все три пункта до первого прогона.
**Not for:** POSIX-окружений (там kill(SIGINT) честный); проверок, где сервер закрывается
штатно (close шлёт FIN — отказ мгновенный).

### EXP-0026 · 2026-08-07 · ❌→✅ · #registry #commands #escaping #guards
**Ситуация:** фаза K3: команда реестра пар в AGENT_GUIDE (сверка «состав навыков ↔ таблицы
README») при дословном запуске напечатала 0 вместо 68 — ложный красный сверки на живом
документе. Причина: обратные слэши перед бэктиками в паттерне — артефакт экранирования под
markdown-ячейку; GNU grep читает `\`+бэктик как якорь начала буфера, и паттерн НЕ МОЖЕТ
совпасть по построению. Как прошлые сессии получали 68 — не логировалось (видимо,
де-экранировали молча).
**Что делали:** паттерн переписан без конфликтующих с разметкой символов
(`grep -c '^| [*.]*./' README.md`); эквивалентность доказана счётом на живом README (68 = 68
против де-экранированной формы).
**Итог:** ✅ команда реестра исполняется копипастой из файла в любом шелле.
**Урок:** канонический однострочник в документе обязан быть КОПИ-ИСПОЛНИМЫМ дословно: команда,
требующая молчаливого де-экранирования читателем, даёт ложный красный по построению (а при
удачном совпадении — ложный зелёный). Паттерны для команд, живущих в markdown-таблицах, строй
из символов, не конфликтующих с разметкой носителя (без бэктиков).
**Repro:** скопируй команду из ячейки реестра БУКВАЛЬНО в шелл → вывод обязан совпасть с
заявленным числом; расхождение = чини команду, не окружение.
**Триггер:** вписываешь исполняемую команду в md-документ (реестр пар, ритуал, Repro-строка) →
прогони её копипастой ИЗ ФАЙЛА, не из головы/чата.
**Not for:** строк-намерений («что наблюдать»), явно не являющихся shell-командами.
