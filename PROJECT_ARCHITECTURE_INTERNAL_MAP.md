# Krinik AI Framework (KAIF) — внутренняя карта архитектуры

Логическая архитектура *этого* репозитория: абстракции, которыми оперирует проект (сфера — «мета/фреймворк»),
их суть и взаимодействия. Спутник — `PROJECT_STRUCTURE_EXTERNAL_MAP.md` (внешняя структура: где что лежит).
Авторитетный справочник абстракций — пояснительная записка `KAIF_REFERENCE.md` (EN, §1–16): источник в
`framework/`, корневая копия генерируется сборкой, развёрнутым проектам едет в `.kaif/`; эта карта — её
проекция на сам исток.

## Как они взаимодействуют (поток генерации и поставки)

```
framework/** ──build-framework.mjs──▶ KAIF.md (тонкое) + dist/{CORE, BUNDLE, manifest, FULL, module-map}
                     │                                   │
                     └── в конце сама исполняет ─────────▶ check-framework.mjs (валидатор + стражи + пин карты)

Целевой проект:  KAIF.md ─▶ KAIF-LOADER (sha256) ─▶ KAIF-CORE ─▶ install/update по бандлу
                 классификация по-модульно (template-sha ─ право замены; owner/adaptive/localized ─ защита)
                 ─▶ задание агенту (только суждение: мерджи, локализация, конвенции владельца)
                 ─▶ чекпоинты (исполняющие) ─▶ update-verify == verify-final гейты ─▶ расписка + history
```

## Контуры KAIF — инвентарь и границы

Определение и анатомия термина — `AGENT_GUIDE.md` → «Контуры» (границы · правила · исполнительный
слой · контроль качества). Ниже — инвентарь контуров этого проекта, по строке на контур; колонка
**Судьба границ** обязательна для каждой строки: «чёткие» / «размыты → переформулированы (ссылка)»
/ «размыты → осознанный долг с адресом в беклоге». Строк без судьбы быть не должно — счёт по

## Инварианты модели

- **Полезная нагрузка — единственный источник.** Корневой `KAIF.md` и весь `dist/` **генерируются**;
  править руками нельзя.
- **Два слоя не смешиваются.** Улучшение *шаблона* → правь `framework/` и пересобирай; улучшение *ведения
  этого проекта* → правь корневую обвязку. Обычно двигать оба синхронно.
- **Язык.** Полезная нагрузка — английская; обвязка — русская (agent-facing вендоренные навыки — EN,
  политика 1.6); содержание держим синхронным.
- **DRY.** Шаблон живёт один раз в `framework/` и встраивается в артефакты; счётчики вычисляются сборкой,
  а не переписываются прозой (bugs/09).
- **Право замены — только у template-sha.** Дисковый sha — состояние, шаблонный — происхождение; замена
  без совпадения происхождения запрещена по построению (bugs/06, 12).
- **Канонический порядок.** Всё сравниваемое/кэшируемое детерминировано: сортировки с тай-брейком,
  сериализация с сортировкой ключей, никаких Date.now/random в диффуемом.
- **Верификация живёт в репо.** Свод пишется в тот же шаг, что фича; смертный скретчпад = смертная
  верификация (EXP-0016); каждый страж доказан красным на сломанной версии.
- **Временный корень прогона уникален по построению.** Ни один инструмент не берёт каталог в общем
  OS-temp по фиксированному имени — только через `tools/lib/temp-root.mjs` (`mkdtemp`): фиксированное
  имя есть разделяемый ресурс без владельца, и два одновременных прогона давали ЛОЖНЫЙ КРАСНЫЙ в
  главном гейте (bugs/59). Ось стережёт преполёт `npm run test:core`.

## Ключевые решения, зашитые в архитектуру

- Само-извлечение: всё нужное для развёртывания — внутри артефактов поставки (`MASTER_PLAN.md`, журнал
  решений №3/№8: тонкое ядро + машинерия из origin, оффлайн-фолбэк FULL).
- Этапная распаковка (v1.1) и механическая распаковка (v1.2, bugs/01): слабые системы не захлёбываются.
- Сигнатурные якоря вместо тегов в документах (решение №16); классы модулей вычисляются.
- Локализация — поле `i18n` + эвристика письменности, пакеты не расширяются (решение №17).
- kaif-provenance — опциональный инструмент, не ядро (решение №19); grep-ступень первой, token-F1 второй.
- Судья перед каждым push/деплоем (решение №13); релиз — только по явному «да» владельца.
