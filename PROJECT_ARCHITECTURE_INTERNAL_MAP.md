# Krinik AI Framework (KAIF) — внутренняя карта архитектуры

Логическая архитектура *этого* репозитория: абстракции, которыми оперирует проект (сфера — «мета/фреймворк»),
их суть и взаимодействия. Спутник — `PROJECT_STRUCTURE_EXTERNAL_MAP.md` (внешняя структура: где что лежит).
Авторитетный справочник абстракций — пояснительная записка `KAIF_REFERENCE.md` (EN, §1–16): источник в
`framework/`, корневая копия генерируется сборкой, развёрнутым проектам едет в `.kaif/`; эта карта — её
проекция на сам исток.

## Ключевые абстракции

| Абстракция | Что это (суть) | Ответственность |
|------------|----------------|-----------------|
| **Полезная нагрузка** (`framework/`) | Канонические универсальные шаблоны (EN) | Единственный источник истины того, что разворачивается в чужие проекты. |
| **Тонкое ядро** (`KAIF.md`) | Точка входа: 3-шаговый бутстрап + встроенный загрузчик | Приводит машинерию из origin с sha256-верификацией; транзиентно в целевом проекте. |
| **Загрузчик** (`KAIF-LOADER.mjs`) | Скрипт доставки | Каналы release/main/`--source`, проверка sha256 по `kaif-manifest.json`. |
| **Машинерия** (`KAIF-CORE.mjs` → `.kaif/kaif-core.mjs`) | Исполняемый установщик/обновлятор | Все механизируемые шаги: install/check/update/diff/adopt-current/checkpoint/verify-final/update-verify/sync/modules; финальные гейты. |
| **Бандл** (`KAIF-CORE-BUNDLE.md`) | Весь комплект поставки FILE:-блоками + мета-блок | Источник файлов для установки/обновления; несёт templateNotes/policyChanges/deprecations/классы модулей по версиям. |
| **Полное ядро** (`dist/KAIF-FULL.md`) | Классический самораспаковывающийся документ | Оффлайн-фолбэк (подмножество: без языков/сфер/tool-модулей); last-resort кандидат синтетического слепка. |
| **Повествовательный стержень** (`framework/_intro.md`) | Проза ядра с маркерами `{{…}}` | Задаёт структуру и инструкции распаковки; счётчик навыков `{{SKILL_COUNT}}` вычисляется сборкой. |
| **Встраиваемый блок** (`> **FILE: …**`) | Помеченный файл-шаблон в ядре/бандле | Говорит распаковщику, какой файл создать; ограждение из 6 бэктиков. |
| **Модуль** (эпик №1 2.0) | Логическая секция шаблона — атом диффа и замены | От заголовка до заголовка; адрес — **сигнатурный якорь** (полная уникальная строка-заголовок), номера строк — производные. |
| **Карта модулей** (`dist/kaif-module-map.json`) | Сгенерированный реестр модулей: якорь · класс · sha | Классы ВЫЧИСЛЯЮТСЯ (`static`/`adaptive`/`owner`; оверрайды — `framework/module-classes.json`); валидатор сверяет карту пересплитом, пин «сплиттер ядра == сплиттер сборки» исполняется на каждой сборке. |
| **Манифест деплоя** (`.kaif/deploy-manifest.json`, v2) | Снапшот-реестр развёртывания | `templateShas` (что развернула версия; EOL-норм) ≠ `shas` (что на диске; побайтно); право механической замены даёт ТОЛЬКО совпадение template-sha; происхождение kept. |
| **Расписка** (`.kaif/last-update.json` + `history` маркера) | Доказательство обновления | from/to/route/date/counters/diverged; `verifiedAt` штампуется update-verify и переживает самоочистку. |
| **Навык** (`framework/skills/<name>/SKILL.md`) | Повторяемый ритуал с YAML-фронтматтером | Глагол работы (`/resume`, `/pause`+`/end-chat`, циклы, `/fable-*`, lifecycle…); счётчик печатает сборка. |
| **Языковой пакет** (`framework/templates/languages/<lang>/`) | Owner-доки + триггер-алиасы на языке владельца | 9 пакетов; навыки остаются EN; поле маркера `i18n: translated` выключает молчаливую замену локализованного. |
| **Сфера** (`framework/spheres/*`) | Библиотека терминов домена + улики/фроды | Адаптирует терминологию и критерии верификации к сфере. |
| **Адаптер** (`framework/adapters/*`) | Проводка под агентскую систему | Куда класть контекст и как транслировать навыки (Zoo Code — приоритет №1). |
| **Опциональный tool-модуль** (`framework/tools/*` → `.kaif/tools/`) | Исполняемые гвардрейлы поставки | `kaif-provenance` (гейт пометок `[AI]`/`[AI-ed]`, реестр приёмки) · `kaif-canon-lint` (запрещённые формулировки / стерегомые строки + selftest). |
| **Полигон** (`tools/sandbox-suite.mjs` + `tools/sandbox/s01–s09`) | Постоянный песочный стенд машинерии | проверки по матрице полевых профилей (число печатает полигон); обязателен после правок installer/tools/сборщика и перед релизом. |
| **Обвязка** (корневые доки + `.claude/`) | KAIF, применённый к самому себе | Dogfooding: ведёт разработку самого фреймворка. |
| **Маркер** (`.kaif/kaif.json`) | Запись развёртывания (Reference §12.1) | framework/version/released/origin/tracking/sphere/`agents`/`language` (+ `i18n`, `canonArtifacts`, `history`); схема валидируется `check`. |

## Как они взаимодействуют (поток генерации и поставки)

```
framework/** ──build-framework.mjs──▶ KAIF.md (тонкое) + dist/{CORE, BUNDLE, manifest, FULL, module-map}
                     │                                   │
                     └── в конце сама исполняет ─────────▶ check-framework.mjs (валидатор + стражи + пин карты)

Целевой проект:  KAIF.md ─▶ KAIF-LOADER (sha256) ─▶ KAIF-CORE ─▶ install/update по бандлу
                 классификация по-модульно (template-sha ─ право замены; owner/adaptive/localized ─ защита)
                 ─▶ задание агенту (только суждение: мерджи, локализация, конвенции владельца)
                 ─▶ чекпоинты (исполняющие) ─▶ update-verify == verify-final гейты ─▶ расписка + history
```

## Инварианты модели

- **Полезная нагрузка — единственный источник.** Корневой `KAIF.md` и весь `dist/` **генерируются**;
  править руками нельзя.
- **Два слоя не смешиваются.** Улучшение *шаблона* → правь `framework/` и пересобирай; улучшение *ведения
  этого проекта* → правь корневую обвязку. Обычно двигать оба синхронно.
- **Язык.** Полезная нагрузка — английская; обвязка — русская (agent-facing вендоренные навыки — EN,
  политика 1.6); содержание держим синхронным.
- **DRY.** Шаблон живёт один раз в `framework/` и встраивается в артефакты; счётчики вычисляются сборкой,
  а не переписываются прозой (bugs/09).
- **Право замены — только у template-sha.** Дисковый sha — состояние, шаблонный — происхождение; замена
  без совпадения происхождения запрещена по построению (bugs/06, 12).
- **Канонический порядок.** Всё сравниваемое/кэшируемое детерминировано: сортировки с тай-брейком,
  сериализация с сортировкой ключей, никаких Date.now/random в диффуемом.
- **Верификация живёт в репо.** Свод пишется в тот же шаг, что фича; смертный скретчпад = смертная
  верификация (EXP-0016); каждый страж доказан красным на сломанной версии.

## Ключевые решения, зашитые в архитектуру

- Само-извлечение: всё нужное для развёртывания — внутри артефактов поставки (`MASTER_PLAN.md`, журнал
  решений №3/№8: тонкое ядро + машинерия из origin, оффлайн-фолбэк FULL).
- Этапная распаковка (v1.1) и механическая распаковка (v1.2, bugs/01): слабые системы не захлёбываются.
- Сигнатурные якоря вместо тегов в документах (решение №16); классы модулей вычисляются.
- Локализация — поле `i18n` + эвристика письменности, пакеты не расширяются (решение №17).
- kaif-provenance — опциональный инструмент, не ядро (решение №19); grep-ступень первой, token-F1 второй.
- Судья перед каждым push/деплоем (решение №13); релиз — только по явному «да» владельца.
