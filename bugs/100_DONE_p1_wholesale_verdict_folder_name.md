## Механизм (чтение кода, `framework/installer/KAIF-CORE.mjs` на build 427)

1. **Вердикт считает заголовки.** `mergeModules`: `baseFound` = число сигнатур baseline
   (заголовков старого шаблона), найденных на диске; `wholesaleCeiling = floor(baseN × 0.15)`
   (при `baseN ≤ 2` — 0); `localized && baseFound ≤ ceiling → frozen`, иначе `merged`.
   У `AGENT_GUIDE.md` 2.4 `baseN` ≈ 40 → потолок 6: перевод, оставивший 6 английских
   заголовков-терминов, замерзает; 7 — сливается. Граница узкая: **±1 сигнатура меняет исход.**
2. **H1 несёт плейсхолдер.** Сигнатура H1 гайда — `# <PROJECT_NAME> — AI Agent Guide` (после
   заполнения — `# <имя> — AI Agent Guide`). Это ЕДИНСТВЕННАЯ сигнатура документа, зависящая
   от значений развёртывания (bug 26 уже знает этот класс: «дрейф сигнатуры H1 при смене
   значений плейсхолдеров»).
3. **Синтетический baseline заполняется значениями ЭТОГО дерева.** `buildSyntheticBaseline`
   режет старый релиз «как деплой»: `stableValues()` — замороженные `values` из
   `.kaif/deploy-manifest.json`, а при их ОТСУТСТВИИ — повторная детекция (`detectValues`):
   `<PROJECT_NAME>` берётся из `package.json` `name`, иначе из **имени папки** (пункт задания
   `project-name` прямо называет этот fallback: «came from a technical identifier
   (package.json/folder)»).
4. **У развёртывания 1.6 манифест v1 — без `values`.** Значит в каждой папке baseline
   заполняется заново. Репетиция шла в git-archive-копии в ВРЕМЕННОЙ папке (`<tmpdir>/…`), бой —
   в папке проекта: если `<PROJECT_NAME>` резолвится из имени папки (в проекте без `name` в
   `package.json`, либо там, где `package.json` не в корне копии), H1 baseline в копии
   получает ДРУГОЕ имя → эта сигнатура на диске не находится → `baseFound` на 1 меньше →
   для файла, стоящего у потолка, вердикт переваливает из `merged` во `frozen` (или обратно).
   Прогон, который считает `baseFound = ceiling`, замораживает; прогон с `baseFound = ceiling + 1`
   сливает. Ровно «20 wholesale против 19».
5. **Почему полигон этого не видит:** каждый свод разворачивает дерево в одной папке; сравнение
   «две папки, одно дерево» ни один свод не делает. s18 U3 сравнивает два `diff --source` по
   ОДНОЙ копии — детерминизм внутри папки, не между папками.

## Что НЕ объясняет гипотеза (честная граница)

Если в дереве Prompt Modding `package.json` с полем `name` лежал в корне и копия его сохранила —
`<PROJECT_NAME>` в обеих папках одинаков и механизм 4 не срабатывает; тогда искать надо в других
детектируемых значениях, попадающих в ЗАГОЛОВКИ (`<AUTHOR>`, `<REPO_URL>` в H1/H2 модулей
других документов — `git remote` в копии без remote даёт `null`), либо в различии наборов
файлов (в git-archive нет игнорируемых `.kaif/install/`, `KAIF_UPDATE_TASK.md` — на
классификацию они не влияют, но `readOwnerText`/`canonicalName()` читают маркер, а не папку).
Проверяется тем же сводом: если два вердикта совпали при разных именах папок — гипотеза
отвергнута, следующая ось — `<REPO_URL>`/`<AUTHOR>` в сигнатурах.

## Лечение (2026-09-04 12:07 +03:00, сессия 50) — кандидат (а) применён

`mergeModules`: счёт wholesale (`baseFound`/`baseN`) ведётся по модулям БЕЗ H1 (`counted()` —
не-преамбула и не `# …`); H1 — единственная сигнатура с deploy-time значением, и bug 26 уже
трактует его несовпадение как дрейф, не как перевод. Наблюдение после фикса (та же проба,
`--no-package`): A и B печатают ОДИНАКОВО «`baseFound 4 of 28, ceiling 4 → frozen`» — один
вердикт; страж s18 U14 запускает пробу и требует exit 0 (красный на ядре build 434 — см.
наблюдение выше, зелёный на фиксе). Прочие своды: s18 U2/U3б (числа `of N` уменьшились на 1 —
регексы держатся), полигон — см. STATUS. Цена (а) для документов из одного модуля (README
директорий): `baseN` = 0 → сеть wholesale выключена, файл идёт модульным путём, H1 не
воскрешается по правилу bug 26 — удвоения нет.

## Кандидаты на лечение (история выбора; применён (а))

- **(а) H1 не участвует в счёте wholesale.** `baseFound`/`baseN` считать по модулям БЕЗ H1
  (bug 26 уже трактует отсутствие H1 baseline на диске как дрейф сигнатуры, а не как факт
  перевода). Цена: у документов из одного модуля (README директорий) `baseN` становится 0 →
  сеть выключена, файл идёт модульным путём (H1 не воскрешается по правилу bug 26 — удвоения нет);
  проверить s07 T6 и s02 S5–S8.
- **(б) H1 сравнивать по форме, не по имени:** сигнатура H1 baseline считается найденной, если на
  диске есть ЛЮБОЙ H1 с тем же хвостом после ` — ` (`— AI Agent Guide`). Точнее (а), но добавляет
  правило-исключение (Оккам против).
- **(в) Синтетический baseline без fallback-значений:** при v1-манифесте без `values` заполнять
  baseline значениями из МАРКЕРА (`projectName`, если записан) и ОТКАЗЫВАТЬСЯ от детекции по имени
  папки (оставлять `<PROJECT_NAME>` буквально) — тогда H1 baseline одинаков в любой папке, но
  «не найден» всегда → сдвиг на −1 детерминирован, а не случаен. Слабее (а).

Рекомендация: (а) + свод «две папки» как страж регрессии; US3б остаётся страховкой на любой
другой недетерминизм.
