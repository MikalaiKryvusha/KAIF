# Bug 102 — охват `doc-header-lint` задан фикс-списками имён, и весь канон вне этих списков стражу невидим

**Status:** 🔬 ПРЕДПОЛОЖИТЕЛЬНЫЙ — не верифицирован, причина не установлена · скоуп **2.3**
**Version/build:** build 279 · **When/context:** круги ревью R1/R2 фазы R, 2026-08-09
**Fix accepted when (observable):** НЕ ОПРЕДЕЛЁН — критерий приёмки задаёт исполнитель после
установления причины (решение №70: разбор и лечение за Fable, не за автором документа)

Семейство из одного вхождения: охват стража `tools/doc-header-lint.mjs` определён не признаком
документа, а тремя фикс-списками — четыре директории FULL, ещё две диалектные и тринадцать
корневых имён. Реестр стражей в `AGENT_GUIDE.md` объявляет этот охват достаточным для целых
классов правил (метки времени, правдивость метки, PENDING без судьбы, закрытие против тела), а
прогон открывает 123 файла из 480 `*.md` репозитория. Вхождение не верифицировано; причина не
устанавливалась.

## 1. Списки `FULL_DIRS` / `ROOT_DOCS` / `EXCLUDE_NAMES` задают охват поимённо — 242 документа не открывает ни одна ось

**Адрес:** `tools/doc-header-lint.mjs:46`
Прочие адреса того же вхождения: `tools/doc-header-lint.mjs:53-58` (`ROOT_DOCS`, 13 имён) ·
`tools/doc-header-lint.mjs:64` (`EXCLUDE_NAMES`) · `tools/doc-header-lint.mjs:518-535`
(`inScope` / `inStampScope`) · `tools/doc-header-lint.mjs:546-586` (сам обход: четыре цикла по
именам + цикл по `ROOT_DOCS`) · `AUTHOR_STYLOMETRY.md:15`.

**Заявлено.** Реестр стражей `AGENT_GUIDE.md:602` описывает предмет оси меток времени как «метки в
`plans/`/`bugs/`/`ideas/`/`researches/`/`interviews/` + корневые ключевые», а сам страж объявляет
изъятия ПОИМЁННО и с причиной — `tools/doc-header-lint.mjs:49-63`: вне списка `GOAL.md`
(первоисточник владельца), `KAIF_REFERENCE.md` (генерат), `README.md` (витрина), `reports/`
(«целиком вне скоупа»). Строка реестра `AGENT_GUIDE.md:658` перечисляет семь осей, включая ось
правдивости метки («примета без ложных срабатываний ПО ПОСТРОЕНИЮ») и ось PENDING без судьбы, не
оговаривая при этом, что каждая из них видит только те же 123 файла.

**Наблюдалось.** Скоуп не выводится из признака документа — он перечислен:
`FULL_DIRS = ['plans','ideas','researches','homeworks']`, `BUGS_DIR`, `INTERVIEWS_DIR`,
`ROOT_DOCS` — 13 имён верхнего уровня, `EXCLUDE_NAMES = new Set(['README.md'])`. Обход
(`:546-586`) — это `listMd` по каждой из шести директорий (только верхний ярус, без рекурсии) плюс
цикл по `ROOT_DOCS`. Следствия, наблюдаемые на текущем дереве:

* корневой канон `AUTHOR_STYLOMETRY.md` (рождён задачей T12 позже составления `ROOT_DOCS`) не попал
  ни в список, ни в перечень изъятий с причиной — он просто не открывается;
* `reports/` (24 файла), `framework/` (154), `.claude/skills/` (39), `dist/` (3), `drafts/` (2),
  а также `plans/README.md`, `bugs/README.md`, `ideas/README.md` и все поддиректории
  (`ideas/academic_style`, `interviews/decisions`, `reports/KAIF_UPDATES`) — вне охвата всех осей
  сразу, а не только тех, для кого изъятие объявлено;
* `bugs/KAIF/` в этом репозитории-истоке отсутствует, но в развёрнутом проекте это первая
  заселяемая директория багов, и по построению списка она в охват не попадает.

**Улика.**

Прогон стража как есть (рабочее дерево не менялось):

```
$ node tools/doc-header-lint.mjs
ось правдивости меток (bugs/78): известный долг 56 — базовая линия tools/doc-header-lint.stamp-baseline.json, она только УМЕНЬШАЕТСЯ; всё новое печатается поимённо выше
plan-naming (T2): детей эпиков 25 — у каждого проверен родитель `MM_EPIC_*`
журнал решений (R2/ось E): строк 71 — номера проверены на дубли и пропуски
doc-header-lint: scanned 123, findings 0 — all headers green
```

Обмер охвата тем же правилом, что и у стража (только чтение, скрипт-зонд вне репозитория):

```
$ node scope-probe.mjs      # inScope повторён из tools/doc-header-lint.mjs:518-523
всего .md: 480 · вне скоупа линтера: 242
из них с маркером PENDING: files=4 occurrences=4

framework/skills/fable-method/references/flowcharts.md × 1
reports/22_kaif_owner_voice_guide_from_unliminium.md × 1
```

Разбивка тех же 242 по верхнему ярусу:

```
framework/ 154 · .claude/ 39 · reports/ 24 · ideas/(поддиректории) 9 · <корень> 5 ·
dist/ 3 · drafts/ 2 · bugs/ 1 · homeworks/ 1 · interviews/ 1 · plans/ 1 · researches/ 1 · tools/ 1
корневые вне охвата: AUTHOR_STYLOMETRY.md, GOAL.md, KAIF.md, KAIF_REFERENCE.md, README.md
```

Круг R2 ставил на том же коде посадочный опыт: одна и та же строка вида

```
— *PENDING → вычитка при приёмке эпика M.*
```

посаженная в семь файлов вне охвата плюс один контрольный в `plans/`, дала единственную находку —
`plans/59:294`. Обход индекса регуляркой оси меток минус её скоуп дал
`OUT-OF-SCOPE files=8 occurrences=55`; выдуманные метки, посаженные в `AUTHOR_STYLOMETRY.md` и
`reports/27_task_T10_notice_class_shipped.md` уже после коммита, дали `findings 0` при том, что ось
правдивости метки объявлена не имеющей ложных отрицаний.

**Кого касается.** Правила, за которые отвечает этот страж, живут ровно в тех файлах, которые он
исключает по имени: обязательство самого `bugs/72` (PENDING без судьбы), полевые отчёты в
`reports/`, едущие разработчику KAIF, поставочный слой `framework/` и `.claude/skills/` (то, что
уезжает в чужие проекты), корневой канон `AUTHOR_STYLOMETRY.md`. В развёрнутом проекте затронуты
`bugs/KAIF/` и всё, что проект держит в поддиректориях своих директорий знаний. Оператор читает
`scanned 123, findings 0` как утверждение о репозитории, тогда как это утверждение о списке имён.

**Замечено.** Круг R2 фазы R (посадочный опыт с маркером PENDING и с выдуманными метками); класс
предвосхищён кругом R1 при разборе `bugs/67` — там же зафиксировано, что ось меток по построению не
смотрела в половину зеркала.
