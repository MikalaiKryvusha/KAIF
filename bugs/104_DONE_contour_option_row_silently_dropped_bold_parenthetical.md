Автор написал в двух вопросах по три строки-варианта; строки рекомендаций несли пометку внутри
жирного: `| **A (Рекомендация)** | … |`. `OPTION_ROW_RE` допускает пометку только ПОСЛЕ закрытия
жирного (`\*{0,2}([A-ZА-Я])[.)]?\*{0,2}(?:\s*\([^)]*\))?`), поэтому:

  (коммит `037cafd`, дифф `tools/verify-contour.etalon.json`);

- владелец ответил Q1=B, Q2=C с неполного набора — решение фальсифицировано постановкой
  (EXP-0081), развилка переспрошена раундом 2.

## Почему не поймали стражи (две дыры, обе — свои классы)

1. **G11 «кандидаты == разобранные» — ОДНОСТОРОННИЙ инвариант:** `candidateLines` считается тем
   же регэкспом (`isOptionLine`), что и разбор, — строка, невидимая парсеру, невидима и счётчику
   кандидатов. Проверка «молча съеденный вариант невозможен» зелёная по построению именно тогда,
   когда вариант съеден этим классом. (Ось «односторонние инварианты» уже стоит в пуле
   `/code-revision` — вот её живое вхождение.)
2. **Селфтест review-core** знает формы «список», «таблица», «пометка вне жирного» — то есть
   только УЖЕ ОПЛАЧЕННЫЕ формы; новой формы в нём нет по построению класса (чинится форма, не
   класс).

## Гипотеза лечения (исполнителю; НЕ исполнено — фаза W чинит по списку W2)

- Минимум: расширить `OPTION_ROW_RE` — пометка в скобках легальна и ВНУТРИ жирного:
  `\*{0,2}([A-ZА-Я])[.)]?(?:\s*\([^)]*\))?\*{0,2}(?:\s*\([^)]*\))?` + красный кейс в селфтест.
- Класс: детектор кандидатов ШИРЕ парсера (например: ячейка из ≤ N символов, начинающаяся с
  одной буквы A–Z/А–Я при любой обвязке из `*_()., `) — тогда любая НОВАЯ форма падает красным
  «кандидат не разобран», а не молчит. Порог ложных срабатываний — проверить на живых интервью
  001–019 (таблицы данных с буквенной первой ячейкой).
