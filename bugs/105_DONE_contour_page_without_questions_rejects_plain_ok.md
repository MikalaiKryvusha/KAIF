# Bug 105 — страница контура без распознанных вопросов не даёт нажать «просто ок»: пустая запись отказывает, а «ОК, прочитано» есть только у notice

**Status:** ✅ DONE (закрыт 2026-08-21 15:26 +03:00 — фикс в той же сессии, что и наблюдение)
**Version/build:** build 361 · **When/context:** показ ДЗ-06 живым контуром, 2026-08-21 ≈ 15:00 +03:00
**Fix accepted when (observable):** одиночный показ документа, в котором парсер не распознал ни
одного вопроса и нет исходящих артефактов, даёт страницу класса «сообщение» — кнопка
«ОК, прочитано», чип «ответа не ждёт», клик без комментария даёт штатный исход «notice read»
(код 0); браузерный прогон `verify-contour` несёт постоянный кейс автовывода, доказанный
красным на до-фиксной версии.

## Symptom

Владелец открыл страницу ДЗ-06, нажал «Записать решение» без полей — страница ответила
«Нечего записывать: ни ответа, ни комментария» и не записала ничего. Слово владельца
(2026-08-21, трижды подряд): «я просто ок нажал, а требует необязательный комментарий» ·
«контур твой сломан». Поле комментария при этом подписано «Можно без ответов — просто
сказать» — заявлено необязательным, а фактически без него ни одно действие не легально.

## Root cause

Два независимых промаха, сложившихся в тупик:

1. **Контур:** класс «сообщение» (I37 — штатный исход «прочитано») включался ТОЛЬКО флагом
   отправителя (`--notice` / kind в очереди). Одиночный показ без флага строил обычную
   страницу, а у неё `doSave` отвергает пустую запись («Нечего записывать») — защита от
   случайного пустого клика на странице С вопросами, которая на странице БЕЗ вопросов
   превращается в запрет единственного осмысленного действия.
2. **Отправитель (я):** вопросы А/Б в ДЗ-06 написаны ПРОЗОЙ («**Вопрос А — …**»), а канон
   говорит прямо (STATUS п. 4): «Варианты ответа — СТРОКАМИ ТАБЛИЦЫ … или списком …; третьей
   формы парсер не знает». Парсер законно увидел 0 вопросов. `questions-guard` это не поймал,
   потому что его охват — `interviews/`, а домашки в `homeworks/` он не сканирует.

## Fix (сделано)

- `tools/review.mjs` → `serveContour`: одиночный показ БЕЗ флага при 0 распознанных вопросов и
  0 исходящих артефактов автоматически обслуживается классом «сообщение» (страница, зов,
  запись, исходы — весь notice-путь); строка лога называет автовывод вслух. Артефактный гейт
  (outbound draft) под автовывод не попадает — там нужен «одобряю/отклоняю». Явный `--notice`
  остаётся способом показать сообщением документ С вопросами.
- `tools/verify-contour.mjs` → новый браузерный блок «10а. АВТОВЫВОД класса „сообщение“»:
  фикстура без вопросов вне очереди, подъём без флага, проверка кнопки/чипа/клика/исхода/
  записи kind:notice/неприкосновенности документа.
- ДЗ-06 переписана: вопросы владельца — в парсуемой форме (`### Q1.` + варианты строками
  таблицы), чтобы страница дала радиокнопки, а не общий комментарий.

## TWINS

`TWINS: searched` — места, где класс показа выбирается без взгляда на содержимое:
`buildDoc` (страница документа ВНУТРИ очереди, `review.mjs`) выбирает класс по файлу
состояния очереди — документ, заведённый в очередь вопросным, но без распознанных вопросов,
даст ту же ловушку В ОЧЕРЕДИ. Не расширено тем же движением: запись notice-исхода для
вопросной позиции очереди рассинхронизирует файл состояния (`markNoticeRead` ищет
notice-item), у полевого случая очереди не было, а «чинится класс, но не выдумывается
скоуп» — граница названа здесь и видима будущей сессии. Возникнет в поле — вход через эту
строку.

## Decisions made without the owner

1. **Автовывод сделан на СЕРВЕРЕ (выбор режима), а не ослаблением клиентской проверки
   «нечего записывать»:** проверка защищает страницы С вопросами от пустой записи — снимать
   её нельзя; меняется классификация показа, весь notice-путь (зов, исходы, запись) остаётся
   единым.
2. **Очередной twin (buildDoc в очереди) не расширен** — обоснование в TWINS.
3. **ДЗ-06 переписана в парсуемую форму** — это исполнение уже записанного канона формы
   вопросов, не новое решение.
