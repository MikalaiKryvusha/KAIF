# Bug 106 — протухший kind:notice в очереди перебил вопросную страницу: сервер записал «прочитано» и ВЫБРОСИЛ ответы владельца

**Status:** ✅ DONE (закрыт 2026-08-21 18:22 +03:00 — фикс той же сессией, что и наблюдение)
**Version/build:** build 362 · **When/context:** повторный показ ДЗ-06 после `bugs/105`, клик владельца ≈ 2026-08-21 18:19 +03:00
**Fix accepted when (observable):** запись с НЕПУСТЫМИ answers идёт полным путём решения при
ЛЮБОЙ классификации документа (флаг, очередь): ответ доезжает до md и decision.json, исход —
«decision recorded»; браузерный кейс в `verify-contour` (блок 10б) доказан красным на
до-фиксной версии.

## Symptom

Зов страницы объявил «вопросов без ответа 2» (страница ВОПРОСНАЯ — радиокнопки Q1/Q2), владелец
выбрал варианты и нажал «Записать решение» — а исход контура: «сообщение прочитано», documento
не тронут, `decision.json` = `{kind: notice, comment: ""}`. Ответы владельца потеряны
безвозвратно: клиентская проверка пропустила непустой payload (ответы были), сервер их выбросил.

## Root cause

`/decide` определяет класс по файлу состояния: `asNotice = (флаг) || (в очереди kind:notice)`.
Принцип «серверу виднее, чем клиентскому флагу» верен, но файл состояния ПРОТУХ: ДЗ-06 была
заведена в очередь сообщением в сессии 39 (тогда вопросов в ней не было), item с kind:notice
пережил переписывание документа в вопросную форму (`bugs/105`) — и перебил живую страницу.
`enqueue` умеет переклассифицировать item только В СТОРОНУ notice; обратной стороны нет.

## Fix (сделано)

`tools/review.mjs` → `/decide`: **непустые answers перебивают любую классификацию** — пришли
ответы → полный путь записи решения (md + decision.json + архив), какой бы kind ни значился в
очереди и каким бы ни был флаг. Ответы человека — его работа; первоисточники владельца
неприкосновенны (AGENT_GUIDE, git-гигиена), сохранность работы владельца — цель №1 вектора 2.2.

Протухший item ДЗ-06 в `interviews/decisions/queue.json` переклассифицирован руками тем же
движением (kind → question, readAt снят): состояние контура, не документ владельца.

## Наблюдения

- Полевая потеря — лог контура: зов «вопросов без ответа 2» + исход «сообщение прочитано»;
  `decision.json` с пустым comment при записи, прошедшей клиентскую проверку непустоты.
- Красный доказан откатом фикса (`git stash` на `tools/review.mjs`): блок 10б — «исход — notice
  read» вместо решения, ответ не в md, kind=notice; ИТОГ «159 зелёных, 3 красных».
- После возврата: полный `node tools/verify-contour.mjs` — **162 зелёных, 0 красных**;
  `npm run test:core` — 14 сводов (итог в коммите).

## TWINS

`TWINS: searched` — потребители kind из очереди: `buildDoc` (batch-страница документа) строит
notice-страницу по протухшему kind — там ответов прийти НЕ МОЖЕТ (радио не рисуются), потеря
невозможна, но показ вопросного документа сообщением остаётся косметической дырой класса
«протухшая классификация»; не расширено — нет полевого случая, вход через эту строку.
Обратной переклассификации в `enqueue` не строил — тем же обоснованием.
