# Bug 10 — Релиз утверждает чужую версию: templateNotes 1.6 описывают 1.5, шапки машинерии лгут

**Status:** 🔴 OPEN
**Version/build:** 1.6 · **When/context:** 2026-07-27, метасинтез восьми полевых отчётов
(`researches/07`, П2) — независимо названо шестью отчётами (01, 02, 03, 05, 06, 08).

## Symptom

Единственный машинный канал «что нового» для обновляющегося агента дезинформирует:

- `templateNotes` в мета-блоке бандла 1.6 байт-в-байт совпадают с 1.5 и заканчиваются строкой
  «Release codename for this version: KAIF 1.5 — Tested KAIF» — агент, честно выполняющий чекпоинт
  `review-news`, вносит новости прошлого релиза и не вносит ни одного пункта 1.6 (тихий провал:
  `update-verify` при этом проходит);
- шапки `KAIF-CORE.mjs` и `KAIF-LOADER.mjs` представляются «KAIF 1.5 — Tested KAIF» при манифесте
  1.6; thin `KAIF.md` 1.6 разворачивает лоадер с чужой версией (отчёт 08, «label is law»);
- контекстная строка легаси-задачи хардкодит «merge the 1.5 template news» независимо от целевой
  версии (отчёт 06);
- заметки не кумулятивны: скачок 1.2→1.6 видит новости ровно одной версии (отчёт 06);
- лог печатает «↻ replaced .kaif/kaif-core.mjs (the machinery itself)» при побайтово идентичном
  ядре (sha равны в манифестах 1.5/1.6) — агент тратит вызовы на проверку ложного сбоя (отчёт 03);
- ассеты релиза перевыпускались без смены версии — воспроизводимость по номеру потеряна (отчёт 02).

## Repro (deterministic)

Открыть блок `kaif-bundle-manifest.json` в `dist/KAIF-CORE-BUNDLE.md` (или релизном ассете v1.6):
последний элемент `templateNotes` — «Release codename for this version: KAIF 1.5 — Tested KAIF»
при `"version": "1.6"`. Источник: `TEMPLATE_NOTES` в `tools/build-framework.mjs:167-174`.

## Root cause

`TEMPLATE_NOTES` — рукописная константа сборщика, не обновлённая при релизе 1.6; гейта соответствия
«заметки упоминают собственную версию» нет ни в сборке, ни в `/release`. Версионные строки шапок
машинерии — тоже рукописные. Класс: **релиз не проверяет собственные заявления о себе** (тот же
класс, что «шесть охот» в релиз-нотах при семи в навыке — отчёт 07, дефект B.1).

## Fix plan

Минимум (1.7/2.0, фаза гейтов): (а) страж в `check-framework.mjs`: сборка падает, если
`templateNotes`/шапки CORE/LOADER не упоминают `version.json`-версию (проверить стража на
сломанной версии); (б) шаг в `/release`: обновить заметки. Системно (эпик №1 2.0): заметки
генерируются из по-модульного диффа версий и хранятся по версиям (печать интервалом при скачке).
