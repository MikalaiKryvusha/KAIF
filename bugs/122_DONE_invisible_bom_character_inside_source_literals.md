## Repro (deterministic)

Класс-условие: агент правит исходник через инструмент, чей параметр — JSON-строка. Последовательность `\uFEFF`, набранная
в параметре, декодируется слоем инструмента ДО записи, и в файл ложится настоящий символ; агент видит в своём сообщении
escape и уверен, что записал escape.

1. Через инструмент правки вписать в `.mjs` строку `s.replace(/^\uFEFF/, '')`.
2. Прочитать записанное обратно ПО КОДОВЫМ ТОЧКАМ (не глазами):
   `node -e "const t=require('fs').readFileSync(process.argv[1],'utf8');console.log([...t].filter(c=>c.charCodeAt(0)===0xFEFF).length)" <файл>`
   → `1` при том, что `grep -c 'uFEFF' <файл>` → `0`.
3. Контроль: тот же текст, записанный СКРИПТОМ-ФАЙЛОМ, который собирает escape из кодов
   (`String.fromCharCode(92) + 'uFEFF'`), даёт `0` настоящих символов и `1` escape.

## Root cause / Hypotheses

Причина снята наблюдением, не рассуждением: слой параметров инструмента правки декодирует `\uXXXX` как JSON-escape.
Урок этого класса уже оплачен дважды и записан — `EXP-0121` (инструмент Bash снимает уровень экранирования) и
`EXP-0135` (кириллица в EN-поставке — только `\uXXXX` скриптом) — и оба раза правило сказано про ДРУГОЙ символ и
ДРУГОЙ инструмент; для кириллицы его держит страж (`check-framework` §9.11 краснеет на букве в `framework/**`), для
невидимых символов стража нет, поэтому 39 мест накопились молча и ни разу не были увидены (когда легло первое — не
снималось: поиск по истории невидимого символа отдельной пробой не делался).
Объявленная цена класса `escaping-layer` в журнале опыта («дёшево невозможно: свойство харнесса») верна для класса в
целом и НЕВЕРНА для этой его формы: невидимый символ в теле исходника ловится одним регулярным выражением.

**Что именно декодирует слой — снято пробой, 2026-09-18 12:25 +03:00** (время записи файла пробы; файл из десяти строк записан инструментом записи,
прочитан обратно по кодовым точкам): декодируется ТОЛЬКО форма «обратная косая + `u` + четыре шестнадцатеричные цифры»
(код латинской `A` лёг буквой `A`, код BOM — настоящим U+FEFF); шесть прочих последовательностей — перевод строки,
табуляция, граница слова, перевод страницы, двойная обратная косая, шестнадцатеричная `x41`, нулевой символ, кавычка —
легли как набраны, двумя и более видимыми знаками. Следствие для инвентаря: 36 мест U+FEFF и, вероятно, NUL и BEL
(их естественная запись — та же четырёхзначная форма) объясняются этим слоем; три BACKSPACE в документах — НЕТ: граница
слова этим слоем не декодируется, значит их породил другой слой, и он не наблюдён (первая лошадь — строковый литерал
JavaScript в скрипте правки, где та же пара знаков означает BACKSPACE; `EXP-0121` описывает соседний слой Bash).
Класс один — «между набранным и записанным стоит слой, который читает escape по-своему», — слоёв больше одного.
