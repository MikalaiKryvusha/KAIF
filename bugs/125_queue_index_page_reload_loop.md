**Fix accepted when (observable):**
- Ситуация. Очередь из двух документов открыта страницей-списком во вкладке браузера; владелец открыл первый документ и записал ответ.
- Действие. Владелец возвращается на вкладку списка.
- Результат. Список один раз показывает, что первый документ отвечен, второй — ждёт; страница больше не перезагружается сама; сервер
  контура жив, второй документ открывается.
- Проверка. Функциональный прогон драйвером браузера по странице поставки (сценарий выше, фокус на вкладку списка — пять раз подряд):
  число загрузок страницы-списка ≤ 2 (исходная + одно обновление после записи), сервер отвечает на `/alive` после пятого фокуса; на
  сборке до починки — перезагрузка на каждый фокус и конец контура «page closed … beacon fast path».

## Symptom

Слово владельца в чате, 2026-09-26 ≈ 07:53 +03:00, дословно: «на одно интервью ответил - страница выпбора интервью вошла в циклические
перезагрузки, не могу открыть вторую». Сервер контура записал ответ и через минуту завершился, будто страницу закрыли:

```
Recorded: interviews/interview_039_kaif_2.8_commits_signed_probe.md (Q1 = A, by Mikalai Kryvusha (KOT KRINIK)). Documents left in the queue: 1 — the page STAYS open, the contour waits.
Outcome: page closed after 1 saved answer(s) — recorded, nothing lost — ending the contour (I14, beacon fast path).
[exited with code 2]
```

Сторож `--wait`, поставленный заново после первой записи, получил «The contour ended without a new record» (код 2). Второй документ
(№040) владелец ответил на ОТДЕЛЬНОЙ странице документа (`node tools/review.mjs <док>`) — она отработала штатно.

## Repro (deterministic)

`node tools/sandbox/probes/contour-index-focus-loop.mjs [<каталог контура>]` — очередь из двух фикстур, контур в процессе (без окна и
голоса), страница-список ВКЛАДКОЙ headless-браузера; скрипт каждой загрузки считает загрузки в `sessionStorage` и шлёт `focus` после
`load` — как вкладка с фокусом. На коде HEAD `ddca251` (2026-09-26 08:32:37): «loads in 3000 ms: 90», после записи первого документа и
одного `focus` — «loads 92 → 189» — **BAD**; на починке (08:35:12): 1 загрузка, после записи «1 → 2», карточка одна — **GOOD**.
Граница модели: что настоящий Edge шлёт `focus` после каждой загрузки вкладки с фокусом, проба не доказывает — она моделирует; петлю у
владельца объясняет именно это.

## Forensics

- Лог сервера — выше (задача `--queue` сессии 75); строка `Window check: … it opened as a TAB in a browser (I26)`.
- Страница-список (лицо очереди, `CFG.index`) несёт обработчик `window.addEventListener('focus', function(){ location.reload() })`
  (`framework/tools/contour/review.mjs:926`); каждая выгрузка страницы шлёт маяк `/closed` с ролью `index:…` (`:924–925`); сервер на маяк
  `index` ставит таймер `BEACON_RELOAD_GRACE_MS` = 3000 мс и, если страница не вернулась пульсом `/alive`, кончает контур
  (`:1256–1268`, снятие таймера — `:1146`).

## Root cause / Hypotheses

1. **(главная)** «Фокус → перезагрузка» без условия: во вкладке событие `focus` приходит и после самой перезагрузки (или на каждое
   возвращение), страница перезагружает себя по кругу; каждый круг — маяк `index`, и как только пульс новой копии не успел за 3 с —
   сервер кончает контур как закрытый. Проверить: считать загрузки на драйвере; вкладка против окна приложения.
2. Обновление списка по фокусу — способ узнать, что документ отвечен в другой вкладке; ему не нужна перезагрузка: состояние очереди
   можно спросить у сервера и перезагрузиться, только если оно изменилось (перезагрузка, после которой состояние то же, цикла не даёт).

## Fix (2026-09-26 08:48 +03:00)

Гипотеза 1 подтверждена пробой. `framework/tools/contour/review.mjs`: `queueRev(docs, notices)` — отпечаток очереди (документы с числом
неотвеченных, сообщения); страница-список несёт его в `CFG.qrev`, пульс `/alive` в режиме очереди отдаёт текущий; фокус зовёт пульс, а
перезагрузка — только когда отпечатки разошлись (перезагрузка, нашедшая тот же отпечаток, другой не запускает — петли нет по построению).

Проверка: свод `s22` (8) — настоящий развёрнутый генератор очереди, вкладка, та же модель «focus после load»: на починке зелёный (100 из
100), на `dist` HEAD `ddca251` — красный ровно на двух проверках (8) («loads 80»), остальные 98 зелёные; полная приёмка
`node tools/verify-contour.mjs` — 213 зелёных, 0 красных (08:47:13 → 08:48:22); самопроверка контура — 109 из 109 трижды.

reloads: the «new revision» button (a click of the owner) and the reload after a save while questions are left (once per save) — both
