# Bug 12 — Снапшот манифеста без происхождения: адаптация, пережившая одно обновление, гибнет на следующем

**Status:** ✅ DONE (2026-07-28)
**Version/build:** 1.6 · **When/context:** 2026-07-27, метасинтез (`researches/07`, П5) —
отчёты 03, 05, 06, 07. Продолжение класса bugs/06 (EXP-0012): поле показало, что класс закрыт
не до конца.

## Symptom

- **Главная грань (отчёт 05, F1):** в конце `cmdUpdate` манифест пишет sha **того, что на диске**
  (`shas[p] = fileSha(p)`), включая файлы, классифицированные diverged и СОХРАНЁННЫЕ. Следующее
  обновление читает эту запись как «наш шаблон, не тронут» → **молча заменяет**. В бою: русский
  `BUG_FIXING_FRAMEWORK.md`, восстановленный при апдейте 1.4→1.5, заменён английским шаблоном при
  1.5→1.6 без единого слова в отчёте машинерии (+ 4 навыка, 4620–5399 символов кириллицы стёрты).
  «Инвариант „sha совпал ⇒ пользователь не трогал“ верен ровно один раз».
- sha пересчитывается **до** предписанной тем же запуском когнитивной работы — все смерженные
  вручную файлы получают в манифесте sha, которого у них уже нет; `update-verify` снимок не
  пересчитывает (отчёт 03).
- `GOAL.md` выпадает из `kept`: `continue` для OWNER_SEEDED срабатывает раньше `adopted.push()` —
  провенанс немонотонен, защита контракта владельца держится только на жёстком списке (отчёт 03).
- `fileSha` не нормализует EOL: CRLF-файл при идентичном смысле навсегда diverged; latent на любом
  Windows-проекте (отчёт 06, T4; класс EXP-0005).
- Ручная миграция обесценивает снапшот целиком (KrinikCam: 113/160 путей разошлись), команды
  «пересобрать снапшот» (`adopt-current`) не существует — один ручной проход навсегда удорожает
  все последующие обновления (отчёт 07, №10).

## Repro (deterministic)

Отчёт 05: install → адаптировать файл → update №1 (файл diverged, сохранён; манифест записал sha
диска) → update №2: файл «нетронут» → молча заменён. Код: `KAIF-CORE.mjs` — пересъёмка
`shas` в конце `cmdUpdate` (:377-383), классификация (:357-366).

## Root cause

Снапшот отвечает на вопрос «что лежит на диске», а классификатору нужен ответ «что развернул
ФРЕЙМВОРК». Ровно урок EXP-0012 («у снапшота должно быть происхождение»), применённый теперь не к
`kept`, а к самому `shas`: происхождение нужно каждой записи, не только списку усыновлённых.

## Fix plan

(а) Хранить sha **развёрнутого шаблона** (после подстановок) отдельно от sha диска — diverged
становится «диск ≠ наш шаблон», устойчиво через любое число циклов (предложение отчёта 05 — одна
строка семантики); (б) пересчёт снапшота в финальном гейте, после мержей; (в) `adopted.push()` и
для OWNER_SEEDED (провенанс монотонен); (г) sha по EOL-нормализованному содержимому +
`.gitattributes eol=lf` при развёртывании; (д) команда `adopt-current` после ручной миграции.
В 2.0 эпик №1: слой «провенанс и снапшоты» — по-модульный провенанс это же решает на меньшей
гранулярности.

Класс мёртв по построению: манифест v2 хранит **sha развёрнутого шаблона отдельно от sha диска**
(авторитет замены — только шаблонный sha; «восстановленное руками» больше не читается как

гейте ПОСЛЕ мержей; `adopt-current` пересобирает снапшот после ручной миграции (и на v1-манифестах
усыновляет ДО пересъёмки — ревью-блокер). Проверено: S5 (двухцикловое выживание локализации — репро
NDim-F1), S10/S10c, регрессии зелёные.
