# Bug 132 — Страница очереди кончает контур на прочтённом сообщении, пока у интервью на той же странице есть открытые вопросы

**Status:** 🔴 OPEN — тикет поля #163 (2026-10-18 11:06 +03:00), разбор `researches/40` §3 · **Severity:** S2 (владелец остался на мёртвой странице с
восемью вопросами и ответил скриншотом; работа владельца не потеряна — ответы записаны агентом из чата)
**Version/build:** KAIF 2.9 + сборка 2.10 WIP (`647304f`) · **When/context:** 2026-10-18, полевое развёртывание (новая игра владельца),
очередь из двух документов одним окном по слову владельца «одним окном».
**Fix accepted when (observable):** самопроверка контура — очередь «интервью с двумя открытыми вопросами + сообщение»: отметка «прочитано» на
сообщении НЕ кончает процесс, страница живёт до последнего ответа интервью; факт показа записан для КАЖДОГО документа страницы.
**Fixing:** версия KAIF 2.10, эпик TK, шаг TK7 (б) (`plans/137`), критерий 22 — взято решением №151 (2026-10-23 08:43 +03:00).

## Вектор цели (Avoid)

Страница очереди, на которой владелец видит N документов, не умирает, пока на ней есть хоть один неотвеченный вопрос: исход одного документа
(прочитанное сообщение, ответ на одно интервью) кончает контур только тогда, когда живых вопросов на странице не осталось.

## Готово, когда (критерии приёмки)

- Ситуация. В очереди интервью с двумя открытыми вопросами и одно сообщение (`--enqueue <интервью>`, `--enqueue <сообщение> --notice`).
- Действие. Владелец на странице `--queue` отмечает сообщение прочитанным и не отвечает на интервью.
- Результат. Процесс не печатает «ending the contour»; страница принимает ответы интервью; после последнего ответа процесс кончается кодом 0.
- Проверка. Случай самопроверки контура `node tools/review.mjs --selftest` «#163 batch lives while questions» — красный на сборке
  `647304f`, зелёный после фикса; строка `Shown recorded (I40): 2 doc(s)` для очереди из двух документов.

## Symptom

Лог процесса `--queue` в поле, дословно: `Outcome: notice read (researches/01_feasibility_recon.md, by …) — ending the contour (I8).` ·
`[exited with code 0]`. Интервью с восемью открытыми вопросами осталось на той же странице с баннером «СЕРВЕР КОНТУРА НЕДОСТУПЕН — ответ НЕ
уйдёт». Плюс `Shown recorded (I40): 1 doc(s)` для очереди из двух документов.

## Repro (deterministic)

1. Свежее развёртывание; в очереди интервью с ≥ 2 открытыми вопросами и одно сообщение.
2. `node .kaif/tools/contour/review.mjs --queue`.
3. На странице отметить сообщение прочитанным; интервью не трогать.
4. Процесс кончается кодом 0 с `Outcome: notice read … — ending the contour (I8)`.

## Forensics

`framework/tools/contour/review.mjs:1318-1320` (HEAD `0d5c7ce`): ветка `outcome = 'notice read'` печатает «ending the contour (I8)» — правило
одного документа I8 («записанное решение КОНЧАЕТ процесс») применено к первому исходу ЛЮБОГО документа пачки. Прогоном у истока не
воспроизведено — подтверждено чтением строки и полевым логом.

## Root cause / Hypotheses

Гипотеза (по чтению): правило §5 контракта «страница ЖИВЁТ, пока у её документа есть неотвеченный вопрос» не поднято на уровень пачки
«страница живёт, пока у ЛЮБОГО её документа есть неотвеченный вопрос». Факт показа пишется для одного документа — близнец той же развилки.

## Fix plan

Условие выхода страницы очереди — «живых вопросов на странице нет»; исход сообщения записывается и не кончает процесс; I40 пишет факт показа
по каждому документу. `TWINS:` — проверить исходы «вычитка/макет» в пачке тем же правилом.
