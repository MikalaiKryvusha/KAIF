# Bug 137 — агент закрыл чат «по окну» на 53 %, не замерив окно

**Status:** 🔧 fix pending verification (ворота закрытия в хуке окна поставки и у истока; шаг 0 навыков закрытия обоих слоёв)
**Version/build:** исток KAIF, сборка 836 · **When/context:** 2026-11-17, сессия 100 (Claude Opus 5.5, VS Code, Windows 11), автономная работа
по слову владельца «работай автономно до закрытия чата по переполнению контекста»
**Severity:** S1 — доверие владельца: «а почему ты этот закрыл?» · «Ты закрыл чат неправильно» · «чини и у себя и в поставке KAIF» ·
«KUMM умеет закрывать правильно» (чат, 2026-11-17 ≈ 11:12–11:20 +03:00)
**Fix accepted when (observable):** в сессии с работающими хуками вызов `/end-chat-soft` ниже уровня закрытия без слова владельца получает
отказ с замером («the window is N % full … too early»); без хуков `node framework/hooks/context-window.mjs --measure` печатает долю окна и код 1
**Fixing:** эта сессия

## Symptom

Сессия провела полное мягкое закрытие (эстафета, стрижка, гейты, судья, коммит, прощание, зов голосом) и сказала владельцу «окно на пределе».
Замер по журналу сессии после вопроса владельца: ≈ 531 тыс. токенов окна 1M — 53 %; порог закрытия проекта — 85 %.

## Repro (deterministic)

Автономный ход без промптов владельца → агент решает «окно кончается» по объёму прочитанного → читает `.claude/skills/end-chat-soft/SKILL.md`
инструментом Read и проходит шаги руками. Хук окна (`framework/hooks/context-window.mjs`) в сессии 100 не запускался вовсе: с 09:48 расширение
Claude Code 2.1.326 не отдавало папке её настроек — ни хуков, ни навыков, ни `CLAUDE.md` (`bugs/138`; исправлено 2026-11-17 14:52 +03:00:
стояло «молчит: он говорит только с 80 %»). Запущенный, он и так молчал бы до 80 %, а закрытие ничем не останавливалось — ни ворот, ни шага
замера в навыке.

## Root cause

Класс — заявление шире наблюдения (`claim-before-evidence`, EXP-0209): «по окну» без замера окна. Механизма против раннего закрытия в поставке не
было; в поле он есть — ворота закрытия хука окна самого развитого развёртывания (после его закрытия на 68 % «по ощущению предела», 2026-11-01).

## Fix

1. `framework/hooks/context-window.mjs` — ворота `closeGate` (PreToolUse · matcher `Skill`): `/end-chat-soft` и `/end-chat-force` ниже `closePct`
   без `owner: «…»` в аргументах навыка отклоняются с замером; нечем мерить или субагент — не мешают.
2. Проводка — `framework/hooks/settings-fragment.json` и у истока `.claude/settings.json`; README модуля хуков.
3. Шаг 0 навыков закрытия обоих слоёв: закрывает слово владельца или ЗАМЕРЕННОЕ окно — `context-window.mjs --measure` (код 0 · 1 · 2), замер
   руками, который держит и там, где агентская система не отдала сессии хуков и навыков (сессия 101: так шла и сессия 100 — `bugs/138`;
   исправлено 2026-11-17 14:58 +03:00: стояло «закрытие — вызовом навыка, не чтением файла (ворота стоят на вызове — ровно та дыра…)» — в сессии 100
   навык вызовом не нашёлся бы вовсе).
4. Стражи: самопроверка хука (ворота · замер · формы имени · `<synthetic>` · «хуки живы»), свод `s14` (развёрнутый хук: 53 % без слова —
   deny, со словом — тишина; `--measure` по журналу 53 % — код 1; `--alive`; проводка), проба `tools/sandbox/probes/gate-close-mutant.mjs`
   (G1–G6 на адресатах).
5. По судье сессии 101 (`researches/38_kaif_2.10_scope_recon/judge-s101-close-gate.md`, вердикт ворот — REFUTED): ворота сверяли сырое имя
   навыка, а Claude Code снимает пробелы и ведущую «/» — `/end-chat-soft` (форма канона) проходил без отказа; теперь имя нормализуется так же, и
   слово владельца читается и после имени. Запись `<synthetic>` с нулевым usage читалась последним ответом («0 %» на журнале сессии 100 при
   настоящих 58 %) — пропускается. `--measure` и `--alive` берут журнал своей сессии по `CLAUDE_CODE_SESSION_ID` (иначе — новейший журнал
   проекта, и вывод это называет) и длинный путь проекта в форме вендора (200 знаков + хеш).
