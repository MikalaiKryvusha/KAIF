## Root cause / Hypotheses

Причина у истока: расширение (не позднее 2.1.323; у истока — с первой сессии на 2.1.326) отдаёт сессии настройки папки только при записи доверия, а запись этой папки — `false` (запись с
заглавной буквой диска — другой ключ). Окно доверия либо было закрыто без «Trust folder», либо не всплыло — не наблюдено.

Класс KAIF: **«подключено» ≠ «работает»** (`claim-before-evidence`). Машинерия судит проводку хуков по файлу настроек и никогда не наблюдает,
что агентская система их запускает; агентская система вправе молча не отдать сессии настроек папки. Модуль хуков, навыки и автозагружаемый
файл контекста гаснут разом, и сказать об этом изнутри сессии некому — всё, что сказало бы, само из этих настроек.

TWINS: searched «запись доверия папки владельца = false» в `~/.claude.json` — found: `d:/work/ai_sandbox/ndim` · `D:/work/ai_sandbox/ndim` ·
`d:/work/ai_sandbox/KPOT` · `d:/work/ai_sandbox/KAGO` (у `D:/…/KAGO` — `true`) · `d:/work/ai_sandbox/KAGO-team-engineer` · `ndim-team/*` (десять
папок) · рабочее дерево ndim. Выключены ли там настройки — не наблюдено: предупреждение «stay unused» в журналах расширения стоит ровно одно —
у истока 2026-11-17; строки `[info]` «no trust record» есть ещё у нескольких папок владельца, которым доверие потом дано (`KUMM`, `KCCP` и
другие — запись `true`); исправлено 2026-11-17 15:55 +03:00 по находке 8 судьи: стояло «строки журнала есть только по истоку и по одному
проекту калькулятора».

3. **Класс в поставке.** FORK: options <A строка задания установки и обновления, README модуля хуков и признаки в `/resume` | B A + `check`
