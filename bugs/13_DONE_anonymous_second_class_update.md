# Bug 13 — Анонимная установка — второсортный гражданин обновления; гейт анонимности ловит владельца

**Status:** ✅ DONE (2026-07-28)
**Version/build:** 1.6 · **When/context:** 2026-07-27, метасинтез (`researches/07`, П6) —
все три анонимных профиля поля (отчёты 01, 02, 08); у отчёта 02 — **блокер**.

## Symptom

1. `cmdUpdate` для anonymous закрыт by design, а `verify-final` при анонимной установке удаляет
   `deploy-manifest.json` → у проекта нет снапшотов → bootstrap-обновление идёт легаси-веткой, где
   сохраняется всё: механика меняет ровно 1 файл (штамп версии в маркере), **вся** дельта — ручной
   когнитивный мердж (отчёт 08: 16 файлов, 209 строк; отчёт 02: 14 файлов).
2. **Гейт анонимности замкнулся на владельце:** `anonLeakScan()` сканирует всё дерево проекта, а
   AUTHOR_TOKENS содержит «Kryvusha/Кривуша» — у проектов, чей владелец и есть автор KAIF (или
   однофамилец), гейт падает на законном имени владельца: 44 ложных срабатывания (42 — выгрузки
   JIRA), `update-verify` заблокирован, healMarker/resyncCopies/самоочистка не отработали, закрытие
   вручную (отчёт 02, блокер); падение на имени в GOAL.md/AGENT_GUIDE.md (отчёт 01). Машинерия при
   этом **сама** вписывает это имя через `<AUTHOR>` из `git config user.name`.
3. Анонимная самоочистка вырезает npm-ключи `kaif:*` **по имени**, а не по значению — сносит
   одноимённые собственные скрипты владельца (отчёт 02: свой `kaif:check`).
4. `resyncCopies()` не фильтрует по `isSkippedAnon` — возвращает в зеркала origin-tied навыки,
   которые установка намеренно пропускала (отчёт 02).

## Repro (deterministic)

Отчёт 02: `node .kaif/kaif-core.mjs update-verify | grep -c "anonymity leak"` → 44 на дереве, где
фамилия владельца совпадает с токеном автора. Отчёт 08: после bootstrap-механики
`git status --short` → « M .kaif/kaif.json» и больше ничего. Код: `cmdUpdate` отказ (:322),
`anonLeakScan` (:409-425), `selfCleanArtifacts` (:472-486).

## Root cause

Анонимность реализована как «отсутствие всего», а семантически это «отсутствие origin в
артефактах»: классификация контента (обезличенный снапшот `{paths, agents, shas, kept}`) и update
по локальному источнику анонимности не противоречат. Гейт ищет токены там, где их писала не
машинерия (всё дерево вместо путей манифеста), и не отличает автора фреймворка от владельца
проекта — притом что значение `<AUTHOR>` ему известно.

## Fix plan

(а) Обезличенный deploy-manifest переживает самоочистку → анонимный update получает ту же
классификацию, что origin (можно и `update --source`); (б) anonLeakScan — только по путям
манифеста; совпадения вне — предупреждение, не блокировка; (в) исключать из AUTHOR_TOKENS значение
`<AUTHOR>`/`git config user.name`; в тексте ошибки — подсказка про случай «имя владельца»;
(г) самоочистка package.json — по значению ключа; (д) `resyncCopies` фильтрует `isSkippedAnon`.

## ✅ STATUS: DONE (2026-07-28, план 21 Фазы 5.4–5.5)

(1) Анонимная самоочистка СОХРАНЯЕТ обезличенный deploy-manifest (origin в нём нет) → bootstrap-
update классифицируется как обычный update: механика вливает апстримные модули, а не двигает один
штамп версии (S13 — полный цикл install → verify-final → bootstrap 9.9). (2) anonLeakScan сканирует
ТОЛЬКО пути манифеста и исключает кластеры токенов, совпадающих с владельцем по git user.name
(транслитерация Kryvusha↔Кривуша учтена) — полевой блокер «44 ложных лика» воспроизведён песочницей
и закрыт; текст ошибки несёт подсказку про имя владельца. (3) Самоочистка снимает npm-ключи ПО
ЗНАЧЕНИЮ — одноимённый скрипт владельца выживает (S13-ассерт). (4) resyncCopies не возвращает
origin-tied навыки анонимной установке (Фаза 5.4/Ф1).

## Решения, принятые агентом без владельца

1. `update --source` для anonymous отклонён осознанно: ядро (несущее origin-URL) у анонимного
   проекта не хранится; механичность обеспечена выжившим манифестом + bootstrap — тот же результат
   без нарушения «анонимность by design».
