# Bug 147 — Kimi: `--alive` принимает свежую сессию Claude за текущую и ложно отвечает «hooks running»

**Status:** ✅ DONE 2026-11-22 09:53 +03:00 — новая Kimi VS Code сессия `session_6d66c1d4…`: `--alive` код 0 и запись её собственного id; живой `Stop` также подтверждён · отчёты `testcases/reports/2026-11-21_bugs147-kimi-alive-fallback.md` и `testcases/reports/2026-11-22_kimi-stop-alive.md`
**Version/build:** исток KAIF 2.10, `1c2001c`, сборка 861 · Kimi Code VS Code 0.9.0, Windows 11 · **When/context:** дефект 2026-11-21 19:40 +03:00; закрытие 2026-11-22 09:53 +03:00
**Severity:** S1 — зелёная проверка скрыла, что в живой сессии не работает ни один хук KAIF; владельцу было сказано «хуки живы»
**Fixing:** исполнено и проверено живьём.
**Fix accepted when (observable):** ручной `--alive` без переменных идентичности агента в живой сессии Kimi выбирает её журнал, а не более старую сессию Claude; если хук этой Kimi-сессии не оставил записи, команда возвращает код 1 и просит `/reload` или новую сессию. Когда хук текущей Kimi-сессии записал присутствие — код 0. Существующие Claude-случаи сохраняют прежние ответы.

## Вектор цели

**Avoid:** проверка живости никогда не подставляет запись другой агентской системы или другой сессии и не выдаёт её за доказательство текущей.

## Symptom

В новой сессии Kimi VS Code `session_70b1e5d5-8d8d-444a-935a-f760d2e67130` первый ручной `node framework/hooks/context-window.mjs --alive` вернул код 0 и назвал Claude-сессию `abca6a3c-…`. Записи текущей Kimi-сессии в `.kaif/context-window.json` нет; файл тестового долга после записи `.mjs` остался пустым; продолжения после `Stop` не было.

## Repro (deterministic)

1. В проекте с маркерами `claude-code` и `kimi-code` есть свежая запись Claude в состоянии окна.
2. Kimi VS Code запускает сессию со старой проводкой `node .kaif/hooks/…`; каждый вызов падает кодом 1, потому что у истока этой папки больше нет.
3. Инструмент `Bash` этой сессии не несёт ни `KIMI_CODE_SESSION_ID`, ни `CLAUDE_CODE_SESSION_ID`.
4. Ручной `--alive` идёт по ветке Claude, берёт новейший журнал Claude проекта и читает его старую запись как запись текущей сессии.

## Forensics

- `state.json` текущей сессии: `id: session_70b1e5d5-…`, `cwd: d:/work/ai_sandbox/KAIF`.
- Глобальный журнал Kimi 2026-11-21T16:29:15–16:37:34Z: хуки `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `Stop` вызывают старые команды `node .kaif/hooks/…` и завершаются кодом 1.
- `--alive`: `KAIF hooks: running in this session (abca6a3c-…) … (session by the newest transcript of the project)`, код 0.
- Проба окружения инструмента: обе переменные идентичности пусты.
- Новый диспетчер в `~/.kimi-code/config.toml` записан и `kimi doctor config` зелёный, но текущий процесс прочитал конфиг при своём старте и продолжает вызывать прежние команды.

## Root cause

Ветка Kimi для ручных `--alive`/`--measure` включается только по `KIMI_CODE_SESSION_ID`. Без неё код безусловно возвращается к новейшему журналу Claude, даже когда маркер проекта включает Kimi и самая свежая сессия проекта — Kimi. Это отдельный дефект от `bugs/142`: там ложный отказ первого вызова, здесь ложное подтверждение чужой системой.

## Fix

`latestKimiSession` выбирает по `state.json → cwd` и mtime `wire.jsonl` новейшую Kimi-сессию текущего проекта. Ручной fallback сравнивает её с новейшим журналом Claude; если новее Kimi, `--alive` судит запись её id, а `--measure` читает её wire. Вывод называет способ выбора. Если в проекте с маркером Kimi существует Kimi-сессия, но новее журнал Claude, обе команды без env-id возвращают код 2 с явной неоднозначностью: чужая запись больше не становится зелёным доказательством, включая Kimi-only маркер. Явный `CLAUDE_CODE_SESSION_ID` разрешает маршрут Claude; Claude-only поведение не изменено.

**Проверено 2026-11-21 22:00 +03:00** (отчёт в шапке): проба `bugs147-kimi-alive-fallback` покрывает оба порядка свежести, Kimi-only маркер и явный id Claude; на текущем дереве зелёная, на `3b78552` воспроизводит ложные зелёные и чтение журналов Claude, а явный Claude остаётся рабочим контролем. Самопроверка окна, три группы мутантов и сборка зелёные. В реальной сессии до перезагрузки `--alive` честно вернул код 1 с её настоящим id, `--measure` прочитал её настоящий Kimi wire. Положительный живой `--alive` и продолжение `Stop` приняты в новой сессии 2026-11-22 09:53 +03:00.
