## Вектор цели

**Maintain:** автоматическое слежение Kimi начинает мягкое закрытие до собственного сжатия Kimi, а не только правильно вычисляет пороги на стенде.

## Symptom

В живой сессии `session_70b1e5d5-8d8d-444a-935a-f760d2e67130` Kimi выполнил `context.apply_compaction` до вызова `/skill:end-chat-soft`. Владелец прямо спросил, видит ли агент сжатие, и назвал его провалом автоматического слежения.

## Repro (deterministic на записанном живом случае)

1. Открыть Kimi VS Code сессию до замены проектных команд `node .kaif/hooks/…` на пользовательский диспетчер.
2. Продолжать длинную работу без `/reload`, пока отображаемый счётчик не достигнет точки сжатия.
3. Прочитать `agents/main/wire.jsonl`: последний счётчик перед сжатием — 891644, затем идёт `context.apply_compaction`; состояние KAIF не содержит id этой сессии.

Для повторения исправленного пути нужна новая/перезагруженная сессия: уже работающий процесс держит прочитанную при старте проводку, и ретроспективно подменить её файлом нельзя.

## Forensics

- `wire.jsonl:2475`: `token_counting.measured`, `tokens: 891644`, время `1795286390552`.
- `wire.jsonl:2483`: `context.apply_compaction`, затем первый новый счётчик — 24898.
- Точка сжатия по конфигурации — 891289 из 1048576; последний счётчик уже выше неё.
- `.kaif/context-window.json` не содержит `session_70b1e5d5-…`: ни один рабочий вызов `context-window --kimi` её не записал.
- `C:/Users/krinik/.kimi-code/logs/kimi-code.log:10714–10827`: для этой сессии `UserPromptSubmit`, `PreToolUse`, `Stop` и `PostCompact` вызывают старую команду `node .kaif/hooks/context-window.mjs --kimi` и завершаются кодом 1, включая `PostCompact` в `2026-11-21T18:42:10.625Z`.
- Сессия стартовала до записи нового диспетчера и продолжает использовать старую проводку. Это наблюдение, а не оправдание результата.

## Root cause

Непосредственная причина подтверждена: живой процесс Kimi не получил ни одного успешного вызова сторожа окна, потому что держит прежние проектные пути, несуществующие у истока после перехода на диспетчер. Пороговая логика в этом процессе вообще не исполнялась.

Дефект контура шире одной опечатки: замена проводки и статические/фикстурные проверки были приняты как достаточные для продолжения длинной работы, хотя живая сессия не была перезагружена и `--alive` не подтвердил её запись. Положительная живая приёмка осталась на потом, а Kimi сжал контекст раньше.

## Fix plan

1. Уже в дереве: пользовательский диспетчер из `bugs/145`/KA2 устраняет проектные пути; `--alive` из `bugs/147` обязан честно назвать незаписанную Kimi-сессию, а не принять чужую Claude-запись.
2. Перед дальнейшей длинной работой запустить новую/перезагруженную Kimi-сессию и получить код 0 `--alive` с её собственным id.
3. Проверить доставку ступеней и `Stop` живьём; не закрывать этот баг без наблюдения мягкого закрытия до compaction на реальном заполнении окна.
4. В `plans/143` KA9 держать эту приёмку блокером выпуска 2.10. Если в новой сессии ступени не доходят, исследовать свежие журналы до дальнейших правок.

TWINS: searched `compaction`, `context-window` и `context.apply_compaction` в `bugs/` — `bugs/144` закрывал чтение свежего счётчика внутри скрипта, но его живой путь был оставлен на `bugs/145`; `bugs/145` — недействительные matcher-и, `bugs/147` — ложная живость по чужой сессии. Этот документ фиксирует новое наблюдение всего живого контура после смены диспетчера, не переоткрывая доказанную часть скрипта из `bugs/144`.
