# Bug 14 — Легаси-путь слеп и самоволен: diverged=[], молчаливые 5 систем, повторный bootstrap стирает чекпоинты

**Status:** ✅ DONE (2026-07-28)
**Version/build:** 1.6 · **When/context:** 2026-07-27, метасинтез (`researches/07`, П7) —
отчёты 01, 06, 08.

## Symptom

1. **`diverged = []` при legacy** (проект ≤1.4 без снапшотов): `writeUpdateTask([], …)` — пункт
   мержа не появляется, формулировка «merge the news pointwise» операционно пуста. На скачке
   1.2→1.6 агент стоит перед 133 блоками бандла против 37 развёрнутых файлов, не зная, где правка
   в 3 строки, а где +128 (отчёт 06); отсюда «ручная археология»: свой распаковщик, 53 шаблона во
   временный каталог, дифф 12 доков + 22 навыков — ~85% времени обновления (отчёт 01).
2. **`--agents` не наследуется из старого маркера** на легаси-пути (наследование есть только в
   `cmdUpdate`): проект с `agent: "claude-code"` молча получает все пять систем и ~80 лишних
   файлов (отчёт 06, T6 — вреда не было лишь потому, что агент заметил и спросил владельца).
3. **Повторный запуск bootstrap** перезаписывает `KAIF_UPDATE_TASK.md` вместе с проставленными
   чекпоинтами (молчаливый сброс прогресса) и порождает бессмысленную контекстную строку
   «legacy update 1.6 → 1.6» (маркер после первого прогона прочитан как legacyOld); формулировка
   «pre-1.5 project has no content snapshots» даёт ложную модель причины на анонимных установках
   (снапшоты удалила самоочистка, а не возраст) — отчёт 08.

## Repro (deterministic)

Проект ≤1.4 (`agent: "claude-code"` в маркере) → bootstrap 1.6 без `--agents`: разворачиваются все
пять систем; сгенерированная задача не содержит списка файлов к мержу. Повторный запуск bootstrap
на уже обновлённом дереве: контекстная строка «legacy update 1.6 → 1.6», чекпоинты стёрты.
Код: `KAIF-CORE.mjs` — legacy-ветка `cmdInstall` (:523-526, :600-602).

## Root cause

Легаси-ветка написана как «install с усыновлением», без попытки восстановить базу для сравнения —
хотя машинерия знает старую версию из маркера, релизный артефакт старого тега доступен, а парсер
(`parseBundle()`) уже есть. Наследование контекста (agents) реализовано только на одном из двух
маршрутов. Идемпотентность повторного запуска не рассматривалась.

## Fix plan

(а) **Синтетический слепок**: при отсутствии снапшотов скачивать артефакт старой версии, парсить
тем же `parseBundle()`, применять обычную sha-классификацию + per-file churn с пометкой
«переносить нечего» при churn=0 (готовый полевой прототип — `tools/kaif-baseline-diff.mjs` проекта
KLAS); (б) наследовать `legacyOld.agents ?? [legacyOld.agent]`, печатать выбор явно; (в) не
перезаписывать задачу с чекпоинтами; при равенстве версий писать «повторный прогон», причину
отсутствия снапшотов выводить из фактического состояния. В 2.0 эпик №1 слепок обобщается до
машинного диффа версий (П1).

## Прогресс (2026-07-27, Фаза 1 плана 20)

Отгружено (песочница S3): agents наследуются из старого маркера (включая сингулярный `agent`
эпохи 1.4) с явной строкой лога — молчаливого разворачивания пяти систем больше нет; повторный

эпик №1, Фазы 3–4 (полевой прототип: `kaif-baseline-diff.mjs` KLAS).
