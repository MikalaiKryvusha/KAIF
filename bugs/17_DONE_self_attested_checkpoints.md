# Bug 17 — Чекпоинты самозаверяемые, обновление недоказуемо: штамп версии без контента проходит все гейты

**Status:** ✅ DONE (2026-07-28)
**Version/build:** 1.6 · **When/context:** 2026-07-27, метасинтез (`researches/07`, П8) —
отчёты 04, 05, 08.

## Symptom

1. **`checkpoint <id>` дописывает строку, `update-verify` грепает её наличие** — агент отчёта 05
   проставил все четыре чекпоинта разом ДО судейского прохода, машинерия не возразила: «для слабой
   модели … это бесплатный проход через самый важный гейт релиза» (F6).
2. **Штамп версии без контента проходит все гейты** — на анонимной установке механика меняет ровно
   один файл (`.kaif/kaif.json`), маркер утверждает 1.6 при дереве 1.5; гейты проверяют чекпоинты
   (ставит сам агент), плейсхолдеры и токены — но не факт мержа (отчёт 08, Д3).
3. **После самоочистки `update-verify` невоспроизводим**: `runFinalGates` начинается с `die()` при
   отсутствии `KAIF_UPDATE_TASK.md`, а заканчивается его удалением — аудитор назавтра получает
   «nothing to verify»; заявление «update-verify ✅» в коммите нефальсифицируемо (отчёт 04, §4).
   Ирония: это ровно тот случай, против которого написан /fable-judge.

## Repro (deterministic)

(1) После `update` выполнить `checkpoint merge-diverged|review-news|recheck|judge` подряд без
какой-либо работы → `update-verify` проходит. (2) Отчёт 08: анонимная установка 1.5 → bootstrap
1.6 → `git status --short` = « M .kaif/kaif.json» → чекпоинты → «update-verify passed».
(3) После успешного `update-verify` вызвать его повторно → «KAIF_UPDATE_TASK.md not found».
Код: `cmdCheckpoint` (:667-680), `runFinalGates` (:489-502), `selfCleanArtifacts` (:472-486).

## Root cause

Чекпоинты проектировались как лекарство от «слабая модель ломает файл правкой» (EXP-0011 —
подтверждено полем) — но проверяют факт НАЖАТИЯ, а не факт РАБОТЫ. Расписки о проведённом
обновлении не существует: доказательства уничтожает та же самоочистка, которая делает дерево
чистым.

## Fix plan

(а) Чекпоинт исполняющий: `checkpoint recheck` сам запускает `check` и отказывается писать отметку
при ненулевом коде; `judge` требует вердикт + строку доказательства; (б) нестираемая расписка
`.kaif/last-update.json` (`from`→`to`, дата, счётчики replaced/added/kept, маршрут, чекпоинты) —
пара килобайт, «поверь коммиту» → «прочитай файл» (отчёт 04); история в маркере
(`history: [{from,to,date,route}]` — отчёт 06, T9); (в) содержательный `update-verify`: пока бандл
жив — проверка опорных строк изменённых шаблонов на диске (метод 209/209 из отчёта 08); отсутствие
— не отказ, а явный список «не смёржено».

## ✅ STATUS: DONE (2026-07-28, план 21 Фаза 5.4)

Чекпоинты стали исполняющими: `recheck` сам запускает `check` (execFileSync, без шелла) и
отказывается записываться при красном; `judge` требует `--verdict` с доказательством, гейты
проверяют строку вердикта, «голый тик» ремонтируется той же командой (дедлок ревью закрыт).
Обновление доказуемо: нестираемая расписка `.kaif/last-update.json` со штампом `verifiedAt` +
`history` в маркере; warning-скан «+»-строк из Module diffs ловит несмерженное (с пропуском
локализованных секций). Проверено: S12/S12c (штамп без контента больше не проходит: судья без
вердикта — отказ; полный путь зелёный), S9.

## Решения, принятые агентом без владельца

1. Скан «+»-строк — предупреждение, а не отказ: переведённые обвязки легитимно мержат смысл, а не
   байты; жёсткость обеспечивает обязательный judge-вердикт рядом.
