# Bug 21 — предсказание прохода недоступно ровно тем, кто обновляется впервые (K3)

**Status:** 🟠 OPEN
**Version/build:** 2.0 (build 68) · **When/context:** 2026-07-31, отчёт ndim (`ai_agents_reports/23`, K3).

## Symptom

Команда `diff` (аудит «что заменится / что защищено») не достаётся обновляющемуся с 1.x дважды:
(1) `diff` живёт в ядре 2.0 — на развёртывании 1.6 его нет; (2) на манифесте v1 режим аудита
отказывает: `die('this deployment carries a v1 manifest … Run the next update … then diff works')`.
Предсказание доступно всем, кроме момента наибольшего риска — первого обновления.

## Repro (deterministic)

Свод s07/s02-вариант: фикстура с манифестом v1 → `diff --source <новая версия>` → сейчас die;
после фикса — картина классов, совпадающая с последующим реальным проходом.

## Root cause

`diff` требует template-провенанс манифеста v2, хотя код построения **синтетической базы** из
бандла старого релиза уже существует (bootstrap-путь: «synthetic baseline: v1.6's own
KAIF-CORE-BUNDLE.md») — аудит просто не переиспользует его.

## Fix plan (план 23, Фаза B2)

1. `diff --source <версия/путь>`: при манифесте v1 строить синтетическую базу тем же кодом, что
   bootstrap (`--baseline`), вместо `die`.
2. Канонизировать полевой приём «песочная копия + настоящий bootstrap» (git archive → песочница →
   прогон; «не модель прохода, а сам проход»; цена — минута и 11 МБ, точность в поле — байт в
   байт) — в `/kaif-update` SKILL.md (оба слоя) и `framework/KAIF_REFERENCE.md` §10.
