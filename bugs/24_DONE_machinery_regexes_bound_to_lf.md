**Status:** ✅ DONE (2026-07-31)

## ✅ STATUS: DONE (2026-07-31)

Аудит проведён по всей поставке (installer + unpack + tools). **TWINS-инвентарь:** живых вхождений
класса три — (1) `kaif-unpack.mjs` blockRe без `\r?` (CRLF-пересохранённое ядро = «no FILE:

## Symptom

Полевой прецедент (сторона проекта): гейт ndim `03-kaif-verify.mjs` требовал `/^---\n…/` → на
CRLF-чекауте «нет YAML-фронтматтера» ×15 — красным оказался ровно набор навыков, переписанных
обновлением 2.0 (машинерия пишет LF, git при следующем чекауте отдаёт CRLF). «Гейт, который агент
учится обходить, хуже отсутствующего». Их фикс — у них; НАШ долг — тот же класс в ПОСТАВКЕ: любой
регексп машинерии/tool-модулей, жёстко привязанный к `\n`, — бомба на Windows-развёртывании
(`core.autocrlf=true` — дефолт поля).

## Repro (deterministic)

Свод: прогон парсящих функций машинерии на CRLF-варианте входа (бандл, SKILL.md, задание,
чекпоинты) — результат обязан совпадать с LF-вариантом. Мутационная проверка (как у ndim): после
нормализации страж обязан по-прежнему ловить настоящую подделку.

## Forensics / инвентарь (TWINS — заполняется аудитом Фазы B3)

Известно доброе: `parseBundle` использует `\r?\n` (KAIF-CORE.mjs:200), `normEol`/`normSha`
нормализуют sha (строки 110–112), `ensureIgnoreFirst` сплитит `\r?\n` (184); canon-lint/provenance
CRLF-хардены судейским проходом 2.0 (EXP-0017). Аудит обязан пройти ВЕСЬ
`framework/installer/KAIF-CORE.mjs` + `framework/installer/KAIF-LOADER.mjs` +
`framework/tools/*.mjs` + `framework/kaif-unpack.mjs` по паттернам `\\n` в регекспах и
`.split('\n')` на данных, читанных с диска БЕЗ normEol, — список вхождений сюда.

## Root cause

Класс EXP-0005 («в регекспах по концам строк всегда `\r?\n`») закрыт в инструментах сборки истока,
но никогда не проходился инвентарём по ПОСТАВКЕ.

## Fix plan (план 23, Фаза B3)

Инвентарь → каждому вхождению: нормализация на чтении (`normEol`) или `\r?\n`; свод с
CRLF-фикстурой красный до / зелёный после; мутационная проверка стражей.
