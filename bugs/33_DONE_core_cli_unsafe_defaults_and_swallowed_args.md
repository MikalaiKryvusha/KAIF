# Bug 33 — класс L-3: CLI ядра небезопасен — голый запуск деструктивен, help не команда, аргументы и флаги глотаются молча

**Version/build:** машинерия 2.1 · **When/context:** 2026-08-07, триаж 4 полевых отчётов об
обновлении до 2.1; класс L-3 — `researches/15` §3. Единственный класс с ПОТЕРЕЙ РАБОТЫ в поле

## Симптом (класс, не экземпляр)

Интерфейс `kaif-core.mjs` нарушает принцип наименьшего удивления в самую опасную сторону:
безобидное намерение («посмотреть список команд») исполняет деструктивную операцию, а мутирующие
команды принимают и молча игнорируют незнакомые аргументы и флаги — «правдоподобный, но не тот
вывод, что просил, — и никакого сигнала об этом».

## Repro (полевые)

KCam Г1: `node KAIF-LOADER.mjs …` (задание на 8 пунктов) → `node .kaif/kaif-core.mjs` без
аргументов → `wc -l KAIF_UPDATE_TASK.md` — пунктов меньше, новостей нет. Остальные грани —
однострочные вызовы из таблицы.

## Root cause

Дефолт голой команды — `install` (деструктивная операция как поведение по умолчанию);
разбор argv не отвергает неизвестное: лишние позиционные аргументы и флаги не сверяются со
схемой команды. Перезапись задания без чекпоинтов не резервируется, хотя имя
`KAIF_UPDATE_TASK.superseded.md` уже зарезервировано в `.gitignore`.

## Fix plan

Фаза **L3** родителя `plans/28_EPIC_kaif_2.2_L_update_field_fixes.md` (якорь: «### L3.
CLI-безопасность и зелёная ложь»): голый запуск = справка, не install; `help` —
команда; неизвестный флаг/аргумент мутирующей команды = отказ, не молчаливое исполнение;
задание с работой не перезаписывается молча (superseded-копия / «задание уже есть» при re-run
той же версии). Гейт фазы: «KCam-инцидент Г1 (потеря задания) воспроизведён красным и закрыт»;
критерий приёмки эпика №4.

## ✅ STATUS: DONE (2026-08-07, фаза L3 — `plans/42`)

Все грани закрыты в `framework/installer/KAIF-CORE.mjs`
(`[TESTED: 2026-08-07 · npm run test:core — 9/9 сводов]`):

1. **Голый/флаговый запуск = справка** (`help` — команда; `--help`/`-h` — тоже; NDim гр.5,
   Unlim Г4, KCam Г9а). Флаговый запуск без команды печатает справку и выходит 1 — скрипт,
   полагавшийся на старый install-дефолт, обязан ЗАМЕТИТЬ, что установки не было. Лоадер
   всегда звал `install` явно — бутстрап не задет (проверено чтением KAIF-LOADER.mjs:79).
2. **Единый спек COMMANDS** ведёт диспетчер, справку и валидацию argv: неизвестная команда →
   справка + exit 1; неизвестный флаг/лишний позиционный аргумент мутирующей и читающей
   команды → отказ с именем и подсказкой (KCam Г10 `sync --dry-run`, Unlim Г3
   `diff PHILOSOPHY.md`, опечатка `--sourse` — s09 G3/G4/G5).
3. **THE инцидент (KCam Г1) закрыт fail-closed:** незавершённое задание БЕЗ чекпоинтов при
   same-version re-run `install` больше не регенерируется — «диффы = поставка», удаление
   только сознательное (s09 G1/G1b: байт-в-байт; красное доказательство — до-фиксный прогон
   потерял диффы ровно как в поле).
4. Изменение поведения объявлено владельцам обновляющихся проектов: policy-запись 2.2 в
   бандл-манифесте (`POLICY_CHANGES_BY_VERSION`) — update-задание выносит её в
   «decisions for the OWNER».

**TWINS:** searched другие точки входа argv — диспетчер один; мини-CLI tool-модулей
(canon-lint, provenance) уже отвергали неизвестные команды списком; лоадер пробрасывает
флаги в явный `install`, который их валидирует. Судья фазы нашёл два близнеца ЭТАЖОМ НИЖЕ
(значение флага и явный help) и одну зеркальную дыру — все закрыты тем же заходом:
опечатка ЗНАЧЕНИЯ `--channel` тихо падала в release (→ отказ со списком, страж G16);
`help install` молча глотал аргумент (→ validateArgv, страж G18); явный `install` посреди
АДАПТАЦИИ сносил задание с чекпоинтами (→ superseded-копия, страж G15).

## Decisions made without the owner

Триаж: «нет таких» — классификация граней однозначна по отчётам. Закрытие: (1) флаговый
запуск без команды — exit 1 (не 0): тихий успех там, где раньше был install, скрыл бы от
скрипта отсутствие установки; чистый 0 оставлен голому запуску и `--help`/`-h`/`help`;

поддержку — это фича вне скоупа фазы, кандидат в беклог эпика O/будущего);
(3) вайтлисты флагов собраны по фактическому чтению `val()`/`has()` каждой командой.
