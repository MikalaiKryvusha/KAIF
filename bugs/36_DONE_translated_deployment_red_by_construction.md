# Bug 36 — класс L-6: update-verify и аудит modules на переведённом развёртывании красны/шумны ПО ПОСТРОЕНИЮ

**Status:** ✅ DONE (фикс L4, 2026-08-07; полигон 10/10; свод s10 S3/S4)
**Version/build:** машинерия 2.1 · **When/context:** 2026-08-07, триаж 4 полевых отчётов об
обновлении до 2.1; класс L-6 — `researches/15` §3. Формулировка поля: «дрессирует оператора игнорировать
аудит целиком, включая те 32 `differ`, где что-то настоящее».

## Симптом (класс, не экземпляр)

Выходные проверки ищут ДОСЛОВНЫЕ английские строки шаблонов на диске переведённого
развёртывания — где их не может быть никогда по решению владельца. Итог: сотни «MODULE ABSENT»
(218/290/216 в трёх проектах), «promised upstream line not found» на намеренно переведённых
строках, красная приёмка со второго захода — 100 %-ложный шум, неотличимый от реальной потери
модуля.

## Repro (полевые)

Unliminium: «перевести любой скилл, обновиться, запустить `update-verify`». Остальное — прогон
`update-verify`/`modules` на любом из трёх переведённых проектов.

## Root cause

Верификатор проверяет свойство «дословное присутствие строки шаблона», которое на переведённом
развёртывании ложно по построению; правильное свойство — «модуль на диске непуст и его
сигнатура известна» / «покрыт ли смысл модуля» (Unliminium Г11, KLAS §4.6). Отдельная грань:
плейсхолдеры ищутся по всем файлам, включая библиотеки чужих сфер (грань пересекается с
bugs/40 — адресация placeholders).

## Fix plan

Фаза **L4** родителя `plans/28_EPIC_kaif_2.2_L_update_field_fixes.md` (якорь: «### L4. Шум и
честность аудита»): отдельный режим переведённого развёртывания —
«absent ≠ дефект», «MODULE ABSENT» не печатается как дефект (или помечается «translated —
сверка по сигнатуре неприменима»); плейсхолдеры — только в файлах объявленной сферы. Гейт —
критерий приёмки эпика №7 («не красный по построению»); страж красным до фикса.

## ✅ STATUS: DONE (2026-08-07, фаза L4 — `plans/43`)

`[TESTED: 2026-08-07 · npm run test:core — 10/10; свод s10 S3 (localized ≠ ABSENT · реальная
потеря видима) и S4 (чужая сфера не блокирует · объявленная стережётся)]`:

- **`moduleAudit`:** при `i18n: translated` файл, чьи absent-сигнатуры совпадают с телом на
  письме владельца, классифицируется **`localized`** («translated wholesale, by-signature
  comparison not applicable») — не печатается дефектом; счётчик сводки несёт отдельное
  «N file(s) localized (translated — not a defect)». Реальная потеря модуля в EN-файле
  осталась «MODULE ABSENT» (доказано сводом на одном прогоне: PHILOSOPHY-RU → localized,
  выпиленный модуль TESTING → ABSENT). EN-путь побайтно идентичен старому (SCRIPTS['en']
  нет → ветка недостижима; подтверждено судьёй исполнением).
- **`scanPlaceholders`:** из сфер сканируется только ОБЪЯВЛЕННАЯ (`marker.sphere`) — чужие
  сферы-справочники с шаблонными слотами (`<BUILD_COMMAND>` в чужой `programming.md` — Unlim
  Г11) больше не блокируют приёмку; незаполненный слот объявленной сферы остаётся красным
  (KCam). Грань «update-verify требует дословных EN-строк» закрыта ранее фазой L2 (скип
  promised-lines при `i18n: translated`) — подтверждено кодом.

## Decisions made without the owner

Триаж: грань «плейсхолдер чужой сферы блокирует приёмку» учтена и
здесь (механизм приёмки), и в bugs/40 (механизм адресации задания) взаимными ссылками — фиксы
в одной фазе L4/L5, дубля работ нет. Закрытие:

1. **Классификация localized — по письму владельца в сыром тексте файла** (SCRIPTS[language]),
   а не через `bodyLocalized` против шаблона: у аудита есть только sha шаблонов, текстов нет;
   честная граница различимости признана вслед за полем (KCam Г13: «отличить по выводу
   невозможно» — метка и говорит «сверка неприменима»).
2. **Модули-«ours» у localized-файла не считаются** — его собственные заголовки И ЕСТЬ перевод,
   счёт их «вашими» был бы тем же шумом с другого бока.
3. **Сфера не объявлена (TODO) → слоты сфер не сканируются вовсе**: рабочая поверхность сфер
   появляется с объявлением; остаточное окно «сфера объявлена ПОСЛЕ verify-final — слот виден
   лишь следующему update-verify» признано и оставлено (страховка — обязательный пункт
   `sphere` задания адаптации + warnSphereLibrary).
