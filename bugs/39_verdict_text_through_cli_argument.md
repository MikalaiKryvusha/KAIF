# Bug 39 — класс L-9: вердикт судьи принимается ТОЛЬКО CLI-аргументом — машинерия нарушает собственную норму «текст через файлы»

**Status:** 🔴 OPEN (заведён триажем L1 эпика L 2.2)
**Version/build:** машинерия 2.1 (`checkpoint judge`) · **When/context:** 2026-08-07, триаж
4 полевых отчётов; класс L-9 — `researches/15` §3.

## Симптом (класс, не экземпляр)

`checkpoint judge` требует `--verdict "<многострочный текст с кириллицей, ёлочками, тире>"` —
файлового варианта нет. Релиз 2.1 сам ввёл в канон правило «TEXT TRAVELS THROUGH FILES, NEVER
THROUGH COMMAND-LINE ARGUMENTS» с четырьмя лицами класса; «Фреймворк требует от проектов
дисциплины, которой не следует в собственном API».

## Repro (полевые)

Любой `checkpoint judge --verdict "…"` с не-ASCII на Windows PowerShell 5.1 — класс
«текст-через-CLI» из AGENT_GUIDE («Гигиена документов и текста», симптом 1: тихая моджибака
при зелёном exit-коде).

## Root cause

API спроектирован до канонизации нормы (норма — 2.1, API — тоже 2.1: разошлись внутри одного
релиза); файловый путь не был предусмотрен.

## Fix plan

Фаза **L3** родителя `plans/28_EPIC_kaif_2.2_L_update_field_fixes.md` (якорь: «### L3.
CLI-безопасность и зелёная ложь» — строка «`--verdict-file` (L-9 — заодно, тот же
слой CLI)»): `--verdict-file <path>` рядом с `--verdict`; строковый вариант остаётся для
ASCII-односложных случаев. Сшивка с решением №42: вердикт едет в коммитимую квитанцию —
файловый путь становится ещё и носителем приёмки.
