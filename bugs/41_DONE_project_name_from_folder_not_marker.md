# Bug 41 — класс L-11: имя проекта берётся из имени каталога, а не из маркера — «klas» вместо KLAS в заголовках документов

**Status:** ✅ DONE (фикс L5, 2026-08-07; полигон 11/11)
**Version/build:** машинерия 2.1 (заполнение `<PROJECT_NAME>`) · **When/context:** 2026-08-07,
триаж 4 полевых отчётов; класс L-11 — `researches/15` §3.

## Симптом (класс, не экземпляр)

Плейсхолдер `<PROJECT_NAME>` заполняется значением из `package.json`/имени каталога (нижний
регистр) и попадает в ЗАГОЛОВКИ документов, которые человек читает первыми
(`# klas — Project History`). Канон того же релиза 2.1 вводит правило «право действия ≠
авторство идентичности»: имя — никогда не решение агента. Формулировка поля: «Машине это
правило тоже стоит соблюдать».

| KrinikCam | судья: `# krinikcam — Project History`, `"the stylistic LoRA" of krinikcam`; остаток — карта плейсхолдеров манифеста (`"<PROJECT_NAME>": "krinikcam"`) | суд.3 |

## Repro (полевые)

Развернуть/обновить проект, чьё каноническое имя отличается регистром/формой от имени каталога
→ прочитать первую строку засеянного `PROJECT_HISTORY.md`.

## Root cause

Источник имени — технический идентификатор (каталог/`package.json.name`), а не канон
(`.kaif/kaif.json` / «Идентичность проекта» AGENT_GUIDE); каскад: раз попав в манифест, имя
тиражируется дальше.

## Fix plan

Фаза **L5** родителя `plans/28_EPIC_kaif_2.2_L_update_field_fixes.md` (якорь: «### L5.
Остальные запросы + судья» — строка «имя проекта из маркера, не из каталога»): маркер
получает поле канонического имени (или читается из AGENT_GUIDE); `package.json`/каталог —
только фолбэк с честной пометкой; существующие карты плейсхолдеров чинятся при обновлении.

## Разведка кода (L5, шаг 1 — 2026-08-07)

- Источник имени: `detectValues` (`KAIF-CORE.mjs` ~:289) — `name = package.json.name || <имя
  каталога>` → `<PROJECT_NAME>` И `<SHORT_NAME>`; канон (маркер/AGENT_GUIDE) не читается нигде.
- Заморозка (bug 26): `snapshotValues`/`stableValues` (~:316) — значения манифеста побеждают
  редетекцию; карта значений персистится в `deploy-manifest.json` при install (~:1587) и
  update (~:1087) → раз попав, техническое имя тиражируется (каскад KCam).
- В маркере поля имени нет; шаблон AGENT_GUIDE несёт строку идентичности
  `| **Name / brand** | <PROJECT_NAME> |` (framework/AGENT_GUIDE.md:169) — при деплое она
  заполняется тем же фолбэком, т.е. «канон в AGENT_GUIDE» на свежей установке ещё не существует.
- Образец механизации: `cmdSphere` (~:1776) — команда, правящая маркер без ручного
  редактирования (урок ДЗ-02: слабая модель перезаписывает kaif.json). Форма фикса —
  аналогичная команда `project-name`.
- `package.json.name` сеется из `<PROJECT_NAME>.toLowerCase()` (~:1552) — это правильный
  lowercase для npm, НЕ трогать (направление каскада: pkg←values, не values←pkg).

пункт `project-name` в обоих заданиях с ИСПОЛНЯЮЩИМ чекпоинт-гейтом (отказ до записи имени).
