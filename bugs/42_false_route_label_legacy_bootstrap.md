# Bug 42 — уникальный (NDim): ложная метка маршрута — `route: "legacy-bootstrap"` при классификации свежим ядром

**Status:** 🔴 OPEN (заведён триажем L1 эпика L 2.2)
**Version/build:** машинерия 2.1 (квитанция `.kaif/last-update.json`) · **When/context:**
2026-08-07, триаж 4 полевых отчётов; уникальный дефект NDim (грабля 6).

## Симптом

Квитанция NDim 2.0→2.1: `"route": "legacy-bootstrap"` при `"classified": true` — хотя проход
шёл СВЕЖИМ ядром 2.1 («machinery 2.1 verified») с модульной классификацией против уцелевшего
манифеста v2. «legacy» описывает не то, кто исполнял обновление, а то, что развёртывание было
создано раньше. «Следующая сессия, читающая расписку, сделает неверный вывод о маршруте».

Контраст: у Unliminium и KrinikCam (1.6→2.1, синтетический baseline) та же метка честна — там
маршрут действительно легаси. Дефект — в неразличении двух случаев.

## Repro (полевое)

Обновление 2.0→2.1 (манифест v2 жив) через тонкий `KAIF.md` → прочитать `route` в
`.kaif/last-update.json`.

## Root cause

Метка ставится по способу входа (bootstrap через тонкое ядро), а не по фактическому пути
классификации (живой манифест против синтетического baseline).

## Fix plan

Фаза **L5** родителя `plans/28_EPIC_kaif_2.2_L_update_field_fixes.md` (якорь: «### L5.
Остальные запросы + судья» — строка «честная метка маршрута»): `bootstrap`, когда
классификацию выполнило свежее ядро по живому манифесту; `legacy-bootstrap` — только когда
шёл синтетический baseline / обновление исполнило старое ядро. Сшивка с решением №42
(квитанция расширяется вердиктом — правится тем же заходом).

## Разведка кода (L5, шаг 1 — 2026-08-07)

- Постановка метки: `cmdInstall` шаг 5 (`KAIF-CORE.mjs` ~:1598–1604) — `writeReceipt({route:
  'legacy-bootstrap'})` + `appendHistory(…, 'legacy-bootstrap')` БЕЗУСЛОВНО при любом
  version-move через бутстрап; фактический путь классификации известен ровно там:
  `cls.baselineOld` (~:1488) — живой `deploy-manifest` (без флага) vs синтетический baseline
  (`synthetic: true`, ~:671) vs `cls === null` (классический adopt-everything).
- `cmdUpdate` (~:1111) пишет `route: 'core-update'` — не трогать.
- Сшивка с решением №42: квитанция уже расширена вердиктом судьи (checkpoint judge →
  receipt), `update-verify` штампует `verifiedAt` (~:1424) — правка метки не задевает эти поля.
