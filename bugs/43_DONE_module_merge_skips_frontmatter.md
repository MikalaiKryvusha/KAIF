# Bug 43 — уникальный (KrinikCam): мерж модулей не трогает frontmatter — `description` противоречит перемержённому телу навыка

**Status:** ✅ DONE (фикс L2, 2026-08-07; верификация — полигон s08/C, 8/8 сводов)
**Version/build:** машинерия 2.1 (модульный мерж SKILL.md) · **When/context:** 2026-08-07,
триаж 4 полевых отчётов; уникальный дефект KrinikCam (судейская находка §4 + пожелание 11).

## Симптом

Модульный мерж режет файл по заголовкам ТЕЛА — YAML-frontmatter не модуль и не обновляется.
После мержа `description` у `/dayloop` и `/nightloop` «продолжал утверждать старое правило
(«любое сообщение владельца рвёт цикл»), пока ТЕЛО навыка мерж уже переписал». Один файл, два
противоречащих утверждения — «А `description` — это то, по чему навык маршрутизируется»:
агентская система выбирает навык именно по нему.

## Repro (полевое)

Обновление, где шаблон навыка сменил и тело, и description, при локально адаптированном файле
→ сравнить description на диске с новым шаблонным после мержа модулей.

## Root cause

Сплиттер модулей начинается с H1/H2-заголовков; frontmatter лежит до первого модуля и не
входит ни в один — у него нет сигнатуры, нет класса, нет пути обновления, кроме полной замены
файла.

## Fix plan

Фаза **L2** родителя `plans/28_EPIC_kaif_2.2_L_update_field_fixes.md` (якорь: «### L2. Класс
перевода: детектор и вставка» — тот же слой модульного мержа): frontmatter
трактуется как именованный псевдомодуль (обновляется при изменении шаблонного, с уважением
локализованных `description`/алиасов — не затирая перевод, класс bugs/31); минимум — дифф
frontmatter в задание. Как класс рассинхрона пары «описание ↔ тело» — взаимная ссылка с
bugs/38 (линт бандла ловит это у автора до релиза).

## ✅ STATUS: DONE (2026-08-07, фаза L2 — `plans/41`)

Уточнение причины по коду (разведка L2): frontmatter УЖЕ был псевдомодулем `<preamble>`
сплиттера — дыра была не в нарезке, а в ВЕЧНОМ РАСХОЖДЕНИИ преамбулы: машинный алиас-хвост
`Trigger aliases (<lang>): …`, который `applyLanguage` пришивает к `description`, при смене
пакета/маршрута (легаси-bootstrap с синтетическим baseline) делает преамбулу «правленной
владельцем» навсегда — и обновлённый `description` не имеет пути на диск, пока тело мержится.

Фикс (`framework/installer/KAIF-CORE.mjs`, `[TESTED: 2026-08-07 · npm run test:core — 8/8]`):

1. Равенство преамбулы со старым шаблоном судится ПО МОДУЛЮ алиас-хвоста (`stripAliasTail`;
   старый текст — из baseline, принимается только при совпадении sha со снапшотом деплоя) —
   «нетронуто, кроме машинного хвоста» = нетронуто, преамбула обновляется вместе с телом.
2. Замена преамбулы не затирает локализацию: свежие алиасы приезжают в новом контенте, а при
   их отсутствии (нет пакета) хвост с диска переносится в новый `description`.
3. Страховочная сеть `localizedAgainst` преамбулу больше не судит (машинные алиасы делают её
   кириллической по построению — ложная «локализация»).
4. Description, правленный владельцем ГЛУБЖЕ хвоста, — не трогается, дифф в задание (общий
   механизм разошедшихся модулей).

Полевое противоречие воспроизведено и закрыто парой стражей s08/C: F5b (тело перемержено) +
F5a (description обновлён) + F5c (алиас-хвост жив).

**TWINS:** searched другие машинные вставки, мутирующие развёрнутые файлы после снапшота, —
единственная (`applyLanguage` алиасы); хвост нормализуется в одном месте (`stripAliasTail`),
обе точки сравнения (`untouchedMod` преамбулы, перенос хвоста при замене) зовут его.

## Decisions made without the owner

Триаж: отнесён к фазе L2 (механизм мержа), а не L4 (линт), потому что первопричина — дыра
сплиттера, а не сверка. Закрытие: (1) первопричина переквалифицирована с «frontmatter не
модуль» на «вечное расхождение преамбулы из-за алиас-хвоста» — по чтению кода, симптом и фикс
те же; (2) при механическом обновлении преамбулы побеждают алиасы НОВОГО пакета (машинный
хвост принадлежит машинерии, не владельцу); правленный владельцем хвост в нестандартной форме
не распознаётся как хвост → преамбула считается правленной → дифф в задание (безопасная
сторона).
