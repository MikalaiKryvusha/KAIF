## ⚠️ РЕЦИДИВ 2026-08-09 01:27:48 +03:00 — второе наблюдение, тот же файл

Условие механизации, записанное этим документом («рецидив — второе наблюдение — переводит баг из
research-only в механизацию»), ВЫПОЛНЕНО. Наблюдение:

- Предкоммитный `git diff --stat` показал `plans/26_kaif_2.2.md | 6 --`. Пропал ровно тот блок,

Рецидив УСИЛИВАЕТ гипотезу 1 и сужает её: пострадал ТОТ ЖЕ файл, и оба раза исчезала САМАЯ СВЕЖАЯ
правка — подпись протухшего буфера редактора, а не случайной записи. Сессия работает внутри
расширения VS Code, и `plans/26` — документ, который владелец держит открытым чаще прочих.

## Symptom

Рабочая копия `plans/26_kaif_2.2.md` оказалась ОТКАЧЕНА к версии до коммита `890fbeb` (закрытие
эпика L): исчезла секция «7. Задача T8 — канон временных меток» (28 строк, решение №49), «Фаза R»
вернулась в §7, строка эпика K в таблице §1 вернулась к «—» (в HEAD она закрыта с K5). 275 строк
→ 251. Агент, не заметив отката, отредактировал протухшую копию (закрыл строки K и M) — и только
предкоммитный `git diff --stat` показал «минус-строки», которых агент не делал.

## Repro (deterministic)

Репро НЕТ — одиночное событие. Наблюдение класса: `git diff` перед коммитом показывает удаления,
которых сессия не делала → рабочая копия чужая/протухшая. Проверка на будущее:
`git diff -- <файл> | grep -E '^-[^-]'` — каждая минус-строка обязана быть твоей намеренной
заменой.

## Forensics

- Хронология доказана коммитами: `b3856b8` (15:12, `git add -A`) НЕ включил `plans/26` → в
  15:12 рабочая копия == HEAD. В 15:26 греп/Read показали старую версию (K «—», без T8).
  Окно отката: 15:12–15:26.
- В окне исполнялись только: `build-framework` (пишет KAIF.md/dist/KAIF_REFERENCE — не plans/),
  фоновый полигон `npm run test:core` (все записи — в OS-temp песочницы), Edit-правки агента
  ДРУГИХ файлов, read-only грепы/чтения.
- Греп исключил инструменты: `writeFileSync(join(REPO`/`cpSync(..., join(REPO` в
  `tools/**/*.mjs` — 0 совпадений; git-операций (checkout/restore/stash) в инструментах нет;
  селфтест `questions-guard` пишет только в tmpdir-бокс.
- Остальные модифицированные файлы проверены тем же сканом минус-строк — откат ТОЛЬКО в
  `plans/26`.

## Root cause / Hypotheses

1. **(основная) Протухший буфер редактора владельца.** Репозиторий открыт в живом VS Code;
   вкладка с `plans/26` могла держать несохранённую/старую версию (файл много правился
   сессиями L5→девятая) и записать её на диск (авто-сохранение/фокус) поверх свежего HEAD в
   момент активности владельца в окне (~15:1x, владелец писал в чат). Симптом совпадает
   точно: файл превращается в снимок эпохи последней загрузки вкладки.
2. (маловероятная) Неизвестная запись стороннего процесса — инструментами репо исключена
   грепом; других писателей в окне не наблюдалось.

## Fix plan (or the fix, if done)

Состояние ПОЧИНЕНО в момент обнаружения: `git checkout HEAD -- plans/26_kaif_2.2.md` +
повторное накатывание единственной намеренной правки (строка эпика M). Потерь нет — откат
пойман ДО коммита ритуалом git-гигиены («git diff --stat перед каждым коммитом; всё, чего не
намеревался менять, — СТОП»), который существует ровно для этого класса.

Страж класса: сам ритуал предкоммитного диффа (уже канон AGENT_GUIDE, сработал в поле) +
правило чтения минус-строк из Repro. Отдельный механический страж не заводится, пока класс
не повторится (второй раз = механизация, канон EXPERIENCE).
