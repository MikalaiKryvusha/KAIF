# Bug 46 — сообщение коммита исковеркано MSYS2-конвертацией argv (git-bash → commit.mjs)

**Status:** ✅ DONE (2026-08-07)
**Version/build:** build 135 (коммит `dbe2db1`) · **When/context:** 2026-08-07, фикс-коммит
закрытия фазы N3, вызов `node tools/commit.mjs "<кириллица + слэши>"` из git-bash
**Fix accepted when (observable):** (1) `node tools/commit.mjs "тест: кириллица"` из git-bash
ОТКАЗЫВАЕТ с готовым решением (exit 1, без коммита и бампа); (2) коммит через
`--msg-file <путь>` даёт `git log -1 --format=%B`, побайтно равное файлу сообщения.

## Symptom

Файлы коммита целы, но САМО СООБЩЕНИЕ в опубликованной истории (`dbe2db1`) исковеркано:
`/` → `\\`, `:` → `;`, а фрагмент `Topic:/Status:` развёрнут в
`Topic;C:\Program Files\Git\Status;` — вставлен путь установки git. Инструмент отработал
«зелёным» (закоммитил и запушил), повреждение поймано только чтением записанного обратно.

## Repro (deterministic)

Из git-bash на Windows: `node tools/commit.mjs "тест: a/b Topic:/Status:"` (до фикса) →
`git log -1 --format=%B` показывает `;`, `\\` и развёрнутый путь. После фикса та же команда
обязана ОТКАЗАТЬ (страж argv); файловый режим воспроизводит текст побайтно.

## Forensics

`git log -1 --format=%B` HEAD `dbe2db1`: «feat(2.2\\N); …», «Topic;C:\Program Files\Git\Status;»,
«Финал; «doc-header-lint; scanned 84…». Повреждены все `:` и `/` сообщения; кириллица как
таковая цела — ломает не кодировка, а path-conversion.

## Root cause / Hypotheses

Причина (подтверждена формой повреждения): MSYS2 (git-bash) при запуске Windows-программы
конвертирует argv, похожие на POSIX-пути: `/` → `\`, списки с `:` → `;`, а `/Word` — в
`<git-prefix>\Word` (отсюда `C:\Program Files\Git\Status`). Прошлые сессии коммитили те же
кириллические сообщения из PowerShell — там этого слоя нет: «работало» было свойством ШЕЛЛА,
не инструмента (канон-класс «текст-через-CLI», AGENT_GUIDE → Гигиена, симптом 4 «разные шеллы —
разные миры»; теперь дописан симптом 5). Внутри commit.mjs добавлял хрупкости и
`git commit -m ${JSON.stringify(msg)}` — второй шелл-слой (cmd) для текста.

## Fix plan (or the fix, if done)

Класс закрыт по построению в `tools/commit.mjs` (механизация, не памятка):
1. **Страж argv:** не-ASCII сообщение через argv отвергается с готовым решением в тексте
   ошибки (паттерн EXP-0008) — до бампа и любых git-действий; красный доказан наблюдением.
2. **Файловый транспорт:** режим `--msg-file <путь>` (UTF-8, BOM-терпимо) и внутри —
   `git commit -F <tmp-файл>`: текст сообщения не проходит через argv/шелл вообще.
3. Канон: симптом 5 в блок «текст-через-CLI» AGENT_GUIDE; строка таблицы инструментов
   обновлена; урок EXP-0034 (механизировано: страж в commit.mjs).

Повреждённое сообщение `dbe2db1` НЕ переписывается без слова владельца (amend опубликованного
= force-push на main — за пределами стоячей авторизации); вся содержательная сводка коммита
продублирована в `plans/53` (закрытие), `STATUS.md`, `EXPERIENCE.md`. Предложено владельцу —
его решение.

## Decisions made without the owner

1. Историю не переписывал (force-push требует цитируемого слова владельца) — предложение
   вынесено владельцу в чат.
2. Страж отвергает ЛЮБОЕ не-ASCII в argv, не только кириллицу: класс шире языка (эмодзи,
   ёлочки, тире).
3. Внутренний транспорт переведён на `git commit -F` и для ASCII-режима тоже — один путь
   вместо двух.

## ✅ STATUS: DONE (2026-08-07)

Оба условия «Fix accepted when» исполнены наблюдением: (1) страж argv красный на кириллице —
«✋ non-ASCII commit message via argv…», exit 1, HEAD и build не изменились; (2) фикс-коммит
`b8cb1c7` через `--msg-file` — `git log -1 --format=%B` побайтно равен файлу-источнику
(скрипт-сверка: «byte-equal: true», следов конвертации нет). Класс закрыт по построению.
