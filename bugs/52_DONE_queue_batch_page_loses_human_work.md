# Bug 52 — очередь одной простынёй: запись по одному документу уносила окно и черновики остальных

**Status:** ✅ DONE (2026-08-08 07:25 +03:00) · **Version/build:** KAIF 2.2-in-progress, build 176
**When/context:** найден ВЛАДЕЛЬЦЕМ на живом прогоне 2026-08-08 ≈07:05 +03:00. Слова дословно:
«я нажал запись решений по документу - закрылся весь браузер, а там ещё ниже вопросы были»,
затем — постановка формы: «Должна быть входная страница - которая показывает документы только в
виде карточек - из неё я кликаю по карточке документа и открываю обычное интервью интерактивное в
отдельном браузере», и решение не продолжать: «не буду отвечать пока что, нужно чинить этот бред
мультидокументов».

**Fix accepted when (observable):** на живом сервере запись решения по ОДНОМУ документу очереди не
завершает контур и не уносит остальные — входная страница остаётся, отвеченный документ уходит с
неё, оставшийся доступен; контур завершается закрытием ВХОДНОЙ страницы.
**Наблюдено:** блок QA8 в `tools/verify-contour.mjs` — девять проверок на настоящем сервере,
включая «КОНТУР ЖИВ после записи одного документа и закрытия его окна» и «отвеченный документ ушёл
с витрины владельца, остался второй».

## Symptom

Пачка рендерилась ОДНОЙ страницей: все документы, все их вопросы, у каждого своя кнопка записи.
Нажатие кнопки записывало решение — и завершало контур целиком (`I8`), после чего окно
закрывалось (`I27`). Документы, до которых человек не дошёл, исчезали с экрана вместе с окном.
В логе это выглядело штатно: «В очереди осталось документов: 2 — перезапуск пачки за агентом».
Со стороны человека — браузер пропал посреди работы.

## Второй дефект того же захода (найден чтением кода, не владельцем)

Очистка черновиков после записи шла по ключу ВСЕЙ ПАЧКИ (`owner-review:queue`): сохранение одного
документа стирало из `localStorage` черновики ответов, набранные по СОСЕДНИМ документам. То есть
терялась не только видимость, но и сам набранный текст. Владелец до этого не дошёл только потому,
что закрыл окно раньше.

## Repro (детерминированный, до фикса)

1. Два документа с неотвеченными вопросами в очереди → `node tools/review.mjs --queue`.
2. Ответить на первый, нажать «Записать решения по этому документу».
3. Наблюдать: окно закрывается, процесс контура завершается кодом 0, второй документ не показан.

## Root cause

**Форма подменяла адресата.** Одна страница на всю очередь означает, что ЛЮБОЙ исход одного
документа (запись, закрытие) — исход всей сессии: у окна один жизненный цикл на всех. Инварианты
`I8` (запись завершает контур) и `I27` (окно закрывается само) писались для страницы ОДНОГО
документа и были механически перенесены на пачку, где «документ» и «сессия» перестали совпадать.
Компенсация («остаток пачки агент поднимет снова») переносила цену на человека: его окно исчезало,
а восстановление зависело от того, вспомнит ли агент перезапустить.

## Fix — форма, заданная владельцем

1. **Входная страница = только карточки** (`buildIndexPage`): по карточке на документ — класс,
   заголовок, путь, сколько вопросов ждёт. Ни одного вопроса, ни одной радиокнопки, ни одной
   кнопки записи на ней нет по построению.
2. **Документ открывается СВОИМ окном** — `href="/d/<путь>" target="_blank"`; сервер отдаёт там
   обычную одностраничную форму интервью (или сообщения — класс определяет файл состояния, не URL).
3. **Запись одного документа больше не завершает контур:** пока в очереди остаются документы,
   сервер живёт, а входная страница перечитывается сама при возврате фокуса.
4. **Контур завершает закрытие ВХОДНОЙ страницы.** Маячок `pagehide` называет роль окна
   (`index:` / `doc:`); закрытое окно документа — событие внутри сессии, а не её конец.
5. **Черновики — по документу, не по пачке:** ключ `localStorage` строится от пути документа.
6. **Витрина владельца показывает то, что ждёт ЕГО:** документ, где он ответил на все вопросы,
   уходит с неё сразу. Документ с протухшим статусом — долг АГЕНТА, его ловит `questions-guard`, и
   человеку он не показывается; документ без вопросов, но со статусом «ждёт», остаётся — его
   ожидание адресовано именно человеку.
7. **Путь принимается только из очереди:** `/d/<...>` вне текущей очереди отвечает 404 — адресная
   строка не становится способом прочитать произвольный файл репозитория.

## Verification

- **Блок QA8** (`tools/verify-contour.mjs`) — живой сервер, фикстура из двух документов, девять
  проверок: карточки по числу документов · ноль радиокнопок на входной · `target=_blank` ·
  4 радиокнопки на странице документа · 404 на путь вне очереди · запись назвала остаток ·
  **контур жив** после записи и закрытия окна документа · отвеченный ушёл с витрины ·
  закрытие входной страницы завершает контур.
- Полный QA-прогон: **110 зелёных, 0 красных**; `npm run test:core` — 14 сводов зелёные.
- Прогон писался ДО фикса и краснел на двух проверках («остался 1 документ» показывал 2;
  «отвеченный ушёл с витрины» не выполнялось) — страж умеет краснеть, доказано не рассуждением.

> **Побочная добыча.** Тот же живой прогон вскрыл дефект тяжелее исходного: ответ владельца
> записывался в документ, но не РАСПОЗНАВАЛСЯ разбором — `bugs/53`. Своды и приёмка были зелёными
> до и после переделки формы одинаково; нашёл его только круговой прогон «записал → прочитал
> обратно» на настоящем сервере.

## Решения, принятые агентом без владельца

1. **Контур завершает закрытие ВХОДНОЙ страницы** (а не «когда отвечено всё»). Владелец задал
   форму, но не назвал условие конца сессии. Выбрал по аналогии с одиночным документом: окно и
   есть сессия; человек вправе уйти, не ответив на всё, и это штатный исход, а не отказ.
2. **Автообновление витрины по возврату фокуса**, а не по таймеру: перечитывание раз в N секунд
   дёргало бы страницу под руками, а фокус — точный признак «человек вернулся к очереди».
3. **Прежняя `buildQueuePage` оставлена в коде** (не вызывается сервером): её удаление — отдельная
   правка с прогоном ростера инвариантов; смешивать со срочным фиксом формы не стал.
4. **Первую заплатку выбросил.** Успел начать чинить старую форму (сервер живёт + перезагрузка
   страницы); после постановки владельца свернул её — чинить форму, которую владелец назвал
   неверной, значит закреплять дефект.
