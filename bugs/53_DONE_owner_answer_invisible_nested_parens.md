# Bug 53 — ответ владельца записан на диск, но НЕ ВИДЕН системе (вложенные скобки в метке времени)

**Status:** ✅ DONE (2026-08-08 07:15 +03:00) · **Version/build:** KAIF 2.2-in-progress, build 176
**When/context:** найден 2026-08-08 ≈07:10 +03:00 живым сквозным прогоном контура, который я писал
для ДРУГОГО дефекта (`bugs/52`). Проявился на настоящем документе: владелец ответил на интервью
№012 в 06:48, ответы легли в файл — и остались невидимыми.

**Fix accepted when (observable):** `parseQuestions` на документе с записанным ответом возвращает
`answered: true`, а `node tools/questions-guard.mjs` перестаёт числить вопрос неотвеченным.
**Наблюдено:** до фикса — `Q1 answered: false · Q2 answered: false` при двух записанных
`**Answer …:** B)` / `A)` в файле; после — `answered: true` для обоих, и страж немедленно поднял
СЛЕДУЮЩЕЕ нарушение («статус ждёт при нуле пустых полей»), которого раньше не видел.

## Symptom

Владелец ответил на оба вопроса интервью №012 через контур. Инструмент записал ответы в документ,
в `decision.json` и в архив — все три места. При этом:

- очередь продолжала показывать №012 как ждущий ответа;
- `questions-guard` продолжал числить оба вопроса неотвеченными;
- любая сессия, читающая состояние, сделала бы вывод «владелец не ответил».

То есть **работа человека существовала на диске и не существовала для системы** — ровно то, чего
вектор цели 2.2 обещает не допускать.

## Repro (детерминированный)

```
node -e "import('./tools/lib/review-core.mjs').then(({parseQuestions})=>{
  const md=require('fs').readFileSync('interviews/interview_012_commit_trailer_model_name.md','utf8');
  for(const q of parseQuestions(md)) console.log(q.id, q.answered)})"
```
До фикса: `Q1 false · Q2 false` (при двух записанных ответах в файле). После: `Q1 true · Q2 true`.

## Forensics

Строка, записанная инструментом:

```
**Answer (дополнение, 8 августа 2026, 06:48 (+03:00)):** B) <!-- owner-review: … -->
```

Регэксп метки ответа:

```
/^\s*\*{0,2}(?:Answer|Ответ…)\s*(?:\((?<mod>[^)]*)\))?\s*:\*{0,2}\s*(?<rest>.*)$/iu
```

`[^)]*` не умеет вложенности: он доходит до первой закрывающей скобки — той, что закрывает
`(+03:00)`, — после чего `\)` съедает её, а следующим символом оказывается `)`, а не `:`. Матч
разваливается; ответ становится обычной строкой прозы.

## Root cause

**Формат метки поменяли в одном месте, а её ЧИТАТЕЛЯ — нет.** Человекочитаемая метка времени
обзавелась смещением в скобках (`(+03:00)` — форма канона временных меток, задача T8), и запись
стала синтаксически невыразимой для разбора, который её же и читает. Ни один гейт этого не
поймал: писатель и читатель метки живут в разных функциях, и ни одна проверка не гоняла их ПАРОЙ —
«записал → прочитал обратно».

Это тот же класс, что `bugs/51` (страж, слепой там же, где код), в другой одежде: там две
реализации делили допущение, здесь писатель и читатель разошлись, и никто не сверял их между
собой. Общее правило обоих: **пару «производитель ↔ потребитель» проверяет только круговой
прогон, а не чтение любой из сторон.**

## Fix

Скобка модификатора допускает один уровень вложенности:

```
\((?<mod>(?:[^()]|\([^()]*\))*)\)
```

Один уровень, а не рекурсия: метка времени — единственный известный вложенный случай, а жадный
универсальный разбор скобок съел бы соседние конструкции.

**Круговой страж вместо чтения одной стороны** — QA-прогон контура теперь пишет ответ настоящим
`recordDecision` и ЧИТАЕТ его обратно `parseQuestions` на живом сервере (блок QA8, `bugs/52`):
именно этот круг и обнаружил дефект, когда я писал его для другой задачи.

**TWINS:** искал по репозиторию другие разборы записанного нами же формата — `ANSWER_LABEL_RE`,
`TARGET_LABEL_RE`, `COMMENT_LABEL_RE` в `review-core.mjs`. Скобочный модификатор есть только у
метки ответа; у остальных двух его нет, вложенность им не грозит. Четвёртого места нет.

## Verification

- живой документ №012: `answered false/false` → `true/true`, выбор владельца читается как `B)` и `A)`;
- `node tools/questions-guard.mjs` — вместо молчания поднял настоящее нарушение (протухший статус
  документа), то есть дефект парсера ВЫКЛЮЧАЛ целого стража;
- QA-прогон контура: **110 зелёных, 0 красных** (блок QA8 гоняет запись→чтение по кругу);
- `npm run test:core` — все 14 сводов зелёные.

## Решения, принятые агентом без владельца

1. **Один уровень вложенности, не рекурсивный разбор скобок.** Рекурсия покрыла бы гипотетические
   случаи ценой прожорливого матча по соседним конструкциям; известный случай ровно один.
2. **Ретроспективно документы не чинил.** Записи в №012 остались как есть — они теперь читаются;
   переписывать историю ответов владельца незачем и запрещено (та же норма, что решение №55).
