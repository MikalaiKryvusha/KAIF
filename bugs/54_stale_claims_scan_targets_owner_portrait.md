# Bug 54 — скан протухших утверждений не знает про портрет владельца

> **Создан:** 2026-08-08 (найден при закрытии задачи T4, `plans/34`). **Родитель:** `plans/34`,
> секция «Решения, принятые агентом без владельца», п. 6. **Статус:** 🔴 OPEN — репро
> детерминированное, фикс не начат. **Вовне:** —.

**Status:** 🔴 OPEN · **Version/build:** 2.1 (build 185) · **When/context:** найден 2026-08-08
при закрытии T4, когда портрет получил канон-имя `AUTHOR_STYLOMETRY.md`.

## Вектор цели (Avoid)

Не допустить, чтобы машинерия обновления предлагала владельцу править ЕГО СОБСТВЕННЫЙ документ.
Класс уже закрывался однажды (`bugs/35`, находка NDim гр.3: скан предлагал править `GOAL.md`) —
лекарством был список `SKIP_FILES`. Портрет — документ того же класса, а в списке его нет.

**Fix accepted when (observable):** в песочнице `s04` портрет `AUTHOR_STYLOMETRY.md`, СОДЕРЖАЩИЙ
токен версии, отсутствует в разделе протухших утверждений `KAIF_UPDATE_TASK.md` после прогона
`update`; ассерт краснеет при удалении имени из `SKIP_FILES` и зеленеет при возврате.

## Готово, когда (критерии приёмки)

1. `AUTHOR_STYLOMETRY.md` не попадает в скан протухших утверждений: файл с токеном версии внутри
   портрета НЕ появляется в задании обновления.
2. Красный доказан мутацией: убрать имя из `SKIP_FILES` → ассерт свода краснеет; вернуть → зелёный.
3. Правило записано ОДИН раз: портрет добавляется к уже существующему списку owner-документов,
   второго механизма исключения не заводится.

## Symptom

`framework/installer/KAIF-CORE.mjs:597` — список файлов, которые скан протухших утверждений
пропускает:

```
const SKIP_FILES = [UPDATE_TASK, TASK_FILE, 'KAIF.md', 'KAIF-LOADER.mjs', 'EXPERIENCE.md', 'PROJECT_HISTORY.md', 'GOAL.md'];
```

`AUTHOR_STYLOMETRY.md` в нём отсутствует. Портрет — **owner-класс**: его пишет агент, а принимает
владелец, и машинерия не имеет права предлагать в нём правки. При этом портрет ЛЕГАЛЬНО содержит
токены версий: реестр корпусов называет версии источников, журнал истории (§9 скелета) фиксирует
версии, в которых портрет менялся.

Комментарий строкой выше уже формулирует правило верно — просто не перечисляет портрет:

> GOAL.md and the declared canon artifacts are the OWNER's documents: the scan once proposed
> editing GOAL.md — a file the machinery itself declares untouchable (bugs/35, NDim гр.3).

## Repro (deterministic)

1. Развернуть KAIF в песочницу, снять портрет: создать в корне `AUTHOR_STYLOMETRY.md`, вписав в
   журнал истории строку с токеном вида `KAIF 2.1`.
2. Прогнать `update` с версии ниже (профиль сводов `s04`, `S14c`).
3. Наблюдать: портрет попадает в раздел протухших утверждений `KAIF_UPDATE_TASK.md` — машинерия
   предлагает править владельческий файл.

**Обходной путь, который СЕЙЧАС работает и маскирует дефект:** объявить портрет в
`.kaif/kaif.json` → `canonArtifacts` (строка 598 расширяет `SKIP_FILES` объявленным каноном).
Обход требует ручного действия владельца и по умолчанию не выполнен — то есть дефект живой.

## Root cause

Список `SKIP_FILES` перечисляет owner-документы ПОИМЁННО, а T4 добавила в поставку новый
owner-документ, не тронув список. Класс — «реестр, который не растёт вместе с поставкой»: тот же
корень, что у `bugs/49` (счётчики README) и `bugs/44` (протухшие языковые пакеты).

## Fix plan

- [ ] 1. Добавить `'AUTHOR_STYLOMETRY.md'` в `SKIP_FILES` (`framework/installer/KAIF-CORE.mjs`),
      комментарий расширить: портрет — owner-класс, легально несёт версии в реестре корпусов и
      журнале истории.
- [ ] 2. Ассерт в свод `s04` (там же, где `S14c`): портрет с токеном версии НЕ попал в задание.
- [ ] 3. Красный доказать мутацией: убрать имя из списка → ассерт краснеет; вернуть → зелёный.
- [ ] 4. Пересборка + `npm run test:core`.
