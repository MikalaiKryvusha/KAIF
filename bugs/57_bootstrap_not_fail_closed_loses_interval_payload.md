## Вектор цели (Avoid)

Не допустить необратимой молчаливой потери когнитивной поставки интервала (нормы, policy-changes,
диффы конфликтных модулей) при том, что маркер, расписка и history уже переведены на новую версию,
а `update-verify` зеленеет по чек-листу ЧУЖОГО интервала. Для анонимных и pre-1.5 развёртываний
bootstrap — ЕДИНСТВЕННАЯ дорога обновления, поэтому дыра бьёт именно по тем, у кого запасной нет.

**Fix accepted when (observable):** после шага «bootstrap 2.3» выполняется ОДНО из двух — либо
`head -1 KAIF_UPDATE_TASK.md` печатает «finish the update to 2.3» И `grep -rl UPSTREAM-NEWS-2.3 .
--exclude-dir=.git` находит файл (задачу или `*.superseded.md`), либо команда завершается ненулевым
кодом и НЕ трогает `.kaif/kaif.json` и `.kaif/last-update.json`.

**Сегодняшнее измеренное состояние:** задача говорит 2.2, grep не находит ничего, маркер уже 2.3 —
оба исхода сегодня ложны, критерий различает починку от текущего поведения.

## Symptom

`framework/installer/KAIF-CORE.mjs:1786` — ветка срабатывает по НАЛИЧИЮ чек-поинтов, а не по
интервалу версий:

```js
    if (existsSync(UPDATE_TASK) && /^KAIF-UPDATE: /m.test(readFileSync(UPDATE_TASK, 'utf8'))) {
```

Наблюдение: `= kept existing KAIF_UPDATE_TASK.md (it carries recorded checkpoints — not overwritten)`
при том, что интервал СМЕНИЛСЯ.

## Repro (deterministic)

Пять шагов, полностью — в карточке F3 аудит-отчёта: install 2.1 → правка модуля владельцем →
bootstrap 2.2 → `checkpoint review-news` → обрыв сессии → bootstrap 2.3.

## Root cause

Гарантия — свойство пути, а не дерева (семейство 4). fail-closed поверх незакрытой задачи
(`bugs/25`) живёт на дороге core-update; bootstrap с тем же деревом её не имеет. Соседние
комментарии закрывают два СМЕЖНЫХ случая (re-run той же версии — `bugs/14`; задание прошлого
интервала БЕЗ чек-поинтов — `bugs/25`), а их пересечение не покрыто ничем.

## Fix plan

- [ ] 1. Разделить ветку по ИНТЕРВАЛУ: при `legacyOld.version !== meta.version` сохранить задачу
      как `KAIF_UPDATE_TASK.superseded.md` (механизм уже есть, строки 1803–1807) и сгенерировать
      задачу нового интервала. Ветку «kept existing» оставить ТОЛЬКО для re-run.
- [ ] 2. Альтернатива той же цены — fail-closed по образцу строки 1154 до любых записей, с
      названными двумя законными ходами.
- [ ] 3. Ассерт в `s04-anon-legacy.mjs` (профили bootstrap живут там) + красный по мутации.
- [ ] 4. Не трогать: re-run той же версии (1788–1794), ветку задачи без чек-поинтов (1803–1807),
      ветку `TASK_FILE` (1831–1841).
