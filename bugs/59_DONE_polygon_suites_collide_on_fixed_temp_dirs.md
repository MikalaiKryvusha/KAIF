## Вектор цели (Avoid)

Не допустить ЛОЖНОГО КРАСНОГО в главном гейте проекта. Ложная тревога опаснее пропуска: она учит
оператора перезапускать и не смотреть — а `npm run test:core` обязателен после любой правки
машинерии и перед релизом. Красный, который «проходит сам собой», обесценивает красный, который
означает поломку.

**Fix accepted when (observable):** два одновременных прогона одного и того же свода завершаются
кодом 0 каждый:
`(node tools/sandbox/s13-requirements-lint.mjs > /tmp/a.log 2>&1; echo A=$? ) & (node tools/sandbox/s13-requirements-lint.mjs > /tmp/b.log 2>&1; echo B=$?) & wait`
→ `A=0` и `B=0`. **Сегодняшнее измеренное состояние:** `A_EXIT=1`, `B_EXIT=0` — критерий различает
починку от текущего поведения и не требует дополнительных замеров.

✅ **Замерено после фикса 2026-08-08 17:20 +03:00:** `A_EXIT=0`, `B_EXIT=0`.

## Symptom

Прогон `npm run test:core` при верификации T3 напечатал:

```
❌ sandbox suite: 1 of 14 suites FAILED
```

Чистый перепрогон через несколько минут: `✅ sandbox suite: all 14 suites green`, EXIT=0. Ничего в
дереве между прогонами не менялось.

⚠️ **Криминалистика первого падения УТЕРЯНА:** прогон был запущен через `| tail -4`, и имя упавшего
свода вместе с его выводом не сохранилось. Это отдельный оплаченный урок (см. `EXPERIENCE.md`
EXP-0052): верификационный прогон, пропущенный через `tail`, теряет ровно ту улику, ради которой
его гоняли.

## Repro (deterministic)

Механизм найден ЧТЕНИЕМ и подтверждён наблюдением. Каждый свод берёт каталог с фиксированным
именем:

```
grep -o "join(tmpdir(), *'[^']*'" tools/sandbox/*.mjs
→ 13 каталогов вида kaif-sbx-<имя>, ни одного уникализированного (pid, случайный суффикс, mkdtemp)
```

Прямая проба — два одновременных прогона ОДНОГО свода:

```
(node tools/sandbox/s13-requirements-lint.mjs …) & (node tools/sandbox/s13-requirements-lint.mjs …) & wait
→ A_EXIT=1, B_EXIT=0
```

Вывод упавшего — сырой стектрейс Node без единого слова диагноза:

```
Error: EPIPE, The process cannot access the file because it is being used by another process.
  '\\?\C:\Users\krinik\AppData\Local\Temp\kaif-sbx-reqlint\.kaif\tools\kaif-requirements-lint.mjs'
  at cpSync (node:fs:3147:3)
  at file:///D:/work/ai_sandbox/KAIF/tools/sandbox/s13-requirements-lint.mjs:31:1
  { errno: 32, code: 'EPIPE', syscall: 'unlink' }
```

Второй прогон сносит и пересоздаёт каталог, пока первый по нему ходит.

## Root cause

Каталог песочницы — фиксированное имя в общем OS-temp, то есть **разделяемый ресурс без владельца**.
Достаточно двух прогонов в одно время: две сессии агента, прогон полигона рядом с прогоном
отдельного свода (ровно это и случилось при T3 — пробный аудит гонял `s07` и `s10` своими
агентами), CI рядом с локальным прогоном, `--selftest` рядом с обычным прогоном.

Два семейства сразу: **12 — отказ, не называющий верного хода** (наружу летит стектрейс `cpSync`
вместо «каталог занят другим прогоном; запусти повторно или дай уникальный корень») и **10 —
зелёное/красное без содержания** (красный не означает поломку кода).

## Fix plan

- [x] 1. Уникализировать корень песочницы: `mkdtemp(join(tmpdir(), 'kaif-sbx-<имя>-'))` вместо
      фиксированного имени — по своду; либо один общий корень прогона, передаваемый сводам.
      Уникальный корень по построению снимает весь класс, а не текущий симптом.
      → **`tools/lib/temp-root.mjs`, функция `tempRoot(name, explicit)`** — один способ получения
      корня на весь репозиторий; имя каталога больше не выбирается руками, поэтому разойтись
      снова оно не может.
- [x] 2. Сохранить возможность стабильного пути для отладки (переменная окружения или флаг), чтобы
      не потерять сегодняшнюю привычку «зайти и посмотреть, что свод оставил».
      → привычка сохранена и УТОЧНЕНА: зелёный прогон убирает свой корень (мусор в temp не
      копится), **КРАСНЫЙ — оставляет и печатает путь** (улика ровно там, где нужна), `KAIF_TMP_KEEP=1`
      оставляет всегда, явный путь аргументом (`node <свод> <путь>`) принадлежит вызывающему.
      Наблюдено живьём: красный прогон `counters-guard --selftest` напечатал
      `ℹ️ временный корень оставлен для разбора: …\kaif-sbx-counters-guard-selftest-sY164m`.
- [x] 3. Отказ при занятом каталоге обязан называть верный ход, а не падать стектрейсом
      (`EXP-0008`: «ошибка инструмента несёт готовое решение, никогда — обход»).
      → для явного пути `rmSync` обёрнут: печатается имя каталога, код ошибки и три верных хода,
      выход — код 2 (отличим от обычного провала проверок). Для дефолтного пути класс снят по
      построению, поэтому отказу там взяться неоткуда.
- [x] 4. Красный доказать: до фикса проба из «Fix accepted when» даёт `A=1`; после — `A=0` и `B=0`.
      → замерено оба раза, см. блок критерия выше.
- [x] 5. Убедиться, что уборка каталога одним сводом не сносит чужой: проверить `rmSync` на старте
      каждого свода.
      → проверено грепом: все прочие `rmSync` в сводах бьют по путям, производным от `ROOT`
      (`join(ROOT,…)`, `S5`, `T2`, `D0`, `FX2`, `marker`), ни один не поднимается выше своего корня.

**Страж класса** (фикс без стража — фикс в кредит): `auditFixedTempNames()` в том же модуле обходит
`tools/` и `framework/` и требует, чтобы ни одна строка с `tmpdir()` не несла фиксированного имени
(легальны `mkdtempSync`, интерполяция уникализирующего ключа, вызов `tempRoot`). Он стоит
ПРЕПОЛЁТОМ в `tools/sandbox-suite.mjs`, то есть в обязательном гейте `npm run test:core`, и доказан
красным: `selfProof()` кормит его синтетической мутацией (ровно та форма, что породила этот баг) и
тремя легальными образцами. На живом дереве до правки он напечатал все 20 вхождений и вышел с
кодом 1.

проверял бы не то. Поэтому корень передан параметром: `makeFixtureRoot(root = tempRoot(...))`,
а QA7 зовёт `makeFixtureRoot(fixtureRoot)`.

## Decisions made without the owner

1. **Красный не замолчан.** Соблазн был прямой: перепрогон зелёный, дерево чистое, коммит готов.
   Но «прошло само» — это не диагноз, а `TESTING_FRAMEWORK` прямо запрещает считать неотработавшую
   проверку пройденной. Потратил один прогон на воспроизведение — и класс оказался настоящим.
2. **Заведён отдельным багом, а не строкой в отчёте аудита.** Найден не аудитом, а верификацией
   T3; смешивать его с находками пробного прогона значило бы приписать аудиту чужую заслугу.
3. **Скоуп расширен с 13 вхождений до 20.** Документ называл своды; инвентарь класса нашёл ещё
   семь мест с ТЕМ ЖЕ механизмом. Канон требует закрывать класс, а не экземпляр, а чинить формой
   двадцать мест не дороже, чем тринадцать: правка одна и та же. Выбор проверяем — каждое
   вхождение названо в таблице выше вместе с тем, что бы сломалось.
4. **Уборка перевешена с «оставляем всегда» на «оставляем на красном».** Прежняя форма оставляла
   каталог после КАЖДОГО прогона; с уникальными именами это копило бы мусор без предела. Выбрал
   правило, которое сохраняет привычку и снимает накопление: зелёный чист, красный оставлен и
   назван вслух. Альтернатива «удалять всегда» отвергнута — она уносит улику ровно тогда, когда
   улика нужна.
5. **Отказ на явном пути даёт код 2, а не 1.** Единица уже занята «проверки не прошли»; занятый
   каталог — не провал проверок, и смешивать их значило бы вернуть тот самый класс «красный без
   содержания», ради которого баг и заведён.
6. **`counters-guard --selftest` НЕ чинился здесь.** Он красный на чистом HEAD по своей причине
   (согласование «161 блок» против зашитого «блоков») — доказано отдельным worktree на `01317a9`.
   Заведён `bugs/60`; чинить чужой дефект внутри этого фикса значило бы смешать два диффа.
7. **Внешняя карта не правилась.** `PROJECT_STRUCTURE_EXTERNAL_MAP.md` перечисляет `tools/`
   выборочно и уже не знает про `review.mjs`, `counters-guard.mjs`, `tools/lib/` — дописать туда
   один новый модуль значило бы залатать симптом чужого дрейфа. Инвариант зафиксирован там, где
   его прочтут: `PROJECT_ARCHITECTURE_INTERNAL_MAP.md` → «Инварианты модели» + строка в таблице
   инструментов `AGENT_GUIDE.md`.
