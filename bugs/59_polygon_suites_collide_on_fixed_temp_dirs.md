# Bug 59 — своды полигона делят каталоги с ФИКСИРОВАННЫМИ именами: параллельный прогон даёт ложный красный сырым стектрейсом

> **Создан:** 2026-08-08 16:45 +03:00 (пойман при верификации задачи T3: `npm run test:core` дал
> `1 of 14 suites FAILED`, чистый перепрогон — зелёный). **Родитель:** `plans/33` шаг 5.
> **Статус:** 🔴 OPEN — механизм доказан прямым наблюдением, фикс не начат. **Вовне:** —.

**Status:** 🔴 OPEN · **Version/build:** 2.1 (build 190) · **When/context:** найден 2026-08-08 при
верификации T3, когда полигон покраснел один раз и позеленел на перепрогоне.

## Вектор цели (Avoid)

Не допустить ЛОЖНОГО КРАСНОГО в главном гейте проекта. Ложная тревога опаснее пропуска: она учит
оператора перезапускать и не смотреть — а `npm run test:core` обязателен после любой правки
машинерии и перед релизом. Красный, который «проходит сам собой», обесценивает красный, который
означает поломку.

**Fix accepted when (observable):** два одновременных прогона одного и того же свода завершаются
кодом 0 каждый:
`(node tools/sandbox/s13-requirements-lint.mjs > /tmp/a.log 2>&1; echo A=$? ) & (node tools/sandbox/s13-requirements-lint.mjs > /tmp/b.log 2>&1; echo B=$?) & wait`
→ `A=0` и `B=0`. **Сегодняшнее измеренное состояние:** `A_EXIT=1`, `B_EXIT=0` — критерий различает
починку от текущего поведения и не требует дополнительных замеров.

## Symptom

Прогон `npm run test:core` при верификации T3 напечатал:

```
❌ sandbox suite: 1 of 14 suites FAILED
```

Чистый перепрогон через несколько минут: `✅ sandbox suite: all 14 suites green`, EXIT=0. Ничего в
дереве между прогонами не менялось.

⚠️ **Криминалистика первого падения УТЕРЯНА:** прогон был запущен через `| tail -4`, и имя упавшего
свода вместе с его выводом не сохранилось. Это отдельный оплаченный урок (см. `EXPERIENCE.md`
EXP-0052): верификационный прогон, пропущенный через `tail`, теряет ровно ту улику, ради которой
его гоняли.

## Repro (deterministic)

Механизм найден ЧТЕНИЕМ и подтверждён наблюдением. Каждый свод берёт каталог с фиксированным
именем:

```
grep -o "join(tmpdir(), *'[^']*'" tools/sandbox/*.mjs
→ 13 каталогов вида kaif-sbx-<имя>, ни одного уникализированного (pid, случайный суффикс, mkdtemp)
```

Прямая проба — два одновременных прогона ОДНОГО свода:

```
(node tools/sandbox/s13-requirements-lint.mjs …) & (node tools/sandbox/s13-requirements-lint.mjs …) & wait
→ A_EXIT=1, B_EXIT=0
```

Вывод упавшего — сырой стектрейс Node без единого слова диагноза:

```
Error: EPIPE, The process cannot access the file because it is being used by another process.
  '\\?\C:\Users\krinik\AppData\Local\Temp\kaif-sbx-reqlint\.kaif\tools\kaif-requirements-lint.mjs'
  at cpSync (node:fs:3147:3)
  at file:///D:/work/ai_sandbox/KAIF/tools/sandbox/s13-requirements-lint.mjs:31:1
  { errno: 32, code: 'EPIPE', syscall: 'unlink' }
```

Второй прогон сносит и пересоздаёт каталог, пока первый по нему ходит.

## Root cause

Каталог песочницы — фиксированное имя в общем OS-temp, то есть **разделяемый ресурс без владельца**.
Достаточно двух прогонов в одно время: две сессии агента, прогон полигона рядом с прогоном
отдельного свода (ровно это и случилось при T3 — пробный аудит гонял `s07` и `s10` своими
агентами), CI рядом с локальным прогоном, `--selftest` рядом с обычным прогоном.

Два семейства сразу: **12 — отказ, не называющий верного хода** (наружу летит стектрейс `cpSync`
вместо «каталог занят другим прогоном; запусти повторно или дай уникальный корень») и **10 —
зелёное/красное без содержания** (красный не означает поломку кода).

## Fix plan

- [ ] 1. Уникализировать корень песочницы: `mkdtemp(join(tmpdir(), 'kaif-sbx-<имя>-'))` вместо
      фиксированного имени — по своду; либо один общий корень прогона, передаваемый сводам.
      Уникальный корень по построению снимает весь класс, а не текущий симптом.
- [ ] 2. Сохранить возможность стабильного пути для отладки (переменная окружения или флаг), чтобы
      не потерять сегодняшнюю привычку «зайти и посмотреть, что свод оставил».
- [ ] 3. Отказ при занятом каталоге обязан называть верный ход, а не падать стектрейсом
      (`EXP-0008`: «ошибка инструмента несёт готовое решение, никогда — обход»).
- [ ] 4. Красный доказать: до фикса проба из «Fix accepted when» даёт `A=1`; после — `A=0` и `B=0`.
- [ ] 5. Убедиться, что уборка каталога одним сводом не сносит чужой: проверить `rmSync` на старте
      каждого свода.

## Decisions made without the owner

1. **Красный не замолчан.** Соблазн был прямой: перепрогон зелёный, дерево чистое, коммит готов.
   Но «прошло само» — это не диагноз, а `TESTING_FRAMEWORK` прямо запрещает считать неотработавшую
   проверку пройденной. Потратил один прогон на воспроизведение — и класс оказался настоящим.
2. **Заведён отдельным багом, а не строкой в отчёте аудита.** Найден не аудитом, а верификацией
   T3; смешивать его с находками пробного прогона значило бы приписать аудиту чужую заслугу.
