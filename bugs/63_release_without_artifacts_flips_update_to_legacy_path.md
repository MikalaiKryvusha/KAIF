# Bug 63 — релиз без артефактов переключает обновление в legacy-путь, а главный гейт зависит от сети

**Status:** 🔬 research-only (класс назван и воспроизведён ЧАСТИЧНО; красный не воспроизводится)
**Version/build:** 2.2 / build 220 · **When/context:** 2026-08-08 23:37 +03:00, сразу после бампа
version.json 2.1 → 2.2 и публикации страницы релиза v2.2 БЕЗ артефактов (задача T11, черновая
витрина к дате 08.08.2026)

## Symptom

Два независимых симптома одного механизма.

**S1 — красный главного гейта, не воспроизводимый.** Первый прогон `npm run test:core` после бампа
дал `❌ sandbox suite: 1 of 14 suites FAILED`: свод `s03-receipts-tools.mjs`, ассерт
`S10 update после adopt-current exit 0`. Вывод упавшей команды обрывался ровно на строке
`update: 2.2 → 9.9` — то есть процесс умер сразу после объявления перехода версий, ничего не сказав.
Следом свод рухнул с `ENOENT` на `KAIF_UPDATE_TASK.md` (файла нет, потому что update не дошёл до его
записи). **Повтор той же команды в том же каталоге — exit 0.** Полный повторный прогон полигона —
`478 ✅ / 14 сводов / exit 0`.

**S2 — смена пути обновления, воспроизводимая на 100 %.** Тот же update, отработавший успешно,
печатает:

```
⟳ no baseline artifact reachable for v2.2 (https://github.com/MikalaiKryvusha/KAIF/releases/download/v2.2)
  — classic adopt-everything legacy path
```

До бампа текущей версией была 2.1, у которой в релизе ЕСТЬ артефакты, и baseline находился —
обновление шло **модульным** путём. Теперь baseline для текущей версии недостижим, и машинерия
честно уходит в legacy-путь «усынови всё».

## Repro (deterministic — для S2; для S1 не найдено)

S2 воспроизводится всегда, пока у релиза текущей версии нет ассетов:

```bash
node tools/build-framework.mjs            # dist/ помечен текущей версией из version.json
node tools/sandbox/s03-receipts-tools.mjs # смотреть строку «no baseline artifact reachable for v<текущая>»
```

S1 не воспроизведён: одно падение, затем зелёный повтор той же команды и зелёный полный прогон.
Изолят на 100+ итераций НЕ гонялся — решение осознанное (см. «Что дальше»).

## Forensics

- Оборванный вывод упавшего update: последние 350 символов — `update: checking <src-9.9>` +
  `update: 2.2 → 9.9`, и всё. Ни кода ошибки, ни трейса: значит процесс умер ВНУТРИ шага, идущего
  сразу за объявлением версий, — а это ровно шаг поиска baseline-артефакта в сети.
- Успешный повтор того же шага печатает `⟳ no baseline artifact reachable for v2.2 … legacy path` —
  то есть у шага ЕСТЬ штатная деградация. Значит первый раз он не деградировал, а упал.
- Временный корень свода оставлен стражем bugs/59 для разбора и осмотрен:
  `C:\Users\krinik\AppData\Local\Temp\kaif-sbx-receipts-IIeB7G`.

## Root cause / Hypotheses

**Механизм S2 установлен:** право модульного обновления опирается на baseline-артефакт релиза
ТЕКУЩЕЙ версии. Публикация страницы релиза **без ассетов** делает такой baseline недостижимым для
всех, кто на этой версии, — и путь обновления меняется у всего парка, а не только в песочнице. Это
прямое следствие решения владельца выпустить страницу 2.2 к дате 08.08.2026 без артефактов, и оно
снимается доездом артефактов ночью.

**Гипотезы по S1, по убыванию правдоподобия:**

1. **Сетевой транзиент на шаге поиска baseline.** GitHub вернул не-404 (таймаут, 5xx, обрыв
   соединения), а деградация написана на «нет артефакта», а не на «сеть повела себя странно» —
   и необработанное исключение убило процесс. Примета при рецидиве: падение снова строго после
   строки `update: <from> → <to>` и снова без трейса.
2. **Гонка с только что созданным релизом.** Страница v2.2 создана в 23:28, прогон стартовал в
   23:31: API/CDN мог отдавать полусогласованное состояние (тег есть, ассетов нет, кэш прогрет
   частично) — тот же класс, что задокументированный skew `--channel main`. Примета: рецидивы
   ЛИПНУТ к первым минутам после публикации релиза и исчезают позже.
3. **Гейт полигона молча зависит от СЕТИ.** Это не гипотеза, а факт, вскрытый первыми двумя:
   главный гейт проекта ходит в интернет и потому не детерминирован по построению. Даже если S1
   больше не повторится, свойство остаётся.

## Fix plan

Ничего не чинится вслепую (правило трёх попыток даже не начато — попытка была одна, и она
зелёная). Порядок, по возрастанию цены:

- [ ] **Артефакты к релизу v2.2** — снимает S2 целиком и, если верна гипотеза 1/2, снимает и S1.
      Идёт штатно ночью, после R2 (слово владельца 2026-08-08 ≈23:45 +03:00).
- [ ] **Деградация шага baseline обязана быть полной**: любой сбой сети (таймаут, 5xx, обрыв) —
      это «baseline недостижим», а не исключение. Сейчас словом «недостижим» покрыт, судя по
      симптому, только чистый 404. Страж — свод, подсовывающий недостижимый origin.
- [ ] **Гейт не должен зависеть от сети молча**: либо офлайн-режим полигона по умолчанию (baseline
      подсовывается фикстурой), либо явная строка в выводе «этот свод ходил в сеть». Второе дешевле
      и уже честно.

## Что дальше — и почему НЕ изолят на 100 прогонов

`bugs/61` оплатил этот урок деньгами: транзиент S9 не воспроизвёлся за **120 прогонов**, и ценность
принёс не поиск призрака, а ФОРМА — помощник `must(run, …)`, из-за которого немая команда больше не
может выбросить свою причину. Здесь причина уже названа (шаг baseline, сеть), поэтому охота за
призраком отложена, а работа идёт в форму: полная деградация + видимость сетевой зависимости.

## Decisions made without the owner

1. **Заведено research-only, а не OPEN.** Красный не воспроизводится, а S2 — не дефект кода, а
   следствие решения владельца выпустить страницу без артефактов; называть это «баг машинерии»
   было бы неправдой.
2. **Изолят не гонялся** — по уроку `bugs/61`/EXP-0060: у призрака уже есть названный механизм,
   и форма дороже поимки.
3. **Прогон не остановлен.** Полный повтор полигона зелёный (478 ✅), поэтому дерево считается
   зелёным с явной оговоркой в этом документе, а не «зелёным вообще».
