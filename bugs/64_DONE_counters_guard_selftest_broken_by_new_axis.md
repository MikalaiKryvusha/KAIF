# Bug 64 — селфтест counters-guard молча сломался, когда у стража появилась новая ось

**Status:** ✅ DONE (2026-08-09 02:10 +03:00)
**Version/build:** build 233 · **When/context:** фаза Q (`plans/67`), прогон селфтестов всех стражей
**Fix accepted when (observable):** `node tools/counters-guard.mjs --selftest` печатает
«чистая копия — зелёный» и завершается кодом 0; список корневых файлов песочницы назван одной
константой рядом с причиной.

## Symptom

`node tools/counters-guard.mjs --selftest` завершался кодом 1 со строкой
«❌ selftest: чистая копия — зелёный» при девяти зелёных мутациях. То есть страж доказывал, что
умеет КРАСНЕТЬ, и не мог доказать, что умеет МОЛЧАТЬ, — а именно молчание на чистой копии отделяет
стража от инструмента, который красит всё подряд.

Обычный прогон `node tools/counters-guard.mjs` при этом был зелёным, поэтому в ритуалах дефект не
проявлялся: селфтест гоняют отдельно и редко.

## Repro (deterministic)

```
node tools/counters-guard.mjs --selftest        # exit 1
node tools/counters-guard.mjs --root <корень песочницы, оставленный прогоном>
# → Error: ENOENT … PROJECT_ARCHITECTURE_INTERNAL_MAP.md
```

## Forensics

- Песочница селфтеста копировала `framework/`, `dist/`, `assets/`, `tools/sandbox-suite.mjs` и
  ровно ОДИН корневой файл — `AGENT_GUIDE.md`.
- Оси бейджей витрины (контуры, принципы) добавили стражу два ЖИВЫХ источника в корне:
  `PROJECT_ARCHITECTURE_INTERNAL_MAP.md` (инвентарь контуров) и `PHILOSOPHY.md` (заголовки
  принципов). Коммит `e6d9573` «бейджи метрик вместо снятых».
- Список копирования при этом не тронули: `liveNumbers()` в песочнице падал на `readFileSync`, и
  первая же проверка селфтеста получала ненулевой код — который читался как «чистая копия
  покраснела».

## Root cause

**Две стороны одного факта, и обновили только видимую** — тот же класс, ради которого этот страж и
существует. У стража ДВА списка того, что он читает: список живых источников (в коде проверки) и
список файлов песочницы (в коде селфтеста). Первый вырос, второй нет. Ошибка не могла проявиться
в обычном прогоне, потому что там корень настоящий и файлы на месте.

Отдельная примета, которая скрыла причину: селфтест интерпретировал ЛЮБОЙ ненулевой код
подпроцесса как «страж покраснел», не различая «нашёл расхождение» и «упал с исключением».
Пункт 3 канона находок (`BUG_FIXING_FRAMEWORK.md`) говорит ровно об этом: «Различай „опровергнуто“
и „верификатор не отработал“».

## Fix

Список корневых файлов песочницы вынесен одной константой `ROOT_FILES` рядом с причиной, по которой
он существует, и с правилом на будущее: завёл живой источник — впиши файл сюда тем же движением.

## Twin check

`TWINS: искал по `tools/*.mjs` селфтесты, копирующие корневые файлы поимённо — найден один
(`counters-guard`). Прогнаны селфтесты ВСЕХ тринадцати стражей репозитория плюс `lib/temp-root`:
двенадцать были зелёными, сломан был только этот. Список прогона —
`counters-guard · doc-header-lint · voice-lint · sandbox-mute-guard · guarded-watchdog ·
owner-quotes-harvest · questions-guard · neutrality-guard · revert-guard · showcase-lint ·
estimates-guard · private-names-guard · lib/temp-root`.

## Decisions made without the owner

1. **Селфтест починен, а не ослаблен.** Соблазн «проверять только мутации» здесь силён и ошибочен:
   молчание на чистой копии — половина доказательства, и без неё страж не доказан.
2. **Разделение «упал» и «покраснел» НЕ введено** в этот селфтест: оно потребовало бы разбора
   stderr подпроцесса, а причина уже названа в комментарии и в этом документе. Пункт остаётся
   кандидатом на следующий прогон `/code-revision` — там он относится ко всем стражам сразу, а не
   к одному.
