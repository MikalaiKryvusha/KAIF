# Bug 68 — рукописные счётчики и инвентари поставки живут вне охвата `counters-guard`: девять протухших зеркал

**Status:** 🔴 OPEN
**Version/build:** build 237 · **When/context:** круг R1 фазы R (`plans/59` шаг 7), 2026-08-09
**Fix accepted when (observable):** мутация КАЖДОГО из девяти зеркал ниже валит
`node tools/counters-guard.mjs` ненулевым кодом; инвентарь зеркал собран грепом по ПОНЯТИЮ и
записан в реестр пар; `--selftest` несёт мутацию каждой новой оси.

## Symptom

`node tools/counters-guard.mjs` печатает «✅ counters OK — 38 зеркал сверены с живыми числами» и
выходит нулём — при девяти рукописных счётчиках поставки, которые сегодня врут. Проверено
адресно: мутация четырёх зеркал до абсурда («14 сводов» → «13», «семь README» → «шесть»,
«четырнадцать ключевых документов» → «тринадцать») оставляет прогон **зелёным**.

Класс объявлен «убитым формой» в `bugs/09_DONE` («Found: 0 других вхождений класса на момент
закрытия») и вернулся на том же самом адресе — `AGENT_GUIDE.md`, дерево репозитория.

## Repro (deterministic)

```
node tools/counters-guard.mjs            # ✅ 38 зеркал сверены, exit 0
```

**тремя разными значениями** (8/9/10): `AGENT_GUIDE.md:482`, `AGENT_GUIDE.md:633`,
`EXPERIENCE.md:57`, `EXPERIENCE.md:68`, `PROJECT_HISTORY.md:44`, `.claude/skills/release/SKILL.md:78`.

Отдельно: две из четырёх живых осей самого `counters-guard` (инвентарь §8.2 витрины и витринные
бейджи, 10 зеркал из 38, рождены 2026-08-09) не названы ни строкой реестра пар, ни описанием
инструмента в `AGENT_GUIDE.md:625` — читатель канона видит перечень «две оси» при четырёх живых.

## Root cause

`counters-guard` стережёт **числа, которые он знает**, — а знает он те зеркала, что ему назвали
руками. Всё, что записано прозой в другой формулировке («the 28 skill templates» в дереве,
«s01–s07» в подписи, «двенадцатый ключевой документ» в записке), в список не попало, потому что
инвентарь зеркал собирался грепом по ЦИФРЕ (EXP-0070 говорит ровно про этот промах: грепи по
ПОНЯТИЮ, а найденное числом считай нижней границей).

Второй слой — рецидив после объявления класса закрытым: `bugs/09_DONE` записал «Found: 0» на том же
файле, где сегодня живут два вхождения. Заявление о полноте было сделано без развёртки класса.

## Fix plan

- [ ] Собрать инвентарь зеркал грепом по ПОНЯТИЮ («навык/skill», «README», «модуль», «свод/suite»,
      «ключевой документ/key doc», «класс») по всем `*.md` вне `dist/` и артефактов знаний;
      результат — в документ бага таблицей, и только потом код.
- [ ] Добавить в `MIRRORS` каждое найденное зеркало; там, где число живёт в прозе-словом
      («семь», «четырнадцать»), стеречь И цифру, И пропись.
- [ ] Завести зеркало для шапок инструментов (`s12` и родня): шапка, называющая состав, обязана
      сверяться с массивом того же файла.
- [ ] Точку входа (`_thin-intro.md`) привести к полному списку 14 либо явно пометить список
      сокращённым — сегодня он молча теряет четыре документа, два из которых входят в ядро
      перечитывания.
- [ ] `plans/68` привести в соответствие с собственным артефактом (38 записей, АП37 дописать или
      снять из шапки).
- [ ] Внести в реестр пар `AGENT_GUIDE.md` строку «содержимое `framework/tools/` + `framework/hooks/`
      ↔ их перечисления в картах» и две недостающие оси `counters-guard`.
- [ ] `--selftest` дополнить мутацией каждой новой оси (EXP-0075: страж, который не проверяют
      селфтестом, ломается тем же дрейфом, который сам стережёт).
