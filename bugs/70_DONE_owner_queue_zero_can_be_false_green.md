# Bug 70 — «Ждут ответа: 0» может быть ложным зелёным: закрытость документа определяется голым словом, а живость вопроса — чужим предикатом

**Status:** ✅ DONE (2026-08-09 10:33 +03:00)
**Version/build:** build 242 · **When/context:** круг R1 фазы R (`plans/59` шаг 7), 2026-08-09

## ✅ STATUS: DONE (2026-08-09 10:33 +03:00)

**Обе половины дефекта закрыты формой, плюс третья, найденная по дороге.**

**(а) Закрытость — РАЗМЕТКА, а не голое слово.** `docStatus` читает теперь только СТРОКУ СТАТУСА
(`> Status:` / `> **Статус:**`), а не первые тридцать строк; распознавание построено
ОТРИЦАТЕЛЬНО (норма G6): документ по умолчанию ЖИВОЙ, закрывает его только явная разметка, и
отрицание внутри строки сильнее галочки. Перед правкой снята разведка по корпусу: **все 17 живых
интервью несут строку статуса** — то есть фикс не порождает ложных красных.

**(б) Ось bugs/62 скоупится СОБСТВЕННЫМ свойством вопроса** (пустое поле `**Answer:**`), а не
чужим предикатом `iv.waiting`. Один прогон больше не может назвать вопрос ждущим и тут же его не
проверить.

**(в) Найдено при починке: селфтест ядра ПЕЧАТАЛ красный и выходил кодом 0.** Свод `s12` судит
его именно по коду возврата — значит красный селфтест ядра контура прошёл бы гейт зелёным. Это
класс `bugs/64`, вернувшийся на соседнем инструменте. Исправлено: `process.exit(1)` на красном.

**Доказательства (фикстуры лежат в селфтесте, а не в сессии — EXP-0016):** семь новых проверок,
каждая формой из карточки бага — «пока НЕ ОТВЕЧЕНО», слитное «неотвечено», «no … yet»,
посторонняя ✅ против явного 🟡, законное закрытие (молчание), документ без строки статуса,
и итоговая — при отрицании пустой `Answer` остаётся неотвеченным. Селфтест ядра: **23 проверки,
зелёный**; мутация «убрать проверку отрицания» **на копии** → `exit=1`.

Гейты: `questions-guard --selftest` зелёный · живой `questions-guard` — «Ждут ответа: 0,
Новых нарушений: 0» · `verify-contour --etalon-only` exit 0 · `npm run test:core` — all 14 suites
green.

## Решения, принятые агентом без владельца

1. **Строка статуса выбрана носителем истины** вместо нового поля схемы: диалект `Status:` уже
   канонизирован в `interviews/`, и заводить второе понятие ради той же задачи — лишняя сущность
   (Оккам). Разведка подтвердила, что носитель есть у всех живых документов.
2. **Отрицание перебивает закрытие, а не наоборот.** При конфликте примет выбрано безопасное для
   владельца направление: лучше лишний раз показать живой вопрос, чем потерять его.
3. **Ось bugs/62 расширена на документы БЕЗ строки статуса** (раньше их не проверял никто).
   Побочный эффект — потенциально больше находок; на живом корпусе их ноль.
**Fix accepted when (observable):** на пяти фикстурах ниже `docStatus` даёт правильный статус;
`node tools/questions-guard.mjs` не может одновременно назвать вопрос ждущим и не проверить его;
обе половины доказаны фикстурами (краснеет / молчит).

## Symptom

Строка `STATUS.md:121` — «✅ ОЧЕРЕДЬ ВЛАДЕЛЬЦА ПУСТА — `node tools/questions-guard.mjs` печатает
„Ждут ответа: 0“» — подаётся как наблюдение о состоянии очереди. Наблюдение опровергается: очередь
может быть непустой при том же зелёном выводе, и оба механизма, приводящих к этому, воспроизведены
фикстурами.

Это дефект контура, ради которого контур существует: вопрос владельцу может потеряться, а страж
скажет, что потерянного нет.

## Repro (deterministic)

**(а) Закрытость по голому слову.** `tools/lib/review-core.mjs:88`:

```
const STATUS_CLOSED_RE = /✅|🟢|STATUS:\s*DONE|ANSWERS\s+RECEIVED|ОТВЕЧЕНО/iu;
```

Проверка идёт ПЕРВОЙ и смотрит первые 30 строк. Пять фикстур:

| Голова документа | `docStatus` | `answered` |
|---|---|---|
| «Status: пока **НЕ ОТВЕЧЕНО**, ждём владельца» | `closed` ❌ | `true` ❌ |
| «неотвечено» | `closed` ❌ | `true` ❌ |
| «no **ANSWERS RECEIVED** yet» | `closed` ❌ | `true` ❌ |
| «🟡 awaiting the owner's answers» + посторонняя строка «задача T12 ✅ закрыта вчера» | `closed` ❌ | `true` ❌ |

Живой прогон на последней фикстуре (два вопроса с пустым `**Answer:**`):
`node tools/questions-guard.mjs` → «— Ждут ответа: 0 вопрос(ов) / — Новых нарушений: 0», EXIT=0.

**(б) Две правды о живости в одном прогоне.** `tools/questions-guard.mjs:199`:

```
if (iv.waiting) for (const q of empty) {
```

Фикстура: интервью с двумя вопросами, варианты записаны прозой (`**A. Первый путь** — …`), строки
статуса нет. Прогон печатает «Ждут ответа: 2 вопрос(ов) — …Q1, …Q2» (строки 191-192 назвали их
ждущими) и **не проверяет** их ось «вопрос ОТВЕЧАЕМ» (строка 199 сочла интервью не ждущим),
EXIT=0. Контроль: тот же текст + строка `🟡 awaiting` → EXIT=1, «✗ [вопрос НЕОТВЕЧАЕМ (bugs/62)]».

## Forensics

- `review-core.mjs:88` (закрытость) и `:89` (`STATUS_WAITING_RE = /🟡|awaiting|ждёт\s+ответ|…/iu`) —
  обе приметы суть голые слова; окно `:91` — `slice(0, 30)`.
- Нарушены две собственные нормы навыка дословно:
  - G10 (`owner-reviews/SKILL.md:475-476`): «Ищи синтаксис `owner-review:` с двоеточием, НИКОГДА
    не голое слово»;
  - G6 (`:459-461`): «Распознавание строится ОТРИЦАТЕЛЬНО … перечислить разрешённое — значит
    однажды не перечислить».
- `questions-guard.mjs`: пять решающих точек на ТРЁХ разных предикатах живости
  (`:192` отчёт «Ждут ответа», `:199` ось bugs/62, `docStatus`/`.closed`/`.waiting` в ядре) —
  разъезд предикатов и есть механизм.
- Отдельно опасное следствие фикстуры (а): без постороннего файла-цитаты тот же документ краснеет
  по ЧУЖОЙ оси (эвристика I21) — то есть настоящий дефект маскируется случайным красным соседа, и
  сессия чинит не то.

## Root cause

Статус документа распознаётся **положительным перечнем голых слов**, а не разметкой. Любое
отрицание («НЕ ОТВЕЧЕНО») и любая посторонняя ✅ в первых тридцати строках переворачивают вердикт;
`closed` принудительно ставит `answered = true` всем вопросам с пустым `**Answer:**`, и «Ждут
ответа: 0» становится ложным зелёным сразу у обоих потребителей.

Вторая половина — скоуп оси привязан к ЧУЖОМУ предикату (`iv.waiting`) вместо собственного
свойства вопроса. Это ровно тот класс, который `bugs/62` уже разбирал («страж мерил ПРОКСИ, а не
свойство»), вернувшийся внутри самого фикса.

## Fix plan

- [x] Статус читать **разметкой**, а не словом: явный ключ в шапке интервью (`Status:` из
      канонизированного диалекта bugs/interviews) с закрытым словарём значений; голое слово в теле
      документа на статус не влияет.
- [x] Распознавание строить ОТРИЦАТЕЛЬНО (норма G6): по умолчанию документ ЖИВОЙ, закрытым его
      делает только явная разметка.
- [x] Ось bugs/62 скоупить СОБСТВЕННЫМ свойством вопроса (есть ли у вопроса неотвеченный
      `**Answer:**`), а не полем интервью; один прогон не вправе давать две правды об одном вопросе.
- [x] Фикстуры: все пять случаев таблицы + два случая (б) — в `--selftest`, обеими сторонами.
- [x] После фикса перепроверить строку `STATUS.md:121`: «Ждут ответа: 0» цитируется только из
      прогона, сделанного ПОСЛЕ фикса.
