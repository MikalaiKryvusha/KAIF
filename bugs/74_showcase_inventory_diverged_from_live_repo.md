# Bug 74 — витринный инвентарь разошёлся с живым репозиторием: десять строк из двенадцати

**Status:** 🟡 PARTIAL — гейт публикации ПОСТРОЕН 2026-08-09 11:10 +03:00 и держит; сами числа
переснимаются перед релизом (окончательный замер владелец назначил ПОСЛЕ R2)
**Version/build:** build 241 · **When/context:** круг R1 фазы R (`plans/59` шаг 7), 2026-08-09

## ✅ Механическая половина закрыта — гейт построен и краснеет

Числа НЕ переписаны намеренно: их окончательный замер владелец назначил на момент после R2, а
дефект был не в самом устаревании, а в том, что **ничто не мешало опубликовать витрину как есть**.

Построен `tools/showcase-stats-guard.mjs`:

- живые значения берёт из `kaif-stats --json` — из ТОГО ЖЕ инструмента, чьи числа печатает витрина
  (не из собственной арифметики, EXP-0025);
- сверяет **каждую половину README отдельно** — счёт «нашлось где-то в файле» узаконил бы пропажу
  строки из одной половины (класс `bugs/55` F1, он же `t4-readme-half-blind` в `bugs/65`);
- **честная граница печатается вслух:** судятся только величины, выводимые из репозитория;
  коммиты, строки, токены, запросы, деньги и время не судятся, потому что живут в git-истории и
  транскриптах сессий, — «не проверено» не должно читаться как «сошлось» (EXP-0037);
- стоит в `/release` преполётом публикации и намеренно НЕ в `/end-chat`: числа версии законно
  отстают, пока версия делается, и красный на каждом закрытии чата обесценил бы сигнал.

**Доказательства обеими сторонами:** `--selftest` — чистая копия молчит, порча EN-половины
поймана, порча RU-половины поймана (по отдельности). **Живой прогон: `exit=1`, 12 расхождений** —
ровно тот класс, что назвал круг R1:

```
Plans written / Планов написано                     — витрина 62, живое 64
Bugs filed / Багов заведено                          — витрина 63, живое 77
Ideas proposed / Идей предложено                     — витрина 24, живое 25
Files in the knowledge directories / Файлов знания   — витрина 228, живое 220
Owner decisions recorded / Решений владельца         — витрина 65, живое 66
Experience lessons written / Уроков опыта записано   — витрина 71, живое 76
```

Пара внесена в реестр `AGENT_GUIDE.md`: «инвентарь репозитория ↔ строки Таблицы обеих половин».

## ⏳ Что осталось

Пересъём самих чисел — перед релизом, по слову владельца (после R2). До тех пор гейт держит
публикацию красным, и это ровно то поведение, которого не было.
**Fix accepted when (observable):** каждое число Таблицы 6 обеих половин README и опубликованной
страницы релиза — цитата вывода `node tools/kaif-stats.mjs`, снятого в момент публикации;
расхождение любой строки валит гейт публикации в `/release`.

## Symptom

Инвентарные строки Таблицы 6 витрины (обе половины README) и опубликованной страницы релиза не
совпадают с живым репозиторием: расходятся **десять строк из двенадцати**.

Числа на витрине читает посторонний человек, и проверить их он не может — а проверить их можно
одной командой, которая в проекте уже есть.

## Repro (deterministic)

```
node tools/kaif-stats.mjs --since 2026-08-07T00:00:00+03:00
# — ИЗМЕРЕНО: документы (текущее состояние репозитория) —
# plans 64 · bugs 64 · ideas 25 · researches 19 · interviews 17 · homeworks 5 · reports 13
# багов закрыто (тег DONE): 60 · решений владельца: 66 · уроков опыта: 75 · навыков: 35

# контроль без инструмента
ls plans/*.md | grep -v README | wc -l     # 64   ← на витрине «Plans written | 62»
ls bugs/*_DONE_*.md | wc -l                # 60
grep -c '^### EXP-' EXPERIENCE.md          # 75

node tools/counters-guard.mjs              # ✅ 38 зеркал сверены, exit 0 — этих строк не видит
```

Расходятся также коммиты (141 против 153), созданные файлы (190 против 199) и файлы знания (228
против 225).

## Forensics

Объявленное окно замера — `README.md:492`: «The window is two days: from 2026-08-07 at 00:00 +03:00
to 2026-08-09 at 00:46 +03:00». Окно строки Таблицы 6 не защищает по трём причинам сразу:

1. тег `v2.2` стоит на **17 коммитов ПОЗАДИ** HEAD;
2. витрина написана уже ПОСЛЕ тега;
3. вся фаза Q принадлежит **невыпущенной** 2.2 — то есть таблица недосчитывает работу, которая в
   релиз входит.

`tools/kaif-stats.mjs:8-13` формулирует правило сам: «Класс „протухший счётчик прозы“ проект уже
оплатил дважды (`bugs/09`, `bugs/49`, урок EXP-0025): число, вписанное руками, врёт со следующего
коммита. Витринные числа тем более: их читает посторонний человек, и проверить их он не может».
Функция `docStats()` (`:180-194`) считает текущее состояние — то есть инструмент, дающий верные
числа, существует и не был прогнан перед публикацией.

## Root cause

Числа Таблицы 6 сняты один раз и вписаны руками, а витрина продолжала меняться: фаза Q добавила
коммиты, планы, баги и уроки уже после замера. Механизма, который валит публикацию при расхождении
витринного числа с выводом `kaif-stats`, нет — `counters-guard` стережёт счётчики ПОСТАВКИ
(документы/навыки/блоки/модули/своды) и об инвентаре версии ничего не знает.

Владелец уже назвал правильный порядок для этой таблицы (слово владельца, `STATUS.md`:
«окончательный замер „Интересных фактов“ **после R2**») — то есть дефект не в самом факте
устаревания, а в том, что **витрина не объявляет себя предварительной и ничто не мешает
опубликовать её как есть**.

## Fix plan

- [ ] Не переписывать числа сейчас: окончательный замер назначен владельцем на момент ПОСЛЕ R2.
      До него — не публиковать Таблицу 6 как измеренную.
- [ ] Завести гейт публикации: шаг `/release` прогоняет `node tools/kaif-stats.mjs` и сверяет
      каждое число Таблицы 6 обеих половин; расхождение — стоп до пересъёма. Это ровно та пара
      «истина ↔ зеркало», которой сегодня нет в реестре.
- [ ] Внести пару в реестр `AGENT_GUIDE.md` («вывод `kaif-stats` ↔ Таблица 6 обеих половин + тело
      страницы релиза»).
- [ ] Проверить, что окно замера объявляется по ФАКТУ публикации (до момента релиза), а не по
      дате написания абзаца.
- [ ] Красная мутация: испортить одну строку Таблицы 6 в копии — гейт обязан краснеть; вернуть —
      молчать.
