# Bug 79 — `commit.mjs` расширяет набор файлов ПОСЛЕ предкоммитной проверки, и правило канона становится неисполнимым

**Status:** ✅ DONE (2026-08-09 13:13 +03:00)
**Version/build:** build 247 · **When/context:** починки R1, `bugs/66` №2, 2026-08-09 11:14 +03:00

## ✅ STATUS: DONE (2026-08-09 13:13 +03:00)

Класс закрыт формой: **проверка и действие смотрят на ОДНО множество, а необъявленный файл в это
множество не попадает.**

- **Набор печатается вслух всегда** (отгружено раньше, 2026-08-09 ≈11:30) — и это уже окупилось
  дважды за один час, см. второе наблюдение ниже.
- **Гейт неожиданного файла:** НОВЫЙ (untracked) файл останавливает **подметающий** коммит и
  называет себя поимённо. Три законных хода печатаются вместе с отказом: назвать набор
  (`--only <путь>`, по флагу на путь — тогда оси нет вовсе, потому что подметания нет), взять
  новые разом (`--with-new`) или оставить файл в дереве. Отслеживаемые правки гейт не трогает: это
  работа самой сессии, и её стережёт `revert-guard`.
  ⚠️ **Ось СУЖЕНА по первой же живой пробе:** первая редакция краснела и при `--only`, если новый
  файл в него не входил. Это шум по построению — `git add -- <пути>` не может увести неназванное,
  — а шумный гейт первым идёт под нож. Правило вывелось само: гейт живёт ровно там, где живёт
  риск, то есть в режиме `git add -A`.
- **Гейт стоит ДО первого побочного эффекта** — до бампа `version.json`. Отказ после бампа оставил
  бы в дереве поднятый номер сборки без коммита, то есть воспроизвёл бы ровно тот класс
  («проверка и действие разошлись»), ради которого гейт и написан. Проба это подтвердила:
  `git diff --stat -- version.json` после отказа пуст.
- **Посторонний аргумент ОТКАЗЫВАЕТ** вместо молчаливого проглатывания — канон установщика
  (`bugs/33`: «stray arguments REFUSE instead of being silently ignored») применён к этому
  инструменту.
- **`--selftest` доказывает оба ответа** (EXP-0059) на чистой функции, за миллисекунды, без
  временного репозитория и без единого коммита: красный на чужом новом файле при пустом намерении
  и при намерении, называющем другое; молчание на названном поимённо, на названном директорией,
  под `--with-new` и на правках отслеживаемых файлов. Плюс путь с пробелами и кириллицей (порция
  `-z`, без кавычек `git status`) и три формы постороннего аргумента.

**Проба живого гейта** (цитата прогона, четыре файла владельца лежали в дереве):
«✋ в дереве 4 новых файл(ов) вне намерения коммита: ?? assets/KAIF_2.2_SOCIAL_POSTER_PROD_v1.png …»
— то есть тот самый полевой сценарий, с которого документ начался, теперь останавливает коммит.

## ВТОРОЕ наблюдение того же класса — стоило документа (2026-08-09 13:06 +03:00)

Печать набора поймала СЛЕДУЮЩИЙ дефект того же инструмента, и поймала его на авторе фикса:
`--only` берёт **ОДИН путь на флаг**, а вызов был написан с девятью путями после одного флага —
восемь были проглочены МОЛЧА. Коммит `51babed` унёс три файла из девяти названных.

Цена оказалась выше очевидной: среди проглоченного был документ этого самого бага 65 — в коммит
уехало его **переименование** в `65_DONE_*` (git показал `R100`, стопроцентное сходство) при теле,
всё ещё говорящем `🟡 PARTIAL`. То есть молчаливое проглатывание аргумента произвело ровно ту
ложь, которую ловит ось «закрытие против тела» (`bugs/76`), — и произвело её В ИСТОРИИ, где ось не
смотрит: линтер судит рабочее дерево, а там тело уже было верным.

Отсюда вторая половина фикса — отказ на постороннем аргументе. И отсюда же урок формы: **печать
набора не заменяет гейт, она его дополняет** — печать нашла дефект, но не остановила коммит.

## Решение, принятое агентом без владельца

**Гейт различает НОВЫЕ и ОТСЛЕЖИВАЕМЫЕ файлы.** План бага допускал более строгий ход — требовать
объявленного намерения всегда (`--only` либо явный `--all`). Отвергнут: он переписал бы каждую
точку вызова в обоих слоях ради класса, который в поле проявился ровно на новых файлах (владелец
кладёт ассеты, чужой инструмент роняет артефакт). Правки отслеживаемых файлов — это работа сессии,
и у неё уже есть свой преполёт. Граница названа здесь, чтобы её можно было пересмотреть словом
владельца, а не забыть.
**Fix accepted when (observable):** инструмент коммита ПЕЧАТАЕТ полный список того, что он
собирается закоммитить, ДО того как это сделает; файл, которого не было в намерении вызывающего,
останавливает коммит или требует явного флага. Проба: положить посторонний файл в рабочее дерево,
запустить коммит — инструмент обязан назвать этот файл и не увести его молча.

## Symptom

Канон git-гигиены (`AGENT_GUIDE.md` → «Неотменяемая git-гигиена») требует: **«`git diff --stat`
перед каждым коммитом. Всё в диффе, чего ты не намеревался менять, — СТОП»**, и отдельно
предупреждает про «диффы, которые сгенерировали *твои инструменты*». Правило неисполнимо в текущей
форме, потому что проверяемое состояние и коммитимое состояние — РАЗНЫЕ:

1. агент стейджит свои файлы и смотрит `git diff --cached --stat` — видит ровно своё;
2. `node tools/commit.mjs` первым делом делает `git add -A` (`tools/commit.mjs:85`) — и коммитит
   ВСЁ рабочее дерево, включая то, что появилось между шагами 1 и 2.

Наблюдение, породившее документ: пока сессия чинила гард 5d, владелец положил в `assets/` два
брендовых файла (`KAIF_2.2_GitHub_LOGO_v2.png`, `.webp`, метки файлов 11:10 и 11:11). Агент их
увидел, объявил в чате «не трогаю и в свои коммиты не беру», проверил `git diff --cached --stat`
(два своих файла) — и коммит `27ac934` уехал в origin с пятью файлами, включая оба чужих, под
сообщением про охват гарда 5d.

## Repro (deterministic)

1. `touch посторонний.txt` в корне репозитория (файл вне намерения агента);
2. изменить и застейджить любой свой файл, посмотреть `git diff --cached --stat` — постороннего нет;
3. `node tools/commit.mjs --msg-file <msg> --as "<модель>"`;
4. `git show --stat HEAD` — посторонний файл в коммите.

## Forensics

- `tools/commit.mjs:85` — `run('git add -A');` — единственная точка стейджинга, безусловная.
- `git show --stat 27ac934` — 5 файлов: `check-framework.mjs`, `bugs/66`, `version.json` и два
  чужих ассета.
- Преполёт `revert-guard` в том же прогоне напечатал «изменённых файлов 2» — он считал ДО
  `git add -A`, поэтому и он видел не тот набор, что уехал.

## Root cause

Проверка и действие смотрят на разные множества. `git add -A` — удобный дефолт для одиночной
сессии в чистом дереве; он же превращает любой параллельный процесс (владелец кладёт файлы, чужой
инструмент пишет артефакт, редактор роняет временный файл) в тихого соавтора коммита. Это тот же
класс, что и весь круг R1: **проверка мерит не то свойство, которое заявлено** — здесь «я проверил
дифф» означает «я проверил ПРОШЛЫЙ дифф».

Усиливающий слой: сообщение коммита пишется ПОД намерение агента, поэтому чужой файл получает
чужую мотивировку — история перестаёт отвечать на вопрос «почему этот файл здесь».

## Fix plan

- [x] Печатать список файлов ПЕРЕД коммитом (`git diff --cached --name-status` после стейджинга) —
      вслух, всегда, а не по флагу: агент не видит того, чего инструмент не сказал.
- [x] Гейт неожиданного файла: вызывающий передаёт намерение (`--only <путь>`, по флагу на путь),
      и новый файл сверх намерения останавливает коммит с готовым верным ходом (`--with-new`,
      если это действительно нужно) — по EXP-0008 ошибка несёт решение.
- [x] Селфтест на класс: посторонний файл в дереве обязан краснить коммит — плюс второй ответ
      (молчание на названном) и отказ на проглоченном аргументе.
- [x] Строка в `AGENT_GUIDE.md` (ОБА слоя): правило «`git diff --stat` перед коммитом» названо
      ИСПОЛНИМЫМ — смотреть набор, который РЕАЛЬНО УЕДЕТ, а не прошлый индекс.
