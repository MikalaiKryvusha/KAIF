# Bug 89 — коммит-маршруты мимо гейта неожиданного файла: подметающий `git` в навыках, в поставке и внутри самого инструмента

**Status:** 🔬 ПРЕДПОЛОЖИТЕЛЬНЫЙ — не верифицирован, причина не установлена · скоуп **2.3**
**Version/build:** build 279 · **When/context:** круги ревью R1/R2 фазы R, 2026-08-09
**Fix accepted when (observable):** НЕ ОПРЕДЕЛЁН — критерий приёмки задаёт исполнитель после
установления причины (решение №70: разбор и лечение за Fable, не за автором документа)

Шесть вхождений, замеченных кругами R1 и R2 вокруг одного наблюдаемого признака: коммит уезжает
набором, который никто не называл и не проверял. Пять адресов — предписания и дефолты, велящие
подметающий `git add -A` / `git commit -am` в обход `tools/commit.mjs`; шестое — внутри самого
инструмента. Причина не устанавливается, связь вхождений между собой не утверждается: они собраны
в один документ по совпадению наблюдаемого признака, а не по общему источнику. Каждое вхождение —
предположение, подлежащее самостоятельной проверке.

## 1. `/pause` предписывал подметающий `git add -A && git commit` в обход гейта

**Адрес:** `.claude/skills/pause/SKILL.md:23` (адрес круга; сегодня на этой строке другой текст)

**Заявлено:** `bugs/79` закрыт формой — «проверка и действие смотрят на ОДНО множество»;
`STATUS.md:118` продаёт гейт неожиданного файла как действующий.

документе как история признака; проверять, воспроизводится ли оно ещё где-то в `.claude/skills/`.

## 2. Шаг публикации `/release` велит `git commit -am`: набор коммита подметается и не печатается

**Адрес:** `.claude/skills/release/SKILL.md:153`
**Также:** `framework/skills/release/SKILL.md:116`

**Заявлено:** фикс `bugs/79` — «набор ПЕЧАТАЕТСЯ вслух ВСЕГДА, агент не видит того, чего инструмент
не сказал».

**Наблюдалось:** `tools/release.mjs` не существует, значит строка исполняется буквально; `-am`
подметает все отслеживаемые правки и не называет ни одной. `commit.mjs` упомянут в навыке только на
шаге README.

**Улика:**
```
grep -n "commit -am" .claude/skills/release/SKILL.md framework/skills/release/SKILL.md
.claude/skills/release/SKILL.md:153:git commit -am "release: X.Y" && git tag vX.Y && git push && git push --tags
framework/skills/release/SKILL.md:116:git commit -am "release: X.Y" && git tag vX.Y && git push && git push --tags
```
`ls tools/` — `release.mjs` отсутствует.

**Кого касается:** в самый необратимый момент (коммит + тег + пуш) в релиз уезжает посторонняя
правка, и гейт неожиданного файла на этом маршруте не вызывается.

**Замечено:** круг R2, 2026-08-09.

**Состояние на 2026-08-09:** адрес на месте, наблюдаемое воспроизводится. Оба слоя — обвязка
(`:153`) и поставка (`:116`) — несут строку дословно; вводная фраза шага по-прежнему условная
(«Если у тебя есть релизный инструмент… Иначе сделай это явно»), а `tools/release.mjs` в дереве нет.

## 4. Дефолтный коммит-поток, подставляемый КАЖДОМУ проекту, — `git add -A && git commit && git push`

**Адрес:** `framework/installer/KAIF-CORE.mjs:389`
**Также:** `dist/KAIF-CORE.mjs:389`, `framework/_intro.md:439`, `dist/KAIF-FULL.md:6685`,
`framework/AGENT_GUIDE.md:418`

**Заявлено:** `bugs/79` закрыт по пункту «ОБА слоя»; `framework/AGENT_GUIDE.md:415-421` требует
дословно: «a NEW file in the tree stops a sweeping commit rather than riding along».

**Наблюдалось:** дефолт остался прежним и подставляется в документы каждого разворачивающего
проекта; механизма (гейт нового файла, именование набора вслух) в поставке нет — только проза,
объявляющая его обязательным. То есть тот самый поток, который текст той же поставки называет
причиной уже случившегося ущерба, отгружается как значение по умолчанию.

**Улика:**
```
grep -n "COMMIT_COMMAND" framework/installer/KAIF-CORE.mjs dist/KAIF-CORE.mjs
framework/installer/KAIF-CORE.mjs:389:    '<COMMIT_COMMAND>': 'git add -A && git commit -m "<msg>" && git push',
dist/KAIF-CORE.mjs:389:    '<COMMIT_COMMAND>': 'git add -A && git commit -m "<msg>" && git push',
```
`tools/commit.mjs` существует только в этом репозитории и упомянут в поставке лишь примером
«e.g. tools/commit.mjs».

**Кого касается:** предполагаемый корень `bugs/79` отгружается как ДЕФОЛТ вместе с текстом,
называющим такой поток причиной уже случившегося ущерба.

**Замечено:** круг R2, 2026-08-09.

**Состояние на 2026-08-09:** адрес на месте, наблюдаемое воспроизводится. Значение
`'<COMMIT_COMMAND>'` на `:389` в обоих слоях идентично. `framework/_intro.md:439` (и его отпечаток
`dist/KAIF-FULL.md:6685`) — таблица плейсхолдеров — приводит тот же подметающий `git` примером
контракта `<msg>`, требуя при этом «**If the project has a commit tool with a staging gate, name
THAT tool here, never raw `git`**». `framework/AGENT_GUIDE.md:418` на месте, формулировка
процитирована точно.

## 5. `--only <КАТАЛОГ>` выключает гейт неожиданного файла и при этом подметает

**Адрес:** `tools/commit.mjs:30`
**Также:** `tools/commit.mjs:194-198`,
`bugs/79_DONE_commit_tool_widens_the_set_after_the_preflight_check.md:31`

**Заявлено:** `bugs/79` закрыт — «необъявленный файл в это множество не попадает»; документ
`bugs/79`, строка 31, приписывает `--selftest` в числе доказанных ответов молчание «на названном
директорией».

**Наблюдалось:** `if (withNew || only.length) return [];` снимает ось по факту непустого `only`, а
`git add -- <каталог>` забирает все untracked под ним; `--only .` подметает всё дерево с пометкой
«(--only)». В селфтесте девять `T()` и ни одного про каталог.

**Улика:**
```
tools/commit.mjs:30:  if (withNew || only.length) return [];
tools/commit.mjs:198:      execFileSync('git', ['add', '--', ...only, 'version.json'], { cwd: ROOT, stdio: 'inherit' });
grep -n "директор\|каталог" tools/commit.mjs → (пусто)
grep -c "  T(" tools/commit.mjs → 9
```
Пробы на копии: владелец кладёт `assets/OWNER_R2_STRAY.png`, агент коммитит `--only assets` → гейт
молчит, коммит `5fed84f` унёс файл; `--only .` → `b8aa921` унёс второй файл и все правки.

**Кого касается:** полевой сценарий `bugs/79` воспроизводится внутри самого инструмента, а документ
`bugs/79` объявляет обратное и приписывает селфтесту утверждение, которого в нём нет.

**Замечено:** круг R2, 2026-08-09.

**Состояние на 2026-08-09:** адреса на месте, наблюдаемое воспроизводится по чтению кода.
`tools/commit.mjs:30` дословен; комментарий выше него (`:26-28`) прямо обосновывает изъятие: «При
`--only` набор объявлен целиком и стейджится поимённо, поэтому посторонний файл не может уехать по
определению». Девять `T()` в блоке `--selftest` (`tools/commit.mjs:54-85`) перечислены поимённо —
среди них `'объявленное намерение (--only) снимает ось — подметания нет'` с аргументом
`only: [mine]` (файл, не каталог); случая с каталогом нет. `bugs/79:31` несёт фразу «на названном
директорией» без изменений.

## 6. Гейт и подметающий `git add -A` разделены записью `version.json`

**Адрес:** `tools/commit.mjs:152-163`
**Также:** `tools/commit.mjs:208`

**Заявлено:** комментарий на `:143-147` — гейт написан против класса «проверка и действие смотрят на
разные множества»; сообщение гейта обещает, что необъявленный файл в коммит не попадёт.

**Наблюдалось:** замер на `:153-155`, запись `version.json` на `:167-170`, стейджинг на `:208` —
файл, появившийся в этом окне, уедет подметающим `add`. Окно сократилось со всей сессии до
миллисекунд, и печать индекса такого попутчика назовёт, поэтому вхождение записано как оговорка, а
не как опровержение.

**Улика:** читан порядок побочных эффектов; пробой НЕ воспроизводилось — гонка миллисекундного окна
недетерминирована, и это названо нехваткой пробы, а не отрицательным результатом.
```
tools/commit.mjs:153:  const unexpected = newFilesOutsideIntent(
tools/commit.mjs:170:writeFileSync(vf, JSON.stringify(v, null, 2) + '\n');
tools/commit.mjs:208:    run('git add -A');
```

**Кого касается:** в подметающем режиме гарантия держится на времени, а не на форме.

**Замечено:** круг R2, 2026-08-09. Тяжесть в круге — minor (остальные пять — major).

**Состояние на 2026-08-09:** адреса на месте, порядок побочных эффектов прежний. Номера строк
сместились на единицы против записи круга: блок гейта — `:143-163`, запись `version.json` — `:167-170`,
подметающий стейджинг — `:208`.
