**Version/build:** build 279 · **When/context:** круги ревью R1/R2 фазы R, 2026-08-09
**Fix accepted when (observable):** НЕ ОПРЕДЕЛЁН — критерий приёмки задаёт исполнитель после
установления причины (решение №70: разбор и лечение за Fable, не за автором документа)

`tools/doc-header-lint.mjs` (строки ~433–495). Все четыре вхождения — про ОХВАТ: страж заведён,

## 1. `CLOSED_CLAIM_RE` узнаёт две формы заявления о закрытии, а её вторая ветка при вызове не исполняется

**Адрес:** `tools/doc-header-lint.mjs:433` (использование — `tools/doc-header-lint.mjs:441`).
Затронутые документы, на которых наблюдалось: `plans/20_kaif_2.0_excellent_kaif.md:12`,
`plans/26_kaif_2.2.md:274`.

**Заявлено.** Ось заведена коммитом `08d65a1` под лозунгом «заявление о закрытии сверяется с
телом»; вторая ветка регулярного выражения написана специально под bugs-диалект
`**Status:** ✅` и якорена на `^`.

**Наблюдалось.** Выражение
`/(?:✅\s*(?:DONE|ЗАКРЫТ|ЗАКРЫТА|ЗАКРЫТО)|^\s*\*\*Status:\*\*\s*✅)/u` объявлено без флага `m`, а
проверяется против СКЛЕЙКИ первых 25 строк (`lines.slice(0, HEAD_LINES).join('\n')`) — то есть
якорь `^` в этом вызове достижим только для первой строки склейки. Мимо первой ветки проходят:
каноническая форма закрытия планов `## ✅ STATUS: DONE (дата)`; секционный штамп
`> ✅ **ЗАКРЫТА …**` (в `plans/26` таких 16); любой глагол вне четырёхсловного списка —
`✅ исполнен` (`plans/20:12` при шести незакрытых `- [ ]` в теле файла), `✅ ЗАВЕРШЁН`,
`✅ ОТВЕЧЕНО`, `✅ РЕАЛИЗОВАНА`.

**Улика.**

```
$ node -e "const RE=/(?:✅\s*(?:DONE|ЗАКРЫТ|ЗАКРЫТА|ЗАКРЫТО)|^\s*\*\*Status:\*\*\s*✅)/u; ..."
multiline: false
false "## ✅ STATUS: DONE (2026-07-16)"
false "> ✅ **ЗАКРЫТА 2026-08-08 10:05 +03:00.**"
false "> **Статус:** ✅ исполнен — 2.0"
false "✅ ЗАВЕРШЁН"
false "✅ ОТВЕЧЕНО"
false "✅ РЕАЛИЗОВАНА"
true  "✅ DONE"
true  "**Status:** ✅ ЗАКРЫТ"

$ grep -c "^\s*- \[ \]" plans/20_kaif_2.0_excellent_kaif.md
6
```

Круг R2 дополнительно прогонял фикстуру `fx5` из четырёх файлов с ОДНИМ и тем же телом: красными
становились только «✅ DONE» и bugs-шаблон.

**Кого касается.** Автора и приёмщика любого закрытого документа: документ, закрытый по
собственному канону проекта (`## ✅ STATUS: DONE`), осью не проверяется вовсе, а то, что она
сегодня ловит, ловится первой веткой.

**Замечено.** Круг R2 фазы R, 2026-08-09.

**Состояние на 2026-08-09.** Адрес на месте, наблюдаемое воспроизводится дословно (см. улику,
прогон сделан сегодня на рабочем дереве после шести закрытых блокеров).

## 2. Изъятие «список-хранилище» ищет подстроку без границ слова

**Адрес:** `tools/doc-header-lint.mjs:436` (применение — `tools/doc-header-lint.mjs:455`).

**Заявлено.** Комментарий над константой: «Изъятия названы, потому что оба — законные жанры:
„Пул автономного беклога“ и подобные списки-хранилища: незакрытый пункт там и есть содержание, а
не долг закрытого документа».

**Наблюдалось.** `BACKLOG_SECTION_RE = /(?:пул|беклог|backlog|задел|хвост|автономн)/iu` — без
границ слова и по всему тексту заголовка. Совпадение даёт `return` для всей секции, то есть
снимает надзор над её незакрытыми `- [ ]`. Совпадают обычные русские слова, к жанру «хранилище»
отношения не имеющие: «пульс», «Манипуляции», «Популяция», «Хвостовые».

**Улика.**

```
$ node -e "const B=/(?:пул|беклог|backlog|задел|хвост|автономн)/iu; ..."
true "Шаг 2 — HEARTBEAT: пульс = завершённая работа, никогда не таймер"
true "Манипуляции с шаблонами"
true "Популяция агентов"
true "Хвостовые правки"
```

Первая строка — не выдумка: это живой заголовок `.claude/skills/guarded-loop/SKILL.md:45`. Круг R2
проверял то же фикстурой `fx6` из пяти файлов с одинаковой шапкой закрытия — красным оставался
только контроль.

**Кого касается.** Всех, кто полагается на зелёный прогон закрытого документа: дверь законного
изъятия наблюдалась шире названного жанра, и заголовок, никак не связанный с беклогом, снимает
надзор со своей секции молча.

**Замечено.** Круг R2 фазы R, 2026-08-09.

**Состояние на 2026-08-09.** Адрес на месте, наблюдаемое воспроизводится. Латентно: сегодня ни
одна секция репозитория не наблюдалась глушащей реальный долг — совпадения найдены на заголовках,
где незакрытых пунктов нет.

## 3. Заявление о закрытии читается только из первых 25 строк

**Адрес:** `tools/doc-header-lint.mjs:440` (`const head = lines.slice(0, HEAD_LINES).join('\n')`,
`HEAD_LINES = 25` — `tools/doc-header-lint.mjs:71`); функция — `tools/doc-header-lint.mjs:438`.
Затронутые документы, на которых наблюдалось: `plans/14_DONE_testing_framework.md:85`,
`plans/10_DONE_experience_memory.md:117`, `plans/26_kaif_2.2.md:274`.

**Заявлено.** `bugs/76` (закрыт) утверждает, что ось покрывает класс «заявление о закрытии
расходится с тем, что закрыто», включая случай (а) — закрытие ЗАДАЧИ ВНУТРИ плана.

**Наблюдалось.** `if (!CLOSED_CLAIM_RE.test(head)) return;` — документ, объявляющий себя закрытым
ниже 25-й строки, отбрасывается до всякого осмотра тела. В исторических планах канонический штамп
`## ✅ STATUS: DONE` стоит именно там: `plans/14` — строка 85, `plans/10` — строка 117. Тег
`_DONE_` в ИМЕНИ файла закрытостью для этой оси не считается. Секционный штамп внутри живого плана
(`plans/26:274`, «✅ **ЗАКРЫТА …**») не проверяется никогда — головы этого файла он не касается.

**Улика.** Прогон по шести историческим планам с тегом `_DONE_` в имени:

```
$ node -e "<CLOSED_CLAIM_RE против head=25 и против всего файла, plans/1[0-5]_*>"
10_DONE_experience_memory.md          | headClaim= false | open= 20 | firstClaimLine= 0
11_DONE_enforcement_hooks.md          | headClaim= false | open=  8 | firstClaimLine= 0
12_DONE_progressive_context_loading.md| headClaim= false | open=  8 | firstClaimLine= 0
13_DONE_kaif_1.5_thin_kaif.md         | headClaim= false | open=  7 | firstClaimLine= 0
14_DONE_testing_framework.md          | headClaim= false | open=  9 | firstClaimLine= 0
15_DONE_kaif_update_migration.md      | headClaim= false | open=  9 | firstClaimLine= 0
```

Итого 61 незакрытый пункт `- [ ]` в шести документах, объявленных закрытыми; ноль находок оси.
Колонка `firstClaimLine= 0` показывает вторую наблюдаемую сторону: даже при снятом окне головы
выражение не узнаёт штамп `## ✅ STATUS: DONE` ни на одной строке (пересекается с вхождением 1).
Круг R2 дополнительно копировал живой `plans/14` в песочный корень — приходили 4 находки ШАПКИ и
ни одной от оси закрытия; фикстура с секцией «✅ ЗАКРЫТА» и `- [ ] НЕ ИСПОЛНЕНО` внутри давала
молчание.

**Кого касается.** Приёмщика фазы и судью: наблюдалось, что случай (а), ради которого ось
заведена, страж не ловит структурно, а охват совпадает с тем, что нашёл детектор в день рождения
оси.

**Замечено.** Круг R1 (первичная примета) и круг R2 (обмер по корпусу), 2026-08-09.

**Состояние на 2026-08-09.** Адрес на месте, наблюдаемое воспроизводится; полный прогон
`node tools/doc-header-lint.mjs --all` сегодня не печатает ни одной находки вида «документ
объявляет себя ЗАКРЫТЫМ, а в теле …» (0 совпадений в выводе).

## 4. Ось «PENDING без СУДЬБЫ» требует двоеточия или стрелки ВПЛОТНУЮ

**Адрес:** `tools/doc-header-lint.mjs:476` (`PENDING_MARK_RE`; применение —
`tools/doc-header-lint.mjs:485`). Затронутые документы, на которых наблюдалось:
`plans/26_kaif_2.2.md:69`, `plans/29_EPIC_kaif_2.2_M_feedback_loop.md:3` (и строка закрытия
`plans/29_EPIC_kaif_2.2_M_feedback_loop.md:126`).

**Заявлено.** `bugs/72` закрыт формулировкой «у обязательства появилась СУДЬБА», критерий приёмки
там записан как «`grep -rn PENDING plans/ researches/` не даёт ни одной живой строки без судьбы».

**Наблюдалось.** `PENDING_MARK_RE = /(?<!`)\*?PENDING\*?\s*(?::|→)/u` требует `:` или `→`
непосредственно после слова (допускается только пробельное). Строка, ради которой ось заводилась,
в дофиксовой редакции несла между словом и двоеточием одиннадцать слов —
`**Открытые PENDING на приёмку владельцем (…; вынесены в Фазу R):**` — и меткой не опознаётся. Две
живые сегодня строки (`plans/26:69`, `plans/29:3`) несут АДРЕС вместо судьбы («PENDING приёмки
владельца — в `plans/29`», «**Вовне:** PENDING приёмки владельца … — снимает Фаза R/вычитка») и
обе не опознаются ни как метка, ни как судьба. При этом `plans/29:126` уже сообщает, что эти
обязательства приняты владельцем 2026-08-09 13:49 +03:00 (интервью №017): правка легла в ТЕЛО
документа, шапку эпика не тронув.

**Улика.**

```
$ node -e "<PENDING_MARK_RE / PENDING_FATE_RE против живых строк>"
plans/26_kaif_2.2.md:69                        mark= false fate= false
plans/29_EPIC_kaif_2.2_M_feedback_loop.md:3    mark= false fate= false
$ node -e "PENDING_MARK_RE.test('**Открытые PENDING на приёмку владельцем (…; вынесены в Фазу R):**')"
false

$ grep -rn "PENDING" plans/ researches/ | grep -v '`PENDING'
plans/26_kaif_2.2.md:69: … PENDING приёмки владельца — в `plans/29`) |
plans/29_EPIC_kaif_2.2_M_feedback_loop.md:3: > … **Вовне:** PENDING приёмки владельца
plans/29_EPIC_kaif_2.2_M_feedback_loop.md:126: ✅ **PENDING на приёмку владельцем ЗАКРЫТЫ …**

$ node tools/doc-header-lint.mjs --all | grep -ci "PENDING"
0
```

Круг R2 прогонял также дофиксовую редакцию (`git show 0a1ba09^:plans/29… | doc-header-lint`) — из
всего корпуса ось называла один `plans/49:90`, где форма `PENDING →` стоит вплотную.

**Кого касается.** Владельца и приёмщика эпика M: шапка `plans/29` наблюдалась заявляющей живое
обязательство перед владельцем, которого по телу того же документа больше нет, а прогон стража при
этом печатает ноль строк про PENDING.

**Замечено.** Круг R2 фазы R, 2026-08-09 (экземпляр-родитель — из живого прогона владельца того же
дня).

**Состояние на 2026-08-09.** Адрес на месте, наблюдаемое воспроизводится: обе живые строки
`plans/26:69` и `plans/29:3` на месте и стражу невидимы; полный прогон линтера сегодня даёт 0
упоминаний PENDING в выводе. Расхождение с записью круга R2: там общий итог прогона зафиксирован
как «findings 0 — all headers green», сегодня итог — `doc-header-lint: scanned 219, findings 141`
(консультативный режим); ни одна из 141 находок к оси PENDING не относится.
