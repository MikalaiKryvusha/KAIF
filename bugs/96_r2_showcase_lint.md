# Bug 96 — витринные линтеры: класс объявляет себя проверкой ФОРМЫ, а внутри — снимок из нескольких слов, и один жёсткий пункт краснеет на правильном русском

**Status:** 🔬 ПРЕДПОЛОЖИТЕЛЬНЫЙ — не верифицирован, причина не установлена · скоуп **2.3**
**Version/build:** build 279 · **When/context:** круги ревью R1/R2 фазы R, 2026-08-09
**Fix accepted when (observable):** НЕ ОПРЕДЕЛЁН — критерий приёмки задаёт исполнитель после
установления причины (решение №70: разбор и лечение за Fable, не за автором документа)

Четыре вхождения о двух стражах витрины — `tools/showcase-lint.mjs` и `tools/voice-lint.mjs`. Круги
наблюдали одну и ту же пару расхождений: три класса `showcase-lint` названы свойством (форма слова,
намёк на закулисье, посторонний символ перед тегом), а внутри у них перечень из нескольких слов или
одна узкая примета — обиходные носители того же смысла проходят зелёными; жёсткий пункт `G1`
`voice-lint` объявляет о себе «ложных срабатываний она не даёт» и на корневом каноне даёт 11
совпадений из 11 ложных. Причина ни по одному вхождению не устанавливалась; ниже — только адрес,
заявление и наблюдение. Все прогоны ниже сделаны 2026-08-09 на КОПИЯХ витринных файлов в
скретчпаде; рабочее дерево не менялось.

## 1. Форм-лист класса BACKSTAGE — ручная копия АП31: связи с `AUTHOR_STYLOMETRY.md` нет, обиходные носители того же смысла проходят зелёными

**Адрес:** `tools/showcase-lint.mjs:100-109` (массив `forms` класса `BACKSTAGE`, объявление класса —
`:84`). Также: `tools/showcase-lint.mjs:92` (комментарий о происхождении форм).

**Заявлено.** Комментарий класса дословно (`:91-93`): «АП31 портрета перечисляет ЧЕТЫРЕ русских
слова — „в действительности“, „на самом деле“, „фактически“, „строго говоря“, — и „фактически“ в
листе не было… Формы взяты из `AUTHOR_STYLOMETRY.md` §5 (АП31) и `plans/68`, а не из головы».
Класс назван свойством смысла: «намёк на второй уровень вне текста (АП31)».

**Наблюдалось.** `showcase-lint.mjs` не читает `AUTHOR_STYLOMETRY.md` ни разу — единственное
упоминание файла в инструменте — тот самый комментарий. Форм-лист — восемь регэкспов, снимок
одного дня. На копии `README.md` дописано «Заплачено <оборот> немного.»; краснеют только два из
шести проверенных носителей того же смысла.

**Улика.**

```
$ grep -n "AUTHOR_STYLOMETRY" tools/showcase-lint.mjs
92:    // «на самом деле» краснело. Формы взяты из `AUTHOR_STYLOMETRY.md` §5 (АП31) и `plans/68`, а не
```

Прогон `node tools/showcase-lint.mjs <копия README>` по одной и той же фразе со сменой оборота
(вторая колонка — число строк с `BACKSTAGE` в выводе):

```
по факту         EXIT=0  0
по сути          EXIT=0  0
на деле          EXIT=0  0
```

**Кого касается.** Владельца и всякого, кто читает витрину: при первой же правке портрета голоса
форм-лист расходится с ним молча, и страж витрины продолжает печатать «✅ нарушений правил витрины
нет» ровно на том, ради чего заведён.

**Замечено.** Круг ревью R2 фазы R, 2026-08-09.

**Состояние на 2026-08-09.** Адрес на месте, наблюдаемое воспроизводится. Отличие от записи круга:
R2 указал `:100-107` и три зелёных обиходных носителя — сегодня массив `forms` занимает строки
`100-109` (восемь форм), а зелёными прошли четыре проверенных оборота из шести.

## 2. Примета STRAY уже класса по пяти измерениям сразу: длина ≤4, только буквы и цифры, только вплотную и в начале строки, только девять HTML-тегов, только HTML

**Адрес:** `tools/showcase-lint.mjs:169` (единственная форма класса `STRAY`, объявление класса —
`:155`). Также: `tools/showcase-lint.mjs:159-167` (комментарий, объявляющий примету достаточной) ·
`README.md:133` · `README.md:677` · `reports/RELEASE_NOTES_2.2.md:62` ·
`reports/RELEASE_NOTES_2.2.md:123` (живые строки, начинающиеся с `<sub`) ·
`bugs/80_DONE_showcase_guards_blind_to_stray_character_before_a_tag.md`.

**Заявлено.** `bugs/80` закрыт как КЛАСС: заголовок — «посторонний символ на витрине проходит мимо
ВСЕХ витринных гейтов», критерий приёмки — «мусорный символ, приклеенный к открывающему блочному
тегу…». Комментарий в коде объявляет узость достаточной дословно: «Примета УЗКАЯ и потому дешёвая:
строка НАЧИНАЕТСЯ с одного-четырёх словесных символов, приклеенных ВПЛОТНУЮ к открывающему
блочному тегу. В markdown такой формы не бывает».

**Наблюдалось.** Форма одна:

```js
/^[\p{L}\p{N}]{1,4}<(?:p|h[1-6]|div|picture|table|img|a|br|hr)\b/gimu
```

Мимо неё, по записи круга R2, проходят: пять и более символов; эмодзи, пунктуация, NBSP, ZWSP, BOM;
мусор через пробел, отдельной строкой, после открывающего тега, с отступом; теги `<details>`,
`<summary>`, `<blockquote>`, `<span>`, `<ul>`, `<li>`, `<code>`, `<pre>` и `<sub`; markdown-заголовок
(`3# Заголовок` уничтожает заголовок целиком). Круг записал 12 зелёных форм из 20 в своей матрице.
Сегодня перепроверены четыре пробы из этой матрицы — граница длины и тег `<sub`, который витрина уже
использует в четырёх живых местах.

**Улика.** Пробы на копиях `README.md`, `node tools/showcase-lint.mjs <копия>`:

```
prefix=abcd   (перед «<p align="center">» первой строки)   EXIT=1
              ❌ STRAY — посторонний символ, приклеенный к открывающему блочному тегу (bugs/80) (1)
prefix=abcde  (то же место, пять символов)                 EXIT=0
              ✅ нарушений правил витрины нет
```

Тот же файл, мусор перед живым тегом витрины — `<sub>An installation is tracked…` заменено на
`3<sub>An installation is tracked…`:

```
EXIT=0
  ✅ нарушений правил витрины нет
```

Контроль на той же копии — `3` в начало первой строки, перед `<p align="center">`:

```
EXIT=1
  ❌ STRAY — посторонний символ, приклеенный к открывающему блочному тегу (bugs/80) (1)
      стр. 1: …3<p align="center">…
```

Живые адреса тега, которого примета не знает:

```
reports/RELEASE_NOTES_2.2.md:123:<sub>Установка по умолчанию привязана к origin. …
```

**Кого касается.** Владельца, поймавшего исходный дефект глазами на опубликованной странице, и
всякого посетителя витрины: визуально тождественные формы того же мусора воспроизводятся — в том
числе на теге, который витрина уже несёт в четырёх местах.

**Замечено.** Круг ревью R2 фазы R, 2026-08-09; исходное наблюдение — живой прогон владельца
2026-08-09 (`bugs/80`).

**Состояние на 2026-08-09.** Адрес на месте, наблюдаемое воспроизводится дословно; все четыре живых

## 3. Класс PASSIVE судит перечень из тринадцати глаголов вместо формы слова, которую объявляет

**Адрес:** `tools/showcase-lint.mjs:214` (единственная форма класса `PASSIVE`, объявление класса —
`:200`, `sectionOnly` — `:208`). Также: `tools/showcase-lint.mjs:209-212` (комментарий класса).

**Заявлено.** Класс назван свойством формы слова: «безличный залог вместо обращения к читателю в
инструкции»; в комментарии приведено слово владельца — «в каком-то залоге „говорится“ „делается“ —
это уже не правила, а руководство по установке». Тот же комментарий сам формулирует урок о
расхождении заявления и проверки: «класс документировал форму, которую не ловил. Ровно то
расхождение между заявлением и его проверкой, ради которого заведён весь `bugs/66`».

**Наблюдалось.** Один регэксп с фиксированным перечнем из 13 глаголов:

```js
/(?<![А-Яа-яЁё-])(?:помещается|говорится|даются|заполняется|запрашивается|кладётся|кладется|спрашивается|берётся|берется|выполняются|производится|делается|делаются)(?![А-Яа-яЁё-])/giu
```

Любой другой возвратный глагол в секции-инструкции проходит зелёным.

**Улика.** В копию `README.md`, в секцию `### 2.2. Порядок установки` (она попадает под
`sectionOnly`), вставлена строка «Дальше <глагол> копия каталога.»; прогон
`node tools/showcase-lint.mjs <копия>`:

```
делается       EXIT=1 PASSIVE-hits=1
создаётся      EXIT=0 PASSIVE-hits=0
указывается    EXIT=0 PASSIVE-hits=0
настраивается  EXIT=0 PASSIVE-hits=0
формируется    EXIT=0 PASSIVE-hits=0
проверяется    EXIT=0 PASSIVE-hits=0
```

**Кого касается.** Владельца и читателя витрины: витрина — поверхность, за которую заплачено волной
из 22 дефектов, и следующая инструкция с глаголом не из перечня уходит в публикацию при зелёном
гейте.

**Замечено.** Круг ревью R2 фазы R, 2026-08-09.

**Состояние на 2026-08-09.** Адрес на месте (`:214` совпадает точно), наблюдаемое воспроизводится;
к четырём глаголам, названным кругом, сегодня добавился пятый зелёный («проверяется»).

## 4. `voice-lint` G1 объявляет о себе «ложных срабатываний она не даёт», а даёт 11 из 11 — и жёстко валит `/release` на грамматически верном русском

**Адрес:** `tools/voice-lint.mjs:127-129` (комментарий с заявлением). Также:
`tools/voice-lint.mjs:137-142` (регэксп и жёсткая проверка) · `tools/voice-lint.mjs:19` (то же
заявление в шапке инструмента) · `.claude/skills/release/SKILL.md:104`.

**Заявлено.** Комментарий (`:127-129`) дословно: «Русский требует согласования по числу, поэтому
пара „который … -ют/-ут/-ат/-ят“ ошибочна всегда — исключений у неё нет, и ложных срабатываний она
не даёт: правильный текст пишет „которые … пользуются“». Шапка (`:19`): «Согласование „который“ по
числу (G1) — форма, у неё нет исключений, она здесь». Пункт объявлен `HARD`; `/release`
(`.claude/skills/release/SKILL.md:104`) предписывает: «Красное = стоп до починки текста».

**Наблюдалось.** Форма — «котор(ый|ая|ое)» и глагол на `-ют/-ут/-ат/-ят` в окне 40 символов
(`:137-139`); подлежащее придаточного от дополнения она не различает, а второе — массовый
правильный случай русского («правило, которое не проверяют»).

**Улика.** Прогон по 18 корневым `*.md` (`node tools/voice-lint.mjs <файл>` по каждому): краснеют
два файла, 11 совпадений, истинных среди них ноль.

```
                 соблюдают · который читают

                 проекты тянут · которое, по канону, нарушают · которое было в ней названо
остальные 16 корневых документов :: G1 — 0 (норма 0)
```
