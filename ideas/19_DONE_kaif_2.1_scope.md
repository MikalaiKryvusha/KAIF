Интервью стоит дублировать в интерактивный HTML, с кнопками на предложенные ответы (A, B, C, D) и с полем текстовым на свой ответ или комментарий Владельца. Могут быть однозначные вопросы, с кнопками [Одобрить], [Отклонить], с полем "Комментарий владельца" Всякое, что требует вычитки автора, развилки, вмешательства, ответа на вопрос - оно документируется по KAIF, и специальным инструментом-машинерией, который создаёт ИИ агент - рендерится в HTML и мгновенно по готовности HTML - окрывать его в браузере для автора во имя максимального интерактива и наглядности для владельца. ИИ агент что-то хочет от владельца - записывает по kaif это в md, тут же машинерией рендерит  HTML - открывает его автоматически в браузере, чтобы автор не копался в рипозитории и не искал md документики. Ответы в HTML - приравниваются к ответам владельца как в md документах, так и = ответам "да" или "нет" владельца в чате с ИИ агентом. Открытие браузера должно сопровозждаться звуковым сигналом. нужна настройка звукового сигнала. Или даже настройка TTS, чтобы оно могло позвать, например "{имя владельца}, нужно согласование с вами по интервью №14". KAIF документирует эту практику для ИИ агентов, KAIF не проектирует конкретных инструментов, а описывает методологию рабочего процесса, который должны организовать ИИ агенты в проекте владельца.

По умолчанию, настраивается цикл так, чтобы агент сам себя будил каждые 10 минут (значение по умолчанию, если не попрошено владельцем другое значение). Для чего нужно: иногда интернет лагает, случаются API ошибки и чат ии агента может зависнуть и не проснуться самостоятельно. Такой защищённый цикл гарантирует, что агент сам побеспокоится о том, чтобы его же локальные код-механизмы его перестраховочно "дёргали" - будили кажные N минут.

ЧЕТЫРЕ РАЗНЫХ СИМПТОМА ОДНОГО КЛАССА, все пойманы за одну сессию 2026-07-29 на проекте KPOT (агент на KAIF 1.6). Ценность в том, что симптомы РАЗНЫЕ и агент не опознаёт их как родственные:

9.1) python -c с кириллицей → SyntaxError: (unicode error) 'unicodeescape' codec can't decode bytes.
Причина: аргумент проходит через консоль в кодировке cp1251/cp866 ДО того, как его увидит Python. Текст уже испорчен на входе.
Коварство: иногда не падает, а МОЛЧА пишет мусор в файл.

9.2) Обратные кавычки в двойных кавычках bash → команда подстановки съедает куски текста.
Писал строку с markdown-кодом вида `bugs/07` внутри python -c "…" — bash выполнил это как подстановку команды, вернул пустоту, и в документ записалась фраза с ДЫРКАМИ на месте всех бэктиков. Скрипт при этом отработал успешно и напечатал «ok».
Это худший подвид: НЕТ ОШИБКИ, есть тихая потеря данных. Ловится только чтением результата.

9.3) Windows-пути внутри строк → SyntaxError: truncated \uXXXX escape.
D:\work\... — это \w и \u как escape-последовательности. Тот же дефект в JS, JSON, YAML.

9.4) Разные шеллы — разные миры, и «работает у меня» ничего не значит.
· npm run package падал из Git Bash: GNU tar принимает D:\... за адрес удалённого хоста → «tar: Cannot connect to D: resolve failed». Из PowerShell тот же скрипт отработал (там tar.exe = bsdtar от Windows).
· файл, записанный в /tmp из Git Bash, НЕ ВИДЕН Windows-питону: у них разные вселенные путей.
· Set-Content/Add-Content в PowerShell 5.1 по умолчанию пишут в ANSI, а не UTF-8 — файл, который потом читает другой инструмент, приезжает битым.
