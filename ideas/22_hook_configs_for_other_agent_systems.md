## Вектор цели (боль + как проверим)

Боль: модуль refresh-hooks поставляет конфиг ровно под ОДНУ агентскую систему (Claude Code),
хотя `researches/19` §1.2 живым обзором показал хуки у Cursor, Codex, Copilot, Windsurf и Cline
— проект на любой из них получает только markdown-ритуал, хотя механический контур там
технически доступен. Хотим (Achieve): у каждой агентской системы с подтверждённым хук-контрактом
есть свой образец конфига в модуле, а сами скрипты остаются одни на всех.

Проверим (при реализации): для каждой системы N — файл-образец в `framework/hooks/` (по
конвенции самой системы: `.cursor/hooks.json`, `.codex/hooks.json`, …) с датой снятия живого
контракта в шапке; свод полигона проверяет, что каждый образец — валидный JSON и адресует
существующие скрипты модуля; README модуля перечисляет системы строкой на систему с честной
пометкой «контракт верифицирован живой докой <дата>» либо «не верифицирован — образец-гипотеза»;
развёртывание на системе без хуков по-прежнему не краснеет.

## Суть

Скрипты модуля (`session-start-refresh` · `prompt-refresh-timer` · `stop-status-guard`) —
обычные Node-программы: читают JSON на stdin, печатают JSON на stdout. Системо-зависима ТОЛЬКО
проводка: имя файла конфига, имена событий и форма выходного поля. Значит цена системы —
один образец конфига плюс, возможно, тонкий адаптер формы вывода, а не второй комплект логики.

Стартовая база уже собрана в `researches/19` §1.2 (снято 2026-08-07): Cursor `.cursor/hooks.json`
(`sessionStart`, `beforeSubmitPrompt`, `preCompact`, `stop`) · Codex `.codex/hooks.json`
(`SessionStart`, `UserPromptSubmit`, `Stop`, `PreCompact`/`PostCompact`) · Copilot agent hooks
(`userPromptSubmitted`, `preToolUse`, `postToolUse`; аналога `sessionStart` не подтверждено) ·
Windsurf pre/post-action (вторичный источник) · Cline lifecycle-хуки (вторичный источник) ·
Zoo Code — хуков нет, честный фолбэк на markdown-ритуал.

## Граница и цена

Заявленный порядок O1 (`researches/19` §1.2) — «Claude Code (референс) → остальные по мере
верификации их контрактов ЖИВОЙ докой; кандидаты пула, не скоуп 2.2». Цена системы — один
живой fetch её доки + образец + строка свода; риск — образец, написанный по вторичному
источнику, выглядит поставкой, а работает гипотезой (класс EXP-0036: карта старше дня — уже
гипотеза). Поэтому правило реализации: **система без живого fetch контракта в день письма
образца в модуль не едет** — она остаётся строкой «не верифицирована» в README.
