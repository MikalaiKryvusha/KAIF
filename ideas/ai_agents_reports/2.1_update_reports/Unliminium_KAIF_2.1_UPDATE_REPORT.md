## 2. Грабли

Каждая — с дословной ошибкой (цитата вывода/файла) и способом воспроизвести.

### Г1. Для локализованного развёртывания задание не самодостаточно: 24 файла без единого диффа

**Дословно из `KAIF_UPDATE_TASK.md`:**

> **merge-diverged** — These framework files carry LOCAL edits and were NOT overwritten — merge the new
> template's changes into each by hand (see the template news below): AGENT_GUIDE.md (translated
> wholesale — its headings are in the owner's language, a by-signature merge is impossible; fold the
> news in by hand) · PHILOSOPHY.md (…) · … 24 файла …

«The template news below» — это маркетинговый список релиза («Release codename for this version: KAIF
2.1 — Strong KAIF» и т. п.). **Ни одного диффа для этих 24 файлов задание не даёт.** Список новостей
не говорит ни где норма живёт в шаблоне, ни какой текст добавлен, ни в какую секцию его класть.

Проверил охват списка: по настоящему диффу шаблонов в него **не попали** как минимум — контракт
`COMMIT_COMMAND` с обязательным слотом сообщения (`framework/_intro.md`), новый раздел «The taste class»
в `TESTING_FRAMEWORK.md`, новый пункт-симптом в `BUG_FIXING_FRAMEWORK.md`, абзац «Taste-class homework»
в `readmes/homeworks.md`, две новые секции и строка фрода в шаблоне сферы. Пять норм, которые агент,
доверившийся заданию, потерял бы молча.

**Обидно то, что данные у машинерии на руках:** она сама пишет
`⟳ synthetic baseline: v1.6's own KAIF-CORE-BUNDLE.md (52 templates) — the legacy path is no longer
blind`. То есть шаблоны 1.6 и 2.1 лежат рядом в момент прохода. Более того, ядро УМЕЕТ строить дифф
модулей (`lineDiff(modText(dm), newText)`, `kaif-core.mjs:661`) — но для файла, попавшего в
`translatedWholesale`, разбор модулей прекращается раньше (`return { translatedWholesale: true }`,
строка 632), и дифф не строится вообще.

**Воспроизведение:** развернуть KAIF, перевести заголовки руководящих документов на любой не-английский
язык, обновиться на версию выше → в `KAIF_UPDATE_TASK.md` для этих файлов будет текстовый список без
диффов.

**Что пришлось сделать вместо:** `git clone https://github.com/MikalaiKryvusha/KAIF && git diff v1.6 v2.1
-- framework/` и вливать по нему. Это единственный надёжный путь, и он не описан ни в задании, ни в
скилле `/kaif-update` (там про `diff --source` и песочницу — оба про ДРУГОЕ: про предсказание прохода,
не про содержание новинок).

### Г2. `merge-modules` требует слить 5 модулей, которых апстрим не менял

**Дословно из задания (повторяется для `plans/README.md`, `ideas/README.md`, `bugs/README.md`,
`researches/README.md`, `homeworks/README.md`, `.claude/skills/kaif-remove/SKILL.md`):**

> **module:** `# `plans/` — детальные пошаговые планы` — an H1 module may not be inserted next to an
> existing H1 — placeholder-signature drift, reconcile by hand (bug 26)

Задание предлагает вставить в файл H1-заголовок английского шаблона (в диффе он идёт как `+`), хотя у
файла уже есть свой — переведённый. **Настоящая дельта апстрима по этим файлам между 1.6 и 2.1:**

```
$ git diff --stat v1.6 v2.1 -- framework/readmes/
 framework/readmes/homeworks.md | 7 +++++++
 1 file changed, 7 insertions(+)
```

То есть из пяти README апстрим тронул **один**. Четыре модуля из семи в пункте `merge-modules` —
ложные срабатывания: они попали туда не потому, что апстрим что-то изменил, а потому, что сигнатура
переведена. Агент обязан вручную сверить пять диффов, четыре из которых пусты по смыслу.

**Воспроизведение:** перевести H1 в `bugs/README.md`, обновиться → модуль попадёт в `merge-modules` при
нулевой дельте апстрима.

**Лекарство (дешёвое):** прежде чем класть модуль в задание, сравнить его текст в шаблоне СТАРОЙ версии
и НОВОЙ. Совпали побайтно — модуль не изменился, в задание не идёт, какой бы ни была сигнатура на диске.
Базлайн для этого уже скачан (см. Г1).

### Г3. `diff <файл>` и `modules <файл>` молча игнорируют аргумент

`KAIF_UPDATE_TASK.md` рекламирует: «`diff` (audit + per-module preview)». Справочник §10.7: «`diff`
(audit: protected vs replace-eligible; `--source`: per-module preview against another version)».

```
$ node .kaif/kaif-core.mjs diff PHILOSOPHY.md | head -2
diff (audit vs deployed templates): 48 diverged file(s) — protected from replacement; 17 match …
  ≠ AGENT_GUIDE.md
$ node .kaif/kaif-core.mjs modules PHILOSOPHY.md | grep -c '"signature"'
643
```

Аргумент не отвергается и не применяется — он **проглатывается**. `modules PHILOSOPHY.md` печатает
дамп всех 643 модулей развёртывания; `diff PHILOSOPHY.md` — полный аудит. Пользователь получает
правдоподобный, но не тот вывод, что просил, — и никакого сигнала об этом. Это ровно тот класс, который
KAIF учит ловить: зелёный ответ не на заданный вопрос.

**Воспроизведение:** любая из двух команд с именем файла.
**Лекарство:** либо фильтровать по аргументу, либо `✖ unknown argument` — но не молчать.

### Г5. Скан `stale-claims` бьёт по дословным цитатам владельца и по журналу решений

В пункте `stale-claims` среди 20 строк:

> · AGENT_GUIDE.md:129 — > работаем на русском языке. то, что каиф 1.6 требует инглиш — игнорируем, главное взять из него
> · MASTER_PLAN.md:151 — | 2026-07-26 | **Рабочий язык проекта — русский ВЕЗДЕ, включая внутренние документы агента и скиллы;
> · MASTER_PLAN.md:152 — | 2026-07-25 | **KAIF обновлён 1.4 → 1.6** (Homeostatic KAIF) уважительной миграцией;

Первая — **дословная цитата владельца** внутри блока `>`. Править её нельзя: канон проекта (и канон
KAIF) требует, чтобы слово владельца оставалось неприкосновенным. Вторая и третья — строки **журнала
решений**, то есть той же летописи, ради которой 2.1 вводит `PROJECT_HISTORY.md`; релиз заявляет «the
stale-claims scan skips chronicles», но знает только один файл-летопись, а журнал решений живёт внутри
`MASTER_PLAN.md`.

Итог: из 20 строк три требуют не правки, а объяснения, почему они правильны. Задание допускает такой
исход («update each or state why it is correct»), но чекпоинт при этом не спрашивает обоснований —
проверить, что агент не «починил» цитату владельца, машинерия не может.

**Воспроизведение:** процитировать владельца с упоминанием текущей версии в блоке `>`, обновиться →
цитата попадёт в `stale-claims`.
**Лекарство:** пропускать строки внутри blockquote и строки таблиц с датой в первой колонке (журнал
решений/ADR — тот же класс, что летопись).

### Г7. `kaif-provenance.mjs check` падает на файле, который породила сама машинерия

```
$ node .kaif/tools/kaif-provenance.mjs check
✖ KAIF_UPDATE_TASK.md carries 1 provenance mark block(s) but is NOT a declared canon artifact —

```

Причина — строка 50 самого `KAIF_UPDATE_TASK.md`, где описывается новинка 2.0:

в этом описании маркер и объявляет нарушением.

канона.

**Лекарство:** исключить из скана транзиенты машинерии (`KAIF_UPDATE_TASK.md`,

### Г8. `kaif-provenance.mjs` слеп к локализованным маркерам — и молчит зелёным

```
$ node .kaif/tools/kaif-provenance.mjs report
✅ no AI text awaits acceptance in the declared canon
```

При этом в объявленном каноне (`rules/`) прямо сейчас лежат **51 блок `[ИИ]` и 40 блоков `[ИИ-ред]`**,
ожидающих приёмки автора, а наш собственный страж на той же книге говорит:

```
$ node tools/rules-provenance.mjs --check
| ИТОГО | 1537 | 1149 | 88 | 80% |
--check: весь текст ИИ помечен, маркеры парные. OK
```

Модуль знает только английские `[AI]`/`[AI-ed]`. KAIF разворачивается на девяти языках и в 2.1 сам
чинит i18n-пути в машинерии — но провенанс-гейт при локализации маркеров отвечает «чисто» вместо
«я ничего не понял». **Это худший класс: ложное зелено, а не отказ.** Проект, который поверит этому
ответу, отгрузит непринятый ИИ-текст как канон владельца.

**Воспроизведение:** локализовать маркеры (`[ИИ]`), объявить `canonArtifacts`, запустить `report`.
**Лекарство:** читать пару маркеров из маркера развёртывания (`"provenanceMarks": ["ИИ","ИИ-ред"]`),
а при отсутствии совпадений в объявленном каноне — предупреждать, а не зеленеть.

### Г10. Обещанного «warning-mode guard» на длину STATUS.md в коде нет

Релиз 2.1: «STATUS.md is now the living SUMMARY of the present (**~200-line soft target, warning-mode
guard**)».

```
$ grep -n "softTarget\|statusLines\|200" .kaif/kaif-core.mjs   # пусто
$ grep -rn "STATUS.md" .kaif/kaif-core.mjs
78:  const OWNER_SEEDED = ['GOAL.md', 'STATUS.md', 'PROJECT_HISTORY.md', …
310:  '`STATUS.md` (current state); …
440:  if (p === 'STATUS.md' && /предыдущ|previous/i.test(lines[i])) continue;   // history, not a claim
```

Единственный «guard» — фраза в шаблоне `STATUS.md`. Наш файл разросся до **1 647 строк**, и ни `check`,

мягкой цели ~200 — пора на бонсай-стрижку (/end-chat)`. Предупреждение, не отказ, — ровно как обещано.

### Г11. `update-verify` для локализованного развёртывания красный по построению

Первый запуск приёмки:

```
⚠ promised upstream line not found on disk (unmerged?): .claude/skills/pause/SKILL.md ::
  A temporary pause, not a goodbye: the human intends to come back to THIS chat
⚠ 57 upstream line(s) from the module diffs are absent on disk — merge them or state why in the judge verdict
✖ placeholder <BUILD_COMMAND> still in .kaif/spheres/programming.md
✖ update-verify FAILED: 2 issues — finish them and re-run
```

Два независимых повода, оба характерны именно для i18n:

1. **57 «непришедших» строк апстрима** — это АНГЛИЙСКИЕ строки шаблонов, которые мы намеренно
   перевели. Верификатор ищет их дословно на диске; в переведённом развёртывании они не могут там
   быть никогда. Формулировка «merge them or state why in the judge verdict» спасает (объяснение в
   вердикте снимает вопрос), но по умолчанию приёмка выглядит красной у всякого, кто перевёл
   развёртывание, — и агент, не разобравшись, может «починить» это, вклеив английский текст в русский
   документ. Та же природа у блока `MODULE ABSENT: AGENT_GUIDE.md :: ### Planning discipline …
   (static)` — машинерия сама подписывает его «usually means its signature drifted — see bug 26».
2. **`<BUILD_COMMAND>` в `.kaif/spheres/programming.md`** — плейсхолдер в библиотеке **чужой сферы**
   (наша — `game-design`), пришедший ещё из 1.6 и переживший обновление. Он **блокировал приёмку**
   обновления, к которому не имеет отношения. Пришлось править файл чужой сферы, чтобы закрыть проход.

**Воспроизведение:** перевести любой скилл, обновиться, запустить `update-verify`.
**Лекарство:** при `"language" != "en"` проверять не дословное присутствие строк, а факт, что модуль
на диске непуст и его сигнатура известна; плейсхолдеры искать только в файлах, относящихся к
объявленной сфере проекта.

### Г12. Вердикт судьи принимается ТОЛЬКО аргументом командной строки

```
$ grep -n "verdict" .kaif/kaif-core.mjs
1528: if (!v) die('checkpoint judge requires --verdict "<VERDICT: one line of evidence>" …')
```

Файлового варианта (`--verdict-file`) нет. Для не-английского проекта это значит: длинный вердикт с
кириллицей, кавычками и тире едет **через аргумент командной строки** — ровно то, что KAIF 2.1 сам
запретил в этом же релизе (`AGENT_GUIDE` → «TEXT TRAVELS THROUGH FILES, NEVER THROUGH COMMAND-LINE
ARGUMENTS», четыре лица класса, лицо 1 — «тихая моджибака»). У нас в Git Bash + Node 24 кириллица
прошла целой (проверено чтением записанной строки назад), но норму писали не для везучих: в
PowerShell 5.1 или при `python -c`-подобной обвязке тот же вызов даёт порчу с зелёным кодом выхода.
Фреймворк требует от проектов дисциплины, которой не следует в собственном API.
**Лекарство:** `--verdict-file <path>` рядом с `--verdict`.

### Г13. Мелочи среды

- Каждый файл, записанный машинерией, вызывает `warning: LF will be replaced by CRLF` на Windows.
  Не ломает ничего (git нормализует), но 33 предупреждения в выводе `git diff` — шум, в котором тонет
  полезное. `.gitattributes` с `*.md text` в развёртывании снял бы вопрос.
- `KAIF_UPDATE_TASK.md` попадает в `.gitignore` только если проект внёс его сам (мы внесли при 1.6).
  Ignore-first в 2.1 добавляет `KAIF_ADAPTATION_TASK.md` и `KAIF_UPDATE_TASK.superseded.md`, но не
  сам `KAIF_UPDATE_TASK.md` — на чистом развёртывании он оказался бы кандидатом в коммит.
- Ignore-first дописывает строки в **конец** `.gitignore`, игнорируя существующую секционную
  структуру (у нас уже была секция «Транзиенты установщика KAIF» — им место в ней). Плюс
  `.kaif/heartbeat.log` избыточен, если в файле есть `*.log`. Мы перенесли строки в секцию руками.

## 2.12. Что нашёл судейский проход на НАШЕЙ же работе

Пять независимых судей (миграция летописи · сохранность местных адаптаций · полнота новинок · факты и
ссылки · механическая целостность) вынесли по вердикту с уликами. Ценно разработчику как карта того,
куда промахивается агент, обновляющий локализованный проект:

- **major — правка авторского текста.** Вливая новую норму «пишешь в артефакт владельца», агент
  ЗАМЕНИЛ собой пункт 19 чек-листа, написанный **лично владельцем** (коммит `64172b1`, тело коммита
  прямо говорит «его шаг 19»). Смысл был сохранён и расширен, но авторская строка исчезла — против
  канона «оригиналы автора неприкосновенны». Восстановлена побайтно (`diff` с версией из коммита
  владельца пуст), новая норма стала отдельным пунктом 20. **Урок для фреймворка:** задание на
  вливание новинок должно предупреждать, что чек-листы и им подобные списки могут содержать строки
  владельца, а не только шаблонные.
- **major — висячая ссылка.** Три канон-документа заявили существующим отчёт, который на момент снятия
  вердикта ещё не был написан. Судьи поймали до коммита.
- **major — ложная отметка о выполнении.** Чекпоинт `placeholders` был отмечен закрытым, хотя
  `update-verify` на том же дереве падал именно на плейсхолдере (Г11). Зелень `check` и `kaif:check`
  провал приёмки **не покрывает** — три проверки отвечают на разные вопросы, и отчёт, опирающийся
  только на первые две, вводит в заблуждение.
- **minor ×12** — среди них: в свежесобранный список открытых багов попал закрытый (`bugs/30_DONE`) и
  не попал открытый (`bugs/20`); из таблицы фаз выпал `TESTING_FRAMEWORK.md`; ошибка на единицу в
  числе строк исходного STATUS (1648 против 1647 по `wc -l`); строка `/help-kaif`, учащая «не называй
  чисел по памяти», сама несла протухшее число; контракт `<msg>` не был отражён в разделе «Коммиты»,
  хотя два скилла на него ссылались; потеряна замыкающая инструкция четвёртого лица класса
  «текст через CLI» («запиши, из какого шелла идёт сборка»). Все исправлены.

Общее: **ни одна находка не касалась механической части 2.1** — все до одной родились в когнитивной
части, то есть там, где машинерия отдала работу агенту.

## 3. Что из новинок 2.1 реально потрогано и как себя повело

### 3.1 Работает и заметно лучше прежнего

- **`route: legacy-bootstrap`** — обновление через тонкий `KAIF.md` вместо `kaif:update` распозналось
  правильно и прошло как обновление, а не переустановка: `⟳ existing KAIF 1.6 detected`. Ни один
  русский документ не перезаписан, содержательные артефакты (`rules/`, `bugs/`, `ideas/`, `interviews/`,
  `researches/`, `homeworks/`, `plans/`, `assets/`, `drafts/`, `sheet/`, ядро игры `tools/engine/`) —
  **ноль изменений** (`git status --short` по ним пуст; единственное исключение — `homeworks/README.md`,
  куда влита новинка 2.1 про класс вкуса).
- **Сеть «translated wholesale» (bug 20 / ndim K1)** — главная защита i18n-развёртывания. Сработала на
  всех 24 файлах: ни один русский документ не удвоен английским шаблоном. В коде честно описан полевой
  случай, ради которого она появилась («field: 25 files, +6534 lines»). У нас — 0 таких строк.
  **Это лучшая часть релиза для нашего класса проектов.** Претензия только к тому, что защита не
  сопровождается диффом (Г1).
- **Синтетический базлайн для legacy-манифеста** — `52 templates` скачаны и использованы;
  классификация «7 заменено · 7 слито · 13 добавлено · 44 сохранено» на нашем дереве оказалась верной
  при построчной проверке.
- **Чекпоинты, исполняющие свои проверки** — подтверждено:
  `node .kaif/kaif-core.mjs checkpoint recheck` → `✔ check ran green (executed by the checkpoint
  itself)`. Раньше чекпоинт был честным словом агента; теперь — фактом.
- **`adopt-current`** — после ручной миграции вернул механический путь:
  `✔ adopt-current: snapshot rebuilt — 17 newly adopted path(s) … The mechanical update path is live
  again`. После него `diff --source <релиз 2.1>` отвечает
  `0 file(s) carry upstream static-module changes; 63 — nothing to do` — то есть машинерия снова
  считает дерево согласованным с апстримом.
- **Квитанция `.kaif/last-update.json` + `history` в маркере** — обновление впервые оставляет
  доказательство, переживающее самоочистку. Полезно ровно в таких отчётах.
- **`diff --source <url>`** — единственная команда, которая делает то, что обещает: сравнение с другой
  версией. Работает (см. выше). Без `--source` — просто аудит (Г3).

### 3.2 Новые сущности, которые пришлось адаптировать

- **`PROJECT_HISTORY.md`** — идея верная: наш `STATUS.md` в 1 647 строк был именно «бездной, а не
  сводкой». Миграция описана как «agent work, not machinery» — так и вышло: машинерия дала пустой
  шаблон, всё остальное сделал агент. Мы мигрировали скриптом с ассертами дословности (перенос, не
  переписка) — **0 потерянных строк**, STATUS сократился до 253. Замечание: у миграции нет ни
  помощника, ни проверки результата (Г10); правило «переносить дословно» нечем подтвердить, кроме
  собственной дисциплины агента.
- **8 новых скиллов** — переведены на русский (713 строк). Из них практически ценны для нас
  `/plan-task`+`/plan-epic` (лестница планирования легла на наш канон «разведка до кода»),
  `/end-chat` (забрал ритуал закрытия у `/pause`), `/guarded-loop`. `/owner-reviews` описывает контур,
  которого у нас нет, — оставлен как опциональный.
- **`/owner-voice` и `/derive-styleguide`** — забавная петля: методология родилась в этом проекте
  (`researches/13`, `researches/14`), ушла в апстрим и вернулась скиллами. Шаблон это честно называет
  («field-proven Unliminium»). Замечание по существу: `/derive-styleguide` предлагает «взять
  объявленные `canonArtifacts` из `.kaif/kaif.json`», но развёртывание такого ключа не создаёт — до
  нашей правки его в маркере не было, и инструкция была мёртвой. Ключ стоит либо заводить пустым при
  развёртывании, либо не ссылаться на него как на существующий.
- **`.kaif/KAIF_REFERENCE.md`** — 361 строка, `/help-kaif` теперь обязан цитировать его секции. Полезно;
  претензий нет.
- **Секции шаблона сферы «Owner's voice» и «Craft recipes» + строка фрода «Voice without a corpus»** —
  апстрим не может внести их в нашу сферу (`game-design` заведена нами, апстрим её не знает), поэтому
  вносили руками. Задание об этом не напоминает: пункт `review-news` формулирует общо («apply anything
  relevant to files this update could not touch mechanically»), а конкретно про сферы не говорит.
  Проект с собственной сферой пропустит эти секции с высокой вероятностью.

### 3.3 Опциональные модули — не подключены, и вот почему

## 4. Пожелания к 2.2

По убыванию ценности для локализованных развёртываний.

1. **Дать i18n-файлам настоящий дифф шаблонов в задании** (лечит Г1 — самое дорогое). Данные уже
   скачаны: синтетический базлайн старой версии + бандл новой. Достаточно для каждого
   `translatedWholesale`-файла приложить `diff <шаблон старой версии> → <шаблон новой>` — агент
   переведёт и вложит сам. Пока этого нет, честнее прямо написать в задании: *«для этих файлов возьми
   `git diff vСТАРАЯ vНОВАЯ -- framework/` в клоне origin»* — одна строка, снимающая класс молчаливых
   потерь.
2. **Не класть в задание модули, которых апстрим не менял** (Г2): сравнивать текст модуля между
   версиями шаблона, а не только сигнатуру с диском.
3. **Починить провенанс-модуль для локализаций** (Г8) — читать пару маркеров из маркера развёртывания;
   отсутствие совпадений в объявленном каноне = предупреждение, а не «✅ чисто». И исключить транзиенты
   машинерии из скана (Г7).
4. **Ненастроенный `selftest` не должен выходить нулём** (Г9).
5. **Механизировать собственную норму про STATUS** (Г10): одна строка предупреждения в `check()`. Пока
   её нет, «warning-mode guard» в заметках релиза — обещание, которого в коде нет; для фреймворка,
   который учит «два удара → механизм», это заметно.
6. **`stale-claims`: пропускать блоки цитат и таблицы-журналы решений** (Г5). Формулировка «update each
   or state why it is correct» хороша, но чекпоинт не требует обоснований — стоит требовать: строка
   осталась → одна строка почему.
7. **Аргументы команд: применять или отвергать, но не глотать** (Г3). И `help` как команда (Г4).
8. **Сказать в задании про сферы и обвязку.** Отдельными пунктами: «в шаблон сферы добавлены секции X, Y
   — перенеси в свою сферу, если она заведена локально» и «если у проекта есть собственный валидатор
   каркаса, обнови его списки документов и скиллов» (у нас `tools/kaif.mjs` знал 12 документов и 26
   скиллов и молча проверял бы устаревший каркас — это уже наш второй такой случай, в 1.6 было так же).
9. **`.gitignore`: добавить сам `KAIF_UPDATE_TASK.md`** в ignore-first (Г13), раз уж туда добавлены его
   `.superseded`-вариант и heartbeat; и класть строки в существующую секцию, если она есть.
10. **`update-verify` не должен быть красным на переведённом развёртывании по построению** (Г11):
    для `"language" != "en"` проверять не дословное присутствие английских строк, а факт непустого
    модуля; плейсхолдеры искать только в файлах объявленной сферы.
11. **`--verdict-file` рядом с `--verdict`** (Г12) — собственная норма «текст едет через файлы»
    должна распространяться на API самой машинерии.
