# Отчёт: обновление KAIF 1.4 → 1.6 в реальном проекте (для агента-разработчика KAIF)

**Дата:** 2026-07-27 · **Проект:** AI Boys / AI Girls — Prompt Modding (внутренний, Nogamelabs)
**Профиль установки:** `tracking: anonymous` · `language: ru` · `sphere: prompt-engineering` ·
`agents: claude-code, codex` · агент обновления: Claude Code (Opus 5, 1M)
**Итог:** обновление **успешно**, `update-verify` пройден, дерево самоочищено. Отчёт — о том, где было
трение, и что стоит поправить во фреймворке.

> Аудитория — агент, который разрабатывает KAIF. Пишу как отчёт разведки: сначала факты и воспроизведение,
> потом предложение. Ничего не приукрашиваю: сам факт «обновилось» не отменяет того, что примерно 85% работы
> оказалось когнитивной, а не механической.

## 1. Как шло обновление (факты)

Анонимная установка **не отслеживает origin**, поэтому `cmdUpdate()` для неё закрыт by design
(`die('anonymous install tracks no origin — update by dropping a fresh thin KAIF.md…')`). Путь был такой:

1. Владелец положил в корень тонкий `KAIF.md` 1.6 → агент написал `KAIF-LOADER.mjs` дословно → запуск с
   `--lang ru --mode anonymous --agents claude-code,codex`.
2. Загрузчик выкачал и сверил sha256 (`KAIF-CORE.mjs`, `KAIF-CORE-BUNDLE.md`), манифест `1.6 / 2026-07-24`.
3. `cmdInstall()` увидел маркер 1.4 и корректно пошёл режимом **UPDATE**: `⟳ existing KAIF 1.4 detected`.
   **22 файла сохранены** как есть, добавлены `TESTING_FRAMEWORK.md`, 4 навыка `fable-*` (+3 reference),
   `.kaif/spheres/` (6 файлов), 22 копии навыков в `.agents/skills/`. 4 origin-навыка пропущены по анонимности.
4. Поля маркера уровня владельца выжили (`tracking`, `sphere`, `language`, `productLanguage`); вперёд ушли
   `version`, `released`, `agents`.
5. Когнитивная часть (моя): мердж новостей 1.5/1.6 в русскую обвязку, гигиена legacy-раскладки, авторская
   библиотека сферы, проход `/fable-judge`, финальный гейт.
6. Финал: `check` → 48 файлов + 24 артефакта агент-систем зелёные; `update-verify` → ресинк 26 копий,
   удаление транзитных файлов, снятие хендлов `kaif:*`.

**Что в проекте изменилось по итогу:** новости вмерджены в `AGENT_GUIDE.md` (чек-лист шаги 7/9/13/18, роутер,
секции «Артефакты разведки», «Дисциплина исполнения», «Языки», гигиена git + постоянная авторизация,
обоснование правок тестов, «Решения, принятые без владельца», волна багов = инцидент процесса, гейт записи
в канон, метки происхождения, детерминизм), `PHILOSOPHY.md` (+2 принципа), `BUG_FIXING_FRAMEWORK.md`
(гейт намерения, близнецы, класс вместо экземпляра, сторожа, верификация находок), `TESTING_FRAMEWORK.md`
(переведён на русский и адаптирован под LLM-сферу), 10 навыков (судья в 3 циклах и `/release`, чек-лист
выкатки поверх работающей системы, разведка в `/bug-research`, цитирование опыта, секция решений в
`/report-bug` и `/check-backlog`, актуализация `/kaif-version` и `/kaif-remove` под раскладку 1.6). Удалён
тул 1.4 `kaif/kaif.mjs` и хендлы `kaif:*`. Дописана библиотека сферы `.kaif/spheres/prompt-engineering.md`.

## 2. Что во фреймворке сработало хорошо (не менять)

- **Legacy-детект по маркеру, а не по версии.** `if (okOnDisk(KAIF_JSON))` → режим UPDATE спас обвязку:
  22 адаптированных русских файла остались нетронутыми. Комментарий про ДЗ-03 («version EQUALITY does not
  opt out») — правильный вывод, видно, что он выстрадан.
- **`writeIfNew` + провенанс `kept`.** Ни один файл владельца не был перезаписан: проверил побайтово
  (`diff -rq` против бэкапа, снятого до обновления) — `GOAL.md`, `STATUS.md`, `MASTER_PLAN.md`,
  `EXPERIENCE.md`, обе карты, `bugs/`, `ideas/`, `plans/`, `interviews/`, `researches/`, `homeworks/`,
  `benchmark/`, `ai_boys_api/` — **идентичны**.
- **Команды `checkpoint` / `sphere` вместо ручной правки файлов.** Отличное решение: агент не трогает
  задачный файл и маркер руками. Обоснование в комментариях («weak models corrupt files…») бьёт в цель.
- **Гейт sha256 в загрузчике** с внятным сообщением про CDN-скос и подсказкой пинить коммит.
- **Содержание новостей 1.5/1.6 сильное.** `TESTING_FRAMEWORK.md` + маркеры `[NOT-TESTED]`/`[TESTED]`,
  обязательный проход судьи, гейт намерения и близнецы, дисциплина в библиотеках сфер — это то, чего в 1.4
  болезненно не хватало. Судья в этом же обновлении нашёл два моих собственных дефекта (см. §4, D3).

## 3. Дефекты фреймворка (с воспроизведением)

### D1 · `check` игнорирует `tracking: "anonymous"` из маркера — 7 фантомных пропаж
**Воспроизведение:** на анонимной установке `node .kaif/kaif-core.mjs check` →
```
✖ MISSING or empty: .claude/skills/kaif-fork/SKILL.md
✖ MISSING or empty: .claude/skills/kaif-switch-origin/SKILL.md
✖ MISSING or empty: .claude/skills/kaif-update/SKILL.md
✖ MISSING or empty: .agents/skills/{kaif-fork,kaif-switch-origin,kaif-update,kaif-version}/SKILL.md
✖ INCOMPLETE: 7 artifacts missing   (exit 1)
```
С `--mode anonymous` — `✅ manifest satisfied`. Причина: `MODE`/`ANON` берутся только из CLI, тогда как для
`AGENTS` в `cmdCheck` уже сделано «читать из маркера». Итог: `npm run kaif:check` (в неанонимных установках)
и любой ручной `check` на анонимной врут, а пункт `recheck` апдейт-таска выглядит как провал апдейта.
**Фикс:** в `cmdCheck` (и вообще в начале любой команды, кроме install) поднимать `tracking` из
`.kaif/kaif.json` → `ANON`; сделать `ANON` не `const`, а производным `let`, как `LANG`/`AGENTS`.
Стоимость — 3 строки, эффект — снятие ложной тревоги.

### D2 · Гейт анонимности ловит ВЛАДЕЛЬЦА, а не автора (замкнутый круг)
`AUTHOR_TOKENS` содержит `Kryvusha`/`Кривуша`. Владелец этого проекта — Николай Кривуша, и его имя
законно стоит в `AGENT_GUIDE.md` (строка «Владелец»), `GOAL.md` (текст видения) и `researches/01_*`.
`update-verify` падал:
```
✖ anonymity leak: AGENT_GUIDE.md → "Кривуша"
✖ anonymity leak: GOAL.md → "Кривуша"
✖ anonymity leak: researches/01_kaif_deployment_notes.md → "Кривуша"
```
**Замкнутый круг:** `detectValues()` подставляет `<AUTHOR>` из `git config user.name` — то есть машинерия
САМА впишет имя владельца в обвязку, а затем сама же на нём и упадёт. Для любого владельца, чья фамилия
совпадает с токеном (а для автора фреймворка, разворачивающего KAIF в своих же рабочих проектах, это
гарантированный случай) анонимная установка недостижима без правки текста владельца.
**Как разрешили здесь:** спросил владельца (это его текст, не моё решение) — он выбрал заменить на
«Николай К.» в трёх файлах. Гейт прошёл.
**Фикс (по возрастанию радикальности):** (а) исключать из `AUTHOR_TOKENS` пересечение с
`git config user.name` / значением `<AUTHOR>`; (б) в анонимном режиме не подставлять `<AUTHOR>` вовсе
(писать «owner» / оставлять пустым — анонимность by design же); (в) в тексте ошибки гейта добавить строку
«если это имя владельца проекта, а не автора фреймворка — см. …», чтобы агент не начал молча править GOAL.md.

### D3 · Плейсхолдеры не проверяются в производных копиях (`.agents/`, `.grok/`, `.cline/`, `.roo/`)
`scanPlaceholders()` сканирует только `AGENT_GUIDE.md` и `.claude/skills/*/SKILL.md`. Факт после
механического прогона: **4 файла в `.agents/skills/`** (`pause`, `autoloop`, `dayloop`, `nightloop`) несли
`<BUILD_COMMAND>`, `<TEST_HARNESS>`, `<COMMIT_COMMAND>`, `<YOUR AGENT/MODEL>` — и гейт бы этого не увидел.
Спасает только `resyncCopies()`, который затирает копии каноном; то есть **качество копий держится на
побочном эффекте, а не на проверке** — а на legacy-апдейте, где канон остался 1.4-русским, копии до ресинка
несут ещё и другой язык. Нашёл это проход `/fable-judge`, а не гейт.
**Фикс:** после ресинка утверждать `копия == канон` побайтово для всех систем из маркера (одна строка `cmp`
на файл) — это заодно и есть проверка плейсхолдеров, и проверка самого ресинка.

### D4 · templateNotes в бандле 1.6 описывают 1.5 (и подписаны кодовым именем 1.5)
`KAIF_UPDATE_TASK.md` → «What's new in the templates» заканчивается строкой
`- Release codename for this version: KAIF 1.5 — Tested KAIF`, заголовки `KAIF-CORE.mjs` и
`KAIF-LOADER.mjs` тоже говорят `(KAIF 1.5 — Tested KAIF; thin-install architecture)`, при манифесте
`1.6 / 2026-07-24`. При этом в вендоренном `fable-judge` явно написано: «the guardrail hunts block in
step 4 (**added in KAIF 1.6**, plans/16)» — то есть у 1.6 есть собственные новости, которых в
`templateNotes` нет вообще.
**Последствие для агента-обновляльщика:** единственный машинный источник «что нового» описывает прошлую
версию, поэтому новости 1.6 приходится добывать диффом вручную и на глаз отличать «новость» от «перевода».
**Фикс:** обновлять `templateNotes`/кодовое имя/заголовки на релизе (кандидат в чек-лист `/release` KAIF:
«codename и templateNotes соответствуют версии манифеста» — механически проверяемо).

### D5 · Апдейт-таск для legacy не говорит, ЧТО и ГДЕ смотреть
Для legacy зовётся `writeUpdateTask([], meta, …)` — список `diverged` **пустой**, потому что снимков sha
у pre-1.5 проекта нет. Текст «every kept framework file may carry local edits — merge the news pointwise»
формально верен, но операционно пуст: ни списка сохранённых файлов, ни того, что изменилось в каждом.
Реальная работа, которую пришлось выполнить руками: написать свой распаковщик бандла (тот же парсер
`FILE:`-блоков + применение `templates/languages/ru/`), развернуть 53 шаблона в temp, продиффить
**12 доков + 22 навыка**, и по каждому решить «это новость или это просто английский оригинал нашего
русского файла». Это и есть те самые 85% времени.
**Фикс (по ценности):** (1) кладите в бандл машиночитаемый по-файловый changelog
`{"AGENT_GUIDE.md": ["+checklist step 7 fable loop", "+section Recon artifacts", …]}` — тогда апдейт-таск
сам напишет адресные пункты вместо общей формулировки; (2) для legacy заполняйте `kept` всеми путями с их
sha, чтобы следующий апдейт стал «умным»; (3) оставляйте распакованные шаблоны в `.kaif/install/templates/`
до `update-verify` — каждый апдейтящий агент всё равно вынужден писать распаковщик, это чистое дублирование.

### D6 · Языковой пакет ru покрывает 8 файлов, а русский проект — весь
Overrides: `GOAL.md`, `KAIF_FRAMEWORK.md`, 6 README директорий. `AGENT_GUIDE`, `PHILOSOPHY`,
`BUG_FIXING_FRAMEWORK`, `TESTING_FRAMEWORK` и все 22 навыка — англ. шаблоны + `Trigger aliases (ru)` к
`description`. Установка 1.4 в этом проекте сделала иначе: перевела обвязку целиком, включая тела навыков.
Поэтому на апдейте шаблон нельзя просто взять — он на другом языке, и каждая версия KAIF будет стоить
проекту «перевести новости». Это цена, о которой стоит сказать вслух.
**Фикс — выбрать позицию и записать её:** либо расширять ru-пакет на ключевые доки/навыки, либо явно
задокументировать «обвязка агента — только английский, локализованы только доки владельца» и предупредить
в апдейт-таске: «если проект локализовал обвязку, новости придётся переносить вручную — см. changelog из
D5». Сейчас позиция не заявлена, и каждый проект решает её заново.

### D7 · Мелочь: маркер накапливает поля разных версий
1.4 писал `agentsSupported`, 1.6 пишет `agents` — после апдейта в `.kaif/kaif.json` лежат оба (следствие
`{...legacyOld}`; для `agent` → `agents` отдельный `delete` есть, для `agentsSupported` — нет). Не вредно,
но маркер со временем станет свалкой. **Фикс:** карта переименований полей при legacy-мердже.

### D8 · Метки происхождения `[AI]…[/AI]` конфликтуют с машинно-потребляемым каноном
В этой сфере канонический артефакт владельца — **строка промпта, уходящая в БД и в LLM**. Метка внутри неё
не «пометка», а порча промпта (модель прочитает `[AI]` как часть инструкции). Пришлось отдельно оговаривать
в `AGENT_GUIDE.md` и в библиотеке сферы: метки живут в документах-кандидатах, а не в отдаваемой строке.
**Фикс:** добавить эту оговорку в шаблон (`AGENT_GUIDE` → write-gate и `_template.md` → носитель метки):
«если артефакт сам является входом для машины (промпт, конфиг, миграция, данные) — носитель метки —
сопровождающий документ, не сам артефакт».

### D9 · Сферы `prompt-engineering` нет в поставке
Маркер этого проекта стоит в `prompt-engineering` с 1.4, а в `.kaif/spheres/` шесть файлов и такой сферы
среди них нет. Написал по `_template.md` (схема хорошая, дисциплина ложится один в один: минимальный набор
доказательств = текущий текст модуля + транскрипт прогона + живой контракт Stage API; проверка наблюдением =
прогон на стенде, а не рассуждение о промпте; таблица подлогов = «заявление без прогона», «мусорный прогон»,
«один прогон как доказательство недетерминированного эффекта»). Файл готов, могу отдать в поставку —
`.kaif/spheres/prompt-engineering.md`, ~90 строк.
**Фикс:** включить сферу в бандл; работа с LLM-промптами — одна из самых естественных сфер для KAIF, и
судя по этому проекту она уже используется.

## 4. Что судья нашёл в моей собственной работе (для калибровки)

Проход `/fable-judge` (обязательный по апдейт-таску) подтвердил все 27 заявленных мерджей грепом по
концепциям и нашёл **два реальных дефекта, которые я иначе бы сдал**:

1. `PROJECT_STRUCTURE_EXTERNAL_MAP.md` продолжал документировать удалённый `kaif/kaif.mjs` (2 строки) —
   висячая ссылка на снесённую машинерию. Починено.
2. Производные копии навыков для Codex не были синхронизированы с каноном (18 расхождений) и 4 из них
   несли плейсхолдеры — см. D3. Починено ресинком, затем гейт сделал то же самое повторно (26 файлов).

Вывод для фреймворка: обязательность судьи оправдана эмпирически — на этом же обновлении он отработал.

## 6. Воспроизводимость этого отчёта

Все числа — из прогонов: лог `install`, `check --mode anonymous` (48+24), `update-verify` (26 копий),
`diff -rq` против бэкапа дерева, снятого до обновления, греп-проверки 27 концепций мерджа. Бандл 1.6
распаковывался локально во временную директорию для диффов (не в проект). Транзитные файлы установщика
удалены самим гейтом; версия читается из `.kaif/kaif.json`.
