# Interview #051 — канонический набор `.claude/skills/` при установке только для Kimi

> Topic: суд версии 2.10 подтвердил, что Kimi-only установка создаёт 37 канонических навыков в `.claude/skills/` и 37 адаптированных копий в
> `.kimi-code/skills/`. Критерий 37 сейчас запрещает любые «другие системные копии», хотя канонический набор нужен машинерии `sync`. Ответ — одна буква.
> Source of the idea: находка A-F1 суда RL1, `reports/KAIF_AUDIT/2026-11-22_rl_court_2.10_registry.md`; `plans/136` критерий 37;
> `framework/adapters/kimi-code.md`; `README.md` §4.1 и §7.2.
> Status: ✅ CLOSED — Q1 = B внесён: канонический набор живёт в `.kaif/skills-canonical/`, посистемные копии ставятся из него; разнос отмечен в `plans/136`.

## Context / what I already found

Независимый судья поставил KAIF в новый проект с единственной системой `kimi-code`. В маркере `.kaif/kaif.json` записан только `kimi-code`.
Фактическое дерево выглядит так:

```text
.claude/skills/       37 канонических SKILL.md — источник для посистемных копий
.kimi-code/skills/    37 адаптированных SKILL.md — читает Kimi Code
CLAUDE.md             отсутствует
.agents/skills/       отсутствует
.grok/ · .cline/ · .roo/ — отсутствуют
```

Канонический набор не является вторым интерфейсом Claude Code: файла `CLAUDE.md` нет. Машинерия `install`, `sync`, `check` и `update-verify`
берёт `.claude/skills/` как единый источник и создаёт из него адаптированные копии для выбранных систем. README описывает ту же архитектуру.
Критерий 37 требует «маркер содержит только `kimi-code`; другие системные копии не созданы». Буквальное прочтение запрещает даже канонический
источник, хотя без него нынешний `sync` не работает.

Судья подтвердил остальное: 37 навыков и 9 reference-файлов на месте, YAML каждого навыка разобран, `check` и `sync` зелёные. Развилка —
разрешить существующую двухслойную архитектуру или перенести канон в новое нейтральное место.

## QUESTIONS

### Q1. Разрешить ли канонический `.claude/skills/` при установке только для Kimi?

**Адресат ответа:** `plans/136` критерий 37 · свод `s01` S15 · README/адаптер при необходимости.

<!-- archaeology: search "kimi|canonic|claud|skill|other|syste" → 862 hits · read: plans/136 criterion 37 · plans/143 KA5 · framework/adapters/kimi-code.md · README §4.1/§7.2 · prior: unrelated — прежние решения принимали канонический набор и посистемные копии, отдельного запрета канонического `.claude/skills/` владелец не давал -->

- **A) (рекомендация `[ИИ]`)** Разрешить `.claude/skills/` как канонический источник. Запретить дополнительные системные зеркала и чужие context-файлы.
  - Ситуация. Владелец устанавливает KAIF только для Kimi Code и открывает дерево нового проекта.
  - Действие. Владелец выбирает A.
  - Результат. Критерий 37 прямо различает канонический источник и посистемные копии: `.claude/skills/` законен, `.kimi-code/skills/` создаётся из него; `CLAUDE.md`, Codex, Grok, Cline и Zoo не создаются. Меняются формулировка критерия и отрицательный assert S15; продуктовая миграция не нужна.
  - Проверка. Свежая Kimi-only установка содержит оба названных набора; S15 отклоняет `CLAUDE.md` и дополнительные зеркала. Цена: в дереве виден каталог `.claude/`, хотя интерфейс Claude Code он не подключает.
- **B)** Перенести канон в новое нейтральное место. При Kimi-only каталог `.claude/skills/` не создавать.
  - Ситуация. Та же установка только для Kimi Code.
  - Действие. Владелец выбирает B.
  - Результат. Канон переезжает, например, в `.kaif/skills-canonical/`; `.claude/skills/` исчезает из Kimi-only дерева. Установка, `sync`, `check`, `update-verify`, обновление существующих проектов и посистемные маршруты получают новый источник. Буквальный запрет критерия сохраняется.
  - Проверка. Нужны миграция машинерии, обновление путей в документах и новые красные контроли для старого и нового источника. Цена: меняется общий архитектурный контраст всех систем, появляется риск регрессии обновлений.

**Answer:** B) — .kaif/skills-canonical/ - сюда переезжает канон набор скилов, из которого они ставятся через адаптер под нужную систему <!-- owner-review: by Mikalai Kryvusha (KOT KRINIK) · 22 ноября 2026, 17:22 (+03:00) -->
