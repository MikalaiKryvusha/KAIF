## Критерии приёмки эпика

1. **Все автоматические пути запрещены.** Scale: число `context.apply_compaction` в одном прогоне. Meter: engine-тест вызывает before-step, after-step и reactive overflow при `[loop_control] auto_compact = false`, затем читает wire и пользовательский результат. Target: **0** compaction во всех трёх путях; overflow даёт видимую ошибку предела контекста, без обрезки истории.
2. **Контрольный прогон доказывает действие выключателя.** Scale: число автоматических compaction при identical fixture. Meter: тот же engine-тест с default/`auto_compact = true`. Target: контроль запускает compaction **≥1**; выключенный режим — **0**.
3. **Kimi-ступени совпадают со словом владельца.** Scale: проценты compaction point. Meter: `context-window.mjs --selftest`, `tools/sandbox/s14-refresh-hooks.mjs`, мутанты Kimi. Target: warn/cut/close/force = **70/75/80/90 %** = **623903/668467/713032/802161** токенов при точке 891289 (минимум для `floor(used / 891289 × 100)` = нужной ступени); значения других агентских систем не меняются.
4. **Soft-entry больше не подавляет force.** Scale: обычные вызовы после достижения force без входа в `end-chat-force`. Meter: воспроизведение живого пути wire 1977–2474 и новый мутант. Target: каждый такой вызов получает код **2**; вход в soft не считается входом в force.
5. **Force-entry не открывает неограниченную работу.** Scale: вызовы вне разрешённого контура эстафеты после входа в force. Meter: deployed-hook прогон с обычными Read/Bash и с операциями STATUS/FAREWELL/git. Target: **100 %** вызовов вне контура отклонены; необходимые операции эстафеты проходят.
6. **Расширение показывает квоты на живой учётной записи.** Scale: наблюдаемые элементы UI. Meter: VS Code с нашей VSIX, managed Kimi provider, снимок и лог без секретов. Target: видны **5h**, **7d или monthly** по данным тарифа, проценты и reset countdown; при ошибке запроса видно unavailable, а не выдуманный ноль.
7. **Свежесть движка сохранена.** Scale: base version и upstream SHA. Meter: manifest нашего форка и `git merge-base`/diff против выбранного upstream. Target: база **не старше установленной у владельца линейки 2.7.2**; из `gxgleo67` перенесён квотный контур, а не старый движок 2.2.0.
8. **Установка самодостаточна и обратима.** Scale: результат чистой установки и отката. Meter: собранная VSIX ставится в отдельный Extension Host без исходного дерева; затем восстанавливается официальное расширение. Target: новая сессия стартует, KAIF hooks работают, откат возвращает официальную сессию без потери проектов.
9. **Живой чат закрывается до compaction.** Scale: порядок событий в wire реального VS Code Extension Host. Meter: тестовая сессия накопленного состояния пересекает close/force на пути пользователя. Target: вызов нужного closing skill и завершающее прощание предшествуют любому compaction; `context.apply_compaction` = **0** после старта приёмки.
10. **Проверка независима.** Scale: вердикт и отчёты. Meter: `/skill:fable-judge` повторяет engine/KAIF гигиену и функциональный VS Code путь. Target: **VERIFIED** либо эпик остаётся открытым с названными незакрытыми сценариями.
11. **Каждый follow-up во время running turn уходит сразу через steer.** Scale: доставка и очередь в реальном Extension Host. Meter: при активном ходе отправить текстовый и media follow-up обычным Enter, затем повторить в момент завершения хода. Target: `SteerInput` предшествует terminal event, новые элементы queue = **0**, содержимое и порядок сохранены; при гонке завершения сообщение запускает новый ход ровно **1** раз; при фактической ошибке текст и media возвращаются в composer, а ошибка видна.
12. **Фон совпадает с тёмной боковой панелью VS Code.** Scale: цвет пустого фона webview и читаемость поверхностей. Meter: наш VSIX в тёмной теме владельца, computed style + снимок рядом с sidebar. Target: body/root используют `var(--vscode-sideBar-background)` с editor fallback, RGB пустого фона равен sidebar **(ΔRGB = 0)**; карточки, поля и текст различимы; владелец принимает снимок глазами.

## Фазы и зависимости

### F1 — R&D: воспроизводимый форк и красные проверки

**Состав:** pinned upstream не старше 2.7.2; изолированный клон нашего форка; baseline build/test; точная карта всех auto paths; красные engine fixtures для off; diff-карта переноса 5h/7d/monthly из `gxgleo67`; карта автоматического steer через существующий `SteerChat`; карта разрешённых операций force-закрытия; способ сборки/установки VSIX и отката.

**Вход:** `researches/51` и этот мета-план существуют; Node/pnpm версии сверены с upstream, не установлены молча.

**Выход:** воспроизводимый чистый baseline; новые проверки красны на названном немодифицированном SHA; план переноса квот не включает multi-account/custom providers без отдельного слова владельца; steer-проверки покрывают порядок, media, queue=0 и гонку завершения; никакие секреты не попадают в логи.

**Почему первая:** без зелёного baseline и красных контролей нельзя отличить наш патч от исходного поведения или случайного отката движка.

### F2 — Два рубежа: engine `auto_compact=false` + исправленный KAIF closure

**Состав:** config schema/plumbing; before/after/overflow gates; видимая overflow error; никакой локальной обрезки; Kimi thresholds 70/75/80/90; soft→force escalation; узкий контур инструментов closing; agent-facing правила мягкого/форс-закрытия; PreCompact как запись инцидента, не ложный veto.

**Вход:** F1 закрыта и принята судьёй; операционный план F2 написан по её урокам.

**Выход:** критерии 1–5 зелёные на исходнике и deployed hook; мутанты возвращают прежний дефект и краснят проверки; KAIF build + полный полигон зелёные; отчёты разделяют гигиену и функциональный прогон.

**Почему вторая:** сначала устраняется потеря контекста; UI-квоты и follow-up UX не должны смешиваться с этим доказательством.

### F3 — Квоты, автоматический steer, VS Code theme background и собранное расширение

**Состав:** перенос managed usage 5h + 7d/monthly, countdown, error/loading states и тестов из `gxgleo67`; удаление click-to-compact из перенесённого ContextRing; автоматический маршрут обычного Enter во время running turn через существующий `SteerChat`, с сохранением порядка/media, rollback composer и одноразовым fallback при гонке; body/root фон из `var(--vscode-sideBar-background)` с editor fallback и различимыми поверхностями; уникальная идентичность нашего extension; pinned base SHA и provenance; повторяемая VSIX; изолированный Extension Host; путь отката.

**Вход:** F2 закрыта; операционный план F3 написан.

**Выход:** критерии 6–8, 11 и 12 зелёные; UI не меняет engine semantics кроме явно принятого маршрута steer; снимки показывают обе квоты, состояние ошибки и совпадающий с VS Code фон; VSIX запускается вне checkout; секреты в отчётах отсутствуют.

**Почему третья:** квоты и follow-up UX строятся на уже проверенном движке, поэтому сбой UI не сможет маскироваться под исправление compaction.

### F4 — Живая приёмка на машине владельца, суд и решение о поставке

**Состав:** установка нашей VSIX в VS Code владельца; новый Extension Host/новая сессия; `--alive`; реальные квоты; автоматический steer и гонка; снимок VS Code dark background; накопленный тестовый контекст; soft→force путь; отсутствие compaction; контрольный официальный путь без изменения данных; полный суд; двуязычное оформление публичного репозитория владельца по выведенному стайлгайду; GitHub Release нашей VSIX по №172; возврат в релизный контур KAIF только после зелёного.

**Вход:** F3 закрыта; владелец доступен для перезагрузки VS Code и визуальной приёмки фона, если автоматический Extension Host не покрывает его накопленный профиль.

**Выход:** критерии 9–12 закрыты; bugs/150 и bugs/151 получают DONE только по живым путям целиком; публичный репозиторий и Release нашего форка опубликованы с проверенной VSIX, EN/RU README и provenance; критерий 38/KA9 остаются переоткрытыми до живого closure; KAIF 2.10 по-прежнему требует отдельного разрешения на публикацию.

**Почему последняя:** прежний ложный DONE возник именно потому, что вход в soft на 87 % был принят за весь путь закрытия.

## Гейты всего эпика

- Ни одна фаза не закрывается по чтению diff: нужен исполненный отчёт `testcases/reports/` и независимый суд.
- Новый страж сначала краснеет на названном upstream SHA или мутанте; `THREAT / PROVED-AGAINST / GAP / ON-REAL-PATH` заполнены.
- `PostCompact` не считается успешным сбросом KAIF: любое автоматическое compaction после старта приёмки = fail.
- Официальное расширение и текущая VSIX владельца не удаляются без снимка версий и проверенного отката.
- Fork/install/public repo/Release выполняются по слову владельца из `researches/51` §1 и §9 и решений №168, №169, №172; публикация KAIF, upstream PR и Marketplace публикация отдельно не авторизованы.
- Дальние фазы не детализируются заранее; план следующей фазы пишется после суда предыдущей.

## Риски

1. **Отключённый overflow recovery приводит к ошибке провайдера на полном окне.** Это принятое следствие запрета compaction; ранний KAIF close обязан срабатывать до него. Проверка: критерии 1, 4, 5, 9; сообщение ошибки не обещает продолжение того же контекста.
2. **Перенос квот из старой копии несовместим со свежим SDK.** Не откатывать движок; адаптировать только view/handler против актуальных типов, гонять unit + Extension Host + живой managed account.
3. **Whitelist force-закрытия либо снова слишком широк, либо блокирует сохранение эстафеты.** Проверить обе стороны на живом trace; запрещённые операции отклоняются, STATUS/FAREWELL и разрешённый git-путь проходят.
4. **Обновление upstream вернёт auto paths или перезапишет патч.** Pinned SHA, маленький набор commits, тест всех auto paths на каждом rebase; без зелёного не устанавливать новую VSIX.

## Решения, принятые без владельца

- База выбрана владельцем: свежий официальный upstream + модули из gxgleo67 (`MASTER_PLAN.md` №169). Прямое использование старой базы отклонено, чтобы не откатывать 2.7.2 до 2.2.0.
- `[ИИ]` Multi-account/custom providers в скоуп не входят: конкретно запрошены пятичасовые окна; лишний auth/UI код увеличивает риск.
- `[ИИ]` Ручной `/compact` может остаться в общем форке для upstream-совместимости, но KAIF обязан блокировать его как рабочий путь; владелец запретил AUTO-compaction и замену закрытия сводкой.
