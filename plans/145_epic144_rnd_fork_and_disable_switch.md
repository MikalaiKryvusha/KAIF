## Критерии приёмки F1

1. **Ситуация.** В отдельном рабочем каталоге закреплён официальный `MoonshotAI/kimi-code` с записанными версией и SHA; рабочая сессия KAIF не используется как сборочный каталог.
   **Действие.** Агент выполняет штатные install/typecheck/test/build команды upstream на немодифицированной базе.
   **Результат.** В отчёте записаны Node, pnpm, версия Kimi, SHA и коды всех команд; baseline сборка создаёт VSIX или точно названо, какой штатный артефакт заменяет её в этой версии.
   **Проверка.** Команды из официального `CONTRIBUTING.md` и `apps/vscode/package.json`; Scale: пройденные baseline шаги; Meter: журнал команд; Target: все обязательные шаги exit 0 до первого продуктового патча.
2. **Ситуация.** Немодифицированный движок имеет before-step, after-step и reactive overflow auto-compaction.
   **Действие.** Агент добавляет только тестовые fixtures для будущего `auto_compact = false` и запускает их на базе без реализации.
   **Результат.** Три названных теста красные по ожидаемой причине: выключатель отсутствует или auto-compaction всё ещё запускается; ручной `/compact` остаётся отдельным контрольным сценарием.
   **Проверка.** `packages/agent-core-v2/test/agent/fullCompaction/`; Scale: независимые автоматические пути; Meter: Vitest + события `compaction.*`; Target: **3/3** новых контроля способны отличить off от on, ни один не проходит случайно.
3. **Ситуация.** `gxgleo67/kimi-code-vscode-fork` содержит квоты и дополнительные удобства на старой базе.
   **Действие.** Агент составляет матрицу переноса модулей на выбранный официальный SHA.
   **Результат.** Для 5h, 7d/monthly, countdown и error/loading названы исходные файлы, новые зависимости/мосты, тесты и несовместимости; multi-account/custom providers и прочие удобства перечислены отдельно и не включены молча.
   **Проверка.** Матрица в отчёте F1 ссылается на `managed-usage.ts`, `UsageStatusBar.tsx`, handler/SDK типы и тесты; Scale: обязательные квотные состояния; Meter: diff источника и цели; Target: **5/5** состояний — 5h, 7d, monthly, reset, unavailable — имеют маршрут переноса.
4. **Ситуация.** Живой wire содержит путь soft → force → обычные вызовы → compaction.
   **Действие.** Агент превращает этот путь в анонимизированную fixture и таблицу операций закрытия.
   **Результат.** Отдельно перечислены вызовы, необходимые для STATUS/FAREWELL/git, и обычная работа, которая обязана получить отказ; soft-entry и force-entry — разные состояния.
   **Проверка.** Fixture воспроизводит wire 1977–2474 без личного содержимого; Scale: классы вызовов после force; Meter: таблица решений; Target: каждый класс имеет verdict allow/deny и проверку, **0** неразмеченных классов.
5. **Ситуация.** У владельца установлено официальное расширение и есть накопленные сессии.
   **Действие.** Агент выполняет baseline packaging в изоляции и описывает установку/откат без записи в текущий профиль VS Code.
   **Результат.** Названы уникальный extension ID нашей будущей сборки, каталог артефакта, команда чистого Extension Host и восстановление официального расширения; существующие сессии не удаляются.
   **Проверка.** `node scripts/vsix-package.mjs` и штатный verify/script этой базы либо названная замена; Scale: изолированные установки; Meter: Extension Host smoke; Target: **1** успешный baseline запуск вне checkout и **1** успешный возврат официального расширения в тестовом профиле.
6. **Ситуация.** F1 произвела baseline, красные fixtures и карты переноса.
   **Действие.** Независимый судья повторяет команды и проверяет, что продуктовое поведение ещё не объявлено исправленным.
   **Результат.** Отчёт судьи различает доказанную воспроизводимость и ещё не реализованный выключатель; F2 планируется по названным пробелам.
   **Проверка.** `/skill:fable-judge`; Scale: заявления F1; Meter: повторный запуск и diff; Target: **VERIFIED** для F1 либо фаза остаётся открытой.

## Шаги

- [ ] **F1.1 — Закрепить официальную базу.** Якорь эпика: «pinned upstream не старше 2.7.2; изолированный клон нашего форка». Сверить установленную версию, выбрать соответствующий tag/commit официального репозитория, записать SHA и происхождение; не смешивать клон с деревом KAIF. Проверка: `git status`, `git rev-parse HEAD`, version/package manifest.
- [ ] **F1.2 — Доказать немодифицированный baseline.** Якорь: «baseline build/test». Прочитать upstream `AGENTS.md` и CONTRIBUTING в клоне; сверить Node ≥24.15.0 и pnpm 10.33.0 без молчаливой установки; выполнить штатные команды. Проверка: отчёт команд с моментами, кодами и читаемым итогом.
- [ ] **F1.3 — Написать красные engine-контроли.** Якорь: «точная карта всех auto paths; красные engine fixtures для off». Покрыть `beforeStep`, `afterStep`, `recoverFromContextOverflow`, default-on и manual-compact control. Проверка: красный прогон на pinned SHA с названными `THREAT / PROVED-AGAINST / GAP / ON-REAL-PATH: NOT YET`.
- [ ] **F1.4 — Составить карту переноса комфорта, автоматического steer и theme background.** Якорь: «diff-карта переноса 5h/7d/monthly из gxgleo67» и «карта автоматического steer через существующий `SteerChat`». Разделить обязательный квотный контур и дополнительные удобства; внести click-to-compact как сознательно НЕ переносимый обработчик. Для follow-up записать красные сценарии `bugs/151`: accepted steer, turn-ended ровно один новый ход, фактическая ошибка с восстановлением текста/media, серия без queue/дублей. Для фона зафиксировать красный computed-style контроль: официальный `.dark` фиксирует oklch, цель — `var(--vscode-sideBar-background)` с editor fallback и различимыми card/popover/input. Проверка: матрица файлы→зависимости→тесты→конфликт, никаких секретов и токенов в выводе.
- [ ] **F1.5 — Формализовать живой failure trace.** Якорь: «карта разрешённых операций force-закрытия». Вынести структуру событий soft/force/ordinary/compaction из wire, не копируя личные тексты; записать allow/deny по классам и будущие мутанты. Проверка: fixture краснеет на текущем `framework/hooks/context-window.mjs` именно на force escalation и post-force ordinary work.
- [ ] **F1.6 — Проверить VSIX и откат на тестовом профиле.** Якорь: «способ сборки/установки VSIX и отката». Собрать немодифицированную базу, проверить артефакт вне checkout и откат; не менять текущий Extension Host владельца. Проверка: лог установки, старт новой тестовой сессии, версия до/после.
- [ ] **F1.7 — Оформить прогон и суд.** Якорь эпика: «Ни одна фаза не закрывается по чтению diff». Создать семипольный отчёт F1 в `testcases/reports/`, отдельно гигиену и функциональный Extension Host smoke; выполнить `/skill:fable-judge`, устранить находки F1 и только затем написать план F2.

## Верификация

- **Upstream:** официальные unit/typecheck/build/test + VSIX verify и Extension Host smoke в изолированном профиле.
- **Compaction:** новые fixtures в `packages/agent-core-v2/test/agent/fullCompaction/`, доказанные красными на pinned SHA; никакого `[TESTED]` у выключателя до F2.
- **KAIF closure:** анонимизированный repro живого wire + текущие `context-window.mjs --selftest`, `tools/sandbox/probes/kimi-window-mutants.mjs`, `s14`; новые красные случаи не подгоняются под текущий latch.
- **Квоты:** на F1 только diff-карта и существующие тесты источника; живые проценты не заявляются до F3/F4.
- **Отчётность:** `testcases/reports/2026-11-23_epic144-f1-baseline.md` (дата фактического прогона может быть новее), суд `reports/KAIF_AUDIT/`; все моменты — реальные метки команд.

## Риски

1. **Официальный tag 2.7.2 не воспроизводит установленную сборку.** Реакция: сличить package/version и SHA, выбрать ближайший официальный тег не старше 2.7.2; не смешивать установленный minified bundle с исходниками.
2. **Baseline красный до наших изменений.** Реакция: зафиксировать стенд и исходную ошибку, не чинить её молча в скоупе нашего патча; отличать upstream debt от дефекта F1.
3. **Квотный UI связан с multi-account кодом.** Реакция: переносить минимальный managed-provider путь, не тащить auth subsystem; если неразрывная зависимость доказана кодом, вынести её владельцу до F3.
4. **VS Code тестовый профиль всё равно трогает общие сессии.** Реакция: отдельный `KIMI_CODE_HOME` и isolated user-data/extensions dirs; никакого запуска теста против текущей сессии владельца.

## Граница фазы

F1 не объявляет auto-compaction отключённым, не устанавливает нашу сборку в основной VS Code и не закрывает bugs/150. Её результат — воспроизводимая база, красные проверки и точные маршруты F2/F3.
