## Цель

Превратить конвенции 1.6 из «правил, которые слабая модель должна помнить» в **механизмы,
которые невозможно забыть**: инструмент считает провенанс, линтер стережёт стиль и канон,
скилл выводит стайлгайд, режимы строгости выбирают конвейер. Релиз **KAIF 1.7** (кодовое имя —
развилка владельцу при старте).

## Состав (из ideas/15, объём — по решению №2 плана 16)

1. **`kaif-provenance`** (15.2.1) — инструмент провенанса ИИ-текста в канон-артефактах владельца:
   - отчёт по git-базлайну (базлайн = коммит с чистым текстом владельца; блочное сопоставление
     token-F1, пороги ~0.8/0.55 отделяют механические правки от переписки);
   - `--mark` — расстановка парных пометок `[AI]…[/AI]` / `[AI-ed]…[/AI-ed]` механически;
   - `--check` — гейт: непомеченный ИИ-текст роняет сборку (встроить в `kaif:check`);
   - `--accept` — приёмка владельцем: снятие пометок + реестр принятых блоков;
   - тонирование помеченных блоков в рендере (PDF/HTML) — вычитка глазами мгновенна.
2. **Скилл `/derive-styleguide`** (15.2.2): вход — образец владельца → выход — стайлгайд на
   утверждение (регистры, эталонные примеры из текста владельца, чек-лист перед записью, словарь
   «одно понятие — одно слово») + список машинно линтуемых правил стиля.
3. **Шаблон линтера канон-артефактов** (15.2.6): каждое отменённое решение — запрещённая
   формулировка; каждое принятое — стерегомая **полная уникальная строка** (не короткое
   вхождение); линтер растёт с каждой починкой; самопроверка стража на сломанной версии — часть
   шаблона.
4. **Режимы строгости** (15.2.10): «черновик» (быстро, вне канона) / «канон» (полный конвейер:
   стайлгайд → согласование → пометки → стражи → приёмка); разметка шагов скиллов «любая модель /
   только сильная»; всё машинно проверяемое проверяет код, LLM оставляют суждения.
