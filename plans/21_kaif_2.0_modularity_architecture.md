## 1. Цель одним взглядом

Сегодня атом всей машинерии — **целый файл**: один изменённый байт в 300-строчном навыке отправляет
весь файл в ручной когнитивный мердж (поле: у KLAS 10 из 15 изменённых файлов несли правки в 1–4
строки). Цель — опустить атом до **модуля** (логической секции документа), чтобы обновление стало:
«машинерия сама заменяет изменившиеся static-модули, сама переносит adaptive-значения, никогда не
трогает owner-модули — а агенту остаются только решения о слиянии смыслов».

**Метрики готовности (из поля, не выдуманные):** доля когнитивной работы при обновлении
85% → «только решения о смыслах» · шагов вне машинерии ~6 → 0 (метрика KPOT) · каждая трудность
П1–П10 из `researches/07` — закрыта / отклонена с причиной / явно вынесена.

## 2. Номенклатура (скелет терминологии — она же первая глава пояснительной записки, эпик №6)

| Термин (EN — канон записки) | Суть |
|---|---|
| **Module** (модуль) | Именованная логическая секция документа или файл целиком — атом сборки, диффа, замены. |
| **Module map** (карта модулей) | Независимый генерируемый артефакт: перечень всех модулей с адресами, классами и sha. НЕ читается агентом в обычной работе — она для машинерии. |
| **Signature anchor** (сигнатурный якорь) | Адрес модуля = его **полная уникальная строка-заголовок** (решение №16). В документы не добавляется ничего; номера строк — производные, пересчитываются каждой сборкой. |
| **Module class** (класс модуля) | `static` — правит только апстрим, механически заменяем · `adaptive` — несёт значения проекта (плейсхолдеры, триггер-алиасы), заменяем с переносом значений · `owner` — контент владельца, вне области машинерии навсегда. |
| **Template sha / disk sha** | Два происхождения снапшота: «что развернул фреймворк (после подстановок)» и «что лежит на диске». Право на замену даёт ТОЛЬКО совпадение с template sha (закрывает bugs/12). |
| **Synthetic baseline** (синтетический слепок) | Восстановленный из релизного артефакта старой версии набор модулей — база сравнения для легаси/анонимных путей (закрывает bugs/13, 14). |
| **Module changelog** | Новости релиза, хранимые ПО ВЕРСИЯМ и ПО МОДУЛЯМ; при скачке печатается объединение интервала (закрывает хвост bugs/10). |

## 3. Архитектура (5 частей)

### 3.1 Карта модулей — `dist/kaif-module-map.json` (генерируется сборкой)

- Сборка (`build-framework.mjs`) режет каждый шаблон по заголовкам `#`/`##`/`###` (+ YAML-фронтматтер
  навыка = отдельный модуль) и эмитит карту: `файл → [ { signature, class, sha256, lines } ]`.
- **Сигнатура** — полная строка заголовка. Валидатор требует уникальности сигнатуры внутри файла;
  неуникальная сигнатура валит сборку (страж). Переименование заголовка = осознанная смена адреса —
  фиксируется в changelog как `renamed` (карта старой версии даёт старую сигнатуру: связка по
  порядку+содержимому, правило в §3.3).
- **Классы модулей** живут в **`framework/module-classes.json`** — рядом с шаблонами, НЕ в их тексте
  (требование владельца: не захламлять контекст LLM). Формат: `файл → класс-по-умолчанию +
  исключения по сигнатурам`. Страж полноты: секция шаблона без класса валит сборку.
- Карта едет в бандле как мета-блок (прецедент: `kaif-bundle-manifest.json`) и сохраняется в
  развёртке как `.kaif/module-map.json` — переживает самоочистку (обезличенный вариант для
  anonymous: без origin-полей — закрывает bugs/13).

### 3.2 Провенанс по-модульно — deploy-manifest v2

- Для каждого файла: `templateSha` (после подстановок) отдельно от `diskSha`; для ключевых
  документов и навыков — по-модульные `templateSha` секций.
- EOL-нормализация при каждом sha (`\r\n → \n`) — CRLF-грань bugs/12 закрывается по построению.
- Пересчёт снапшота — в финальном гейте (после мержей), а не в конце механического прохода.
- `kept`-провенанс сохраняется и становится по-модульным; `adopted.push()` и для OWNER_SEEDED
  (монотонность провенанса — грань bugs/12 из отчёта KPOT).

### 3.3 Классификация update по-модульно

Для каждого модуля нового бандла против карты и снапшота развёртки:

| Класс | Диск == template sha старой версии | Диск разошёлся |
|---|---|---|
| static | **заменить механически** (вынуть модуль — вставить новый) | в `merge-diverged`, но с **по-модульным диффом** «старый шаблон → новый шаблон» прямо в задании |
| adaptive | заменить с переносом значений (плейсхолдеры/алиасы из текущего текста) | то же + дифф |
| owner | не трогать (и не упоминать) | не трогать; если шаблон owner-модуля сменил КОНВЕНЦИЮ — пункт задания «перенеси конвенцию, не трогая содержимое» (грань отчёта KPOT про EXPERIENCE-формат) |

- Файл, у которого разошлись только N из M модулей, больше НЕ уходит в ручной мердж целиком —
  меняются его static-модули, разошедшиеся перечисляются по-модульно.
- **Эвристика письменности** (решение №17): модуль на языке владельца при английском шаблоне не
  заменяется молча → diverged с явной пометкой «локализован» (+ поле маркера `i18n`).

### 3.4 Машинный дифф версий и changelog

- Команда **`kaif-core diff [--from <ver>|--source <dir>]`**: скачать/взять старый бандл, построить
  синтетический слепок, сравнить по модулям; вывод: изменённые модули + churn, «переносить нечего»
  для нетронутых. Работает и как послеобновленческий аудит (просьба Unliminium §9).
- `KAIF_UPDATE_TASK.md` печатает **по-модульный список** вместо «merge the news pointwise»;
  changelog хранится по версиям, при скачке 1.2→2.0 печатается объединение интервала.
- **Расписка `.kaif/last-update.json`** (from→to, дата, маршрут, счётчики, чекпоинты) — обновление
  доказуемо постфактум; история в маркере `history: []` (закрывает bugs/17 + T9).
- Команда **`adopt-current`** — пересборка снапшота после ручной миграции (закрывает хвост bugs/12
  из отчёта KrinikCam №10).

### 3.5 Гейты и чекпоинты становятся содержательными

- `checkpoint recheck` сам запускает `check` и не пишет отметку при провале; `checkpoint judge`
  требует строку вердикта (закрывает bugs/17).
- `update-verify` проверяет факт мержа опорными строками изменённых модулей, пока бандл жив
  (полевой метод 209/209 из отчёта 08).
- Схема маркера — в карте модулей; валидатор сверяет маркер со схемой (хвост bugs/11).
- Греп «протухших утверждений»: машинерия знает старую/новую версию и счётчики — после прохода
  ищет их упоминания по дереву и выдаёт пунктами задания; бандл несёт `deprecations` (П9).

## 4. Что НЕ меняется (контракт поля, `researches/07` §3)

Святой инвариант (владельческое байт-в-байт) — усиливается, не ослабляется · sha256-гейт загрузчика ·
legacy-детект по маркеру · команды checkpoint/sphere · resyncCopies · единый runFinalGates ·
вежливая проводка package.json. Формат `FILE:`-блоков бандла сохраняется (карта — НАД ним, а не
вместо него): старые ядра продолжают понимать новые бандлы на файловом уровне — деградация мягкая.

## 6. Риски

| Риск | Защита |
|---|---|
| Резка по заголовкам не совпадёт с логическими модулями (секция-«мешок») | спайк 5.1 покажет фактическую гранулярность; правило: модуль можно ДРОБИТЬ переименованием заголовков в апстриме — это штатная эволюция карты |
| Неуникальные заголовки в реальных шаблонах | страж сборки + отчёт спайка; лечится уточнением заголовка (осознанная правка канона) |
| Рост сложности машинерии (KISS) | карта ГЕНЕРИРУЕТСЯ, руками не ведётся; классы — один JSON; ядро остаётся одним файлом; каждый механизм закрывает названный полевой класс, «на всякий случай» не строим |
| Старые развёртки без карты | update строит синтетический слепок из релизного артефакта их версии — карта не обязана существовать на стороне проекта заранее |

## Решения, принятые агентом без владельца

1. Классы модулей — отдельным JSON рядом с шаблонами, а не аннотациями в тексте (прямое следствие
   вашего требования «не захламлять контекст»; альтернатива — комментарии в файлах — отклонена).
2. Формат FILE:-блоков сохранён как транспорт (мягкая деградация для старых ядер); модульность —
   слой НАД ним.
3. Терминология §2 — на английском как канон (следствие решения №18: записка — один полный
   EN-документ).
