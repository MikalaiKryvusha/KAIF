**Формула эпика (капслок владельца — суть):** «ВСЕ ВЗАИМОДЕЙСТВИЯ, ЧЕГО ХОЧЕТ АГЕНТ ОТ ВЛАДЕЛЬЦА,
ВЫНОСЯТСЯ СТРОГО В ИНТЕРВЬЮ» — и с новым воркфлоу рендера интерактивных HTML демонстрируются
владельцу быстро, проактивно и наглядно. Ответы в HTML = слово владельца (как в md и в чате),
решения фиксируются в историю с автором. Режим — опциональный сахар: просьба перейти на него —
опциональный навык; KAIF описывает методологию, инструменты строит агент проекта.

**Главный полевой вывод (отчёт 13):** «HTML — не цель, а транспорт. Цель — страж» — правило места
вопросов нарушал агент, который его знал; страж нашёл 2 никем не увиденных вопроса (висели 5 и
13 дней). Страж — первый обязательный артефакт практики, рендер — второй.

## Фаза D2 — методология: инварианты и контракты (скелет)

Нормативная часть («что обязано быть») отдельным разделом методологии (место: AGENT_GUIDE или
документ-спутник — решить по объёму, Оккам): инварианты I1–I7 отчёта 13 (md — источник · ответ в
три места, имя файла решения производно от документа · одобрение = SHA-256 тела + договорённость о
нормализации · гейт на стороне отправки, fail-closed · сигнал после открытой страницы · тишина
перебивает всё, окно через полночь · накопление для автоциклов) + контракт имён (блок метаданных:
title/kind/artifacts{id,target,format,body_file-ссылка}; запись решения:
kind/document/by/at/comment + answers/artifacts) + грабли прямым текстом (нормализация в стыке
хэшей · exit 0 ≠ сигнал дошёл · прогон по всем живым документам — условие сдачи · обе темы ОС ·
`\p{L}` для кириллицы в Node) + индустриальные добавки (§11.2: четвёрка Approve/Reject-с-причиной/
Edit/Respond · payload виден целиком · аудит включая отказы · запрос не самоодобряется по
таймауту). Разделение уровней явно: норматив vs «как построить — проект».

## Фаза D3 — опциональный навык развёртывания контура (скелет)

Рабочее имя `/owner-reviews` (финальное — ответ №5 интервью): вызов = агент проекта строит
локальный контур по методологии D2 в порядке отчёта 13 («наш был хуже» → правильный: страж →
рендер+запись решения → гейт отправки → сигнализация → накопление → пилот на настоящих данных);
критерий приёмки — «полный цикл рутины без единого уточнения в чате»; ноль внешних зависимостей
поощряется прямо; звук/TTS — параметры (имя голоса — параметр, не меню), тихие часы обязательны.
+ обвязка, алиасы 9 пакетов, README.

## Фаза D4 — дополнение /interview (скелет)

Шаблон /interview: опциональный шаг «отрендери в HTML и открой владельцу» (если контур D3 в проекте
есть) + правило эквивалентности ответов (HTML = md = чат) + фиксация «кто решил» (by/at) + режим
накопления для циклов (I7). Совместимость: интервью без контура работает как раньше (сахар не
становится обязанностью).
