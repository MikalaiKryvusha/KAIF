## Вектор цели

Обновление на переведённом/локализованном развёртывании проходит без единого ложного пункта
СЛИЯНИЯ в задании (merge-диффы — только реальные), без единой английской вставки в переведённый
файл, без единого зелёного лжеца среди стражей — а шум предупреждающих сканеров (stale-claims,
аудит modules) снижен кратно и замерен числом; агент-обновленец тратит токены на РЕАЛЬНЫЕ
слияния, а не на разгребание шума.

## Критерии приёмки эпика (наблюдаемые)

1. Полигон-свод на КАЖДЫЙ класс L-1…L-11 (`researches/15` §3, таблица); каждый страж свода
   доказан красным на сломанной версии ДО фикса (EXP-0016/0017).
2. Тестовое обновление переведённого профиля: ноль вставок EN-модулей в `i18n: translated`
   файлы; ноль «двухголовых» навыков (детектор `>1 H1` — гард в check).
3. Задание содержит ТОЛЬКО реальные диффы от предыдущего релиза: пункт с пустым диффом
   невозможен по построению; для i18n-файлов — настоящий дифф шаблонов или явное «шаблон не
   менялся».
4. CLI-безопасность: голый запуск ядра НЕ деструктивен; `help` — команда; неизвестный
   флаг/аргумент мутирующей команды — отказ, не молчаливое исполнение.
5. Ни один страж поставки не зелёный без конфигурации: отдельный код/`SKIPPED`; счётчики сводок
   считают запись, не намерение; чекпоинты с существующим сканером ИСПОЛНЯЮТ его.
6. `stale-claims`: точность на полевых фикстурах (образцы из 4 отчётов) — доля полезных
   срабатываний ≥ 50 % (сейчас ≈19 %); цитаты владельца и журналы решений не трогаются.
7. `update-verify`/аудит `modules` на переведённом развёртывании не красный по построению
   (отдельный режим или честная классификация «локализован ≠ absent»).
8. Линт бандла перед релизом существует и зелёный: пары «документ ↔ ведущий его навык», нормы
   релизных нот против шаблонов (класс «обещанный guard не существует» закрыт).
9. «Не сломать»-лист (`researches/15` §3) проверен полигоном: тонкое ядро+sha256 ·
   adopt-current · сохранность владельческого · translatedWholesale (пороги чинятся, сеть
   остаётся) · recheck · verdict · квитанция · PROJECT_HISTORY-миграция.

## Чек-лист регрессии «не сломать» (выход триажа L1; вход фаз L2–L5 и полигона)

Похвалено всеми четырьмя отчётами — каждая строка обязана остаться зелёной после ВСЕХ фиксов
эпика; полигон-своды L прогоняют этот список как регрессию:

- [ ] Тонкое ядро + sha256-гейт лоадера (обе суммы сходятся; битый набор не ставится).
- [ ] Сохранность артефактов владельца: bugs/ideas/interviews/researches/plans/homeworks и код
      проекта — `git status` по ним пуст после обновления (во всех 4 проектах — ноль потерь).
- [ ] `adopt-current` возвращает механический путь после ручной миграции («19 путей принято»,
      «0 file(s) carry upstream static-module changes» после него).
- [ ] Сеть `translatedWholesale` ОСТАЁТСЯ (лучшая часть релиза для i18n-класса — Unliminium);
      фиксы L2 чинят пороги и вставку, не выбрасывают сеть.
- [ ] Чекпоинт `recheck` исполняет `check` сам («executed by the checkpoint itself»).
- [ ] `checkpoint judge` требует вердикт с уликами (файловый путь добавляется, требование
      остаётся).
- [ ] Квитанция `.kaif/last-update.json` + `history` маркера переживают самоочистку;
      `verifiedAt` штампуется.
- [ ] `PROJECT_HISTORY.md` + миграция летописи с ассертами дословности (4 успешных миграции:
      2900→278, 1647→253, 1928→176, 205→180 строк).
- [ ] Самоочистка удаляет ровно транзиенты (KAIF.md, KAIF-LOADER.mjs, задание, .kaif/install/).
- [ ] `diff --source <версия>` работает как сравнение с другой версией; `sync` пересобирает
      зеркала байт-в-байт.
- [ ] ignore-first для транзиентов сохраняется (расширяется по решению №42, не сужается).
- [ ] Канон 2.1 и `KAIF_REFERENCE.md` — содержание не регрессирует.
- [ ] Предсказание прохода песочницей (`git archive | tar -x` → прогон → sha-сверка) остаётся
      воспроизводимым методом (2 проекта подряд byte-exact).
