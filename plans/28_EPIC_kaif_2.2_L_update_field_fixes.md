**Формула эпика:** механическая часть 2.1 надёжна (ноль потерь владельческого во всех четырёх
проектах) — а вся цена обновления легла на когнитивную часть: задание завалено ложными пунктами
(NDim: полезны ~80 строк из 352; KCam: 35 % пунктов merge-diverged пустые; KLAS: ~1,9 млн
токенов на обновление), переведённые файлы получают английские вставки, стражи лгут зелёным.
Эпик L делает обновление 2.1→2.2 таким, каким его хвалят за механику — И по когнитивной части.

## Вектор цели

Обновление на переведённом/локализованном развёртывании проходит без единого ложного пункта
задания, без единой английской вставки в переведённый файл, без единого зелёного лжеца — и
агент-обновленец тратит токены на РЕАЛЬНЫЕ слияния, а не на разгребание шума.

## Критерии приёмки эпика (наблюдаемые)

1. Полигон-свод на КАЖДЫЙ класс L-1…L-11 (`researches/15` §3, таблица); каждый страж свода
   доказан красным на сломанной версии ДО фикса (EXP-0016/0017).
2. Тестовое обновление переведённого профиля: ноль вставок EN-модулей в `i18n: translated`
   файлы; ноль «двухголовых» навыков (детектор `>1 H1` — гард в check).
3. Задание содержит ТОЛЬКО реальные диффы от предыдущего релиза: пункт с пустым диффом
   невозможен по построению; для i18n-файлов — настоящий дифф шаблонов или явное «шаблон не
   менялся».
4. CLI-безопасность: голый запуск ядра НЕ деструктивен; `help` — команда; неизвестный
   флаг/аргумент мутирующей команды — отказ, не молчаливое исполнение.
5. Ни один страж поставки не зелёный без конфигурации: отдельный код/`SKIPPED`; счётчики сводок
   считают запись, не намерение; чекпоинты с существующим сканером ИСПОЛНЯЮТ его.
6. `stale-claims`: точность на полевых фикстурах (образцы из 4 отчётов) — доля полезных
   срабатываний ≥ 50 % (сейчас ≈19 %); цитаты владельца и журналы решений не трогаются.
7. `update-verify`/аудит `modules` на переведённом развёртывании не красный по построению
   (отдельный режим или честная классификация «локализован ≠ absent»).
8. Линт бандла перед релизом существует и зелёный: пары «документ ↔ ведущий его навык», нормы
   релизных нот против шаблонов (класс «обещанный guard не существует» закрыт).
9. «Не сломать»-лист (`researches/15` §3) проверен полигоном: тонкое ядро+sha256 ·
   adopt-current · сохранность владельческого · translatedWholesale (пороги чинятся, сеть
   остаётся) · recheck · verdict · квитанция · PROJECT_HISTORY-миграция.

## Фазы

### L1. Триаж: 45 запросов + 11 классов → документы bugs/ — ДЕТАЛЬНО: `plans/36_epic28_L_phase1_triage.md`

Каждый класс L-1…L-11 и каждый уникальный дефект — документ в `bugs/` по канону (симптом ·
репро · причина · план фикса; свод классов, не экземпляров); запросы-предложения без дефекта —
строки фаз L2–L5; противоречивые запросы (git vs ignore для KAIF_UPDATE_TASK.md) — в интервью
007 Q10. Выход: полный реестр «класс → баг-док → фаза фикса», ноль потерянных запросов
(сверка: 9+11+12+13 = 45).
**Гейт:** каждый из 45 запросов имеет судьбу (баг-док / строка фазы / развилка / отклонён с
причиной); судья-проход триажа.

### L2. Класс перевода: детектор и вставка (L-1, L-2) (скелет)

`i18n: translated` блокирует и ВСТАВКУ модулей, не только замену; сеть распознавания перевода —
по доле, не по абсолютным порогам (вырождение на малых N — EXP-0019); авто-простановка
`i18n: translated` для до-2.0 проектов; кириллица из тел EN-шаблонов — в языковые пакеты
(инвариант §9.11); диффы задания — от ПРЕДЫДУЩЕГО РЕЛИЗА (синтетический baseline уже
скачивается машинерией); ноль изменений апстрима = ноль пунктов; настоящий дифф шаблонов для
merge-diverged. Полигон-профиль «переведённое развёртывание» расширяется до воспроизведения
всех трёх полевых лиц класса (NDim/KLAS/KCam).
**Гейт:** критерии приёмки 2–3 зелёные на полигоне; стражи красные до фикса.

### L3. CLI-безопасность и зелёная ложь (L-3, L-4) (скелет)

Голый запуск = справка, не install; задание с чекпоинтами не перезаписывается молча; `help`;
неизвестные флаги мутирующих команд = отказ; `--verdict-file` (L-9 — заодно, тот же слой CLI);
стражи без конфигурации → `SKIPPED` с кодом 3; счётчики считают запись; чекпоинты исполняют
существующие сканеры; провенанс читает локализованные маркеры из маркера развёртывания;
`check`/`report` согласованы; `check` не зелёный при дрейфе зеркал (или `recheck` зовёт `sync` —
по триажу L1).
**Гейт:** критерии 4–5 зелёные; KCam-инцидент Г1 (потеря задания) воспроизведён красным и закрыт.

### L4. Шум и честность аудита (L-5, L-6, L-7, L-8) (скелет)

`stale-claims`: скоуп — версия ФРЕЙМВОРКА; пропуск цитат/журналов/зеркал; миграция летописи ДО
скана; кап по файлам. `update-verify`: режим переведённого развёртывания (absent ≠ дефект,
«MODULE ABSENT» не печатается как дефект). Warning-guard длины STATUS — СУЩЕСТВУЕТ (одна строка
в check; обещания релиза = код). Линт бандла: пары «документ ↔ ведущий навык» + сверка нот с
шаблонами.
**Гейт:** критерии 6–8 зелёные; точность stale-claims замерена на полевых фикстурах числом.

### L5. Остальные запросы + судья (скелет)

SEMANTIC REPLACE как класс задания (смена смысла навыка — KLAS/KCam-ожог `/pause`; питает и
эпик P) · резервная копия `.kaif/backup-<from>-<to>/` · честная метка маршрута · предупреждение
«чек-листы могут содержать строки владельца» в задании слияния · имя проекта из маркера, не из
каталога (L-11) · placeholders с реальными адресами + строка про сферы/обвязку/локальные
валидаторы · `.gitignore`-гигиена по ответу Q10 · машиночитаемый инвентарь скиллов · команда
«покажи неотвеченные вопросы» в поставку (сшивка с эпиком K). Финальный судья эпика +
полигон целиком.
