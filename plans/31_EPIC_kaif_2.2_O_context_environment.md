## Вектор цели

Свежесть канона в контексте агента обеспечивается МЕХАНИЗМАМИ (хуки/триггеры/проверяемые
действия) с честным markdown-фолбэком; знание окружения — датированным, машиноснимаемым досье в
AGENT_GUIDE, которое агент собирает по формализованной процедуре и поддерживает актуальным, —
так что новая сессия никогда не «оказывается в окружении как в первый раз».

## Критерии приёмки эпика (наблюдаемые)

1. Двухконтурная архитектура освежения задокументирована в каноне: markdown-ритуал (обязательный,
   работает в любой системе) + hook-контур (опциональная поставка для систем с хуками);
   развёртывание без хуков не краснеет (инвариант §9.10).
2. Hook-конфиги в поставке (опциональный модуль): минимум SessionStart(compact) — «канон после
   сжатия», UserPromptSubmit-таймер (>60 мин → приказ перечитать), Stop-страж STATUS; каждый
   впрыскивает ПРИКАЗ перечитать, не документы (кап 10k символов, антипаттерн автовпрыска);
   у каждого — предикат срабатывания и cooldown.
3. Освежение = проверяемое действие: timestamp-маркер обновляется фактом перечитывания;
   /fable-judge умеет спросить свидетельство («когда последний раз перечитан канон?») — recall
   без adherence (DriftBench) закрыт механизмом.
4. Ярус «обязательного перечитывания» взят из таксономии эпика N (не изобретён здесь второй);
   правило «раз в час ИЛИ перед тяжёлой задачей» — в каноне и в навыках циклов
   (/autoloop//dayloop//nightloop//guarded-loop — итерации длинных циклов включают освежение).
5. Досье окружения: формализованная процедура сбора (ЧТО собрать: ОС/железо · шеллы и кодировки ·
   PATH/тулчейн · пакетные менеджеры · особенности поведения) + унифицированный формат секции
   AGENT_GUIDE (машиночитаемо где можно, ДАТИРОВАНО, с командой перегенерации и
   staleness-правилом «факты старше N недель — гипотеза»); шаблон в payload.
6. Dogfooding: этот репозиторий имеет живое досье окружения (Windows 11 · PS 5.1 · Git Bash ·
   Node — оплаченные уроки EXP-0005/0007/0013 и «Гигиена текста» вплетены, не продублированы) и
   работающий hook-контур; наблюдение: свежая сессия после /clear получает впрыск и перечитывает.
7. Полигон/греп-своды: канон-строки в песочнице; hook-модуль доезжает опционально и не ломает
   системы без хуков.

## Фазы

### O1. Разведка механизмов и проектирование двухконтурной схемы (детальный операционный план)

- [ ] O1.1. Карта механизмов по системам (разведдок; внешняя правда — читать доки, не память):
      Claude Code hooks — СНЯТО в §11.3 (SessionStart с матчерами · UserPromptSubmit ·
      PostToolBatch · Stop · PreCompact/PostCompact · FileChanged/watchPaths; кап 10k; exit-коды)
      — перепроверить по живой доке на момент исполнения; остальные системы поставки (адаптеры:
      Zoo Code и др. по `framework/adapters/`) — что у них есть похожего; честный вывод «где
      хуков нет — только markdown-ритуал».
- [ ] O1.2. Спроектировать markdown-контур (ядро): правило освежения в AGENT_GUIDE (триггеры:
      час · тяжёлая задача · после компакции/паузы) + проверяемое действие (timestamp-маркер
      `.kaif/last-refresh` или строка в STATUS — решить по Оккаму) + точки в ритуалах
      (/resume — вход; /refresh-context — сам ритуал, усилить принудительностью; циклы — каждая
      N-я итерация; /pause→возврат).
- [ ] O1.3. Спроектировать hook-контур (опциональный модуль поставки, класс tool-модулей 2.0):
      состав конфигов из критерия 2; формат поставки (`.kaif/hooks/` + инструкция подключения в
      settings.json — агент проекта подключает сам, KAIF не трогает чужие настройки молча);
      анти-шум: cooldown и предикаты (антипаттерн «частые напоминания без троттлинга»).
- [ ] O1.4. Спроектировать досье окружения: процедура сбора (последовательность команд-проб по
      платформам; образец ansible facts — снимается командами, не воспоминаниями) + формат
      секции (шаблон с полями и датой снятия + команда перегенерации) + правило staleness +
      граница с «Гигиеной документов и текста» (досье ССЫЛАЕТСЯ на оплаченные классы, не
      дублирует их — DRY).
- [ ] O1.5. Верификация фазы: проект схемы (O1.2–O1.4) — коротким research-доком с развилками;
      судья фазы: «двухконтурность честная? фолбэк без хуков полноценен? нет второго канона?».

### O2. Канон и ритуалы (скелет)

Правила освежения + проверяемое действие — в AGENT_GUIDE (payload+обвязка); ярус перечитывания —
ссылкой на таксономию N; вплетение в /resume, /refresh-context, циклы, /pause; строка в
hunt-list судьи (заявленное освежение без обновлённого маркера — фрод класса ложного TESTED).

### O3. Механизмы и досье (скелет)

Hook-модуль в поставку (регистрация по инварианту §9.6; своды полигона); процедура сбора досье +
шаблон секции — в payload AGENT_GUIDE + навык (/refresh-context или отдельный — по Оккаму
решить в фазе); AGENTS.md-совместимость (дешёвая витрина: ссылка на AGENT_GUIDE + досье) —
оценить и, если дёшево, сделать.

### O4. Dogfooding, полигон, судья (скелет)

Наше досье окружения снято по процедуре; hooks подключены; наблюдение впрыска после /clear;
полигон-своды; судья эпика.

## Развилки владельцу (интервью 007)

## Решения, принятые агентом без владельца

*Заполняется при закрытии. Текущие (планирование):* hook-контур — опциональный модуль, не ядро
(прецедент kaif-provenance, решение №19 из 2.0); впрыск приказа, а не документов (кап 10k +
антипаттерн token tax); досье живёт СЕКЦИЕЙ AGENT_GUIDE, а не отдельным файлом (слова владельца:
«записать в AGENT_GUIDE.md» — дословно).
