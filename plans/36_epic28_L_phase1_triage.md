## Вектор цели

Каждый из 45 явных запросов «Пожелания к 2.2» и каждый дефект из 4 полевых отчётов имеет
записанную судьбу: баг-док класса в `bugs/` / строка фазы L2–L5 / развилка владельцу /
отклонён с причиной — и ни одно полевое наблюдение не потеряно между отчётами и планом эпика.

   запрос: `проект-источник · формулировка (цитатой) · класс (L-1…L-11 / уникальный /
   не-дефект) · судьба · адрес (bugs/NN | фаза | Q-номер интервью | причина отклонения)`.

   (числа перепроверить по секциям «Пожелания к 2.2» самих отчётов — дайджест мог округлить);
   плюс дефекты, не оформленные запросами.
3. Классы L-1…L-11 (`researches/15` §3) заведены баг-доками `bugs/31+` по канону
   (/report-bug: симптом · репро из отчётов · причина/гипотезы · план фикса → ссылка на фазу
   эпика); классы, повторившиеся в ≥2 проектах, — со сводной таблицей проявлений по проектам
   (класс, не экземпляр — BUG_FIXING).
4. Противоречивые запросы (KAIF_UPDATE_TASK.md: git vs ignore) — НЕ решены самовольно, а

6. Судья фазы: адверсарная сверка «возьми любой отчёт, найди наблюдение без судьбы» — ноль
   находок; счёт критерия 2 сходится.

   баг-доках взаимными ссылками, решает порядок фаз родителя, не дубль-фиксы.
