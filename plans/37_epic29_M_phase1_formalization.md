## Вектор цели

Петля обратной связи KAIF описана в терминах управления (вектор целей · вектор ошибки ·
допустимая ошибка) с классификатором всех типов сигналов, fingerprint-схемой дедупликации и
готовыми шаблонами — так, чтобы фазы M2–M5 вшивали протоколы по готовым формам, а полевые
агенты производили сигналы, которые разработчик KAIF может триажить без разгребания шума.

## Готово, когда (критерии приёмки)

1. Рабочий документ «Петля KAIF в терминах управления» существует: вектор целей фреймворка
   (иерархизированный список проверяемых инвариантов) · вектор текущего состояния (источники
   наблюдений) · вектор ошибки (структура расхождения) · допустимая ошибка (error budget —
   какие расхождения НЕ порождают тикет) · схема предиктор-корректор; формулировки ПФУ сверены
   с первоисточником ДОТУ (PDF vodaspb, ред. 2011 — честный пробел веб-разведки закрыт), поданы
   нейтрально, парой с индустриальными аналогами (PDCA/SRE).
2. Классификатор сигналов покрывает все типы: БАГ KAIF · ЗАПРОС НА УЛУЧШЕНИЕ · отчёт об
   обновлении · отчёт об установке · аудит-отчёт (T3) · предложение принципа (п. 14); для
   каждого — куда пишется, адресат, обязательный состав.
3. Fingerprint-схема дефекта ({документ/навык · класс симптома · версия KAIF}) + правило
   дедупликации («сначала греп bugs/KAIF и open issues; совпадение = +1 наблюдение») +
   progressive collection — записаны как проверяемые правила.
4. Три шаблона готовы (EN): issue-тикет (автозахват версии/проекта/ОС из kaif.json; поля
   «ожидал по канону / получил в поле»), отчёт об обновлении, отчёт об установке.
5. Ретро-проверка: отчёт NDim 2.1 укладывается в шаблон отчёта об обновлении без потери смысла
   (наблюдение, не мнение).
6. Судья фазы пройден; закрытие M1 отмечено в родителе с датой; операционный план M2 написан
   по урокам M1 (канон N+1).

## Верификация

Каждый критерий — наблюдением: документ существует и содержит названные секции; ретро-прогон —
живой; сверка ДОТУ — по конкретным страницам PDF с цитатами.

## Риски

1. Утонуть в теории управления (антипаттерн веб-разведки: полная математика не берётся) →
   документ шага 1 — рабочий, короткий, с дисциплиной «измерение → сравнение → коррекция →
   проверка».
2. Термины ДОТУ прочитаются как идеологическая привязка → нейтральная подача парой с
   PDCA/SRE-аналогами (заметка владельца в AGENT_GUIDE: фреймворк универсален).
3. Шаблоны разбухнут → «краткие, тезисные, без воды» — слова владельца из п. 11, тест — ретро-
   прогон шага 5.
