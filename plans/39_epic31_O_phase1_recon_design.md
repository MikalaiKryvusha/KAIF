## Вектор цели

Спроектирована честная двухконтурная схема освежения контекста (markdown-ритуал обязательный +
опциональные hook-конфиги) и процедура досье окружения — коротким research-доком с развилками,
по которому фазы O2–O4 вшивают канон и строят механизмы без переизобретения.

## Готово, когда (критерии приёмки)

1. Карта механизмов по системам существует (разведдок): Claude Code hooks — перепроверены по
   живой документации на дату исполнения (события, матчеры, кап additionalContext, exit-коды);
   для каждого адаптера поставки (`framework/adapters/`) — что есть похожего; честный вывод
   «где хуков нет — только markdown-ритуал».
2. Проект markdown-контура: правило освежения (триггеры: час · тяжёлая задача · после
   компакции/паузы) + проверяемое действие (timestamp-маркер или строка STATUS — выбор по
   Оккаму, обоснован) + точки в ритуалах (/resume · /refresh-context · циклы · возврат из
   /pause).
3. Проект hook-контура (опциональный модуль): состав конфигов (минимум SessionStart(compact) ·
   UserPromptSubmit-таймер >60 мин · Stop-страж STATUS), формат поставки (`.kaif/hooks/` +
   инструкция подключения — KAIF не трогает чужие settings молча), анти-шум (предикат +
   cooldown у каждого).
4. Проект досье окружения: процедура сбора (последовательность команд-проб по платформам —
   образец ansible facts) + формат секции AGENT_GUIDE (поля, дата снятия, команда
   перегенерации, staleness-правило) + граница с «Гигиеной документов и текста» (ссылка, не
   дубль — DRY).
5. Судья фазы: «двухконтурность честная? фолбэк без хуков полноценен? второго канона нет?»;
   закрытие O1 в родителе; операционный план O2 написан по урокам O1.
