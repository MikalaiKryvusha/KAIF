## Готово, когда (критерии приёмки)

1. `/report-bug` (payload EN + обвязка RU): ветка-детектор «это дефект фреймворка, не проекта» →

   имени владельца — через гейт отправки (стоячая авторизация).
2. Контур «дефект в САМОМ KAIF» (5 шагов, п. 1.11 NDim — вендорить с адаптацией) — в payload
   `AGENT_GUIDE.md` (до фазы греп 0 совпадений) + сшивка с `/experience`; RU-зеркало обвязки

3. `/kaif-update` + машинерия: задание обновления несёт пункт «полевой отчёт ОБЯЗАТЕЛЕН» (между

4. Финиш установки: задание адаптации ставит отчёт об установке (скелет шаблона D) той же
   механикой чекпоинта; анонимный профиль — отчёт локальный, БЕЗ попыток тянуться к origin.
5. `/kaif-version`: строка-подсказка о канале (дефекты/улучшения → `bugs/KAIF/` + issue origin

6. Полигон: красным-вперёд ассерты «задание содержит пункт отчёта» и «чекпоинт отчёта не

## Решения, принятые агентом без владельца

1. **Позиция пункта field-report в задании обновления — ПОСЛЕ judge**, а не между recheck и
   judge: шаблон C §5 требует ЦИТИРОВАТЬ вердикт судьи, значит отчёт пишется после судейского
   прохода; «между verify и commit» критерия 3 прочитано как позиция в рабочем потоке (после
   судейства, до `update-verify`/коммита) — хвост «then run update-verify» переехал из пункта
   judge в пункт field-report.
2. **Версионный пин чекпоинта:** update — по расписке `last-update.json` (`.to`), install — по
   версии маркера; при нечитаемости пин мягчает до суффикса вида отчёта (graceful — файл
   чужого вида всё равно не пройдёт).
3. **Текст пунктов заданий не упоминает origin НИ В ОДНОМ режиме** (не только в анонимном):
   доставка апстрим целиком в навыках (/report-bug ветвится по tracking) — Оккам + риск 2 по
   построению, без ветвления текста задания.
4. **Раскладка ассертов:** «задание содержит пункт» — s02 (update) и s04/S13 (install+аноним),
   «чекпоинт не ставится без файла» — s03/S12; план называл профили s02/s03 — install-плечо
   легло в s04, где уже гоняется полный анонимный install (заодно закрывает критерий 4 одной
   песочницей); s07 — ремонт фикстур, не стражи.
5. **Регистрация в KAIF_REFERENCE §7.2/§10.3** — сверх буквы плана (доктрина полного круга
   регистрации из M2: справочник перечисляет исполняющие чекпоинты поимённо).
6. **Шаблоны A/B вендорены в /report-bug ЦЕЛИКОМ**, не ссылкой: полевой агент не имеет
   `researches/18`, поставка самодостаточна; RU-обвязка тела шаблонов не дублирует (DRY +
   оговорка истока — здесь они не применяются).
7. **Имя файла install-отчёта в задании — с плейсхолдером `<PROJECT>`:** канонное имя может
   быть ещё не подтверждено к моменту генерации задания; чекпоинт пинит суффикс и версию,
   не имя.
8. **M4+M5 — одним дочерним планом `plans/51`:** обе фазы лёгкие (M4 — пара канон-строк;
   M5 — dogfooding-сверка + эвал-ловушка + судья эпика), помещаются в одну сессию; церемония
   двух планов перевесила бы работу (развилка «возможно одним планом» заложена критерием 6).
