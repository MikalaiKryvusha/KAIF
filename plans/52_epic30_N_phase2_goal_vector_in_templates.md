## Вектор цели

Каждый целевой документ, который агент заводит по шаблонам KAIF (план, эпик, баг, идея),
ОТКРЫВАЕТСЯ вектором цели и критериями приёмки — блок стоит ПЕРВЫМ в шаблонах навыков
планирования и README директорий, с оговоркой модифицируемости; написание блока направляет
`REQUIREMENTS_FRAMEWORK.md` (доставлен фазой N1).

## Готово, когда (критерии приёмки)

1. `/plan-task` (EN шаблон + RU обвязка): план открывается блоком «Вектор цели» + «Критерии
   приёмки» (существующее «Готово, когда» усилено/переименовано по канону N1); ссылка на
   REQUIREMENTS_FRAMEWORK в точке письма блока.
2. `/plan-epic` (EN+RU): мета-план эпика открывается вектором цели эпика; операционные планы фаз
   наследуют блок.
3. `/report-bug` (EN+RU): шаблон документа бага несёт критерий приёмки фикса (наблюдаемый).
4. `/propose-idea` (EN+RU): шаблон идеи открывается «какую боль решает + как проверим».
5. README `plans/` `bugs/` `ideas/` (payload `framework/readmes/`): конвенция «вектор цели +
   критерии приёмки первыми» — строкой; локализации всех трёх README ресинканы в 9 языковых
   пакетах ТЕМ ЖЕ коммитом + перепин `_lang-pack-source-shas.json` (доктрина 5f; все три файла —
   в пин-списке).
6. Канон-строка в AGENT_GUIDE обеих половин (чек-лист/роутер): «заводишь план/баг/идею → вектор
   цели и критерии приёмки первыми, по REQUIREMENTS_FRAMEWORK»; оговорка модифицируемости
   («меняются по мере работы») — в шаблонах при блоке.
7. Dogfooding-проверка: греп-скан живых планов 2.2 (`plans/26–52`) на блок вектора
   цели/критериев — счёт «открываются/всего» в закрытии фазы (наши планы уже исполняют канон
   досрочно — подтвердить числом).
8. Кандидаты, отложенные из N1 (греп «TESTING без REQUIREMENTS»): `/release` и сфера
   `programming` — решить по месту: нужна ли им ссылка на канон требований (решение с одной
   строкой обоснования в закрытии; линтер-вплетение — скоуп N5, не тянуть сюда).
9. Сборка зелёная (счётчики цитатой вывода); полигон зелёный; судья фазы; закрытие N2 в
   родителе + план N3 по канону N+1.

## Верификация

Критерии 1–6 — чтением шаблонов против REQUIREMENTS_FRAMEWORK (блок стоит первым) + пересборкой;
критерий 5 — страж протухания пакетов зелёный в том же коммите; критерий 7 — грепом с числом в
закрытии; сборка/полигон — цитатой вывода (EXP-0025).

## Риски (уроки N1)

1. Кириллица в EN-телах шаблонов → гард 5d красный по построению: примеры в EN-шаблонах только
   латиницей, русские формы — в RU-зеркалах обвязки (грабля N1: EARS-ключи и RU-колонка словаря).
2. Правка `plans/bugs/ideas` README (пин-лист пакетов) без ресинка 9 локализаций → страж
   протухания красный: ресинк + перепин ТЕМ ЖЕ коммитом (доктрина 5f; в N1 перепин потребовался
   дважды).
3. Канон-документ — не летопись: без провенанс-пометок (чаты/номера идей) и без мета-воды
   («пару дополняет до тройки» — замечания владельца в N1); механизм связи, не этикетка.
4. Церемония перевесит работу (шаблоны маленьких документов) → блок в /plan-task для «совсем
   маленькой» задачи остаётся секцией в документе идеи/бага, не отдельным планом (канон
   /plan-task не ломать).
