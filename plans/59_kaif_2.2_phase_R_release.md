## Вектор цели

**Achieve:** KAIF 2.2 «Yolden KAIF» опубликован в GitHub Releases — с заявлениями, которые
переисполнены адверсарным судьёй, а не приняты на слово; долг перед полем закрыт (issue #2
отвечен и закрыт от имени владельца); README снова открывается дословным определением владельца
«KAIF — это…», потерянным в 2.1. Боль: пять закрытых эпиков лежат неотгруженными — поле ждёт
фиксы, а незакрытый тикет висит у автора обращения; и чем дольше лежит, тем дороже слияние для
парка проектов.

**Maintain:** ни одно заявление релиза не уезжает непроверенным — ложное «работает» в релизе
скачивает весь мир (`TESTING_FRAMEWORK.md`, принцип 1 + решение №13).

## Риски (ранжированы — Мерфи)

1. **Скоуп T1–T9 кратно раздувает Фазу R** (наивысший). Восемь открытых задач — это не хвост, а
   вторая половина релиза. Реакция: решение владельца шагом 1; дефолт при молчании — минимальный
   набор (T9 + то, что уже сделано по построению), остальное кандидатами 2.3 рядом с эпиком P.
   Агент НЕ решает состав релиза сам.
2. **Полный суд 2.2 не помещается в сессию.** Реакция: нарезка по эпикам, вердикты копятся в этом
   документе, каждая сессия начинает с уже накопленной таблицы; незавершённый суд НИКОГДА не
   округляется до «зелено» (`/fable-judge` охотится ровно на это).
3. **`send-outbound --apply` откажет без записанного одобрения** — он зовёт ту же `checkApproval`,
   что и гейт, и отказывает ненулевым кодом даже под `--apply`. Реакция: страницу гейта поднять
   ЗАРАНЕЕ, отдельной пачкой, не в момент релиза.
4. **Публикация необратима.** Кодовое имя есть (№32), но «да» на саму публикацию — отдельное
   слово владельца; в автономном режиме релиз не публикуется никогда (`/release`).
5. **Ноты сползают в копию README** (полевой класс). Реакция: механическая проверка критерия 2
   абзац за абзацем перед публикацией.
