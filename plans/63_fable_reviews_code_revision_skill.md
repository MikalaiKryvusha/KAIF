## Вектор цели (Achieve)

Навык, по которому работает Fable, обязан быть проверен САМИМ Fable. Сегодня `/code-revision`
адресован «сильнейшей доступной модели», а формулировал его Opus — инструкция для исполнителя
написана наблюдателем, и это единственное свойство навыка, которое задача T3 (`plans/33`) проверить
не могла в принципе. Цель — закрыть разрыв: исполнитель читает свою инструкцию скептически и правит
там, где его собственный опыт ревью и аудита кода расходится с написанным.

## Готово, когда (критерии приёмки)

1. Fable вынес по навыку различимый вердикт: **либо** переписанные `framework/skills/code-revision/SKILL.md`
   и `references/audit-report-template.md` (+ побайтовая копия в `.claude/skills/`), **либо** явное
   «менять нечего» с ПЕРЕЧНЕМ проверенных мест. Молчание и общее одобрение приёмкой не являются.
2. Каждое предложение правки несёт **дословную цитату** правимого места и названный провал
   исполнения — «в таком-то прогоне такая формулировка даёт такой-то результат», а не «так лучше».
   Правка без названного провала отклоняется (вердикт по умолчанию — «менять не нужно»).
3. После правок: `node tools/build-framework.mjs` → EXIT 0 · `node tools/counters-guard.mjs` → EXIT 0 ·
   `npm run test:core` → все своды зелёные · реестр пар без расхождений.
4. Контракт ВЫХОДА (`reports/KAIF_AUDIT/`: семейства находок · карточка из 8 полей · карта покрытия ·
   бюджет шума) сохранён, либо каждое отступление названо с причиной — он проверен пробным аудитом,
   давшим `bugs/55`–`59`.
5. Результат прогнан `/fable-judge` перед объявлением готовности.

(коммит `1dd1747`, дистилляция двух полевых аудитов — KLAS и NDim) и переработанный задачей T3.

автор Opus, исполнитель Fable, ревью нужно ровно поэтому, — но **апстрима у навыка нет**: правки
идут прямо в `framework/` и пересобираются, мерджить не с чем. Без этой строки исполнитель искал бы
апстрим fable-method и потерял бы итерацию.
