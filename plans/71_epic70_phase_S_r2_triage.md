## Вектор цели (Achieve)

Превратить 104 ПРЕДПОЛОЖИТЕЛЬНЫХ вхождения двадцати R2-семейств (`bugs/84`–`bugs/103`) в
проверенные вердикты с адресами: подтверждённое — адресовано эпикам T/U/V/P/W мета-плана,
опровергнутое и протухшее — закрыто с причиной. Отдельно и немедленно: исток перестаёт врать о
собственной версии (семейство 101). Якорь мета-плана: «S первым — по канону „находка не находка,
пока не верифицирована"… Триаж дешевле любой починки и раздаёт адреса всем остальным эпикам».

## Готово, когда (критерии приёмки)

1. **104/104.** Сводная триаж-таблица (`reports/KAIF_AUDIT/<дата>_r2_triage_SUMMARY.md`) несёт
   строку на каждое вхождение: `семейство.№ · вердикт CONFIRMED/REFUTED/STALE · тяжесть ·
   эпик-адресат (для CONFIRMED) · улика`. Meter: счёт строк таблицы против счёта вхождений по
   баг-докам — скриптом, не глазами.
2. **Вердикт двухступенчатый.** Механическая часть (цитата существует? адрес жив? поведение
   воспроизводится?) выполнена скриптом ДО суждения модели (`BUG_FIXING_FRAMEWORK.md` →
   «Находка — не находка»); скептик-проход выполнен с вердиктом по умолчанию REFUTED при
   сомнении. Упавший верификатор ≠ пустой список подтверждений — различие видно в таблице.
3. **Каждый баг-док семейства дополнен секцией «Триаж 2.3»** с вердиктами своих вхождений;
   семейство с полностью закрытыми вхождениями (все REFUTED/STALE) получает тег `DONE`;
   семейства с CONFIRMED остаются открытыми до починки в своих эпиках.
4. **Гигиена истока исполнена** (при CONFIRMED семейства 101): все носители версии истока
   (`.kaif/kaif.json` · `KAIF_FRAMEWORK.md` · что найдёт twin-поиск) сведены к живой версии, пара
   «version.json ↔ носители версии истока» добавлена в реестр пар `AGENT_GUIDE.md` с командой
   сверки, страж доказан красным на сломанной копии.
5. **Публичная ложь витрины остановлена** (при CONFIRMED соответствующих вхождений 88): числа,
   расходящиеся с деревом СЕГОДНЯ, исправлены по правилу трёх мест витрины (обе половины README +
   ноты + перезаливка тела релиза) — ЛИБО, если починка тянет за собой перестройку стражей,
   зафиксирована строкой в адресации эпика T с пометкой «публично, срочно».
6. **Судья фазы** (лёгкий, по прецеденту №48) — вердикт записан; урок фазы — в `EXPERIENCE.md`.

      названной улики. Фолбэк без ultracode: последовательный разбор сессиями Fable по
      семействам, от blocker-кандидатов (84, 85, 86, 88, 89, 91, 92, 97, 101) к гигиене.
- [ ] 4. Вердикты + тяжести + эпик-адреса — в таблицу и в секции «Триаж 2.3» баг-доков;

- [ ] 5. Гигиена истока (критерий 4): фикс всех носителей версии одним движением + twin-поиск

- [ ] 6. Витрина (критерий 5): подтверждённые публичные расхождения — починить или адресовать с

## Верификация наблюдением

Каждый вердикт CONFIRMED цитирует наблюдение этой фазы (прогон, греп, диф), не текст баг-дока;
каждый STALE называет коммит, снявший симптом. Счёт 104/104 — скриптом. Стражи шага 5 — красным
на мутации.

## Риски

- **Топ-1: триаж расползается в починку.** Граница жёсткая: в фазе S чинятся ТОЛЬКО критерии 4–5
  (ложь истока о себе и публичная ложь витрины); всё остальное — адресация. Любая «маленькая
  попутная починка» — дефект фазы.
- **Топ-2: владелец не включает ultracode в моменте.** Фолбэк в шаге 3 назван; фаза удлиняется,
  но не блокируется.
- **Топ-3: дайджесты сессии планирования принимаются за первоисточник.** Шаг 0 прямо требует
  перечитать баг-доки; таблица строится парсером из первоисточников, не из дайджестов.
- **Топ-4: массовые REFUTED демотивируют доверие к R2.** Ожидание названо заранее: R2 писал
  слабый исполнитель по решению №70 БЕЗ верификации — доля отсева заложена в замысел, и
  «опровергнуто» — штатный исход триажа, а не провал круга.
