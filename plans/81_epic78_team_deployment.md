архетипы), дистиллированная из живой команды NDim; **markdown-поставка БЕЗ машинерии-оркестратора**

## Решения, принятые агентом без владельца

1. **Шаблоны живут в `references/` навыка**, а не в `framework/templates/_team-*.md`: сборщик
   встраивает `references/` каждого навыка автоматически (прецедент `/code-revision`), нулевая
   правка механики встраивания против трёх явных строк embedBundle. Оккам; обратимо переносом.
2. **Библиотека ролей — один файл** (5 контрактов + 2 архетипа), не файл-на-роль: меньше
   движущихся частей при том же содержании; рост библиотеки в 2.5 может разрезать.
3. **Имена ролей в библиотеке — англоязычные идентификаторы** (`manager`, `qa-verifier`…) с
   русскими подписями в обвязке: id согласованы с полевым инструментом NDim (`manager` ·
   `designer` · `qa` · `dev-N`) и держат адресацию машинно-читаемой.
4. **Условия активации архетипов — категориальные** («от средней»), не числовые пороги: числовых
   данных для порогов нет ни в поле, ни в справочнике; выдуманное число хуже отсутствующего.
5. **Второй H1 библиотеки понижен до H2** при починке «two-headed document» — структура файла,
   не содержание; выбор между «разрезать файл» и «понизить заголовок» сделан по Оккаму.
6. **PDF не перегенерирован** — прецедент чата 1 (SC/FP тоже не трогали README.pdf в
   мид-версии); PDF обновляет `/release` (эпик RL).
