## Вектор цели (Achieve)

**Боль** (источники — NDim `bugs/KAIF/01` ×2 версии, issue #37; сверка с HEAD —
`researches/24` §2/§4): доставка тикета о дефекте KAIF живёт ПРОЗОЙ шага 4 навыка `/report-bug`,
и классификатор агентской системы отказывает не формулировке, а самому ПРЕДМЕТУ шага — на
Claude Code модуль шага 4 дважды (2.3 и 2.4) не удалось даже записать на диск; три тикета KAGO
и два тикета NDim лежали `Delivered upstream: NOT YET` часами и днями. CN1 сделал исключение из
гейта AUTH ЗАКОННЫМ; SG делает его ИСПОЛНИМЫМ: одна команда, которую система разрешений
человека allowlist-ит один раз, а навык говорит только «запусти».

**Где хотим оказаться.** `node .kaif/kaif-core.mjs report <тикет>` доставляет локальный тикет
`bugs/KAIF/NN_*.md` в origin через `gh`, вписывает URL в строку `Delivered upstream:`, отказывает
с названной причиной на `tracking: anonymous`, без `gh`, на уже доставленном тикете и на тикете
без шапки; шаг 4 `/report-bug` обоих слоёв говорит «запусти команду» и цитирует авторизацию
одной строкой; свод полигона доказывает оба ответа на фикстурном `gh`.

## Готово, когда (критерии приёмки)

1. **Команда существует и доставляет.** `report <путь>` в таблице `COMMANDS` (`mutating: true`,
   `pos: 1`, флаг `--dry-run`): читает `.kaif/kaif.json` → `tracking`/`origin`; читает тикет
   (H1 → заголовок issue; тело файлом через `--body-file`, канон гигиены текста); зовёт
   `gh issue create --repo <owner/repo из origin> --title … --body-file …` со сроком (по образцу
   `tools/send-outbound.mjs`: три исхода — успех · отказ · НЕИЗВЕСТНО при таймауте, и
   «неизвестно» никогда не называется отказом); на успех переписывает строку
   `**Delivered upstream:** NOT YET` на URL и печатает его. *Meter:* свод полигона с подменным
   `gh` на PATH (шим печатает URL и пишет аргументы в файл): после прогона строка тикета несёт
   URL, аргументы шима — `issue create` с заголовком H1.
2. **Четыре отказа названы.** `tracking: anonymous` → «сигнал остаётся локальным; NOT YET здесь
   законно» (exit 2) · `gh` не найден / `gh auth status` красный → причина и команда лечения
   (exit 2) · тикет уже доставлен (в строке URL) → «уже доставлен <URL>» без второго issue
   (exit 0, идемпотентность) · нет H1 или строки `Delivered upstream:` → «не тикет KAIF» (exit 1).
   *Meter:* четыре ассерта свода, каждый по своей фикстуре.
3. **Трейлер авторства в теле.** Issue заканчивается строкой «Filed by the project's agent
   under the KAIF owner's standing authorization (origin issue #15); transport — the `gh`
   account of the deploying machine» — транспорт и авторство как две оси (шаг 4 навыка сегодня).
   *Meter:* греп трейлера в теле, переданном шиму.
4. **Навык говорит «запусти».** Шаг 4 `/report-bug` обоих слоёв (`framework/skills/report-bug`,
   `.claude/skills/report-bug`): на `origin` — `node .kaif/kaif-core.mjs report <тикет>` в том
   же движении, раньше текущей работы (формулировка CN1 сохранена); авторизация — одной строкой
   со ссылкой на issue #15; длинный абзац про классификаторы и оси переезжает в комментарий
   команды и `KAIF_REFERENCE` §10 (предмет шага в тексте навыка сжат до минимума — гипотеза NDim
   «классификатор реагирует на предмет, не на императив»). *Meter:* греп `kaif-core.mjs report`
   в шаге 4 обоих слоёв; `wc -l` шага 4 меньше прежнего (число снять ДО правки, EXP-0053).
5. **Поставка и документы.** `KAIF_REFERENCE` §10 — команда в списке с четырьмя отказами;
   ноты шаблонов и policy-изменение 2.5 в сборщике (INERT до version 2.5); счётчики поставки
   зелёные; `KAIF-CORE.mjs` help печатает команду. *Meter:* `node tools/build-framework.mjs`
   EXIT 0 · `node tools/counters-guard.mjs` · греп `report` в help.
6. **Приёмка полем — отложенный meter.** Обновление 2.4→2.5 на Claude Code переносит модуль
   шага 4 16/16 без divergence note (NDim `bugs/KAIF/01`, «Expected effect»). Проверяется ТОЛЬКО
   полем после релиза — в этом репо не воспроизводимо; фиксируется как ожидание в ответе на
   тикет (эпик RL, черновики ответов).
7. Дерево зелёное целиком: сборка · `npm run test:core` (новый свод s17) · `counters-guard` ·

## Риски (ярусы Мёрфи)

- **(а)** Классификатор агентской системы реагирует на ПРЕДМЕТ, а не на слова (NDim +1) — даже
  «запусти команду» может не записаться на диск при обновлении. Смягчение: текст шага 4 сжат до
  минимума предмета; если поле снова откажет — следующий шаг 2.6: доставку зовёт хук/чекпоинт
  машинерии, а навык не упоминает доставку вовсе.
- **(б)** `gh issue create` от аккаунта владельца выглядит как СЛОВО владельца — трейлер
  авторства обязателен в теле (критерий 3), иначе нарушается ось «идентичность без автора»
  (охота судьи).
- **(б)** Дубли issue при повторном вызове — идемпотентность по строке `Delivered upstream:`
  (критерий 2); дедуп по `kaif-fp` против списка issues — НЕ в этом срезе (сетевой вызов
  списка — 2.6, если поле попросит).
- **(в)** Таймаут `gh` после фактической публикации — исход «неизвестно», не «отказ»; пользователю
  печатается команда ручной проверки (`gh issue list --repo … --search "<H1>"`).

## Решения, принятые агентом без владельца

1. Доставка — действие команды по умолчанию, `--dry-run` — флаг (а не наоборот, как у
   `send-outbound` с `--apply`): у `send-outbound` гейт одобрения владельца, у `report` —
   стоячая авторизация #15; команда и есть тот allowlist-один-раз, о котором просило поле.
2. Дедуп против origin по `kaif-fp` отложен (сеть в полигоне не зовётся; идемпотентность по
   строке тикета закрывает повтор на одной машине).
