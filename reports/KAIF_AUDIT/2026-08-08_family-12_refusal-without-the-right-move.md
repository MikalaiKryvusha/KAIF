**Механизм:** инструмент краснеет или падает, но не называет действие, которым чинится, — и
ближайший доступный ход оказывается либо запрещённым, либо несуществующим. Здесь крайняя грань
класса: вместо диагностики наружу летит сырой стектрейс Node, а восстановительного хода нет ни у

зеркал не стережёт ни один свод.

## F4 — `resyncCopies` пишет зеркала без `mkdirSync`: любой навык, созданный САМИМ проектом, роняет `sync`, оба чек-поинта и ОБА финальных гейта сырым ENOENT

**1. Цитата.** `framework/installer/KAIF-CORE.mjs:1428` (и идентично в поставочном
`dist/KAIF-CORE.mjs:1428`):

```js
    for (const f of canon) { writeFileSync(f.path.replace('.claude/skills', base), f.content); synced++; }
```

`writeFileSync` — сырой импорт `node:fs` (строка 35), обёртки с `mkdir` нет. Фикс ложится сюда же
плюс в zoo-code-ветку строки 1432.

**2. Сценарий провала.** Воспроизведено вживую (песочница скептика):

1. `install --agents claude-code,codex` реальным dist-бандлом;
2. проект заводит собственный навык `.claude/skills/my-project-skill/SKILL.md` — **канон прямо это
   предписывает**: «The canonical skill set lives in `.claude/skills/`; mirrors derive from it
   mechanically» (`KAIF_REFERENCE` §7.3);
3. `node .kaif/kaif-core.mjs sync` → необработанное исключение:
   `errno: -4058, code: 'ENOENT', syscall: 'open', path: '…\.agents\skills\my-project-skill\SKILL.md'`.

`deployAgentSystems` (строка 417) создаёт каталоги только для навыков ИЗ БАНДЛА через `writeIfNew`
(`mkdirSync` на строке 407), поэтому `.agents/skills/my-project-skill/` не появится никогда, а
`resyncCopies` перебирает `readdirSync('.claude/skills')` целиком. Тот же краш убивает финальный
гейт: `verify-final` печатает список недостающих чек-поинтов и падает стектрейсом — установку
закрыть нечем.

**3. Severity.** impact ВЫСОКИЙ (финальный гейт установки/обновления физически непроходим,
диагностика заменена стектрейсом Node) × likelihood СРЕДНЯЯ-ВЫСОКАЯ (достаточно многосистемного
развёртывания — дефолт `--agents` = все пять — и одного навыка, написанного проектом) → **Act**.

**4. Базовая линия.** `новая`. Аттестация: пройдены `bugs/` (включая DONE 11, 13, 27, 34, 49),
полевые отчёты обновлений, `MASTER_PLAN`, `EXPERIENCE`, `KAIF_REFERENCE` §7.3, комментарии у кода —
записанного решения «зеркалим только навыки из бандла» нет нигде; канон утверждает обратное.

**5. Эскиз фикса.** Перед каждой записью зеркала создать каталог тем же способом, что уже применяет
`writeIfNew` (строка 407): `const to = f.path.replace('.claude/skills', base); mkdirSync(dirname(to),
{ recursive: true }); writeFileSync(to, f.content);` — и то же для zoo-code-ветки (строка 1432,
`.roo/commands`). Дополнительно обернуть тело цикла так, чтобы отказ на одном файле называл путь и
команду восстановления, а не выбрасывал ENOENT наружу из финального гейта (это и есть лечение
самого семейства, а не только симптома).

**6. Фикс принят, когда.** Репро из сценария: `install --agents claude-code,codex` → создать
`.claude/skills/my-project-skill/SKILL.md` → `node .kaif/kaif-core.mjs sync` завершается кодом 0,
печатает «↻ re-synced N system skill copies», и `test -f .agents/skills/my-project-skill/SKILL.md`
истинно; `node .kaif/kaif-core.mjs verify-final` доходит до строки `✖ verify-final FAILED: N issues`
вместо `code: 'ENOENT'` в выводе. **Сегодняшнее измеренное состояние:** обе команды падают
стектрейсом — критерий различает починку от текущего поведения, дополнительных замеров не требует.

**7. Не трогать.** Анонимное развёртывание обязано по-прежнему пропускать ORIGIN_TIED-навыки при
ресинке (строка 1417). Зеркала систем, которых нет в `agents` маркера, обязаны по-прежнему НЕ
создаваться (строка 1427). Для zoo-code обязана сохраняться срезка строки `name:` (строка 1432).

**8. Мета.** Семейство 12 (первый слой) + 9 «механика ходит по нормальному состоянию дерева».
Родня: `bugs/33`, `bugs/27`, `bugs/40`, `EXP-0008`, `EXP-0011`. Свод для покрытия — профиль
многосистемного развёртывания.
