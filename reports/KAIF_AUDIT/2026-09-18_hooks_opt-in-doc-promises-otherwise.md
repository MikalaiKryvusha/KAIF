## F9 — Дымовая проба подключения не исполняется на платформе владельца: ни в PowerShell, ни в `cmd`

**1. Цитата.**
`framework/hooks/README.md:36`
```
   `node .kaif/hooks/prompt-refresh-timer.mjs < /dev/null` with no `.kaif/refresh-marker.json`
```
`framework/hooks/README.md:40`
```
   `printf '{"prompt":"resume\\nplan the day"}' | node .kaif/hooks/prompt-resume-word.mjs` must print
```

**2. Сценарий провала.** Владелец проекта на Windows открывает единственный документ подключения и
исполняет шаг 3 «Smoke» дословно. PowerShell 5.1: `ParserError: The '<' operator is reserved for future
use.` — скрипт не стартует вовсе. `cmd /c "node …prompt-refresh-timer.mjs < /dev/null"` → `The system
cannot find the path specified.`, exit 1. `printf` в PowerShell отсутствует (`Get-Command printf` → не
найдено), поэтому вторая проба невыполнима ни в одной из двух родных оболочек Windows. При этом сами хуки
кросс-платформенны: `cmd /c "… < NUL"` и `'' | node …` в PowerShell печатают приказ — цена лежит ровно в
тексте документа. Документ уже оплатил полевой урок про эту же пробу («a two-minute timeout on the first
try», `:38-39`) — и починил его только для POSIX; слова Windows/PowerShell/cmd в модуле нет ни одного.

**3. Тяжесть.** Влияние средне-высокое (единственный документ подключения на платформе владельца не
исполняется, а провал читается как дефект модуля) × вероятность высокая (исток и поле — Windows) →
**Act**.

**4. Базовая линия.** `known: EXP-0121` (#harness #escaping — как класс «текст через файлы»), плюс
профиль хоста, записанный в каноне: `AGENT_GUIDE.md:239-240` (PS 5.1 Desktop, pwsh 7 не установлен),
`framework/AGENT_GUIDE.md:790-792` («Know WHICH shell you are in; record in the project docs which shell
the build runs from»), `framework/tools/kaif-canon-lint.mjs:66` (адрес исправлен по судье — прежняя
редакция называла `tools/kaif-canon-lint.mjs:66` без префикса `framework/`; текст строки верен)
(«CRLF checkouts and PS5.1 Out-File BOMs are the
documented Windows profile of real projects»).
`Dedup attestation:` греп `windows|powershell|cmd\.exe|BOM|CRLF` по `framework/hooks/` → 0; `/dev/null`
по `framework/**/*.md` → только `README.md:36` и `framework/skills/kaif-version/SKILL.md:28` (там
`2>/dev/null` в фенсе ```bash со словом «e.g.» — жанр примера, не пробы); история строки —
`plans/86_DONE:221` и `plans/87_DONE:196` (R5: `< /dev/null` вписан ради починки зависания на stdin,
Windows не назван ни словом); ассертов на строки Opt-in — 0.
`kaif-fp: hooks-readme :: opt-in-smoke-not-runnable-on-the-owner-shell :: v2.7`

**5. Эскиз починки.** В разделе «Opt-in» дать пробу ДВУМЯ строками на систему: POSIX (как сейчас) и
Windows — `'' | node .kaif\hooks\prompt-refresh-timer.mjs` (проверено: печатает приказ) или
`cmd /c "node … < NUL"`. Событие четвёртого хука подавать ФАЙЛОМ (`node … < event.json`, рядом готовый
`event-sample.json`), а не строкой с `\n` в argv — на Windows это ещё и обходит BOM (F6). Добавить строку
«если позитивный случай молчит — сначала проверьте, что JSON валиден: сырой перевод строки внутри строки
JSON рвёт парс молча».

**6. Починка принята, когда.** Суд (расширение `s14` или проверка README) исполняет КАЖДУЮ командную
строку раздела «Opt-in» в обеих оболочках прогонного хоста и сверяет вывод с обещанным («печатает приказ»
/ «печатает ничего»); минимальная форма — пара `check-framework` требует в README токен Windows-формы.
**Измерено 2026-09-18 08:47 → 08:49 +03:00 (исполнитель):** PowerShell — `ParserError: The '<' operator is
reserved for future use.`; `Get-Command printf` → NOT FOUND; Git Bash — строка 36 печатает приказ (exit 0),
строка 40 ИЗ ФАЙЛА печатает приказ `/resume`; ассертов на строки Opt-in — 0, упоминаний Windows в модуле —
0. Скептик независимо: то же плюс `cmd` (`The system cannot find the path specified.`, exit 1) и
Windows-эквиваленты, которые работают.

**7. Не трогать.** Сами хуки — они кросс-платформенны (`node:path`, `tmpdir()`). POSIX-форму пробы не
удалять (она работает). Текст полевого урока про двухминутный таймаут оставить.

**8. Мета.** 2026-09-18. Сужение по скептику принято: половина находки «проба рассыпается в руках агента
из-за экранирования» — **REFUTED**, это названный датированный урок `EXP-0135` (тот же эпик RS, 2026-09-18),
квалифицированный как правило рук класса `EXP-0121`, плюс канон `AGENT_GUIDE.md:830` («текст передаётся
через файлы, а не через аргументы командной строки»). Остаётся первая половина: две владельческие строки
пробы не исполняются на объявленном профиле хоста. Связано с F6 (BOM — тот же путь на Windows).

## F10 — «Каждый хук несёт предикат И cooldown» — ложное придаточное в документе подключения, опровергаемое своей же страницей

**1. Цитата.**
`framework/hooks/README.md:19-20`
```

predicate and a cooldown; injections are ORDERS to re-read, never document bodies (the output
```
Опровержение той же страницей — `framework/hooks/README.md:14` (колонка «Predicate (anti-noise)»):
```
| `session-start-refresh.mjs` | `SessionStart`, matcher `compact\|clear` | none — compaction is itself rare | injects the ORDER to re-read the re-read core + stamp the witness |
```
и шапкой поставленного скрипта — `framework/hooks/prompt-resume-word.mjs:16`:
```

```

**2. Сценарий провала.** Абзац поднимает утверждение до уровня «canon requirements» и не несёт оговорки

**3. Тяжесть.** Влияние низкое (решение о подключении и ожидания владельца, не поведение машинерии) ×
вероятность высокая (абзац стоит сразу под главной таблицей) → **Attend**.

**4. Базовая линия.** `known: bugs/71` (правило канона объявлено механизированным без исполнителя).
`Dedup attestation:` греп `cooldown` по `framework/hooks/` — `README.md:20` (общее утверждение),
`prompt-resume-word.mjs:16` («No cooldown»), `prompt-refresh-timer.mjs:11` («Cooldown: the marker

**5. Эскиз починки.** Переписать утверждение по наблюдаемому: «каждый хук несёт предикат ИЛИ объявленную

`resume` повторяются НАМЕРЕННО — цена названа в их шапках». Плюс четвёртая колонка «Cooldown» в таблицу

**6. Починка принята, когда.** Пара `check-framework` («hooks README ↔ шапки хуков») требует, чтобы слово

**7. Не трогать.** Сами предикаты и отсутствие cooldown у таймера и `resume`-хука — осознанный размен с

## F11 — `[TESTED]` таймера называет свидетелем свод, который четвёртого перечисленного свойства не подаёт

**1. Цитата.**
`framework/hooks/prompt-refresh-timer.mjs:22-24`
```
// [TESTED: 2026-08-07 · polygon s14: fresh marker → silent; missing marker → order ("no refresh
//  witness"); marker older than the interval → order naming the age; MALFORMED marker → judged by
//  the file's mtime instead, so malformed+fresh is SILENT and malformed+old speaks]
```
Свидетель, на которого ссылается маркер, целиком — `tools/sandbox/s14-refresh-hooks.mjs:113`:
```
writeFileSync(marker, 'not json at all');
```

**2. Сценарий провала.** Маркер называет наблюдением полигон и вешает на него ЧЕТЫРЕ свойства, включая
«malformed+old speaks». В своде битый маркер пишется один раз и только при СВЕЖЕМ mtime (`utimesSync` в
`s14` касается только `STATUS.md`), ассерта «битый маркер + старый mtime → приказ с возрастом» нет, и
отчёта-свидетеля тоже нет (`grep -rln "prompt-refresh-timer" testcases/` → 0). Половина заявленного
наблюдения не наблюдалась: регрессия в ветке фолбэка оставила бы свод зелёным, а канонный триггер «раз в
час» умер бы молча именно там, где маркер испорчен. Класс тот же, что ложный `[TESTED]`: заявление шире
наблюдения (`TESTING_FRAMEWORK.md` — «проверено наблюдением, улика названа»).

**3. Тяжесть.** Влияние низкое (сегодня код ведёт себя как заявлено — наблюдено) × вероятность низкая
(нужна регрессия в этой ветке) → **Track**.

**4. Базовая линия.** `new` в оси маркеров зоны; класс — `TESTING_FRAMEWORK.md` (ложный `[TESTED]` /
заявление шире наблюдения).
`Dedup attestation:` четыре маркера `[TESTED]` в `framework/hooks/*.mjs`; у `prompt-resume-word.mjs:30-38`
наблюдение названо АДРЕСОМ отчёта (`testcases/reports/2026-09-18_hook-resume-word.md`, прогон 17) — эталон;
у трёх хуков 2.2 свидетель — только полигон, и у таймера перечень шире того, что полигон читает; фикстур
битого маркера в своде — 1 (`grep -c "not json at all"` → 1).
`kaif-fp: hooks-timer :: tested-marker-wider-than-the-suite :: v2.7`

**5. Эскиз починки.** Один ассерт в `s14` рядом со строкой 115: битый маркер + `utimesSync` на 2 часа
назад → приказ, называющий возраст (`/last refresh 1\d\d min ago/`). Равноправная честная альтернатива —
сузить текст маркера до трёх наблюдённых свойств; класс лечится любой из двух, но не обеими половинами
сразу.

**6. Починка принята, когда.** `s14` содержит ассерт на пару (битый маркер, СТАРЫЙ mtime) и краснеет на
мутанте-эталоне `if (Number.isNaN(at)) { statSync(markerPath); at = Date.now(); }` (битый маркер
читается как «только что освежились», отсутствующий по-прежнему бросает) — именно на нём, а НЕ на удалении
фолбэка целиком: удаление ломает ещё и ассерт отсутствующего маркера и краснеет по другой причине.
**Измерено 2026-09-18 09:09 +03:00 (исполнитель):** битый маркер + свежий mtime → тишина (единственный
ассерт свода, `:113-115`); битый маркер + mtime 2 ч назад → приказ «last refresh 120 min ago» (то есть
свойство сегодня ЖИВО, но не наблюдается сводом); фикстур битого маркера — 1; `utimesSync` в своде —
только на `STATUS.md` (`:154`, `:164`, `:168`). Скептик независимо: тот же результат плюс мутант
`at = Date.now()` — `s14` EXIT 0, 68 ✅, все четыре ассерта таймера зелёные.

**7. Не трогать.** Ассерт `:115` (свежий + битый → тишина) — он несёт ДРУГОЕ свойство; сам фолбэк на
mtime; маркер `prompt-resume-word.mjs` — он образцовый (наблюдение + адрес отчёта).
