## F4 — `cwd` события ниже корня проекта: таймер нагнетает вечно, страж STATUS молчит вечно — один и тот же неизвестный обработан в противоположные стороны

**1. Цитата.**
`framework/hooks/prompt-refresh-timer.mjs:63`
```
  const markerPath = join(cwd, MARKER);
```
Зеркальная половина — `framework/hooks/stop-status-guard.mjs:45-46`:
```
  const statusPath = join(cwd, STATUS_FILE);
  if (!existsSync(statusPath)) process.exit(0);   // no STATUS.md — nothing to guard
```
Проводка, которая корень ЗНАЕТ и не передаёт — `framework/hooks/settings-fragment.json:23`:
```
            "args": ["${CLAUDE_PROJECT_DIR}/.kaif/hooks/prompt-refresh-timer.mjs"],
```

**2. Сценарий провала.** Событие несёт `cwd` рабочей директории агентской системы. По ЖИВОЙ доке
Claude Code `cwd` — «current working directory when the hook is invoked», и отдельный раздел «Hook
paths don't follow the worktree» говорит: после входа в worktree `cwd` — корень worktree, после `cd`
модели — новый каталог, тогда как `${CLAUDE_PROJECT_DIR}` остаётся корнем проекта. Тогда
`join(cwd, '.kaif/refresh-marker.json')` не существует → `ageMin = Infinity` → таймер впрыскивает
приказ «no refresh witness found this session» в КАЖДЫЙ промпт, и послушание его не гасит: агент
штампует маркер там, где хук не смотрит. Тот же неизвестный у стража STATUS обработан наоборот: в
подкаталоге `STATUS.md` нет → `exit 0` молча, то есть единственный блокирующий хук модуля выключается
тем же условием. Живая улика: в ЭТОЙ сессии (worktree истока, хуки подключены в `.claude/settings.json`)
событие с `cwd` рабочего дерева даёт приказ «no refresh witness», хотя маркер корня свеж.

**3. Тяжесть.** Влияние среднее (контур канона либо превращается в неустранимый шум в каждом промпте,
либо выключается — оба состояния неотличимы от неподключённого модуля) × вероятность средняя (worktree
и любой `cd` модели — прямо в доке вендора как известная ловушка) → **Attend**.

**4. Базовая линия.** `new`.
`Dedup attestation:` грепнуто `CLAUDE_PROJECT_DIR` по `framework/hooks/` — только `settings-fragment.json`
(`args` трёх записей), ни один скрипт его не читает; `input.cwd` — два сайта
(`prompt-refresh-timer.mjs:60`, `stop-status-guard.mjs:35`; `session-start-refresh.mjs` `cwd` не
использует вовсе); греп `из корня проекта|from the project root` по `AGENT_GUIDE.md`,
`framework/AGENT_GUIDE.md`, `README.md`, `framework/hooks/`, `framework/installer/KAIF-CORE.mjs` → 0;
греп `\bcwd\b` по `bugs/ ideas/ interviews/` → ни одного документа об этой оси; в `s14` все прогоны
подают `cwd` равным корню песочницы.
`kaif-fp: hooks-state-resolution :: event-cwd-not-project-root :: v2.7`

**5. Эскиз починки.** Искать корень проекта ВВЕРХ от `cwd` (первый каталог, где есть `.kaif/` или
`STATUS.md`), либо читать корень из окружения, когда система его даёт (`CLAUDE_PROJECT_DIR`; у Grok в
контракте — отдельный `workspaceRoot`/`GROK_WORKSPACE_ROOT`, `researches/19:154`), и только затем падать
на `cwd`. В `s14` — по ассерту на хук: событие с `cwd` = подкаталог даёт ТОТ ЖЕ вывод, что событие с
`cwd` = корень.

**6. Починка принята, когда.** Проба на копии модуля: событие с `cwd` = `<корень>/src/deep` при СВЕЖЕМ
маркере в корне даёт ТИШИНУ у таймера, а у стража STATUS при протухшем `STATUS.md` в корне и грязном
дереве — БЛОК. **Измерено 2026-09-18 08:53 +03:00 (исполнитель):** `cwd` = корень → тишина; `cwd` =
`src/deep` → приказ «no refresh witness found this session»; страж с `cwd` = `src/deep` → тишина (то
есть обе половины сегодня неверны). Скептик независимо получил то же плюс улику на реальном дереве
истока.

**7. Не трогать.** Фолбэк `cwd = process.cwd()` при нечитаемом stdin. Правило «не краснеть там, где не
наблюдаем» (не-git проект; проект, где `STATUS.md` нет ВООБЩЕ — законная тишина). Тишину таймера на
свежем маркере.

**8. Мета.** 2026-09-18. Поднято ИСПОЛНИТЕЛЕМ прогона (ни один из двух ревизоров этой оси не назвал) —
и это само по себе улика: ось «поле события означает не то, что нужно» видна только тому, кто держит в
руках проводку и контракт вендора одновременно. Оплаченные классы: `EXP-0042` (портируемость решает не

## F5 — `at` в БУДУЩЕМ глушит часовой таймер, и объявленный фолбэк на mtime не включается

**1. Цитата.**
`framework/hooks/prompt-refresh-timer.mjs:70`
```
    if (Number.isNaN(at)) at = statSync(markerPath).mtimeMs;
```
Обещание над ней — `framework/hooks/prompt-refresh-timer.mjs:64-65`:
```
  // Age of the last refresh: the marker's own `at` field is the truth; a malformed field falls
  // back to the file mtime; a missing file means "never refreshed" → infinitely stale.
```

**2. Сценарий провала.** Маркер пишет ТОТ САМЫЙ агент, которого таймер стережёт — приказ хука велит
проштамповать `{ "at": "<ISO>", … }` от руки. Дата в будущем парсится успешно, поэтому она не
«malformed», фолбэк на mtime не включается, `ageMin` уходит в минус, предикат ложен — хук молчит. Молчит
он не потому, что предикат не выполнен, а потому, что сравнил не то. Достижимо штатным путём: ISO с
неверной зоной (`…T11:00:00Z` вместо `+03:00` даёт 3 ч в будущее), опечатка в годе, часы машины впереди.
Класс «метка опережает свой момент» в проекте оплачен буквально в этой версии (`bugs/78_DONE`;
инструмент `tools/refresh-stamp.mjs`, снимающий момент сам, живёт ТОЛЬКО в истоке — в поставке его нет,
`grep -c refresh-stamp dist/KAIF-FULL.md dist/KAIF-CORE-BUNDLE.md` → 0 и 0).

**3. Тяжесть.** Влияние средне-высокое (механическая половина контура освежения выключается бесшумно) ×
вероятность низкая-средняя (нужен один неверный штамп; штампует модель от руки) → **Attend**.

**4. Базовая линия.** `new`; родственный оплаченный класс — `bugs/78_DONE` (страж проверял форму метки, а
не правду).
`Dedup attestation:` верхней границы у `at` нет нигде; греп `future date|in the future|> Date.now()` по
`tools/ framework/ --include=*.mjs` → единственный хит `tools/doc-header-lint.mjs:411` (ось метки «не в
будущем» с допуском) — она судит md-шапки против их коммитов и `.kaif/refresh-marker.json` не читает
вовсе; греп `refresh-marker` по дереву (без `dist/`) — маркер упоминают каноны, хуки,
`tools/refresh-stamp.mjs`, охоты судьи и планы, осей ПРОВЕРКИ маркера нет; в `s14` состояний маркера
четыре, будущего среди них нет.
`kaif-fp: hooks-state-resolution :: marker-timestamp-in-the-future :: v2.7`

**5. Эскиз починки.** Одна строка: `if (Number.isNaN(at) || at > Date.now() + 60_000) at = statSync(markerPath).mtimeMs;`
(допуск на дребезг часов назван). В `s14` — ассерт: `at` = now +2 ч при mtime старше интервала → приказ,
называющий возраст по mtime.

**6. Починка принята, когда.** Проба на копии: `at` = +1 год и `at` = +2 ч печатают приказ, `at` = now
остаётся тишиной, `at` = 5 ч назад печатает приказ (контроль).
**Измерено 2026-09-18 08:51 +03:00 (исполнитель):** `at` = +1 год → тишина; `at` = 2030-01-01 → тишина;
контроль `at` = 5 ч назад → приказ. Скептик независимо: семь состояний, включая контроль на фолбэк
(`""`, `null`, отсутствующее поле → приказ).

**7. Не трогать.** Фолбэк «битый `at` → mtime» и тишину на свежем маркере (`s14:112`, `s14:104`); приказ
`no refresh witness` при отсутствии маркера (`s14:100`); не начинать валидировать `docs`/`trigger` — вторую
половину улики ловит судья, не хук.

**8. Мета.** 2026-09-18. Сужение по скептику: «глушит навсегда» верно для далёкой даты; при дребезге +2 ч
тишина длится смещение плюс интервал. Судьи, которые ловят ложный маркер постфактум, есть
(`framework/skills/fable-judge/SKILL.md:49` «Refresh witness», `:65` «Resume word ignored») — они СНИЖАЮТ
тяжесть, но не опровергают: хук молчит независимо от них. Связано с F4 и F6.

## F6 — Три байта BOM перед событием обнуляют предикат: `/clear` штампуется как «compaction», четвёртый хук становится no-op, и ни один ассерт этого не подаёт

**1. Цитата.**
`framework/hooks/prompt-resume-word.mjs:68`
```
    const input = JSON.parse(readFileSync(0, 'utf8') || '{}');
```
Та же строка — `session-start-refresh.mjs:53`, `prompt-refresh-timer.mjs:59`, `stop-status-guard.mjs:34`.
Оплаченный класс рядом, в той же поставке — `framework/installer/KAIF-CORE.mjs:148`:
```
// JSON reader tolerant of a UTF-8 BOM (Windows tools like PowerShell 5 write one).
```

**2. Сценарий провала.** Windows PowerShell 5.1 ставит `EF BB BF` перед ЛЮБОЙ строкой, поданной в
native-команду (измерено: строка через пайп, `Write-Output`, `Get-Content`, `cmd /c "… < file"` —
все с BOM; чистый только `cmd /c "echo … |"`). `JSON.parse` на таком вводе падает, `catch` оставляет
дефолты — и хук печатает НЕ ТО, оставаясь внешне корректным:
`session-start-refresh` с событием `source: "clear"` приказывает штамповать `trigger "compaction"` и
говорит «the context was just compacted» (ровно то свойство, ради которого в `s14:92-97` живёт находка
судьи фазы O3); `prompt-resume-word` молчит (no-op, неотличимо от неподключённого);
`stop-status-guard` съезжает на `unknown-session` и `process.cwd()`; таймер теряет `cwd` события и
может дать ложную тревогу. Путь достижения назван поставкой: дымовая проба
`framework/hooks/README.md:40` — конвейер строки в `node`, а в PowerShell `printf` нет, и естественный
перевод («строку в пайп») BOM'ится.

**3. Тяжесть.** Влияние высокое (молчаливое обнуление предиката при виде подключённого модуля) ×
вероятность средняя — с честной границей: **не живая проводка Claude Code** (она пишет stdin сама, без
BOM), а ручной прогон, обёртка или дымовая проба на Windows → **Attend**.

**4. Базовая линия.** `known: EXP-0007` (#windows #installer: PowerShell пишет UTF-8 с BOM → `JSON.parse`
падал → инсталлятор молча пересоздавал `package.json` владельца; правило урока — «на Windows любой
JSON-парс входных файлов только BOM-терпимым ридером»).
`Dedup attestation:` правило проведено в `framework/installer/KAIF-CORE.mjs:149`, `tools/commit.mjs:107`,
`framework/tools/contour/core.mjs`, `kaif-canon-lint.mjs`, `kaif-attribution-lint.mjs`,
`kaif-provenance.mjs`, `tools/questions-guard.mjs`; греп `bom|feff|byte order` по `framework/hooks/` → 0;
пересечение «bom» × «hook|stdin» по `bugs/ ideas/ interviews/ plans/` → 0; `feff|BOM` по
`tools/sandbox/` → ни одного файла (ни один свод не подаёт хуку BOM).
`kaif-fp: hooks-stdin :: bom-breaks-the-predicate :: v2.7`

**5. Эскиз починки.** Один однострочник в четырёх хуках — снять ведущий U+FEFF перед `JSON.parse` (та же
процедура, что принята в `tools/commit.mjs:107`). В `s14` — по ассерту на хук: событие с BOM даёт
ПОБАЙТНО тот же вывод, что событие без него (для `session-start` — именно `trigger "ritual:/clear"`).
**Класс шире четырёх хуков** (проверено скептиком своим сканом 144 мест `JSON.parse` внешнего входа):
BOM не снимают и ридеры МАРКЕРОВ — `framework/hooks/prompt-refresh-timer.mjs:69`,
`framework/tools/kaif-testrun-lint.mjs:178`, `framework/tools/kaif-voice-lint.mjs:317,323` — и
`framework/installer/KAIF-CORE.mjs:3575` (`.kaif/kaif.json`), при том что `readJson` на `:149` ТОГО ЖЕ
файла BOM снимает; плюс `KAIF-CORE.mjs:1811,3499`, `KAIF-LOADER.mjs:97`, `contour/review.mjs:805,1144`.
Починка только хуков закрывает класс наполовину.

**6. Починка принята, когда.** `s14` подаёт каждому из четырёх хуков одно событие в двух лицах (с BOM и
без) и сверяет выводы на равенство; красный доказан снятием фикса в любом из четырёх.
**Измерено 2026-09-18 09:02 +03:00 (исполнитель):** событие `source:"clear"` без BOM → приказ с
`"trigger": "ritual:/clear"`; то же событие с BOM → приказ с `"trigger": "compaction"`;

независимо: та же таблица четырёх хуков + измеренные байты stdin из PowerShell (`ef bb bf`).

**7. Не трогать.** Политику «непонятный ввод → тишина/дефолт, exit 0» (канон модуля); фолбэк таймера на
`process.cwd()`; существующие чистые фикстуры `s14` — добавлять ВТОРОЕ лицо события, не переписывать

**8. Мета.** 2026-09-18. Оплаченные классы `EXP-0007`, `EXP-0133` (зелено на своей чистой фикстуре).
