## Что ты делаешь

1. Прочитай планы своего кластера (список — в частной части): вектор цели, «Готово, когда», отметки `✅` под шагами, «Решения, принятые

   `plans/117_EPIC_kaif_2.8.md` (номера — в частной части). Каждый эпик уже прошёл лёгкого судью, и его находки починены — прочитай и их.
2. Собери РЕЕСТР ЗАЯВЛЕНИЙ кластера: строка на заявление — источник (`файл` крит./строка) · команда переисполнения · ожидаемое. Бери
   несущие заявления: каждая строка «Проверка» критерия, каждое число в отметке `✅`, каждое «красное доказано», каждое «в обоих
   слоях», каждое `[TESTED: …]` новых файлов эпика. Ориентир — 12–25 строк на кластер; приоритет — то, что владелец или поле увидят руками.
3. ПЕРЕИСПОЛНИ каждое заявление (прогон · счёт · дифф · греп). Перечитать — не переисполнить. Вердикт строки: `CONFIRMED` · `WEAKENED`
   (заявление живо, но проверка слабее заявленного, число разошлось, дыра рядом) · `REFUTED` (не воспроизвелось — приложи вывод).
4. Пройди ОХОТЫ судьи (`.claude/skills/fable-judge/SKILL.md`, шаг 4 — классические и весь KAIF-блок): назови ПОИМЁННО применимые и исход
   каждой («находок нет» — тоже исход). Обязательные: ослабленные проверки (`git log -p --since=2026-09-24 -- <своды и стражи кластера>`) ·
   заявление шире наблюдения · `[TESTED]` без отчёта прогона · гигиена, доложенная как тест · решение агента в одежде слова владельца ·
   стоячая ложь (утверждение, которое позднейший коммит опроверг, а текст остался).
5. Второй угол (парадокс пестицида): на каждый эпик — хотя бы ОДНА проверка, которой в плане НЕТ: адресный мутант на копии, путь
   пользователя по развёрнутой копии (`install` из `dist` во временный каталог → команда → прочитанный вывод), граничное значение,
   второй язык поставки.

## Правила суда (нарушение = твой результат не принимается)

- **Работай в своём клоне:** `git clone D:/work/ai_sandbox/KAIF <временный каталог ОС>` → `git -C <клон> remote remove origin`.
  Репозиторий-оригинал не правишь и не коммитишь; исполнитель работает в нём параллельно.
- **Никогда не пиши `git config`** ни в оригинале, ни в его связанных worktree (они делят `.git/config` — так случился `bugs/124`);
  личность для своих коммитов в песочнице — только переменными `GIT_AUTHOR_*` / `GIT_COMMITTER_*` или в своём `git init`.
- **Тишина у владельца.** Ни одного окна и ни одного звука: контур — только `node tools/review.mjs --selftest` и
  `node tools/review.mjs <док> --check`; НИКОГДА без `--check`, НИКОГДА `--no-open`, НИКОГДА `--queue` без `--list`, `--call` — только
  с `--dry-run`. Шов `KAIF_DIST=<старая сборка>` НЕ применяй к сводам контура (`s12`, `s22`) и к любому своду, который зовёт генератор
  страницы (`bugs/116`). `node tools/verify-contour.mjs` — только с `--etalon-only`.
- **Полигон целиком (`npm run test:core`) не гоняешь.** Отдельный свод — по одному за раз; нативный крах (`status 3221226505`) —
  повтори ОДИН раз и доложи оба исхода. Сборку (`node tools/build-framework.mjs`) — только в своём клоне.
- **Числа — только из вывода инструментов**; лог — в файл во временном каталоге; каждая находка несёт дословную цитату `файл:строка`.
- **Скрипты правок и проб — файлом**, запуск по пути: инструмент Bash снимает уровень экранирования. Не-ASCII в argv не передавай.
- **Соседние развёртывания на диске** — только чтение (копии — через `git archive`); имена проектов в отчёте — псевдонимами
  (деревья A–D, `project A…F`), без имён людей (правило №90).
- **Сеть:** `gh` — только чтение; ничего не отправляй и не закрывай.
- **Время** — пробой `date '+%Y-%m-%d %H:%M %z'` в момент записи. Ориентир по времени — около сорока минут; не переисполненное назови.
