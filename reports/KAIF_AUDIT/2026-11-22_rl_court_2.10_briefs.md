### Context and boundaries

1. Work in your own temporary clone: `git clone D:/work/ai_sandbox/KAIF <unique-temp-path>` then remove its `origin` remote. The origin checkout
   is read-only for you. Do not commit, push, send, publish, close issues or change any global/user config.
2. The origin working tree contains new RL0/RL1 documents not yet in HEAD. Copy the registry and briefs into your clone only if needed for
   reading; do not treat their absence from HEAD as a product defect.
3. Silence: no windows and no sound. Contour only `--selftest`, `<doc> --check`, `--queue --list`, or `--call ... --dry-run`; never a bare page
   launch. `verify-contour` only `--etalon-only`. Set `KIMI_CODE_HOME` to a nonexistent temp path for suites. Do not edit the owner's real Kimi
   config or invoke a fresh paid model run.
4. Do not run the full polygon and do not run two heavy suites concurrently. Build only inside your clone. A native Node crash
   `3221226505` is repeated once and both outcomes reported.
5. Real session wires/logs and neighboring deployments are read-only evidence. Do not print private project names or owner secrets. Use paths
   already cited in public run reports where possible. Do not open `.env`, credentials or unrelated private files.
6. Every finding needs an exact `file:line` quote plus command/output evidence. Mechanical existence/count checks come before judgment. Then try
   to refute the finding; doubt defaults to `REFUTED`, not to a product defect.
7. A release blocker is limited to a reproducible failure of criteria 37–40 or publication safety: install/update failure, owner-data loss,
   false ready claim on the shipping path, undeclared window/sound, or a false release claim. A stale working-document number is a caveat, not
   automatically a blocker.
8. Do not modify product code or tests. Return evidence and the smallest suggested correction. The orchestrator owns fixes and the registry.
9. Time-box to about 40 minutes. Anything not re-executed is `NOT-RUN`, never silently green. Numbers come only from tool output.

### Required work

1. Read `plans/136` criteria for your cluster, `plans/141`, the relevant operational plans and run reports. Read your assigned registry rows.
2. Re-execute every assigned row. For live claims, a deterministic check of the actual recorded Kimi event/wire is valid re-execution; directly
   invoking a hook script is not live evidence.
3. Run the applicable judge hunts: weakened checks · claim wider than observation · tested without a run report · hygiene presented as a
   functional test · agent decision dressed as owner word · standing falsehood · fork without recon · refresh witness · done without the real
   world. Name applicable hunts and their outcomes.
4. Add one second-angle check not written in the plan: a boundary input, negative control, real installed-tree path, or a consistency comparison.
   Do not invent a large new test program.
5. Report REAL WORLD explicitly: what accumulated owner state was actually inspected and what was only a clean temporary stand.
