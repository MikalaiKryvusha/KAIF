## 2. Грабли

### Грабля 1 (главная). `i18n: translated` отключает замену, но НЕ отключает вставку модулей — английский текст попал в русские файлы

Тот же прогон, две строки лога подряд, противоречащие друг другу:

```
⟳ marker declares i18n: translated — mechanical replacement disabled for files carrying the owner's script; upstream changes ship as per-module diffs
...
↻ merged 3 module(s) into .claude/skills/kaif-remove/SKILL.md (1 kept for you)
↻ merged 4 module(s) into .claude/skills/pause/SKILL.md (1 kept for you)
```

Что оказалось в файле (`git diff .claude/skills/pause/SKILL.md`) — английский блок **над** русским
заголовком, дублирующий его же содержание:

```diff
+## Step 1. Reach a logical stopping point — never park mid-surgery
+
+Finish the smallest coherent unit of the work in flight: the tree must **build green and pass its
+checks**. ...
+
 # /pause — мягкая парковка чата (продолжаем ЗДЕСЬ же)
```

`kaif-remove` — то же самое: +51 строка английского перед русским H1.

**Отягчающее обстоятельство:** шаблоны обоих файлов между 2.0 и 2.1 **не менялись вообще**.
Проверено хешами распакованных бандлов:

```
.claude\skills\kaif-remove\SKILL.md : template 2.0 == 2.1 : True
.claude\skills\pause\SKILL.md       : template 2.0 == 2.1 : True
```

То есть машинерия вписала английский текст в русские файлы ради нулевого апстрим-изменения.

**Воспроизведение:** развёртывание с `"i18n": "translated"`, где переведены заголовки; любой файл,
у которого сигнатура H1 не совпадает с шаблонной → модули «вставляются рядом». Формально это тот же
класс, что и `bug 26` (placeholder-signature drift), но в 2.1 он бьёт по файлам, у которых **нечего**
было обновлять.

**Что я сделал:** `git restore` обоих файлов. Потери — нулевые, потому что вставка была шумом.
Но заметить это можно было только сверкой с бандлом 2.0 вручную.

### Грабля 2. `PHILOSOPHY.md`: 19 модулей объявлены «NEW module in this release» при нулевом изменении шаблона

`KAIF_UPDATE_TASK.md` (строки 51–320, ~270 строк из 352) требует слить 19 модулей, каждый с меткой:

```
**module:** `## Occam's Razor` — NEW module in this release (not inserted — i18n: translated)
```

Проверка:

```
PHILOSOPHY.md : template 2.0 == 2.1 : True
```

Шаблон `PHILOSOPHY.md` байт в байт одинаков в 2.0 и 2.1; в списке из 43 изменившихся файлов его нет.
«NEW module in this release» здесь означает не «новое в релизе», а «модуля с такой сигнатурой нет в
твоём файле» — а его там нет ровно потому, что заголовок переведён на русский.

**Цена:** 77% задания — диффы, которые не нужно сливать. Слабая модель либо честно вставит 19
английских блоков в русский документ (регресс), либо привыкнет игнорировать задание целиком. Оба
исхода хуже, чем отсутствие пункта.

**Воспроизведение:** `i18n: translated` + любой документ с переведёнными заголовками ⇒ все его
модули помечаются NEW при каждом обновлении, независимо от апстрима.

### Грабля 3. `stale-claims`: 16 строк, из них по существу — 3. Сканер не отличает версию ФРЕЙМВОРКА от версии ПРОДУКТА

Задание перечислило 16 строк «still assert the OLD version (2.0)». Разбор:

| Категория | Строк | Пример дословно |
|---|---|---|
| Настоящее устаревание | 3 | `KAIF_FRAMEWORK.md:59 — \| **Версия KAIF** \| `2.0` «Excellent KAIF»` |
| **Версия ПРОДУКТА, а не KAIF** | 6 | `GOAL.md:25 — начинаем строить условный NDim Space 2.0`; `MASTER_PLAN.md:34`; `AGENT_GUIDE.md:266, 753` |
| Законная историческая провенанс-ссылка | 3 | `AGENT_GUIDE.md:703 — (приехали с 2.0)`; `KAIF_FRAMEWORK.md:51` |
| Летописные записи (их же переносит миграция) | 4 | `STATUS.md:2015–2035` — запись об обновлении до 2.0 |

Точность ≈ 19%. Худший пункт — **`GOAL.md`**: это документ владельца, который машинерия во всех
остальных местах принципиально не трогает («GOAL.md — the owner's document, the agent did not fill
it in»), а `stale-claims` предлагает его править. У нас проект называется «NDim Space 2.0», и
совпадение с номером релиза KAIF превращает сканер в генератор ложных срабатываний.

**Воспроизведение:** любой проект, чья собственная версия совпадает с номером релиза KAIF.
Достаточно `grep -n '2\.0' *.md` без проверки, что рядом стоит маркер фреймворка.

### Грабля 4. Порядок пунктов: `stale-claims` сканирует STATUS ДО миграции летописи, которую предписывает то же задание

Пункт `merge-modules` / `stale-claims` отрабатывает по STATUS «как есть», а релиз-новость того же
задания говорит:

```
MIGRATION — agent work, not machinery: move the overgrown history out of your STATUS into
PROJECT_HISTORY (machinery cannot judge what counts as history; do it once, by the /end-chat rules)
```

В итоге 4 из 16 stale-claims указывают на строки, которые через два пункта уедут в
`PROJECT_HISTORY.md` — где, по вашим же правилам, «a chronicle legitimately speaks of old versions,
and the stale-claims scan knows to leave this file alone». Сканер флагует то, что сам же велит
перенести туда, где это законно.

**Воспроизведение:** любое обновление на 2.1 с непустым STATUS. Пункт `stale-claims` обязан идти
ПОСЛЕ миграции летописи либо исключать строки, попадающие в перенос.

### Грабля 5. У ядра нет справки; голый запуск и `--help` падают на самоочищенном пути

После успешного `update-verify` (который сам удалил `.kaif/install/`):

```
> node .kaif/kaif-core.mjs
✖ bundle not found: .kaif/install/KAIF-CORE-BUNDLE.md (pass --bundle <path>)

> node .kaif/kaif-core.mjs --help
✖ bundle not found: .kaif/install/KAIF-CORE-BUNDLE.md (pass --bundle <path>)

> node .kaif/kaif-core.mjs help
✖ unknown command: help (install | check | verify-final | update | update-verify | checkpoint |
  sphere | sync | modules | diff | adopt-current | version)
```

Список команд добывается **только** через ошибку «unknown command». Голый вызов и `--help`
дефолтятся в `install` и упираются в путь, который штатная самоочистка стёрла, — то есть штатно
завершённое развёртывание отвечает на невинную команду красной ошибкой «bundle not found»,
читающейся как «развёртывание сломано». Для слабой модели это прямой путь к ложному диагнозу и к
попытке «починить» рабочий KAIF.

**Воспроизведение:** любое развёртывание после `verify-final` / `update-verify`.

### Грабля 6. Расписка: `route: "legacy-bootstrap"` при `classified: true`

`.kaif/last-update.json` после прохода:

```json
{ "from": "2.0", "to": "2.1", "route": "legacy-bootstrap",
  "counters": { "replaced": 10, "mergedModules": 7, "added": 8, "kept": 45, "adopted": 27 },
  "classified": true, "date": "2026-07-31", "verifiedAt": "2026-07-31" }
```

Проход шёл СВЕЖИМ ядром 2.1 (загрузчик скачал его, `machinery 2.1 verified`), с модульной
классификацией против уцелевшего манифеста. «legacy» здесь — ложная метка: она описывает не то, кто
исполнял обновление, а то, что развёртывание было создано раньше. Следующая сессия, читающая
расписку, сделает неверный вывод о маршруте.

## 3. Что из новинок 2.1 реально потрогано и как себя повело

**Потрогано и проверено:**

- **`PROJECT_HISTORY.md` и стрижка бонсая** — главная ценность релиза для нас. Механически файл
  создан («+ wrote PROJECT_HISTORY.md»), содержательную миграцию машинерия честно НЕ делала и прямо
  об этом сказала. Разрез сделал я скриптом по диапазонам строк: STATUS **2 900 → 278**,
  `PROJECT_HISTORY` 2 698 строк, кириллица **116 745 → 119 796** (прирост — мои новые шапки),
  потеряно 2 строки-разделителя. Правила из шапки шаблона (append-only, свежее сверху, перенос
  дословный, деление по эпохам) — рабочие; правило «летопись не входит в `/resume`» я перенёс в наш
  русский `/resume` отдельным блоком.
- **Предсказание прохода песочницей** (канон 2.1 в `/kaif-update`) — сработало точно: 24 из 25
  изменённых файлов совпали с боем **байт в байт**. Единственное расхождение —
  `.kaif/deploy-manifest.json` (пересчитанные sha), и оно объясняется CRLF/LF-артефактом самого
  метода `git archive`, а не машинерией. Это второй проект подряд, где предсказание совпадает
  (первый — 1.6→2.0), метод можно считать проверенным.
- **Чекпоинты, которые ИСПОЛНЯЮТ свою проверку** — подтверждаю на `recheck`:
  ```
  > node .kaif/kaif-core.mjs checkpoint recheck
  ✅ manifest satisfied: 65 files + 140 agent artifacts present
  ✔ check ran green (executed by the checkpoint itself)
  ✔ recorded: KAIF-UPDATE: recheck done
  ```
  Отметиться, не прогнав проверку, нельзя — это ровно тот класс фрода, который иначе не ловится.
- **`checkpoint judge --verdict`** — вердикт с доказательствами уходит в файл задания, а не в чат.
  Единственное место, где заявление судьи переживает сессию. Работает.
- **`sync` + предупреждение о дрейфе зеркал.** `check` назвал отставшие копии поимённо и указал
  команду:
  ```
  ⚠ 8 mirror copies lag the canon (5 more not listed) — normal until re-sync; run `node .kaif/kaif-core.mjs sync`
  ```
  `sync` пересобрал 145 копий, `update-verify` сделал это ещё раз автоматически. **Уточнение, чтобы
  не приписать релизу лишнего:** обе команды есть и в ядре 2.0 (список команд идентичен), в 2.1
  добавлена сводная строка с количеством. Это снимает ручную пересборку зеркал из 1.6 (EXP-0051),
  но новой возможностью 2.1 не является.
- **Самоочистка `update-verify`** — удалила `KAIF_UPDATE_TASK.md`, `KAIF.md`, `KAIF-LOADER.mjs`,
  `.kaif/install/`, проштамповала `verifiedAt`. Расписка пережила очистку, как и задумано.
- **ignore-first для транзиентов** — `+ .gitignore: ignore-first for KAIF_UPDATE_TASK.superseded.md,
  .kaif/heartbeat.log`. Правило канона механизировано до того, как файл появился. Верно.
- **`diff` на манифесте v2** — работает (в 1.6→2.0 отказывался): `38 diverged file(s) — protected
  from replacement; 27 match — replace-eligible on update`. Как предсказатель ПЕРЕД обновлением не
  проверял: пошёл песочницей, потому что она даёт настоящий дифф, а не список имён.
- **Канон 2.1 в `AGENT_GUIDE`** — перенёс по-русски 5 блоков: лестница планирования (тест тяжести
  ≥2 из 5 — единственный проверяемый критерий «тяжести», который я видел), гигиена документов и
  текста (четыре лица класса «текст-через-CLI» — у нас это живая боль, PowerShell 5.1 + кириллица),
  реестр пар «истина ↔ зеркало» (завёл со стартовыми строками), место вопросов, класс вкуса,
  разрешение ≠ авторство идентичности. Последние два ложатся ровно на наши полевые инциденты
  (правило четырёх макетов, бренд-решения владельца) — заводить их в канон стоило.
- **Конвенции `EXPERIENCE`: Repro обязателен + Trigger + `mechanized:`** — перенёс. Формулировка
  «урок, который повторился, — урок, проваливший себя как текст; два повтора → механизм» — то, чего
  не хватало: у нас 102 записи, и часть из них повторяется классами.

**НЕ потрогано (говорю прямо, чтобы не выдать чтение за проверку):**
`/plan-task`, `/plan-epic`, `/guarded-loop` (в т.ч. `heartbeat.log` и охота судьи на «timer-fed
heartbeat»), `/code-revision`, `/owner-voice`, `/owner-reviews` — прочитаны, разложены по зеркалам,
внесены в маршрутизацию и в `/help-kaif`, но ни один не исполнялся. CRAFT-слоты `/fable-method`
и новые охоты `/fable-judge` пришли заменой файла целиком; судейский проход этого обновления я гнал
по инструкции 2.1, включая «mutation addressivity» (см. ниже), — но это один прогон, не выборка.

**Побочный факт, полезный для 2.2:** после установки шести новых скиллов наш собственный гейт
(`tools/03-kaif-verify.mjs`, хардкод-список ожидаемых скиллов) выдал:
```
⚠ неизвестные скиллы в .claude/skills: code-revision, guarded-loop, owner-reviews, owner-voice, plan-epic, plan-task
```
Правил руками. Обе правки валидатора доказаны адресными мутациями — предсказание объявлено ДО
прогона, попадание точное:

## 4. Пожелания к 2.2

1. **`i18n: translated` обязан блокировать и ВСТАВКУ модулей, не только замену.** Сейчас гарантия
   даётся в логе и тут же нарушается (грабля 1). Минимум: на translated-развёртывании ни один
   модуль не пишется на диск — только диффы в задание.
2. **Считать модульные диффы от ПРЕДЫДУЩЕГО РЕЛИЗА, а не от «есть ли модуль в твоём файле».**
   Нулевое изменение апстрима обязано давать ноль пунктов задания. Я сделал это руками: скачал
   `KAIF-CORE-BUNDLE.md` v2.0, распаковал оба бандла, сравнил деревья — 30 строк скрипта. Машинерия
   может делать это сама, если релиз будет публиковать хеш/копию предыдущего бандла (или `diff`
   научится брать `--baseline` из предыдущего тега автоматически). Это снимает грабли 1 и 2 разом
   и сокращает задание с 352 строк до ~80.
3. **`stale-claims`: сузить до версии ФРЕЙМВОРКА.** Требовать, чтобы токен версии стоял рядом с
   маркером (`KAIF`, `kaif.json`, `framework`, `фреймворк`), и никогда не сканировать `GOAL.md` и
   прочие объявленные документы владельца. Иначе проект с собственной версией 2.0 получает
   19%-точность и предложение править документ, который машинерия сама объявляет неприкосновенным.
4. **Порядок пунктов задания:** миграция летописи — ДО `stale-claims`, либо исключать из скана
   строки, которые миграция переносит. Сейчас задание флагует то, что само же велит убрать.
5. **`help` как команда** и осмысленный голый запуск. Сейчас единственный способ узнать список
   команд — вызвать несуществующую, а `--help` на штатно очищенном развёртывании отвечает
   «bundle not found», что читается как поломка.
6. **Машиночитаемый инвентарь скиллов** (в маркере или отдельным ключом манифеста): проекты держат
   собственные гейты, и после каждого релиза с новыми скиллами их приходится править руками.
   `deploy-manifest.shas` для этого годится, но об этом нигде не сказано — достаточно строки в
   `KAIF_REFERENCE.md`.
7. **Честная метка маршрута:** `bootstrap`, когда классификацию выполнило свежее ядро;
   `legacy-bootstrap` — только когда обновление выполнило старое.
8. **Аудит `modules` на translated-развёртывании:** не печатать 218 `MODULE ABSENT` с советом
   «eyeball the file». Либо подавлять для переведённых файлов, либо помечать
   «translated — сверка по сигнатуре неприменима». Аудит, который нельзя выполнить, обесценивает
   аудит, который выполнить нужно.
9. **Мелочь по STATUS-стражу:** мягкая цель ~200 строк объявлена в шаблоне шапки, но исполняемой
   проверки к ней нет. Однострочный `kaif-core` подкоманда или строка в `check`
   («STATUS.md: 278 строк — выше мягкой цели 200») превратила бы правило из текста в механизм —
   ровно по вашему же принципу «два повтора → механизм».
