Your report arrived on the release day, after the list of the version's tickets was fixed. The origin's owner took all four of its remarks into 2.8.

- **An install from an unreleased build names that build.** The build now ships its identity in the bundle meta: `build.sourceTree` (the fingerprint of the sources the build was made from) and `build.prerelease` (the version whose notes the build already carries while its version is still the last release's). `install` writes both into `.kaif/kaif.json` — `"build": "<12 hex digits>"` and `"prerelease": "2.8"` — and prints `ℹ this build is a PRE-RELEASE of KAIF 2.8 … recorded in .kaif/kaif.json as "prerelease": "2.8"; the update to 2.8 will say so`. An update that reaches that version, on either route, adds the task item `prerelease-origin` ("installed from an UNRELEASED build of 2.8 … check each against the disk and do only what is missing") and marks the heading of the 2.8 notes the same way; a release build clears `prerelease` from the marker.
- **The placeholders item says the mirrors re-sync by themselves.** The install task's item now ends: "These are the canonical copies — the skill mirrors of the other agent systems re-sync from them at `checkpoint placeholders`, so never fill a mirror by hand."
- **An untouched template is named a template.** `kaif-voice-lint check` compares a file with the sha the deploy recorded in `.kaif/deploy-manifest.json` → `shas`. A byte-equal file gets a warning — "byte-equal to what the deploy wrote … an untouched template, not a text written past the portrait — the load witness does not judge it" — instead of the witness finding; its lines are still judged by the §8 table. An edited file with an old write time is judged by the witness as before.
- **Which portrait edition.** The owner-voice item of the install task now says: when the owner keeps two editions — a full private portrait and a public snapshot whose first line names it so — a public repository takes the public snapshot, the edition made for publication.
