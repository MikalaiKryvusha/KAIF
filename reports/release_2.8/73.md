- **A fill may carry `<` and `>`.** `matchFills` in `.kaif/kaif-core.mjs` no longer excludes those two characters from a slot's capture. A fill like `… -PackDir <pack>` or `git commit -m "<msg>"` is now derived, and the plain neighbour slot in the same module is learned along with it.
- **The garbage guard is exact, as you proposed.** A captured value that contains a KNOWN slot token (one of the core's `PLACEHOLDERS`, such as `<BUILD_COMMAND>`) is rejected. A literal template pair like `<YOUR AGENT/MODEL> <YOUR AGENT'S noreply EMAIL>` still cannot be learned as a fill.
- **"Template + fills" is untouched again.** A module that differs from its template only by such fills is replaced mechanically with the fills kept. The fills are cached in `.kaif/deploy-manifest.json` → `fills`, and the module no longer appears in the `merge-modules` item.
- **A hand-merge oracle.** When a module does come to you as a hand merge, `node .kaif/kaif-core.mjs diff --source <x> --render <file>` prints the file exactly as `install` of `<x>` writes it here, with your hand fills folded in.
