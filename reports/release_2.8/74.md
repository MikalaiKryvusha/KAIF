- **The door searches itself** — your fix (b). `node .kaif/tools/contour/review.mjs --search "<the question>"` runs the search in Node: a Unicode-aware, case-insensitive match over the same stems and the same paths as the printed command (`interviews/ GOAL.md MASTER_PLAN.md plans/`), so no shell and no locale decide whether a capital Cyrillic letter is found. - **The printed command carries the locale** — your fix (a). The refusal of `node .kaif/tools/contour/review.mjs <doc> --check` now prints `LC_ALL=C.UTF-8 grep -rniE "…" interviews/ GOAL.md MASTER_PLAN.md plans/`.
- **"Found, and nothing read" is refused.** An attestation `N hits · read: none` with N > 0 is exit 3 from `--check` and from every show, even beside a legal `prior: unrelated — …`; the refusal names `--search`.

Boundaries, said plainly. The door does not recount an attested `N` against its own search — a `→ 0 hits` is still taken at its word; what changed is that the search the agent runs no longer lies on Git Bash, not that a false zero is caught. `--search` reads the `.md` files under those paths, while the printed grep reads every file there. The question arrives as a command-line argument, so in Git Bash a word beginning with `/` can be expanded into a path — the words survive, extra hits may appear (named in the run report, not fixed).
