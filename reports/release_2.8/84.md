Shipped in [KAIF 2.8 — Noble KAIF](https://github.com/MikalaiKryvusha/KAIF/releases/tag/v2.8): both parts of the change your ticket proposed.

**1. A ratchet instead of a cliff.** `node .kaif/kaif-core.mjs check --gate-budgets` now reads `.kaif/budget-baseline.json` and rewrites it on every run. Commit that file with the closing.
- **First gate of a version:** it records the debt above budget and passes (`↳ … debt recorded … from the next closing it passes only while it shrinks`).
- **After that:** a document above budget passes only while its own lines SHRINK (`↳ … shrinking A → B since the last closing`), and the base tightens with it.
- **What stops the closing:** growth, a standstill, or a new overflow (`✖ … grew` / `stood still` / `crossed its budget since the last closing — a new overflow is never free`).
- **Back under budget:** the document leaves the file.
- **An unreadable base** stops the gate (restore it from git). It is never a free pass.

One difference from your wording: a standstill stops the closing. The KAIF owner's rule is that the count must go down. Ratchets elsewhere in the industry let an unchanged count pass; this one does not, on purpose, and the core's comment says so.

**2. The archive declaration.** In `.kaif/kaif.json`, set `"archives": { "GOAL.md": { "digest": "<digest file>", "owner": "<where his word lives>" } }`.
- The short form `"GOAL.md": "<digest file>"` works too, and `check` then reminds you to name the owner's word.
- The budget is judged on the digest, which is the operative text. The archive's size is printed as information (`ℹ GOAL.md: a declared archive of the owner (N lines — information, never a stop)`).
- The digest must NAME its archive, so the file has to mention `GOAL.md`. A missing digest, or one that does not name the archive, leaves `GOAL.md` judged as before. As your ticket asked: without a digest, the stop stays.
- `check` also checks the marker entry itself: a key outside the re-read core, or an entry with no digest, is named as a schema issue.

**Around the gate.**
- Every move-out address now names its file and the command that creates it: `HOUSE_RULES.md (no file yet: cp .kaif/_house-rules-template.md HOUSE_RULES.md)`. `STATUS.md` gets that as a second address, for standing rules and reference tables, next to the chronicle.
- The update task has a new item, `closing-gates`. It runs the closing ritual's machine gates read-only over the tree the update just wrote and names where the first closing will stop. On the `update` route the task is written by your outgoing core, so there `checkpoint recheck` of the fresh core names the same gates.
