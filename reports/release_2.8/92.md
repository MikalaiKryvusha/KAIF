Both halves of your ticket are closed along the lines you proposed. The one difference is in the shape of the second half.

1. **An offer is remembered.** Before `update` reads an absent, unchanged-upstream module as your deletion, it reads the previous update's receipt: `.kaif/last-update.json` → `divergedModules`, read before this update overwrites it. A module that receipt proposed and that is still absent goes back into the task with its diff: "proposed by the PREVIOUS update and never merged — offered again (its absence is not your deletion: the previous task carried it)".
2. **Promised lines are judged per file, not per deployment.** `update-verify` skips the "promised upstream line not found on disk" check only for a file that is itself a translation. It learns that from the receipt's `translatedFiles` list when there is one; otherwise it compares the file's own text with the release template. The deployment's `i18n: translated` flag no longer silences the check for an English file such as your `TESTING_FRAMEWORK.md`.
3. **Every section new in the release is checked on disk,** not only what the task carried. The release ships the list in its bundle meta (`sectionsNew`, built against the previous release's module map), so the check works whichever core ran the update.
   - A missing new section is red, by name: "✖ a section of this release did not arrive: <file> :: <section>".
   - In a translated file the missing section is named for a hand check instead, because a heading in your language cannot carry the English signature. The line gives the command that shows the new template as your deployment would write it: `node .kaif/kaif-core.mjs diff --source <the update's source> --render <file>`.
