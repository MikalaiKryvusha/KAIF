Shipped in [KAIF 2.8 — Noble KAIF](https://github.com/MikalaiKryvusha/KAIF/releases/tag/v2.8):

2.8 mechanizes the decision half where the decision is taken, as a clock probe and a printed line. It does not use a hook.

- **The moment is probed, never felt.** This is now a stamp rule in `AGENT_GUIDE.md`:
  - Probe with `date '+%Y-%m-%d %H:%M %z'` in the SAME tool call as the write. The `+0300` it prints is written as `+03:00`. In PowerShell: `Get-Date -Format 'yyyy-MM-dd HH:mm zzz'`.
  - "a decision about a named hour reads the probe too".
  - A moment that was not captured is written as an honest `≈`.
  - The refresh marker's `at` is also taken from a clock probe (`date -Iseconds`), never a moment by feel.

  Before 2.8 the origin kept this rule for itself and never shipped it.
- **The named hour has a boundary line.** `/end-chat-soft`, `/dayloop`, `/nightloop` and `/autoloop` now do what `/guarded-loop` already did. The loops read the clock with a probe at the start of each iteration. Before any closing ceremony they print `BOUNDARY: now <that probe> · named <the owner's time> · pool <empty | N items>`, and `/end-chat-soft` opens its report with that line when a named time started the closing. "the clock decides, never the agent's estimate".
- **The judge hunts it** in all four skills. A finding is any of:
  - a close with no `BOUNDARY:` line whose `now` came from a probe in the same call;
  - a verdict about the named hour ("time is up", "did not make it") with no probe behind it;
  - any stamp of a moment written without a probe in the same call.

What you do: merge. `/end-chat-soft` and the three loop skills change in 2.8, so if you edited them, the task carries the diffs.

Proof:
- A fresh install from the release build carries the rule (one line with `%H:%M %z` in the guide), a `BOUNDARY` line in each of the four skills, and the judge's hunt.
- The epic's judge found that `%z` prints `+0300` while the stamp convention writes `+03:00`. The rule now says so.
- The rule is prose the agent executes, so no sandbox suite covers it. Its first live use was the origin's own night session, which closed on its named hour with `BOUNDARY: now 2026-09-26T06:33:20+03:00 · named 2026-09-26T06:33:00+03:00 · pool …` (commit `f396998`).
- Run reports: `testcases/reports/2026-09-26_ch3-time-from-the-clock.md`, `testcases/reports/2026-09-26_ch5-judge-fixes.md`.

Limits:
- **Proposal 1 was weighed and not taken:** a clock line injected by a `UserPromptSubmit` hook, plus a deadline file. A prompt hook sees only the start of a turn, so a seven-hour turn would get one clock line. A deadline file is a second copy of the named hour, and a copy drifts from its source. The probe in the same call covers every decision inside the turn.
- **Proposal 3 did not ship as a machine check:** a guard over the refresh marker's `at`. 2.8 ships the rule only. The refresh-timer hook still trusts a future `at`; that read side is on the list for the next version.
- **No machine check of stamps ships at all.** 2.8 ships the rule and the judge's hunt, so your project's `stamps:check` stays yours.
- **The "≤ 2 minutes left" threshold of proposal 2 is not a number in the canon.** The probed line decides.
- **Not yet observed in the field.** The first closing on a named hour in a field deployment after 2.8 will be that observation.
