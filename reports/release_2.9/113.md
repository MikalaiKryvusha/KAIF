Shipped in [KAIF 2.9 — Distilled KAIF](https://github.com/MikalaiKryvusha/KAIF/releases/tag/v2.9):

- **The address is a disk check, not a constant.** `MOVE_OUT_ADDRESS` and the `STATUS.md` row of `DOC_BUDGETS` in `.kaif/kaif-core.mjs` now name the file only: `'HOUSE_RULES.md for local rules, routes and tools · …'`. The parenthesis `(no file yet: cp .kaif/_house-rules-template.md HOUSE_RULES.md)` is added at print time by one function, `overflowAddress()`, and only when `okOnDisk('HOUSE_RULES.md')` is false. That is the fix you proposed.
- **All the printers use it.** Every printer of the address goes through `overflowAddress()`: the `check` warning (both of its forms), the closing forecast of the update task, and the `--gate-budgets` door (`↳` / `✖` lines). The origin's own budget door reads the table without the parenthesis.

What your side does: after the update you can drop the local warning next to the gate's description in your guide. On your project, with `HOUSE_RULES.md` filled, `node .kaif/kaif-core.mjs check --gate-budgets` names `HOUSE_RULES.md` without any `cp`.

Proof: sandbox suite `tools/sandbox/s16-doc-budgets.mjs`, section SW4 (4b), on a fixture with a filled `HOUSE_RULES.md` of 90 rules. The `check` warning and the closing door name the file with no "no file yet: cp …", for both `AGENT_GUIDE.md` and `STATUS.md`, and the run leaves the file untouched. Without the file both lines still print the command, as before. The mutant M-SW4 in `tools/sandbox/probes/budget-mutants.mjs`, which prints the parenthesis unconditionally, is red. On the v2.8 build `s16` is red on 5 checks (`tools/sandbox/probes/sw-red-on-v28.mjs`). The suite's earlier assertions had pinned the literal parenthesis; they now hold only for the "no file" case.

Boundaries, said plainly: the fix decides by whether the file exists, not by whether it is filled. A `HOUSE_RULES.md` you copied but left as the skeleton is named the same as a filled one, which is safe because nothing is offered to overwrite it.
