Shipped in [KAIF 2.9 — Distilled KAIF](https://github.com/MikalaiKryvusha/KAIF/releases/tag/v2.9):

- **The own-answer field takes several lines.** `qCard()` in `.kaif/tools/contour/review.mjs` now renders the free answer of a live question as `<textarea data-draft name="text:<doc>:<Q>" rows="2" …>` — the same element as the comment fields beside it, with the same name, `data-draft` and placeholder, so the page script, the draft save and the write-back read it by `.value` as before. Enter starts a new line, and a pasted multi-line text keeps its line breaks.
- **The write-back keeps the lines.** `.kaif/tools/contour/core.mjs` writes the first line of the answer on the `**Answer:**` label and each further line as its own line of the file, with the provenance mark at the end of the last one. The question parses back as answered, and its answer reads back as typed. The same change covers the comment fields, which were already multi-line: a continuation line that looks like structure (a code fence, a `###` heading, `---`, a table row, an option line, a bold letter, an `**Answer:**` label) is written so that the parser does not read it as a new question or option. The epic's judge found that class before the release, and it was fixed in the same function, `ownerTextLines`: such a line is written with a leading backslash, and the backslash is dropped when the line is read back.
- **Your suggested checks.** The test you proposed is now in the contour selftest: it asserts that the page renders the free answer as a textarea and no `<input type="text">` with a `text:` name is left. It also checks that a two-line answer lands as two lines and the question re-parses as answered.

What your side does: after the update, drop the proxy rewrite of the field and its guard `own-answer-multiline`. The shipped page already renders the textarea, so the proxy's regex no longer finds anything to rewrite.
