Thank you for the field report. What it brought into [KAIF 2.9 — Distilled KAIF](https://github.com/MikalaiKryvusha/KAIF/releases/tag/v2.9):

- **§2.1 — a target that is not a git repository.** The summary at the end of `install` now checks for that case. When the folder is not a git work tree, it prints: "⚠ this folder is not a git repository, and the deploy ends with a commit — run `git init` now; commit the owner's own files first, exactly as they are (his originals are committed before any edit), then the deploy commit." `KAIF.md` itself did not grow; the machinery says it where the agent reads the outcome of the install.
- **§2.2 — the refresh timer fired on the first message after install.** The `study` item of the install task now has the agent re-read the nine core documents and stamp `.kaif/refresh-marker.json` from those reads. `checkpoint study` refuses the mark unless the marker exists, names what was re-read and is younger than an hour. The timer then stays silent at the owner's first message. The other cure, a timer that stays silent without a marker, was weighed and not taken: it would silence the timer exactly where no refresh happened.
- **§2.3 — the size of `kaif-voice-lint load`.** New option: `node .kaif/tools/kaif-voice-lint.mjs load --out <file>` writes the selection into a UTF-8 file, with the same load witness, and tells the agent to read the file. A path inside the git tree that git does not ignore is refused before anything is written, so the portrait cannot reach a commit this way.
- **§2.4 — one extra turn per mid-turn message.** It is gone. `stop-owner-answer.mjs` (and `pretool-owner-word.mjs` with it) left the delivered set in 2.9 (#144). The rule now: unless the owner asks the agent to stop, it answers at once, as text and before its next tool call, then goes on with the work in the same turn.
- **§3.1 — the version label of a pre-release.** Not changed by 2.9. Between 2.8 and 2.9, the source of the `KAIF.md` header (`framework/_intro.md`) and the loader changed only in the commit example and in stripping a byte-order mark. The PRE-RELEASE line the install prints is still what resolves the label.
- **§3.2 — which edition is the public snapshot.** The 2.8 rule stands: the public snapshot is the edition whose first line names it so. 2.9 adds one case next to it: a root `AUTHOR_STYLOMETRY.md` that only points at a private voice core, named in `.kaif/kaif.json` → `voicePortrait`, is left alone by the update.
- **§3.3 — where to deliver a pre-release report.** No change. The standing authorization you found is the answer.
- **§4 and the judge verdict in your comment.** Recorded, and so is its caveat: `verify-final` cleans up after itself, so its pass is evidenced only indirectly. No 2.9 plan takes that caveat up, and neither does the 2.10 list.

What your side does: nothing for §2.1–§2.3 on an installed tree. They act at install time, and `load --out` whenever you use it. On the update to 2.9, the task removes the two retired hooks from `.claude/settings.json` (the task item `wire-hooks`). If your own texts tell the agent to end an answer with `⏩`, drop that rule.
