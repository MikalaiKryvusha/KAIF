- **The canon sentence.** "The owner's word mid-turn", rule 3, no longer names the two hooks or the arrow. It now says: "no hook stops the work on his other words (2.9 retired the two that did — #144)". Rule 2 now ends with the rule the KAIF owner set after the release's court: "Unless he asked you to stop, answer, then WORK ON with what you were doing before his word, in the same turn — never end the turn just to answer; the final message repeats the answer." A "stop" is still a stop.
- **"What in KAIF led to this", point by point.** (1) Every mid-turn word was a hard stop. Nothing stops the turn now. A clarification or a backlog note is answered and recorded by the rule's kinds (a note → the drive-by rule), and the work goes on. (2) The resume protocol leaked into the owner's chat. No resume marker exists any more, visible or hidden, so nothing is printed. (3) The answer check matched the literal first words. That check was the Stop hook, and it is retired, so no machine judges the answer's opening.
- **Your additional field fact: an agent in auto mode cannot unwire the hooks.** The fix does not depend on that edit. It works in three layers. (a) The update removes the untouched script files (the retirement list of the build). A hook still wired after its file is gone only exits 1, which Claude Code treats as a non-blocking error: it prints a hook-error notice and does not stop the turn. (b) `node .kaif/kaif-core.mjs wire-hooks`, an item of the update task, removes from `.claude/settings.json` every entry that runs a retired hook. A group or event emptied by that removal goes too, and all other lines of the owner stay in place and in order. (c) `check` and the task's `recheck` name any wiring of a retired hook that is left, with the command. An entry in the personal `.claude/settings.local.json` is named, never edited. If the harness refuses the write of `wire-hooks`, the task item says not to work around it: record the refusal with `checkpoint wire-hooks --verdict` and give the owner the one command.

What your side does: run the update. The task's `wire-hooks` item removes the two entries. Then drop any rule in your own texts (`STATUS.md`, house rules, experience) that tells the agent to end an answer with `⏩`. If you edited either hook script locally, the update keeps your copy and names it. Delete it yourself; the wiring is removed by script name either way.
