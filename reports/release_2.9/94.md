Shipped in [KAIF 2.9 — Distilled KAIF](https://github.com/MikalaiKryvusha/KAIF/releases/tag/v2.9):

- **Suggested fix 1, the root instead of the event's `cwd`.** All four hooks of the module now resolve the project root first: `prompt-refresh-timer.mjs`, `stop-status-guard.mjs`, `session-start-refresh.mjs` and `prompt-resume-word.mjs`. The root is the nearest folder at or above the event's `cwd` that holds `.kaif/kaif.json` (`projectRoot(cwd)` in each script). The timer reads `<root>/.kaif/refresh-marker.json`. After one `cd` into a subdirectory, a fresh root marker keeps the timer silent.
- **Suggested fix 2, the STATUS guard.** `stop-status-guard.mjs` reads `<root>/STATUS.md` and runs `git` in the root, so from `src/deep` it blocks under the same rule as from the root. Its reason now names what it saw ("the worktree has uncommitted changes" / "a commit landed within the last 3 h") instead of "this session changed the tree".
- **Suggested fix 3, the full path in the orders.** The orders of the timer, the session-start hook and the first-word hook name the marker by its full path, `<root>/.kaif/refresh-marker.json`. An agent that obeys from a subdirectory stamps the file the hook reads, and the stray witness of your near-miss cannot appear.
- **Suggested fix 4, the suite.** Polygon suite `s14` now feeds the hooks events whose `cwd` is a subdirectory of the project and expects the same verdict as from the root.
- **Which root form, and why not yours.** The 2.8 reply called your `import.meta.url` form right. When the fix was built, three forms were weighed. The first was the hook's own location (`new URL('../..', import.meta.url)`): a hook copied outside `.kaif/hooks/`, and the suites that feed hooks the events of other fixtures, would judge the wrong project. The second was the second deployment's local fix, `$CLAUDE_PROJECT_DIR` first and then the nearest ancestor with `.kaif/kaif.json`: the variable belongs to one agent system, and a suite inherits it from the agent's own session and swaps the sandbox root. The third, which was taken, is the ancestor search alone. It is one function with no environment variable, the same on every system that passes `cwd`.
- **The rest of the module's findings, carried with this ticket from the 2.8 list.** Every JSON a delivered tool reads now drops a leading byte-order mark. That is 21 lines of the class, and the build's guard 5o refuses a new one. On 2.8, `node .kaif/kaif-core.mjs version` crashed on a `.kaif/kaif.json` that began with a BOM. A marker `at` stamped in the future is no longer a witness: the timer says "lies N min in the future" and orders a refresh. The session-start order says "compacted" only after a compaction.

What your side does: after the update, drop the workaround. The session's directory may leave the root, and the timer's order no longer needs a manual check of the marker's age. A deployment that carries a local fix of the two hooks (`LOCAL FIX` in `.kaif/hooks/prompt-refresh-timer.mjs` and `.kaif/hooks/stop-status-guard.mjs`): the update keeps the edited copies and lists them as diverged. Take the delivered files whole; the local fix is no longer needed.

Proof: polygon suite `tools/sandbox/s14-refresh-hooks.mjs`. It has 13 new cases, and 12 of them are red on the `v2.8` build: the timer from `src/deep` with a fresh root marker (silent; v2.8 orders a refresh) and with a 2-hour-old one (the order names the root marker by its full path), the `/resume` order and the compaction order from a subdirectory, the STATUS guard from `src/deep` (a soft block; v2.8 is silent), the future stamp, the session-start words. The 13th is a control, green on both. Hook mutants M22–M31 are red on their own cases. Guard 5o found 21 lines on the v2.8 tag and 0 on the fix. Functional run on the origin's live tree: an event with `cwd` = `tools/sandbox` and a root marker 21 minutes old. The new timer stayed silent, and the v2.8 timer printed "no refresh witness found this session". Run report: `testcases/reports/2026-09-28_hk-hooks-project-root.md`; plan `plans/128_epic126_HK_hooks_find_the_project_root.md`.

Boundaries, said plainly: the events in the proof were fed to the hooks through the hook contract (stdin JSON). An event with a subdirectory `cwd` produced by the harness itself after the agent's `cd`, and a Windows path, were not observed by the origin. The fix waits for the first field update to show them. If the event's `cwd` lies outside the project tree altogether, no ancestor holds `.kaif/kaif.json` and the hooks fall back to that folder. The second deployment's local fix covered that case through `$CLAUDE_PROJECT_DIR`; 2.9 does not.
