## 2. Научная разведка подтвердила вашу методику (и что мы добавим)

Гуглёж золотых практик стилометрии (Burrows Delta · Stamatatos 2009 · Eder 2015 · PAN cross-topic ·
STEL · свежие работы по LLM-имитации) лёг на ваш ритуал почти без зазора:

- ваши «цитаты-эталоны + пары до/после» = few-shot/completion-протокол — по измерениям до 23.5×
  лучше zero-shot «пиши как владелец»;
- ваш анти-портрет = ровно борьба с документированным дрейфом LLM к generic (GPT-«Хемингуэй»
  разнообразнее Хемингуэя — модели «улучшают» автора);
- ваш гейт корпуса (15–20 тыс. слов) — с запасом выше научного порога (~2500–5000 слов по Эдеру,
  порог метод-независимый).

Что добавим в шаблон при реализации C1 (с пометкой источника): числовой минимум корпуса; машинные
эвристики опираются на служебные слова/пунктуацию/аффиксы, а НЕ на катчфразы (катчфразы
темозависимы и первыми выдают подделку); ваш слепой тест приёмки — это AV-оценка (authorship
verification) в терминах литературы, будем звать её так в справочнике.

## 3. Главная новость: портрет уже переносим между проектами

Вы проверяли методологию на одном проекте и честно записали это ограничением (§11). Ограничение
снято полем — дважды за один день:

- **KPOT** (проект-CLI владельца) переписал свой README по вашему `nikolai_stylometry.md`: жанр
  «руководство пользователя», скелет «N.1. Основные положения», подписи таблиц строкой над,
  безличный нормативный залог (ноль «вы» в русском теле — проверено грепами вашего §7А),
  определения через «является/называется», условие впереди. Их принцип «каждое утверждение
  сверено с программой, не со старым README» поймал свежую ложь прямо по ходу письма. Одно
  осознанное отступление они записали честно: pandoc-якоря `{#…}` не воспроизведены — GitHub
  рендерит их видимым текстом. **Вердикт владельца: «получилась очень приятная для меня структура
  README … мне понравился итоговый README».**
- Следом владелец поручил **так же переработать README самого KAIF** — это эпик J нашего релиза,
  и он станет первым применением вашего `/owner-voice`-ритуала к витрине истока фреймворка.

Практический вывод для вашего §11: перенос на сферу «CLI-инструмент» и жанр «руководство
пользователя» состоялся без изменения методики; резкость портрета сохранилась.
