# 06 — Лицо KAIF: как сделать README наглядным (разведдок)

> **Тип артефакта:** разведдок по чек-листу `AGENT_GUIDE.md` (шаг 8). Задача опирается на **внешнюю
> правду** — что на самом деле умеет рендерер GitHub, что делают лучшие README, что переживает наш
> PDF-конвейер. Всё ниже снято с живых источников (докs GitHub, `api.github.com/markdown`, боевые
> READMEs, файлы репозитория), а не по памяти. Каждый факт помечен как **проверено** либо
> **НЕ ПРОВЕРЕНО**.
>
> **Статус:** живой справочник (тегом `DONE` не помечается). Дата съёма — 2026-07-26.
> **Порождён задачей:** сделать `README.md` наглядным (владелец, 2026-07-26).

## 1. Зачем это исследование

**Это не украшательство, а закрытие незакрытой строки видения.** `GOAL.md:32` дословно требует:
«Всё это оформлено в **красивый** README.md на английском (основной) и русском языках (копия —
перевод английского), по README.md выполнена рендер-копия в README.pdf». Строка про PDF и два языка
выполнена; строка про «красивый» — нет. Сегодня `README.md` — **650 строк почти сплошного текста**:
2 ASCII-блока, 9 бейджей, 6 таблиц, 1 картинка-мем. Это документация, а не витрина.

**Постановка владельца (дословно, 2026-07-26):**

> «не смотря на то, что у автора игривый мемный OG - это как разрядка и лёгкость, ты же понимаешь, что
> в душе своей автор - глубокий филосов и инженер - и kaif пропитан тем же. Да, он масштабен и глубок.
> Но его нужно объяснить и подать легко и понятно. Это главный признак ума и гениальности - ты
> понимаешь очень много и глубоко, но можешь любому это объяснить за пять пинут на пальцах, и это
> будет не примитивное объяснение, а именно глубокое, но понятное.»

Из этого следует **проектный бриф**, которому обязана подчиняться каждая картинка:

1. **Честность.** За каждой схемой стоит реальный механизм из кода/доков, а не декоративная стрелка.
   Схема, которая врёт или приукрашивает, — фрод для судьи ровно как ложный `[TESTED]`.
2. **Мгновенная читаемость.** Целое понимается одним взглядом, без легенды и без чтения подписи.
3. **Не примитив.** Упрощать до «ИИ пишет код» запрещено — показывать надо *настоящую* глубину,
   но в виде, который считывается за секунды.
4. **Послойность.** Первый экран — целое; второй слой — механика; текст — для того, кто уже захотел
   глубину. Мем остаётся тем, чем является: разрядкой, а не тезисом.

## 2. Что на самом деле умеет рендерер GitHub (проверено наблюдением)

Метод: POST-пробы в `https://api.github.com/markdown` (**режим `gfm`** — именно он работает на
github.com), чтение HTML живых страниц, чтение задеплоенных бандлов и CSS GitHub, `curl -I` по
раздаче. Всё перепроверено вторым, адверсарным агентом; расхождения ниже отмечены.

### 2.1 Что работает

| Возможность | Вердикт | Существенная деталь |
|---|---|---|
| **SVG-файл в репо через `<img>`/`<picture>`** | ✅ работает | Относительный путь переписывается в `/<owner>/<repo>/raw/<branch>/<path>`, **не** проксируется camo. Высшая точность из доступного. |
| **`<picture>` + `prefers-color-scheme`** | ✅ работает | Тема светлая/тёмная — двумя файлами. Относительный `srcset` тоже переписывается. Обёртка `<themed-picture>` добавляется GitHub. |
| **Mermaid ```` ```mermaid ```` ** | ✅ на github.com | Версия **11.16.0** (снята чтением бандла `mermaidMarkdown-*.js`). |
| **Анимированный SVG (CSS `@keyframes` и SMIL)** | ✅ работает | CSP раздачи даёт `style-src 'unsafe-inline'`. Проверено на живом `Platane/snk` (100 140 байт, 257 `@keyframes`). |
| **Алерты `> [!NOTE]` / `[!TIP]` / `[!WARNING]`** | ✅ работает | Цвет и иконка бесплатно, без единого ассета. |
| **Таблицы как сетка** (`<td width="50%">`) | ✅ работает | Внутри ячеек живёт markdown: заголовки `###`, ``` фенсы ```, списки. Лучший «feature grid» без картинок. |
| **`<details>/<summary>`** | ✅ работает | Обязательна **пустая строка** после `</summary>`, иначе markdown внутри останется буквальным (поведение проверено пробой; в доках правила нет). |
| **`align`, `width`, `height`** на `img`/`td`/`p`/`h1..h6` | ✅ выживают | GitHub сам дописывает `style="max-width:100%"`. |
| **Задачи-чекбоксы** | ✅ через markdown `- [x]` | Рукописный `<input>` вырезается. |

### 2.2 Что НЕ работает — и это определяет архитектуру решения

| Ограничение | Последствие для нас |
|---|---|
| **Инлайновый `<svg>` УДАЛЯЕТСЯ целиком** (проба вернула пустой `<p></p>`) | Векторную графику можно поставлять **только файлом**. Никаких «нарисуем прямо в markdown». |
| **`style=` и `class=` вырезаются везде** | Ни фона, ни отступов, ни цвета, ни рамок у текста. **Вся типографика и цвет должны быть запечены внутрь SVG.** |
| **`<script>`, `<style>`, `<iframe>` не удаляются, а ЭКРАНИРУЮТСЯ** и показываются читателю как текст | Забытый тег виден на странице. |
| **Внешние ресурсы внутри SVG мертвы** (CSP `default-src 'none'`, нет `font-src`) | **Кастомные шрифты не грузятся.** Только общесистемные семейства — либо текст, переведённый в контуры (`<path>`). Приём shields.io: общий стек + `textLength` + `lengthAdjust`. |
| **`<video>` вырезается** | Демо — только GIF (≤10 МБ) или анимированный SVG. |
| **Mermaid деградирует в сырой код** вне github.com | Мобильные приложения GitHub, GitHub Pages, **печать/PDF**, зеркала — покажут исходник диаграммы. |
| **Лимиты mermaid неотключаемы** | `maxTextSize: 50 000`, `maxEdges: 500`, ключи в `secure:[…]` — `%%{init}%%` их не поднимет. |
| **Ссылки `id=` переписываются в `user-content-*`** | Наши 8 рукописных якорей работают на github.com, но ломаются в других рендерерах. |
| **Мобильный: фенс-блоки не переносятся** | **Наш ASCII-блок «How it works» шириной до 97 символов** (`README.md:55-65`, замерено) на телефоне рвёт вёрстку. Это уже баг витрины, а не риск. |
| **Соцкарточка (unfurl в Slack/X) — НЕ README** | `og:image` берётся из Settings → Social preview. Ни один герой из README туда не попадёт. |

### 2.3 Опровергнутое при перепроверке (чтобы не унести в план ложь)

- **Миф «camo кэширует картинки на 5 дней».** Замер трёх живых camo-URL: `max-age` = 60, 300 и 86 400.
  TTL наследуется от origin, фиксированных пяти суток нет. Для нас неважно: **ассеты в репо camo не
  проксирует вовсе** — ещё один довод хранить картинки у себя.
- **Миф «VS Code отстаёт по mermaid».** VS Code и github.com оба на 11.16.0 (PR microsoft/vscode
  #326040 от 2026-07-15). Расхождения сегодня нет.
- **Режим API имеет значение.** `/markdown/raw` НЕ рендерит алерты, mermaid-обогащение и таблицы
  так, как github.com. Проверять разметку можно только `mode=gfm`.

## 3. Ограничения нашего репозитория (проверено по файлам)

1. **`README.md` — рукописный.** `tools/build-framework.mjs` его не читает и не пишет (в `DOC_TARGETS`
   только шесть README директорий); `check-framework.mjs` про корневой README не утверждает ничего.
   Правим руками — правило «не правь сгенерированное» здесь не действует.
2. **`README.pdf` — КОММИТИТСЯ** (`git ls-files` его показывает, 11 коммитов), рендерится
   `tools/readme-pdf.mjs` через `md-to-pdf` 5.2.5 → headless Chromium.
   - Локальные растровые картинки в PDF **встраиваются** — доказано: в текущем PDF ровно один поток
     `DCTDecode` 1200×630 = это `KAIF.jpg`, плюс 56 растеризованных бейджей shields.io.
   - **`md-to-pdf` не исполняет mermaid.js** → фенс ```` ```mermaid ```` напечатается в PDF **сырым
     кодом**. Это прямой удар по строке `GOAL.md:32`.
   - **НЕ ПРОВЕРЕНО:** рендерятся ли в PDF *локальный* `.svg` по относительному пути и элемент
     `<picture>`. Chromium это умеет, но у нас наблюдением не снято → **обязательный спайк в плане**.
   - Конвейер готов к запуску прямо сейчас: `tools/node_modules` с `md-to-pdf` и `puppeteer` на месте,
     Chromium в кэше. При рендере нужна **сеть** (16 бейджей тянутся живьём).
3. **`.gitattributes`:** `* text=auto eol=lf`, бинарные — `*.png`, `*.jpg`, `*.pdf`. **Правила для
   `*.svg` нет** → git считает SVG текстом и нормализует в LF. Рабочее дерево смешанное (часть файлов
   на диске CRLF), поэтому **SVG надо писать с LF явно**, не надеясь на checkout.
4. **Директории для ассетов не существует.** В репо ровно две картинки: `KAIF.jpg` (1200×630,
   прогрессивный JPEG — формат соцкарточки) и `README.pdf`. `.gitignore` картинки не трогает.
5. **Восемь рукописных якорей** (`README.md:5, 72, 94, 171, 329, 392, 416, 494`) — цели шести бейджей
   и переключателя языков. Сломать якорь = молча убить бейдж.
6. **Переключатель языков есть только в английской половине** (`README.md:9-13`). Русский читатель
   вернуться к английскому не может — существующий дефект паритета.
7. **Ритуалы завязаны на README:** `/release` шаг 2 (обновить README на всех языках), шаг 3
   (перегенерировать PDF + собрать фреймворк), шаг 4.5 (judge; `REFUTED` блокирует релиз); `/pause`
   шаг 2–3 — то же. Значит, любая правка README проходит через judge перед публикацией.
8. **Полезная нагрузка не затрагивается.** Развёртываемому проекту корневой README **не** поставляется
   (в бандле только шесть README директорий). Единственная связка — фраза `framework/_intro.md:27`
   «The full pitch for humans lives in `README.md`». Значит, **работа над лицом — чисто слой обвязки,
   пересборка фреймворка не требуется**. Это резко снижает blast radius.

## 4. Как это делают лучшие (25 живых README, исходники прочитаны)

Разбирались методологические и инструментальные проекты: `humanlayer/12-factor-agents`,
`github/spec-kit`, `BMAD-METHOD`, `claude-flow`, `SuperClaude_Framework`, `aider`, `cline`,
`langgraph`, `crewAI`, `autogen`, `OpenHands`, `zed`, `biome`, `bun`, `astro`, `excalidraw`,
`tldraw`, `charmbracelet/vhs` и `gum`, `Best-README-Template`, `system-design-primer`, `ruff`,
`mermaid`, `claude-code`, `opencode`, `developer-roadmap`, `awesome-readme`.

### 4.1 Что работает (паттерны, годные именно нам)

- **Первая картинка — это ДОКАЗАТЕЛЬСТВО или ДВИЖЕНИЕ, а не декорация.** `ruff` открывается
  бенчмарк-диаграммой; `aider` — анимированным SVG-кастом реальной сессии (15,5 с, бесконечный цикл);
  `vhs` — GIF, сделанным самим инструментом, со ссылкой на исходник. Все трое **доказывают
  утверждение**, а не показывают интерфейс.
- **`<picture>` со светлой/тёмной парой — отраслевой стандарт** (LangGraph, Biome, tldraw, Excalidraw,
  ruff, opencode). Наша чёрно-белая линейная графика **обязана** иметь тёмный близнец, иначе в тёмной
  теме получится слепящий белый прямоугольник.
- **Слот `<h3><em>` под баннером — одно предложение, ≤14 слов**, называющее категорию и аудиторию.
- **Баннер может нести и вордмарк, и слоган вектором** (Biome: «Biome — Toolchain of the web»),
  тогда `h1` не нужен вовсе (Astro, BMAD).
- **Бейджи: 3–6 штук, ОДНОГО стиля, смысловые, а не административные.** `aider` вместо CI-статуса
  пишет заработанные факты («Singularity 88%» — доля релиза, написанная самим aider). У нас **9
  бейджей в двух визуальных группах** — это уже конфетти.
- **Сетка возможностей из HTML-таблицы**, а не из картинок: `cline` кладёт в `<td width="50%">`
  заголовок `###`, описание и команду в фенсе. Работает везде, включая телефон.
- **Ряд числовых плиток** (SuperClaude): 4 колонки, строка жирных чисел, строка подписей — «дашборд»
  на чистом markdown.
- **Утверждение + ссылка на доказательство** как базовая единица текста (Biome).
- **Социальное доказательство абзацем ссылок**, а не логотипной стеной (tldraw).
- **Самодемонстрация** (vhs, gum, aider): артефакт сделан тем, что он рекламирует.

### 4.2 Антипаттерны (в том числе наши)

- **Широкий ASCII в фенсе** — наш случай, 97 символов, на мобильном нечитаемо.
- **Бейдж-конфетти и смешение стилей** (claude-flow: 13 бейджей в двух стилях).
- **Оглавление и анонсы выше ценности.**
- **Баннер без демо** — брендинг, но не доказательство.
- **Спрятанное демо** (claude-flow держит GIF на ~154-й строке).
- **Гигантские таблицы высоко в файле** — на телефоне это горизонтальная простыня.

### 4.3 Главный вывод бенчмарка для нас

Проекты **без интерфейса** (12-factor-agents, system-design-primer, spec-kit) не имитируют скриншот —
они показывают **структуру и доказательства**: карточную сетку понятий, диаграмму-героя, таблицу фаз.
`awesome-readme` в своём словаре похвал чаще всего называет «GIF Demo». Вывод: **нам не «нечего
показать» — у процессного фреймворка продукт и есть сессия; её можно снять**, а рядом положить
схему механизма и график экономии.

## 6. Технический вердикт: чем рисовать

Разбор по бритве Оккама и квадрату Декарта.

| Критерий | SVG-файлы в репо + `<picture>` | Mermaid в фенсе |
|---|---|---|
| Точность и брендовый язык (чёрная линия, как `KAIF.jpg`) | **полный контроль** | стиль навязан темой GitHub |
| Тёмная тема | пара файлов, честно | автоматически |
| **README.pdf (`GOAL.md:32`)** | картинка (растеризуется Chromium) — **спайк обязателен** | **сырой код в PDF** ❌ |
| Мобильные приложения GitHub | картинка видна | сырой код ❌ |
| Правка | редактируем XML/скрипт | правим текст ✅ |
| Диффабельность | SVG — текст, `git diff` читаемый | текст ✅ |
| Композиция «было/стало», «айсберг» | свободная | недоступна ❌ |
| Шрифты | только системные стеки либо контуры ⚠️ | системные |

**Рекомендация: SVG-файлы, ноль mermaid в README.** Причины по Оккаму: (1) mermaid ломает
**коммитируемый** PDF, который прямо назван в `GOAL.md`, — это не косметика, а невыполнение видения;
(2) mermaid не умеет композиций, которыми объясняются именно наши три главные мысли; (3) две
технологии вместо одной — лишняя сущность. Mermaid при этом остаётся там, где он уже живёт и где PDF
не при чём (`skills/fable-*`, `researches/03`) — трогать не нужно.

**Правила безопасного SVG для нас** (следствия §2):
- шрифты — только стек `system-ui, -apple-system, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`;
  критичные надписи пинить `textLength` + `lengthAdjust="spacingAndGlyphs"` (приём shields.io), либо
  переводить в контуры;
- никаких внешних ссылок, `@font-face`, `<image href="http…">` — CSP их убьёт молча;
- обязательный `viewBox`, ширина задаётся на `<img width>`; проектировать под резиновую колонку;
- пара файлов `*-light.svg` / `*-dark.svg` под `<picture>`; `alt` пишем словами, а не «diagram»;
- писать файлы с **LF**;
- рядом с картинкой — **однострочная курсивная подпись** (приём ruff): картинка становится
  аргументом.
