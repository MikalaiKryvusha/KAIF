## 1. Чего сегодня нет (дыра, которую закрывает эпик)

Ни один существующий документ не выполняет роль пояснительной записки:
- `KAIF_FRAMEWORK.md` — пост-инжекционная «страница технологий» проекта (высокоуровнево, без
  устройства); README — витрина; карты — про структуру *этого* репозитория; `researches/04` —
  разовая карта установки эпохи 1.5.
- **Внутренней терминологии с именами не существует**: сущности «тонкий KAIF.md», «бандл»,
  «FILE:-блок», «маркер», «снапшот», «усыновление (kept)», «зеркала агентских систем»,
  «поверхность утверждений» живут в прозе разных документов без единого глоссария — полевые отчёты
  называют одно и то же по-разному, а `/help-kaif` отвечает по состоянию своей эпохи (отчёт 04:
  оператор получал ответ про 1.4 при развёрнутой 1.6).

## 3. Эталон стиля (снято с BSUIR-первоисточника, СТП-П-01-2013)

Черты **языка** (владелец: «вдохновляться СТИЛЕМ, не правилами оформления»):
- иерархическая нумерация разделов/подразделов/пунктов арабскими цифрами (2.1.1) — даёт адресуемость
  «глава-параграф», которую требует `/help-kaif`;
- нормативная модальность: «должен», «следует», «не допускается», «допускается», «применяют» —
  требования отличимы от рекомендаций грамматикой, а не курсивом;
- безличные/пассивные конструкции («записку выполняют…», «текст излагают…»), никакого «я/мы решили»;
- терминологическая дисциплина: «применять термины, установленные стандартами», запрет синонимии
  («запрещается применять иностранные термины при наличии равнозначных»); одно понятие — одно слово
  (созвучно словарю из `/derive-styleguide`, эпик №3);
- определения при первом употреблении, перечисления по строгой форме, примеры под маркером
  «Например:», содержание с адресами.

Тон KAIF при этом сохраняется по брифу владельца «глубокое объясняй просто» (AGENT_GUIDE, заметки):
записка — строгая, но не канцелярит; каждая глава открывается «целым одним взглядом», затем механика.

## 4. Сцепка с другими эпиками (главный проектный вывод)

**Записка и карта модулей эпика №1 обязаны использовать одну систему имён.** Карта модулей даёт
машине адреса; записка даёт людям те же модули с определениями. Терминология вводится ОДИН раз
(глоссарий записки = имена модулей карты), иначе получаем два расходящихся словаря (DRY).
Следствие для порядка работ: скелет записки (номенклатура модулей + глоссарий) пишется на фазе
ПРОЕКТИРОВАНИЯ эпика №1, до реализации машинерии; полный текст — после, когда устройство 2.0
зафиксировано. `/help-kaif` перестраивается на чтение записки (ответ + ссылка на параграф).

## 5. Развилки владельцу (→ интервью 004)

- **Язык и место:** записка на русском (стиль BSUIR — русский академический) живёт в репо истока,
  а в payload едет английский перевод (иначе `/help-kaif` развёрнутых проектов её не имеет)? Или
  двуязычный документ как README? Рекомендация — RU-оригинал + EN-копия в payload, синхрон по
  правилам двух языков AGENT_GUIDE.
- **Объём payload-версии:** полная записка утяжелит бандл (сотни строк × 2 языка) — везти целиком
  или главами (модульность эпика №1 это разрешает)?
