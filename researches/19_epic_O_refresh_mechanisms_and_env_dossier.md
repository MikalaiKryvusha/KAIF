## 1. Карта механизмов по системам [TESTED: 2026-08-07 · живой fetch доки + WebSearch; Claude Code — полный референс, конкуренты — по вторичным источникам]

### 1.1 Claude Code — референс-контракт (code.claude.com/docs/en/hooks, fetch 2026-08-07)

Пригодные эпику O события (полный список в доке — ~30 событий):

| Событие | Матчеры | Блокирует (exit 2)? | Роль в контуре O |
|---|---|---|---|
| `SessionStart` | `startup`, `resume`, `clear`, `compact`, `fork` | нет | впрыск «перечитай канон» на старте/после сжатия |
| `UserPromptSubmit` | — | да | stateful-таймер «>60 мин с последнего освежения» (дефолт timeout 30 с) |
| `Stop` | — | да (`decision: "block"` + `reason`) | страж «STATUS обновлён?» перед завершением ответа |
| `PreCompact` / `PostCompact` | `manual`, `auto` | PreCompact — да / PostCompact — нет | пред/пост-обработка сжатия (дублирует SessionStart(compact) — выбрать одно) |
| `PostToolBatch` | — | нет | периодическое напоминание в длинных прогонах без промптов |
| `FileChanged` | литеральные имена файлов | нет | слежение за самим каноном (watchPaths из SessionStart) |

Контракт: вход — JSON на stdin (`session_id`, `cwd`, `hook_event_name`, …; у `SessionStart` —
`source`, у `UserPromptSubmit` — `user_input`); выход при exit 0 — JSON на stdout, поле
**`additionalContext`** впрыскивает текст в контекст модели — оно ВЛОЖЕНО:
`{"hookSpecificOutput": {"hookEventName": "<событие>", "additionalContext": "…"}}` (уточнение
повторным fetch 2026-08-07 при исполнении O3; верхнеуровневым полем не работает), **кап 10 000
символов** (сверх — файл + превью-путь). Блокировка `Stop` — верхнеуровневые
`{"decision": "block", "reason": "…"}`. Exit 2 = блокировка + stderr модели (только у
блокируемых событий). Конфиг: `.claude/settings.json` (проектный, коммитится) /
`settings.local.json` / `~/.claude/settings.json`; поля хэндлера: `type: "command"`, `command`,
`args`, `timeout`, `async`, `shell`, `once`. Плейсхолдер `${CLAUDE_PROJECT_DIR}` — путь проекта.
**Две формы вызова** (уточнение третьим fetch 2026-08-07 при исполнении O4): `args` ПРИСУТСТВУЕТ
→ **exec-форма** (прямой spawn без шелла, каждый элемент `args` — ровно один аргумент); `args`
опущен → шелл-форма (нужна для пайпов, `&&`, глобов). Дока рекомендует exec-форму именно там,
где в путях стоят плейсхолдеры, — поэтому образец модуля и подключение истока написаны
`"command": "node", "args": ["${CLAUDE_PROJECT_DIR}/…/<скрипт>.mjs"]`. Строка про поля выше
перечисляла их неполно (без `args`) — не ошибка контракта, а неполнота карты: не «чини» по ней
рабочий фрагмент.

### 1.3 Контракты, снятые ЖИВЫМ fetch в фазе O5 (2026-08-07)

Правило фазы (слово владельца «Делаем, если поддерживают»): **образец конфига пишется только под
контракт, прочитанный в живом источнике в день письма**. Ниже — снятое; систему без строки в этой
секции в модуль не пускать.

#### Cursor — ✅ подтверждён 2026-08-07, полный аналог с ОДНИМ содержательным расхождением

- **Носитель:** `<project-root>/.cursor/hooks.json` (плюс уровни user `~/.cursor/hooks.json`,
  enterprise, team; приоритет Enterprise → Team → Project → User).
- **Схема:** `{"version": 1, "hooks": {"<имя>": [{"command": …, "type": "command|prompt",
  "timeout": <сек>, "loop_limit": <n|null>, "failClosed": <bool>, "matcher": …}]}}`.
- **События нашего контура:** `sessionStart` · `beforeSubmitPrompt` · `preCompact` · `stop`.
- **Впрыск контекста:** `sessionStart` → `{"env": {…}, "additional_context": "<строка>"}` —
  прямой аналог `additionalContext` Claude Code, наш приказ ложится сюда как есть.
- **Экзит-коды:** 0 — успех (читается JSON), 2 — блокировка действия, прочие — фейл, действие
  ПРОХОДИТ (fail-open); `"failClosed": true` меняет на fail-closed.
- **Подарок совместимости:** среди переменных окружения хука есть **`CLAUDE_PROJECT_DIR` —
  явный алиас совместимости** рядом с `CURSOR_PROJECT_DIR`. Значит пути в нашем образце
  переписывать не придётся.
- ⚠️ **Расхождение, которое НЕЛЬЗЯ замазать:** ни `beforeSubmitPrompt`, ни `preCompact` не умеют
  впрыскивать контекст АГЕНТУ. У `beforeSubmitPrompt` выход — `{"continue": bool,
  "user_message": …}` (сообщение ЧЕЛОВЕКУ либо блокировка промпта), у `preCompact` — только
  `user_message`, и он объявлен наблюдательным («cannot block or modify compaction»). У `stop`
  выход — `{"followup_message": …}`, который АВТО-ОТПРАВЛЯЕТСЯ как следующий промпт (лимит
  `loop_limit`). Вывод для O5: на Cursor из трёх наших хуков сразу ложится один
  (`sessionStart`); таймер и страж STATUS требуют либо другой формы вывода, либо честной
  пометки «частично». Копировать claude-фрагмент один в один — значит отгрузить неработающее.

#### Google Antigravity CLI — ✅ подтверждён 2026-08-07, частичный (и это СМЕНА ПЛАТФОРМЫ)

- **Сначала главное о ландшафте:** Google **закрывает Gemini CLI** — переход на **Antigravity
  CLI** (общедоступен с мая 2026), а Gemini CLI и расширения Gemini Code Assist **перестали
  обслуживать запросы 2026-06-18**. У KAIF адаптера под Google нет вообще — то есть это не
  «протухший снимок», а НЕПОКРЫТАЯ система, и покрывать надо сразу Antigravity.
- **Носитель:** `hooks.json` в каталоге кастомизации — `.agents/` в рабочей области либо
  `~/.gemini/config/`.
- **События:** `PreToolUse` · `PostToolUse` · `PreInvocation` · `PostInvocation` · `Stop`.
- **Впрыск контекста:** `PreInvocation` → `{"injectSteps": …, "terminationBehavior":
  "force_continue"|"terminate"}` — сюда ложится ТАЙМЕР освежения (срабатывает перед вызовом
  модели, то есть на каждом ходе).
- **Страж STATUS:** `Stop` → `{"decision": "continue"|…, "reason": …}` — форма почти совпадает с
  нашей claude-версией (мы печатаем ровно `decision`/`reason`).
- **Вход:** `conversationId`, `workspacePaths`, `transcriptPath`, `artifactDirectoryPath`,
  `modelName`, `stepIdx` (tool-события), `invocationNum` (invocation-события). Таймаут по
  умолчанию — 30 с.
- ⚠️ **Чего НЕТ:** ни события старта сессии, ни события компакции. Дока прямо говорит, что
  события «до/после сессии, агента, модели» ожидаются позже. Значит на Antigravity хук «канон
  после сжатия» невозможен по построению — честная строка «частичный контур: таймер + страж
  STATUS», а не молчаливая дыра.

#### Grok Build (xAI) — ✅ подтверждён 2026-08-07: события ЕСТЬ, впрыска в родном контракте НЕТ, но читается наш собственный

- **События (шире, чем у Claude Code):** `SessionStart` · `SessionEnd` · `UserPromptSubmit` ·
  `PreToolUse` · `PostToolUse` · `PostToolUseFailure` · `PermissionDenied` · `Stop` ·
  `StopFailure` · `Notification` · `SubagentStart` · `SubagentStop` · **`PreCompact` ·
  `PostCompact`**.
- **Носитель:** отдельные JSON-файлы — `~/.grok/hooks/*.json` (личные) и
  `<project>/.grok/hooks/*.json` (проектные); внутри объект `hooks` с массивами на событие
  (`matcher` регэкспом, `type`: `command`|`http`).
- **Вход:** JSON на stdin с `hookEventName`, `sessionId`, `cwd`, `workspaceRoot` (+ `toolName`,
  `toolInput` для tool-событий); в окружении — `GROK_HOOK_EVENT`, `GROK_HOOK_NAME`,
  `GROK_SESSION_ID`, `GROK_WORKSPACE_ROOT`.
- **Таймаут:** 5 с по умолчанию (у Claude Code — 60 с; наш образец ставит 15 с — влезает).
  Таймаут, падение, кривой вывод — **fail-open**.
- ⚠️ **Ключевое расхождение:** в РОДНОМ контракте `SessionStart`, `UserPromptSubmit`,
  `PreCompact` и `Stop` объявлены пассивными — «stdout is ignored; exit 0 on success». Поля
  вроде `additionalContext` в доке нет; JSON-вывод читается только у блокирующего `PreToolUse`
  (`decision`/`reason`). То есть родной путь Grok умеет ЗАПУСКАТЬ скрипт по нашим событиям, но
  не умеет принимать от него приказ в контекст.
- ✅ **И тут же — обходной путь, подтверждённый той же докой:** Grok читает **`.claude/settings.json`
  и `.cursor/hooks.json` НАРЯДУ** со своими файлами, включая camelCase-имена событий Cursor.
  Значит гипотеза адаптера («читает раскладку `.claude/` целиком») **подтвердилась**, и рабочий
  вариант для Grok — не собственный образец, а наш claude-фрагмент как есть.
- **Открытый вопрос для шага 2:** уважает ли Grok на claude-совместимом пути форму вывода
  `hookSpecificOutput.additionalContext` — или гасит её так же, как в родном контракте. Дока
  этого не говорит. До ответа строка Grok в README модуля — «конфиг Claude Code читается;
  впрыск контекста не верифицирован», а не «поддержано».

#### Meta Muse Code — ✅ система НАЙДЕНА, хуки ЕСТЬ (снято 2026-08-07; сама система моложе трёх дней)

Поручение владельца («посмотреть, есть ли у Meta своя ИИ агентская система… Делаем, если
поддерживают») закрыто утвердительно, и вовремя: **Muse Code — терминальный агент Meta
Superintelligence Labs, бета опубликована 2026-08-05**, за два дня до этой разведки, на модели
Muse Spark 1.2 (macOS и Linux; многоагентный, с воспроизводимым журналом событий).

- **Хуки есть:** «scripts that lock on and fire when certain events occur from your agent».
  Названы события: **отправка промпта пользователем** · правка файла · вызов инструмента · вызов
  MCP-инструмента. Аналога старта сессии и компакции в найденных источниках НЕТ.
- **Модель доверия — своя, и это важно для поставки:** проектные и пользовательские хуки требуют
  **явной команды доверия** перед первым запуском; «управляемые» хуки из центральной настройки
  предодобрены для администрируемых парков. Команда хука исполняется ВНЕ песочницы и системы
  одобрений агента. Для KAIF это ложится на наш собственный канон опт-ина («KAIF never edits your
  settings.json») даже плотнее, чем у прочих систем.
- ⚠️ **Чего пока НЕТ у нас:** первичной вендорской доки с точным контрактом — имя и место файла
  конфига, точные имена событий, форма stdin/stdout. Найденное снято с обзорных источников и
  разбора, вендорский блог отдал только заголовок. **Поэтому по правилу фазы образец под Muse
  Code НЕ пишется**, пока контракт не прочитан в доке Meta: система получает строку «хуки
  заявлены, контракт не верифицирован — ждём доку». Это ровно тот случай, ради которого правило
  и заведено: соблазн «событие отправки промпта же есть, значит таймер напишем» — и есть
  образец-гипотеза.

#### OpenAI Codex — ✅ подтверждён 2026-08-07: БЛИЖАЙШИЙ АНАЛОГ, скрипты работают без единой правки

- **Носитель:** `<repo>/.codex/hooks.json` или `~/.codex/hooks.json` (плюс инлайн-таблицы
  `[hooks]` в `config.toml`). Структура — **тот же объект `"hooks"` в корне**, что у Claude Code.
- **События:** `SessionStart` · `SessionEnd` · `SubagentStart` · `PreToolUse` ·
  `PermissionRequest` · `PostToolUse` · **`PreCompact` · `PostCompact`** · `UserPromptSubmit` ·
  `SubagentStop` · `Stop`.
- **Матчер `SessionStart` — по полю `source` со значениями `startup` · `resume` · **`clear`** ·
  **`compact`**: буква в букву наш матчер `compact|clear`.
- **Впрыск контекста — ТЕ ЖЕ ИМЕНА ПОЛЕЙ:** `"hookSpecificOutput": {"additionalContext": "…"}`
  (а простой текст на stdout тоже принимается как developer-контекст). Для `SessionStart` и
  `UserPromptSubmit` — то есть под оба наших впрыскивающих хука.
- **Вход:** snake_case, как у Claude Code — `session_id`, `transcript_path`, `cwd`,
  `hook_event_name`, `model`, `permission_mode`.
- **Экзит-коды:** 0 — успех, 2 — блокирующий сигнал (причина в stderr), прочее — фейл. Таймаут по

- **Вывод для O5:** образец = наш `hooks`-объект в другом файле. Единственное непроверенное —
  форма вывода у `Stop` (наш страж печатает `decision`/`reason`; дока Codex описывает блокировку

#### GitHub Copilot — ✅ подтверждён 2026-08-07: частичный, но с приятным сюрпризом совместимости

- **Носитель:** `.github/hooks/*.json` (репозиторий) · `~/.copilot/hooks/*.json` (пользователь) ·
  инлайн в `.github/copilot/settings.json`; формат `{"version": 1, "hooks": {"<событие>": [...]}}`.
- **События:** `sessionStart` · `sessionEnd` · `userPromptSubmitted` · `userPromptTransformed` ·
  `preToolUse` · `postToolUse` · `postToolUseFailure` · **`preCompact`** · `permissionRequest` ·
  `notification` · `agentStop` · `subagentStart` · `subagentStop` · `errorOccurred`. То есть
  прежняя строка карты («аналог `sessionStart` не подтверждён») **устарела — событие есть**.
- **Сюрприз:** поддержаны ДВЕ конвенции имён — camelCase-события с camelCase-полями И
  **PascalCase-события со snake_case-полями, то есть ровно конвенция Claude Code**.
- ⚠️ **Впрыск `additionalContext` разрешён не везде:** только на `postToolUse`,
  `postToolUseFailure`, `notification`, **`sessionStart`**, `subagentStart`. На
  `userPromptSubmitted` и `agentStop` — нет. Значит из трёх наших хуков ложится один
  (приказ после сжатия), таймер и страж STATUS — нет.
- **Экзит-коды:** 0 — успех (stdout парсится), 2 — предупреждение (для `preToolUse`/
  `permissionRequest` — отказ), прочее — fail-open, кроме fail-closed `preToolUse`.

#### Windsurf / Cascade — ⛔ НЕ ПОДДЕРЖИВАЕТСЯ нашим модулем (и сменил дом)

- **Ландшафт:** `docs.windsurf.com/windsurf/cascade/hooks` теперь **редиректит на
  `docs.devin.ai/desktop/cascade/hooks`** — продукт переехал под Devin. Адаптер `windsurf.md`
  (снимок 2026-07-03) этого не видит.
- **Хуки есть:** `.windsurf/hooks.json` (+ системный и пользовательский уровни), структура
  `{"hooks": {"<СОБЫТИЕ>": [{"command", "powershell", "show_output", "working_directory"}]}}` —
  кстати, единственная система с явным полем под Windows-команду.
- **События (snake_case):** `pre_read_code` · `pre_write_code` · `pre_run_command` ·
  `pre_mcp_tool_use` · `pre_user_prompt` · `post_read_code` · `post_write_code` ·
  `post_run_command` · `post_mcp_tool_use` · `post_cascade_response` ·
  `post_cascade_response_with_transcript` · `post_setup_worktree`.
- ⛔ **Ни события старта сессии, ни компакции; и главное — хуки НЕ УМЕЮТ впрыскивать контекст
  вовсе:** общение с агентом только через exit-коды (0 — дальше, 2 — блок у pre-хуков).
  Наш модуль стоит на впрыске приказа, поэтому здесь честное «не поддержано», а не «частично».

#### Cline — ⛔ НЕ ПОДДЕРЖИВАЕТСЯ нашим модулем (хуки есть, но другого рода)

Хуки Cline — **программные плагины SDK**: объекты TypeScript/JavaScript, передаваемые массивом
`extensions` в конфигурацию, а не файл конфига с shell-командами. События — `beforeRun`/
`afterRun` · `beforeTool`/`afterTool` · `beforeModel`/`afterModel` · `onEvent`; старта сессии и
компакции нет, впрыска контекста в рассуждение модели тоже нет. Наш модуль поставляет
Node-скрипты, вызываемые системой по конфигу, — форма несовместима. Честное «не поддержано»;
работает markdown-ритуал.

**Главный вывод разведки — единой формы вывода не существует.** Три наших скрипта печатают
форму Claude Code. Codex принимает её дословно; Cursor ждёт плоский `additional_context`;
Antigravity — `injectSteps`; Copilot — `additionalContext`, но только на разрешённых событиях.
Значит развилка формы (шаг 2 `plans/60`) решается так: **явный флаг формы в самом образце
конфига** (`--emit claude|codex|cursor|antigravity|copilot`), а не автоопределение по входу.
Причины: (1) предикатная логика — ценная часть скриптов — остаётся ОДНА, обёртки её бы
размножили; (2) автоопределение по форме stdin — это догадка, а хук обязан молча выходить при
любой неясности, то есть тихо перестал бы работать; (3) образец, называющий свою форму явно,
читается человеком и проверяется сводом полигона. Вариант «писать образцы только там, где форма
совпадает» отвергнут: он выбросил бы Cursor, Antigravity и Copilot, которые впрыск поддерживают
— просто иначе.

## 2. Проект markdown-контура (обязательного) — правило освежения + свидетельство

**Правило освежения** (канон-секция AGENT_GUIDE, payload + обвязка, фаза O2). Триггеры
перечитывания яруса «re-read core» (девятка из таксономии N4 — второй список не заводим):

1. **Час:** прошло > 60 минут с последнего освежения в живой сессии (формула владельца «раз
   минимум в час»).
2. **Тяжёлая задача:** перед стартом задачи, проходящей тест тяжести (AGENT_GUIDE →
   «Дисциплина планирования»), в том же долгоживущем чате.
3. **После сжатия/паузы:** после компакции контекста, возврата из `/pause`, длинного простоя.
4. **Точки ритуалов:** `/resume` (полный проход — уже канон), `/refresh-context`, итерации
   длинных циклов (`/autoloop`, `/dayloop`, `/nightloop`, `/guarded-loop`).

**Свидетельство перечитывания** (DriftBench: recall ≠ adherence — пересказ правила не
доказывает следования). Предлагаемое решение по Оккаму — **двухчастное свидетельство**:

- **Маркер:** файл `.kaif/refresh-marker.json` (`{ "at": ISO, "docs": [...], "trigger": "..." }`),
  обновляемый агентом в момент освежения; в `.gitignore` (состояние сессии, не проекта).
  Машиночитаем: судья и хуки читают возраст маркера одной командой.
- **Цитата-приёмка:** обновление маркера легально ТОЛЬКО вместе с цитатой в чате одной
  конкретной строки из перечитанного, релевантной текущей задаче («освежил: STATUS п. 1 —
  „…“»). Маркер без цитаты — фрод класса ложного `[TESTED]`; строка охоты для `/fable-judge`
  (фаза O2 вшивает в hunt-list).

Отвергнутые альтернативы: строка в STATUS.md (git-шум на каждое освежение; STATUS — сводка
проекта, не журнал сессии); только цитата без маркера (непроверяема механически — хуку и судье
нечего прочитать); коммит-маркер (освежение не обязано рождать коммит).

## 3. Проект hook-контура (опционального модуля поставки)

**Состав** (минимум из мета-плана, все три — Claude Code; предикат + cooldown у каждого):

| Хук | Событие | Предикат (анти-шум) | Действие |
|---|---|---|---|
| канон-после-сжатия | `SessionStart` (matcher `compact\|clear`) | всегда (сжатие само — редкое событие) | `additionalContext`: ПРИКАЗ перечитать ярус re-read core + обновить маркер (не тела документов — кап 10k и token tax) |
| таймер освежения | `UserPromptSubmit` | возраст `refresh-marker.json` > 60 мин; cooldown — сам маркер (впрыск сбрасывает отсчёт только фактом освежения) | `additionalContext`: приказ освежиться до начала работы |
| страж STATUS | `Stop` | в сессии были правки/коммиты И STATUS.md не тронут дольше N часов; cooldown 1 раз/сессию | `decision: "block"` мягко — напомнить обновить STATUS (единственный блокирующий; nudging, не forcing) |

**Формат поставки:** скрипты в `.kaif/hooks/*.mjs` (Node — уже обязателен для KAIF) +
фрагмент-образец конфига; **KAIF не редактирует чужие `settings.json` молча** — установка
хуков = явный опциональный шаг с согласием владельца проекта (инструкция в модуле; прецедент
дефера `.gitattributes` из L5 — та же природа: мутация политики чужого репозитория).
Развёртывание без хуков не краснеет нигде (инвариант §9.10).

**Анти-шум как канон-требование:** впрыск — приказ, не документы; каждый хук несёт предикат
срабатывания и cooldown; частота пульса ограничена (наука: IFScale — плотность инструкций сама
разрушает следование; частые напоминания без cooldown — задокументированный антипаттерн).

## 4. Проект досье окружения + смок процедуры [TESTED: 2026-08-07 · процедура прогнана на машине истока, факты ниже — вывод проб]

**Процедура сбора** (образец — ansible facts: структурированный инвентарь хоста, снимаемый
заново, а не вспоминаемый). Пробы по осям, в КАЖДОМ доступном шелле отдельно (урок «разные
шеллы — разные миры»):

1. **ОС/железо:** версия ОС, CPU/ядра, RAM.
2. **Шеллы и кодировки:** какие шеллы есть (PS 5.1? pwsh 7? git-bash?), консольная кодировка,
   ANSI-кодировка по умолчанию (`Set-Content`-риск), локаль каждого шелла.
3. **Тулчейн:** node/npm/git/gh (+ версии), python, чем являются `tar`/`curl`/`find` в PATH
   каждого шелла (системный бинарь ≠ GNU).
4. **Git-политики:** `core.autocrlf`, credential helper.
5. **Пакетные менеджеры:** winget/choco/scoop (или apt/brew).
6. **Особенности поведения:** ссылки на оплаченные уроки (не дубли) — MSYS2-конвертация argv,
   BOM PS5.1, keep-alive Windows и т. п.

**Смок на машине истока (2026-08-07) — черновик нашего досье:**

| Факт | Значение (проба) |
|---|---|
| ОС | Windows 11 Pro 10.0.26200 |
| CPU/RAM | AMD Ryzen 7 5700G · 8 ядер/16 потоков · 32 ГБ |
| PowerShell | 5.1 Desktop (pwsh 7 НЕ установлен) |

| node/npm | v24.15.0 / 10.8.2 |

Смок подтвердил ценность процедуры наблюдением: пробы поймали ЖИВЬЁМ три класса, уже
оплаченных полем (шелло-зависимые `tar`/`find`, ACP-1251, пустая локаль git-bash), — досье
делает их видимыми будущей сессии ДО первого наступания.

**Формат секции** «Досье окружения» в AGENT_GUIDE (шаблон в payload, фаза O3): таблица
«факт → значение → проба-команда», шапка секции несёт **дату снятия**, **команду
перегенерации** и **staleness-правило: факты старше 4 недель — гипотеза, перепроверь пробой
перед тем, как на них опираться** (4 недели — интервал между полевыми обновлениями парка;
уточняется по опыту). Носитель процедуры — по Оккаму решить в O3: расширение
`/refresh-context` против отдельного навыка (склонность — расширение: отдельный глагол не
нужен, сбор досье и есть форма освежения знания об окружении).

**Граница DRY с «Гигиеной документов и текста»:** досье — ФАКТЫ машины (что установлено, чем
является `tar`, какая кодировка); гигиена — ПРАВИЛА ПОВЕДЕНИЯ, выведенные из инцидентов (текст
через файлы, читай записанное обратно). Досье ссылается на уроки по тегам (EXP-0005/0032/0034),
никогда не копирует их текст; правило поведения, найденное при сборе досье, уходит в гигиену
или EXPERIENCE, а в досье остаётся только ссылка.

## 5. Развилки и решения

**Развилок владельцу нет** — постановка идеи 20 пп. 3, 7 однозначна, интервал 60 минут взят из
формулировки владельца дословно («раз минимум в час»). Точечные решения агента (перечислены для
секции закрытия фазы, всё дёшево откатить): двухчастное свидетельство (маркер+цитата, §2);
маркер в `.gitignore`; три хука минимума и Stop — единственный блокирующий (§3); порядок
авторинга hook-конфигов «Claude Code первым» (§1.2); staleness 4 недели и склонность «процедура
досье — в `/refresh-context`» (§4).
