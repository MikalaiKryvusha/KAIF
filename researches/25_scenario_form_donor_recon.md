## §1. Слово владельца — источник формы (донор: `ideas/35` п. 1, 2026-09-04)

Дословно: *«Вместо технической формулировки будем писать сценарий: в такой-то ситуации, при
таком-то действии, должен получиться такой-то результат. Такой сценарий одновременно и постановка
задачи, и готовый тест».* Шаблон из четырёх строк — его же: **Ситуация** («Когда происходит вот
это») · **Действие** («И пользователь или система делает вот то») · **Результат** («Тогда в
системе появляется вот это, наблюдаемое снаружи») · **Проверка** («Проверяется командой, тестом
или запросом, вот таким. Пока не проходит, к следующему пункту не переходим»). Две цели: А)
владелец описывает требования языком заказчика, без реализации; Б) агент объясняет механики
языком сценариев. Ключевые слова — слова автора (там интервью #035 А2).

## §3. Что берём в KAIF и как (перенос ≠ копия)

1. **Канон** — подраздел «The scenario form» в `REQUIREMENTS_FRAMEWORK.md` обоих слоёв, под
   «The fit criterion»: четыре строки в fenced-блоке (линтер fence-aware — шаблон не считается
   сценарием), мост Given/When/Then + четвёртая строка, маппинг EARS → сценарий, семь правил с
   ❌/✅ (примеры нейтральные, без домена донора), две границы поля (пустая «Check» владельца ·
   правка «Check» при исполнении = ослабленный тест). Граница «Not Gherkin-everywhere» остаётся —
   канон предлагает ОДНУ опциональную форму для этого выбора и не требует её.
2. **Tool-модуль** `framework/tools/kaif-scenario-lint.mjs` → `.kaif/tools/` — по форме
   `kaif-guard-lint` (EN-комментарии, правила — данные, `check` / `selftest`, SKIPPED=3 без единого
   сценария, селфтест на фикстурах В ПАМЯТИ с адресностью мутаций). Отличия от донора: ключевые
   слова — таблица по языкам (`en` Situation · Action · Result · Check, `ru` Ситуация · Действие ·
   Результат · Проверка; проект добавляет строку), словари правил — EN + RU, `sim:` донора не
   переносится (команда донора), `\b` только для латиницы, кириллица — просмотрами.
3. **Свод s19** в полигоне: селфтест · плохая фикстура красная с семью именами правил ×2 языка ·
   чистая зелёная · SKIPPED на дереве без сценариев · ⚠ пустая «Check» не красит.
4. **Шаблоны** четырёх навыков обоих слоёв — четыре строки как вторая форма критерия (в
   code-fence шаблона); `/interview` — шаг 3а «механику — сначала сценарием».
5. **Зеркала:** `KAIF_REFERENCE` таблица модулей · карты (корень) · `TEMPLATE_NOTES['2.5']` ·
   релиз-ноты 2.5 п. 7 · README Таблица 5 · счётчик сводов 18 → 19.

## §4. Чего НЕ берём (и почему)

- Домен донора (кости, Цепочка, Мудрость) — примеры канона нейтральные (правило №90).
- Ручка `npm run req:lint` и шаг в `/end-chat` донора — у KAIF модуль опциональный; проект сам
  ставит его в свои ритуалы (как `kaif-requirements-lint`).
- Обязательность формы в `plans/bugs/ideas` (донорское #035 А3) — в KAIF форма остаётся выбором
  проекта (граница канона); линтер стережёт форму там, где сценарий НАЧАТ.
