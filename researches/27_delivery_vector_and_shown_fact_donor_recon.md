существует, строка `DELIVERY:` печатается с пометкой „реестр строится“… Классификация — вопрос
видения: окончательный список механик утверждает автор, агент готовит проект списка с
обоснованием каждой границы».*

**Как донор собирается печатать вектор** (`plans/47` донора, критерии К1–К5): одна команда
`npm run delivery` печатает `DELIVERY: систем 12 · завершённость 41 % · вплетённость 33 % · дыр 7
· противоречий 2 · багов 23`, каждое число выведено из файлов репозитория; `--json` — те же шесть
чисел объектом, детерминированно (два прогона — пустой diff); `--system <имя>` — дробь
завершённости; `--edges <имя>` — рёбра питания; `--gaps` — дыры/противоречия; фазы: реестр →
счётчик → классификация находок → вплетение в ритуалы. Реестр там ещё не заполнен — команда не
реализована; KAIF получает форму раньше донора, и донор сможет взять её обновлением.

## §2. Факт «показан» и очередь с возрастом — реализация донора (#47, локальная починка)

Снято с `tools/interview-page.mjs` донора (`[TESTED: 2026-09-05 · гейт увиден КРАСНЫМ на четырёх
непоказанных документах, затем зелёным после записи показа]`):

- **Хранилище — одна карта рядом с решениями:** `interviews/decisions/shown.json` =
  `{ "<doc>": { "at": "<ISO>", "transport": "страница | пачка | чат" } }`; пишется в момент, когда
  документ реально встал перед владельцем (после открытия окна браузера в `open`, для каждого
  живого документа пачки) — не когда агент о нём вспомнил. Транспорт называется, силу ответа не
  меняет (эквивалентность HTML = md = чат).
- **Очередь печатает возраст:** `показан автору: <дата> — N дн. назад (<транспорт>)` или
  `⛔ НИ РАЗУ НЕ ПОКАЗАН АВТОРУ — он не знает, что этот вопрос существует`.
- **Гейт, а не печать:** непоказанный ждущий документ роняет команду кодом выхода:
  «Напечатать очередь ≠ донести вопрос. Показ — действие агента, а не ссылка. Подними страницей,
  по одному… Документ мёртв и показывать нечего → почини его статус, и он уйдёт из очереди».
- **Протухший статус:** «статус ждёт, а все N полей заполнены» — отдельный предупреждающий список
  (обратное направление намеренно не проверяется — ложных тревог столько же, сколько настоящих).
- **Вопросы вне `interviews/`:** `reportStrayQuestions()` — по ЗАГОЛОВКУ секции («Вопросы автору»,
  «Развилки владельцу», «Спросить у автора») в `researches/`, `plans/`, `bugs/`, `ideas/`, кроме
  DONE; границы слова — кириллические просмотры, не `\b` (в JS `\b` слеп к кириллице — тот же
  урок, что EXP-0084 истока). Поправка владельца к #47: вопрос из `interview_018` жил ПРОЗОЙ в
  `bugs/39` и заголовком не ловился — нужна вторая примета, по строке.

## §4. Развилки, закрытые агентом без владельца (цена ошибки низкая — обратимы правкой строки)

1. **Имя оси — «системы» (systems), не «механики».** Основание — решение владельца А1 в поле и
   занятость слова в KAIF (№97). Обратимо переименованием.
2. **Четыре части завершённости универсализированы** как specified · accepted · implemented ·
   verified-in-use — прямое соответствие А3 и гейту 6 `TESTING_FRAMEWORK`; проект вправе назвать
   свои четыре в шаблоне (колонки — данные, не код).
3. **Вплетённость = доля закрытых потребностей** (А4: связь — «питание», не ссылка); системы без
   объявленных потребностей в среднее не входят, их число печатает `--json` как `isolated` — не
   седьмая компонента строки (владелец назвал шесть), а диагностика.
4. **Реестр — отдельный файл `SYSTEMS_REGISTRY.md`**, не секция `MASTER_PLAN.md`: таблицу читает
   машина, а `MASTER_PLAN` — проза владельца; прецедент отдельного опционального канон-файла —
   `AUTHOR_STYLOMETRY.md` (№59). `MASTER_PLAN` ссылается на него строкой «Delivery vector».
5. **Проект реестра агент составляет НЕМЕДЛЕННО и печатает вектор из черновика** с пометкой
   «draft, awaiting approval» — утверждение владельцем идёт write-gate'ом видения, но не
   блокирует ни строку, ни ранжирование `/what-next`: тупика нет по построению (№97).
