## §1. Размер и форма файла инструкций агента — вендоры и исследования

| Источник | Что сказано (дословно) | Что берём |
|---|---|---|
| Anthropic, память Claude Code — code.claude.com/docs/en/memory | «target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence.» · «Claude Code loads a CLAUDE.md file of up to 4 MiB in full and skips a larger file. Shorter files produce better adherence.» | Единица бюджета у вендора — СТРОКИ; короче — лучше соблюдается. Число 200 — для файла проекта, не для канона метода (§9) |
| Там же — импорт и HTML-комментарии | «helps organization but doesn't reduce context, since imported files load at launch.» · «in CLAUDE.md files are stripped before the content is injected into Claude's context.» · «When you open a CLAUDE.md file directly with the Read tool, comments remain visible.» | Вынос в импорт или комментарий контекста НЕ экономит: наше руководство читается инструментом Read — обоснование должно уехать в другой ФАЙЛ |
| Там же — авто-память | «or the first 25KB, whichever comes first, are loaded at the start of every conversation. | Anthropic, лучшие практики — code.claude.com/docs/en/best-practices | «Keep it concise. For each line, ask: "Would removing this cause Claude to make mistakes?" If not, cut it. If you emphasize many lines, none of them stands out.» | Тест строки для CK3; объяснения — вон из файла инструкций; ПРОПИСНЫЕ — на одной строке, а не на половине файла |
| Anthropic, промптинг — platform.claude.com (claude-prompting-best-practices) | «Providing context or motivation behind your instructions, such as explaining to Claude why such behavior is important, can help Claude better understand your goals» (по разведчику A; судья нашёл на странице) | Правило сохраняет ОДНО придаточное «зачем»; уезжает «свидетельство о рождении» — тикет, цитата, версия, полевая история |
| Cursor — cursor.com/docs/rules (по разведчику A; судья нашёл на странице) | «Keep rules under 500 lines» | Советы вендоров: 200 строк (Anthropic) · 500 строк (Cursor) · ≈ 1 000 строк (Copilot, ниже); жёсткие пределы — в байтах: 4 MiB (Claude Code), 32 KiB на все файлы (Codex, по разведчику A) |
| GitHub Copilot — docs.github.com (customize-code-review) | «Very long instruction files may result in some instructions being overlooked.» · «Limit any single instruction file to a maximum of about 1,000 lines.» · «Begin with 10–20 specific instructions» | Потолок в ≈ 1 000 строк — уже выше вендорского ориентира; наш шаблон 1200 выше и его |
| IFScale, Jaroslawicz и др., 2025 — arxiv.org/abs/2507.11538 | «even the best frontier models only achieve 68% accuracy at the max density of 500 instructions»; по разведчику A — лучшие модели почти без потерь до ≈ 150 инструкций, дальше спад, ошибки — в основном пропуски | Число ОБЯЗАТЕЛЬСТВ шаблона — метрика риска; CK2 его посчитает |
| Встречные данные: McMillan 2026 (arxiv 2605.10039), Gloaguen и др. 2026 (arxiv 2602.11988) — по разведчику A, не перепроверено | размер файла не дал заметного эффекта на соблюдение ОДНОГО простого правила; файлы контекста в целом не повышали успех задач | Выигрыш сжатия меряется функциональным прогоном (`plans/118` → «Верификация»), а не верой |
| Vercel, 2026 — по разведчику A, не перепроверено | всегда загруженный сжатый индекс обыграл навыки «по требованию» (100 % против ≤ 79 %) | ПРАВИЛА остаются в файле, который читается всегда; уезжает только обоснование |

**Вывод §1.** Советы вендоров о размере даются строками, жёсткие пределы — байтами; сходятся все на «короче — лучше соблюдается»;
объяснения и учебный текст из файла инструкций исключают прямо. Импорт и HTML-комментарий нам контекста не экономят — обоснование переезжает в другой файл.

## §2. Правило отдельно от обоснования — как это делают зрелые области

| Область | Устройство (дословно) | Что берём |
|---|---|---|
| ADR — Microsoft Well-Architected (learn.microsoft.com/en-us/azure/well-architected/architect-role/architecture-decision-record) | «Avoid making decision records design guides. If more justification or design ideation is available, provide a link to a document as supplemental material, but the decision must be clear and stand alone without that material.» · «The ADR serves as an append-only log. Don't go back and edit accepted records.» · «Always include context and rationale. A record without justification loses its value over time» | Правило ОБЯЗАНО читаться без обоснования; обоснование обязано СУЩЕСТВОВАТЬ и быть находимым |
| ADR — Nygard, 2011 (по разведчику B) | «A new person coming on to a project may be perplexed, baffled, delighted, or infuriated by some past decision.» · «If a decision is reversed, we will keep the old one around, but mark it as superseded.» | Забор Честертона: без адресуемого «почему» следующая сессия примет правило вслепую или снесёт вслепую |
| ESLint — eslint.org (custom-rules) | `meta.docs.url`: «Specifies the URL at which the full documentation can be accessed. Code editors often use this to provide a helpful link on highlighted rule violations.» | Правило несёт КЛЮЧ к объяснению, а не само объяснение |
| Vale · OPA · Semgrep (по разведчику B) | у правила — `message` и `link`; `related_resources`; `metadata.references` | Та же форма: короткое сообщение + ссылка на обоснование |
| PEP 1 — peps.python.org | «The rationale fleshes out the specification by describing why particular design decisions were made.» · «Once resolution is reached, a PEP is considered a historical document rather than a living specification.» | Спецификация и обоснование — отдельные разделы; история ревизий — ДОПОЛНЕНИЕ к написанному обоснованию, не замена |
| W3C QA Framework, ISO Directives (по разведчику B) | разделы помечаются normative / informative; «Try to avoid language that sounds normative in an informative section.» | Раздел обоснований — информативный: собственных правил не несёт |
| Чек-листы — Гаванде, ВОЗ (по разведчику B, вторичные заметки к книге) | 5–9 пунктов на паузу; «killer items»; чек-лист поддерживает обученного специалиста, объяснение живёт в руководстве по внедрению рядом | Точка применения — короткая; знание «почему» — в соседнем документе, в одном шаге от правила |
| Google developer documentation style — developers.google.com/style/procedures | «Make sure that the first sentence in a procedural step includes an imperative verb.» · «In general, use one step for each action.» | Метр голоса шаблона EN — §6 |

**Вывод §2.** Во всех найденных областях правило в точке применения короткое и самостоятельное, а у каждого правила есть
адресуемая запись «почему» в ДРУГОМ месте, и правило связано с ней ключом. «Только история git» ни одна зрелая область
обоснованием не считает.

## §6. Метод сжатия без потерь — полевой замер (#93 §2.3–2.4, R6) и мера голоса

Полевой проект сжал своё руководство с 2054 до 698 строк, и три его наблюдения — вход CK3:

1. **Механический инвентарь недостаточен.** Команды, номера и ссылки уцелели все, а 19 из ≈ 480 обязательств (≈ 4 %) пропали:
   терялось придаточное вокруг команды. Дословно из тикета: «The mechanical inventory was green while these were missing —
   commands and ids survived, the clause around them did not.» → ключ инвентаря — ВЕСЬ пункт (нормализованный текст пункта),
   а не команда внутри него; категория «changed» — команда на месте, текст пункта иной — идёт в смысловой аудит.
2. **Смысловой аудит — чистым экземпляром.** Независимый аудитор прочёл старый и новый тексты целиком: вердикт по умолчанию
   «сохранено», потеря доказывается цитатой и пустым `grep`. Выход аудитора в поле не был сохранён — у нас он ложится файлом
   в отчёт прогона.
3. **Мера голоса.** Первый срез вышел телеграфом: средний колон 3,52 при полосе владельца 4–6 (портрет `AUTHOR_STYLOMETRY.md`,
   правило С2: колон — отрезок между двумя ближайшими разделителями, 4–6 слов). Дословно: «без воды» и «рублено» — разные
   вещи. Для русской копии истока метр — средний колон в полосе 4–6; для английского шаблона — те же счёт колона против его
   собственной базы v2.7 и правила Google: первое предложение шага — с повелительным глаголом, одно действие на шаг.

## §7. Развилки CK — решения

**(а) Куда уезжает «свидетельство о рождении» правила.**
`FORK: options <A: новый раздел-приложение пояснительной записки «Why the guide says so» — запись на правило, ключ — полный заголовок секции руководства, раздел помечен информативным (второй вариант поля #93 §2.4 п. 1: «or into .kaif/KAIF_REFERENCE.md, read by the router on demand») | B: отдельный файл обоснований AGENT_GUIDE_RATIONALE.md (первый вариант того же пункта) | C: только история git и заметки версий бандла> · price of error <C: забор Честертона — правило без находимого «почему» следующая сессия снесёт или примет вслепую; B: новая сущность поставки с маршрутом обновления и ещё одна пара «истина ↔ зеркало»; A: раздел не должен нести собственных правил> · consulted <Microsoft ADR «must be clear and stand alone» + append-only · Nygard · ESLint docs.url · PEP 1 · W3C normative/informative · Anthropic «Long explanations or tutorials» в Exclude — §2, §1>`
Решение `[ИИ]`: **A.** Отрасль требует одного — адресуемой записи на правило вне файла правил; пояснительная записка уже и есть
поставляемый файл «почему» (`.kaif/KAIF_REFERENCE.md`, читается роутером по требованию), так что B повторяет A в новом файле
(Оккам). Ключ записи — полный заголовок секции руководства: KAIF уже адресует модули сигнатурными якорями (решение №16), и
правило не несёт в своём тексте ни одной лишней ссылки — хватает одной строки роутера «почему правило такое → записка,
раздел с тем же заголовком». В правиле остаётся одно придаточное «зачем» (промптинг Anthropic). Полная история версии остаётся
и в заметках бандла (`TEMPLATE_NOTES_BY_VERSION` — уже едет полю), но как дополнение, а не единственный носитель (PEP 1).
Для корневой русской копии истока адресом служит журнал решений `MASTER_PLAN.md` §7 (№NN): дословные слова владельца там
уже лежат, в правиле остаётся «(№NN)».

**(б) Запас шаблона под бюджетом, который держит страж сборки.**

## §8. Вход для шагов CK2–CK5

- **CK2 (`tools/canon-inventory.mjs`):** ключ обязательства — нормализованный текст ВСЕГО пункта плюс ближайший заголовок;
  категории `lost` · `moved` · `changed` (команда уцелела, текст пункта иной) · `new`; `changed` и `lost` — вход смыслового
  аудита CK3. Счёт обязательств шаблона печатается — метрика риска (порядок величин — IFScale ≈ 150, по разведчику A; инструкции
  IFScale — включение ключевых слов, а не обязательства канона, так что число сравнимо лишь по порядку).
- **CK3:** тест строки Anthropic («Would removing this cause Claude to make mistakes?») · свидетельства → раздел записки по (а)
  · три проверки §6 (инвентарь `lost 0` · аудит чистым экземпляром файлом в отчёт · метр колона) · фикстура `s16` случая 1 — от
  длины шаблона (отчёт CK0 §4в).
- **CK5:** константа запаса по (б) и страж сборки над девятью шаблонами · строка «переведено целиком» по (в) называет место,
  оставленное шаблоном · `archives` в маркере по (г) · `.kaif/budget-baseline.json` по (д); выше бюджета проходит только убывание (е).

## §9. Риски и границы

- **(а) Число вендора — не наше число.** «Under 200 lines» сказано о файле проекта; руководство KAIF — канон метода, и 200 строк
  без раскола на файлы недостижимы. Переносится принцип («короче — лучше соблюдается», объяснения — вон), не число.
- **(б) Встречные исследования** (размер без эффекта на одно простое правило) — выигрыш сжатия доказывается функциональным
  прогоном по трём фикстурам (`plans/118` → «Верификация»), не цитатами.
- **(б) Запас 25 % взят из бюджетов бандлов JS** — аналогия, не прямой прецедент: шаблон, который растят потребители, отрасль
  не бюджетирует (разведчик C сказал это сам).
- **(в) Вторичные источники** — чек-листы Гаванде и часть ADR взяты по заметкам и разведчику, не перепроверены; ни одно решение
  §7 на них одних не стоит.
