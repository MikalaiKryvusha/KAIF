## Вопрос разведки

Почему ответ агента на слово владельца, пришедшее посреди хода, не доходит до чата (поле: #118 — первый текст через 108 вызовов;
сессия 76 — ответ перед вызовом не лёг в запись текстом, а текст в одном сообщении с вызовом страж не увидел), и какой механизм агентской
системы проверяет доставку надёжно.

## §1. Вендор — Claude Code, документация хуков (живая загрузка)

Источник: https://code.claude.com/docs/en/hooks.md — загружено `curl` 2026-09-28 20:56 +03:00, 330 813 байт (копия — скретчпад сессии 76).
Дословно:

- Общее поле входа `transcript_path`: «The transcript file is written asynchronously and may lag the in-memory conversation, so it may not
  yet include the current turn's most recent messages when a hook fires. Hooks that need the final assistant text of the current turn
  should use `last_assistant_message` on [Stop](#stop) and [SubagentStop](#subagentstop) instead of reading the transcript».
- `Stop`: «Runs when the main Claude Code agent has finished responding. Does not run if the stoppage occurred due to a user interrupt.»
- Вход `Stop`: «Stop hooks receive `stop_hook_active`, `last_assistant_message`, `background_tasks`, and `session_crons`. The
  `stop_hook_active` field is `true` when Claude Code is already continuing as a result of a stop hook. … Claude Code applies an
  8-consecutive-continuation cap».
- «The `last_assistant_message` field contains the text content of Claude's final response, so hooks can access it without parsing the
  transcript file. … the transcript file isn't guaranteed to include the final message at Stop time on all versions.»
- Решение: «`"block"` prevents Claude from stopping. Omit to allow Claude to stop» · «`reason` — Required when `decision` is `"block"`.
  Tells Claude why it should continue» · «A hook that blocks by exiting 2 routes the same way as `reason`».

## §3. Следствия для KAIF

1. Текст между вызовами инструментов — НЕ гарантированная доставка: его может не оказаться в записи вовсе (случаи 1–2), а страж вызова
   видит запись с опозданием (случаи 3–4). Гарантированно видимый вендору текст — ИТОГОВЫЙ ответ хода: его отдаёт `last_assistant_message`
   события `Stop`, не завися от записи.
2. Значит, проверять «ответ дошёл» надо в конце хода: страж `Stop` сверяет итоговый ответ с каждым словом владельца этого хода и, если
   ответа нет, возвращает ход агенту один раз (`decision: "block"` + `reason`; повтор запрещён самим вендором через `stop_hook_active`).
   Работа не встаёт: страж срабатывает там, где ход и так кончается (слово владельца №133 — «не стапал работу, а продолжал работать»).
3. Механическая мера «ответил» без суждения о смысле: итоговый ответ открывает ответ на каждое слово владельца его первыми словами
   (сравнение по нормализованным словам, с границами слов — «го» не находится внутри «говорю»). Суть ответа по-прежнему судит судья.
4. Лаг страж вызова лечит перечитыванием записи с короткой паузой перед отказом — асинхронная запись успевает лечь.

## §4. Живой путь истока — уточнение решения (записано 2026-09-28 21:49 +03:00, сессия 76)

- 2026-09-28 18:21:43Z и 18:23:13Z владелец написал посреди хода («Как идет? Получается?», «Ты сегодня в облаке…»). Ответ, который агент
  писал ПЕРЕД вызовом инструмента, в запись текстом не попал оба раза (пустое размышление + размышление + вызов); ответ ОТДЕЛЬНЫМ сообщением,
  без вызова после него, лёг текстовым блоком (запись 1508). Из пяти попыток сессии «ответить перед вызовом» четыре легли размышлением.
- Трассировка входа `Stop` (18:25:24Z, клиент 2.1.283): `last_assistant_message` есть; `stop_hook_active` = true после отзыва
  стража окружения. Отзыв другого стража записывается `user`-записью строкой БЕЗ источника промпта — первая редакция хука приняла её
  за начало хода, и слова владельца «ушли в прошлый ход».
- **Уточнённое решение:** ответ владельцу — отдельным сообщением (без вызова инструмента после него), открытым его первыми словами;
  осталась работа — последняя строка `⏩ <следующий шаг>`, и страж конца ответа сам возвращает агента к работе (`decision: "block"`
  с «continue»; строка `⏩` исполняется только в ходе, куда писал владелец, потолок вендора — 8 продолжений). Так ответ виден и работа
  не встаёт (слово владельца №133). Ход открывает только запись с `promptSource`/`origin`. Отчёт — `testcases/reports/2026-09-28_oa-owner-answer-end-of-turn.md`.
