## Охоты

1. **Стоячая ложь в поставке (❌, REFUTED).** `framework/hooks/README.md:171` (`git blame` → `e055db3`, до судьи): «unless the project states
   `contextWindow.tokens`; a usage above 200K **always** means the 1M window». Код после `8992c43`: `if (Number(tokens) > 0) return Number(tokens)`
   (`context-window.mjs:38`), и случай самопроверки «the project's tokens win over the floor» — при `tokens: 200000, seen: 300000` окно 200 000. То есть «always»
   ложно. Коммит судьи поправил код и шапку хука, а README модуля не тронул.
2. **Слово владельца шире критерия (⚠️).** Интервью №047, Q6 = B (строки 149, 160, 163): «на 80 % — предупредить **голосом**», «владелец **слышит** одно
   предупреждение». В критерии 35 строка «Результат» голос не называет. Строка хука его несёт («tell the owner once by voice»), но самопроверка это
   не проверяет: регулярка проверяет только отсутствие слов закрытия. Если вырезать фразу о голосе, все 11 случаев останутся зелёными (по чтению кода; мутант не гонял — граница брифа).
3. **Повторного круга нет (⚠️).** `st.said` никогда не очищается внутри одной сессии (`context-window.mjs:144–148`). Сценарий: после автосжатия
   (тот же `session_id`) занятость падает, затем снова растёт до 80 / 85 % — и хук молчит. README называет это «once per level per session», но ни
   критерий, ни README не говорят, что после сжатия предупреждений больше не будет.
4. **Окно 200K может сжаться раньше 85 % (⚠️, гипотеза).** Свои цифры плана 142 и хука: автосжатие окна 1M ≈ 967K, то есть окно минус ≈ 33K. Если тот же
