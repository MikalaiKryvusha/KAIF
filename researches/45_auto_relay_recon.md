## 1. Что из стека документа у KAIF уже есть

| Часть документа | У KAIF | Разница |
|---|---|---|
| датчик окна по `usage` транскрипта (`input + cache_read + cache_creation`, без `isSidechain`) | хук окна `framework/hooks/context-window.mjs` — та же формула, 80 % предупреждение, 85 % — довести до среза и `/end-chat-soft`; ворота закрытия и `--measure` (`bugs/137`) | у документа один порог передачи (85 % на 1M, 70 % на 200k) |
| передача «с чего продолжить» (`HANDOVER.md`) | эстафета `STATUS.md` п. 0 + прощание `stop-farewell-capture.mjs` → `FAREWELL_MESSAGE_FROM_THE_PREVIOUS_CHAT.md` | у KAIF два носителя уже есть — третий файл передачи был бы парой (DRY) |
| приказ новому чату («auto-relay continue» → навык) | хук первого слова `prompt-resume-word.mjs`: `resume` → `/resume` | слово входа у KAIF — `resume` |
| лимит цепочки и `stop` | условия остановки циклов (`/dayloop` · `/autoloop` · `/guarded-loop`) | счётчика чатов нет |
| **открыть новый чат на машине** | **нет** | ново: `code -r <папка>` → ссылка `vscode://anthropic.claude-code/open?prompt=…` → Enter только в окно проекта (`open-chat.ps1`) |
| **Stop-хук открывает чат после конца хода** | нет (Stop-хуки KAIF — страж STATUS, прощание, хук тестирования) | ново; один чат работает в каждый момент |
| привязка передачи к id сессии (`state.json`) | нет | ново |

## 2. Проверено на этой машине (Windows 11, расширение 2.1.326)

1. `CLAUDE_CODE_SESSION_ID` есть в окружении команд агента и равен имени журнала сессии: `node -e "console.log(process.env.CLAUDE_CODE_SESSION_ID)"` →
   `fc8be07d-655a-4f87-8d5d-6c09a27d37d7` (документ §6: «на Windows не проверено» — теперь наблюдено).
2. `code -v` → `1.123.0` — команда в PATH.
3. Обработчик ссылки в 2.1.326 на месте: `case"/open":{let b=A.get("session")??void 0,T=A.get("prompt")??void 0; … sl("claude-vscode.primaryEditor.open",b,T)` —
   тот же маршрут, что документ снял с 2.1.325.
4. **Предусловие, которого в документе нет:** хуки и навыки папки сессия получает только при доверии Claude Code к папке (`bugs/138`,
   `researches/46`). Без доверия Stop-хук не запустится, навык `/auto-relay` не найдётся — цепочка молча не начнётся. У истока доверия сейчас
   нет (`homeworks/08`); приёмка §5 документа — только после неё. Сессии расширение ставит `CLAUDE_CODE_IGNORE_PERSISTED_TRUST` — доверие
   решает само расширение по своему окну.

## 3. Не проверено (и почему)

- Открывашка (`open-chat.ps1`) и Enter в окно проекта — открывают окно и печатают в чат у владельца: только под его присмотром (§6 документа).
- Выход окна VS Code на передний план из фонового процесса на Windows — риск «высокий» документа, не наблюдался.
- Порог автосжатия на окне 1M у истока (поле: ≈ 89 % у документа, ≈ 96,7 % у поля — эстафета сессии 99) — не замерен.

## 4. Развилки для владельца (по этой разведке)

1. **Носитель передачи:** `HANDOVER.md` документа или эстафета `STATUS.md` п. 0 + прощание, как уже работает KAIF.
2. **Слово входа нового чата:** «auto-relay continue» документа или `resume` — хук первого слова KAIF уже приказывает полный вход.
3. **Подталкивание на Stop** (`decision: block` один раз, «работай дальше»): документ его несёт, а хуки остановки на слове владельца сняты
   словом №144 — это другое поведение (подталкивает к работе, не останавливает), но решение — его.
4. **Версия:** кандидат критерия 36 версии KAIF 2.10 (решение №160 версию не назвало).

`[ИИ]` Рекомендация разведки к развилкам 1–2 — носители KAIF (одно место на факт); 3–4 — только словом владельца.
