# Тест-кейсы — перенос канонических навыков в `.kaif/skills-canonical/`

**Создан:** 2026-11-22 19:32 +03:00 · **Проверяется:** установка, синхронизация и обновление навыков KAIF 2.10 ·
**Версия/сборка:** рабочее дерево после `29c94f7`, артефакты `dist/` этой работы.
**Тестовый базис:** интервью №051 Q1 = B: канонический набор переезжает в `.kaif/skills-canonical/`, адаптеры создают посистемные копии из него; `plans/136` критерий 37: Kimi-only дерево не создаёт копии других систем; `framework/adapters/kimi-code.md`: Kimi получает адаптированные навыки и reference-файлы.

## 1. Вектор цели

**Maintain / Avoid:** накопленные проекты переезжают на нейтральный канон с сохранением локальных правок, собственных навыков и происхождения файлов; свежая Kimi-only установка не создаёт `.claude/`.

## 2. Проверяемые требования

| # | Требование | Критерий соответствия |
|---|---|---|
| R1 | При установке только для Kimi система должна создать нейтральный канон и Kimi-копии без `.claude/` | Каталоги и 37 навыков читаются на диске; `.claude/` отсутствует; `check` возвращает 0 |
| R2 | При переносе старого дерева система должна сохранить локальную правку канонического навыка | Строка-маркер читается в нейтральном каноне и выбранной посистемной копии |
| R3 | При переносе система должна сохранить собственный навык проекта | Собственный `SKILL.md` существует в нейтральном каноне после переноса |
| R4 | При обновлении прежним ядром система должна завершить перенос в новом `update-verify` | После обновления ядром v2.9 и запуска нового `update-verify` строка-маркер читается в каноне и Kimi-копии |
| R5 | При переносе система должна сохранить откатный материал и перевести происхождение manifest | Строка-маркер читается в резервной копии; `canonicalSkills` равно `.kaif/skills-canonical`; старые пути отсутствуют в `paths` |
