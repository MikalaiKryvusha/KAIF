## 5. Найдено

- **Д1 (найдено живым прогоном 11, починено до коммита; S2 — по лестнице документ не заводился, урок EXP-0139):** `--close`
  через ≈ 3 с после первого нажатия ЗАКРЫЛ страницу — замок узнавал о вводе только со следующим 15-секундным пульсом, а
  страница без единого пульса читалась как «ввода не было». Ровно класс тикета #66, воспроизведённый его же починкой. Починка:
  пульс в течение секунды после ввода + правило «страница моложе порога не закрывается без слова владельца».
- **Д2 (найдено отладочным прогоном, починено):** возраст страницы сбрасывался каждым пульсом — `startedAt` снимался внутри
  `writeLock`; метка снимается один раз.
- **Д3 (найдено прогоном 12, починено):** `process.exit()` сразу после `console.log` в конвейер на Windows теряет последние
  строки (stdout в pipe асинхронный) — отказ `--close` приходил кодом 4 БЕЗ строки причины; `--close` и отказ на незнакомый
  флаг переведены на `process.exitCode`.
- **Д4 (найдено прогоном 5, починено):** жёсткое убийство браузера через ≈ 2 с после записи теряет `localStorage` (Chromium
  сбрасывает пачками ≈ 5 с) — в своде окно закрывается штатно (`Browser.close`), в заборе headless живёт 6 с после забора,
  чтобы очистка ключей дошла до диска (иначе ответ записался бы дважды).
- **Д5 (дыра доказательства, названа):** мутант «порог по умолчанию = 0» зелёный на окончательном своде — свод задаёт порог
  параметром `contour.closeQuietMs`, и константу по умолчанию не исполняет ни один ассерт; значение 180 с по умолчанию
  наблюдено только живым прогоном («younger than the quiet threshold (180 s)»). Адресные мутанты класса — «ввод» и «возраст».
- **Д7–Д9 (найдены СУДЬЁЙ эпика, прогон 18, починены до коммита — ни один ассерт и ни один живой прогон их не видел):**
  Д7 — `--close` после всех проверок убивал pid, прочитанный из файла замка: к моменту чтения pid может принадлежать другому
  процессу (замок пережил свой сервер) — теперь команда просит завершиться сам сервер страницы по токену из замка и без
  `--force` никого не убивает; Д8 — ответ лежал только в `localStorage`, который Chromium сбрасывает пачками ≈ 5 с: владелец,
  у которого браузер умер сразу после «Записать», терял ответ при зелёной строке «сохранён» — носителем стал IndexedDB (замер:
  долговечен через ≈ 0,5 с), свод теперь убивает браузер жёстко; Д9 — забор при ОТКРЫТОМ окне владельца поднимал второй
  браузер на занятом профиле (Chromium отдаёт такую страницу в уже открытое окно) — забор откладывается, пока профиль занят.
- **Д10 (найден наблюдением через минуту после коммита эпика, починен следующим коммитом; S3 по лестнице — не стоил ни одного
