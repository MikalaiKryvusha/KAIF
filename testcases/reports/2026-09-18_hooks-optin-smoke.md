## 1. Работа

Проверялась починка дешёвых находок ревизии кода зоны `framework/hooks/` до суда версии 2.7: (1) проба шага 3 README
модуля исполнима в оболочке того, кому адресована (`bugs/121` №1), универсалия о cooldown заменена наблюдаемым (№2),
свойство «битый маркер + старый mtime» наблюдается сводом (№3); (2) событие с ведущим BOM читается четырьмя хуками как
событие без него, маркер с BOM — по своему `at` (`bugs/119` №3, половина хуков); (3) фрагмент конфига Claude Code стоит
под осью «какой скрипт под каким событием» (`bugs/118` №1). Базис — блоки «Fix accepted when» трёх баг-документов
(сценариями) и строки `INTENT:` / `FORK:` в `bugs/121` и `bugs/118`. Отдельного набора тест-кейсов нет — его роль
играют сценарии приёмки багов; каждый новый ассерт свода называет свой баг в имени.

## 2. Контур

Часть системы — опциональный модуль refresh-hooks (`framework/hooks/*` → бандл → `.kaif/hooks/` развёрнутой копии).
Стенд — РАЗВЁРНУТАЯ копия из `dist` во временном корне ОС (`tools/lib/temp-root.mjs`), Windows 11, Node из
`process.execPath`; оболочки — bash поставки Git (`C:\Program Files\Git\bin\bash.exe`, найден через `git --exec-path`)
и Windows PowerShell 5.1, обе запускаются скрыто, с закрытым stdin и сроком 30 с. Шов сборки до фикса — `KAIF_DIST` на
копию `dist/` ревизии `95c7883`, снятую до первой пересборки. Мутанты — на КОПИЯХ `dist` во временном каталоге.

**РЕАЛЬНЫЙ МИР: накоплено · данные и техника · путь.** Продакшен этой правки — владелец развёрнутого проекта,
исполняющий пробу README руками в своей оболочке.
- *Техника* — **проверено на реальном**: шесть строк README исполнены на машине владельца истока в двух оболочках,
  которыми он ходит (Git Bash и Windows PowerShell 5.1), вывод каждой прочитан.
- *Путь* — **ПРОКСИ, и это сказано вслух** (поправка 2026-09-18 14:50 +03:00 по находке F9 судьи сессии; первая
  редакция называла «проверено на реальном» и технику, и путь разом): оболочки запускал агент — скрыто, из `node`, с
  закрытым stdin. В ТАКОМ запуске у PowerShell `Console.InputEncoding = cp866`, BOM перед строкой в конвейере НЕТ, и
  хук ДО фикса отвечает на том же событии так же, как новый (прогон 14) — то есть скрытый запуск обе грабли README не
  видит. Грабля живёт в запуске, где ввод консоли — UTF-8 (`Console.InputEncoding = utf-8`, так запускает PowerShell
  инструмент агента; так же — терминал, переведённый на UTF-8): там байты события `efbbbf7b22…`, хук ДО фикса молчит
  (0 символов), хук дерева отвечает приказом (891 символ) — прогон 15, «до» и «после» сняты В ОДНОМ режиме.
  СОБСТВЕННОЕ окно терминала владельца не наблюдалось: какая кодировка ввода стоит у его консоли, не снималось; хуки к
  этому теперь безразличны, а инструкция README исполнима в обоих режимах.
- *Накопленное состояние* — не применимо к пробе (она идёт без маркера по построению README); живое срабатывание
  четвёртого хука на пути владельца наблюдено раньше — `testcases/reports/2026-09-18_hook-resume-word.md`, прогон 17.

## 5. Найдено

- **`bugs/122` (S2, открыт):** escape-последовательность вида «обратная косая + `u` + четыре шестнадцатеричные цифры»,
  набранная агентом в параметре инструмента правки, приезжает в файл НАСТОЯЩИМ символом (проба 12:25: прочие шесть
  последовательностей ложатся как набраны). Поймано правилом скрипта мутантов «мутация, которая не применилась, — отказ»:
  игла была ASCII-escape, в бандле стоял невидимый символ. Шесть собственных мест нормализованы до коммита; проба по
  дереву нашла 39 мест исходников прежних сессий (U+FEFF 36 · NUL 2 · BEL 1; 25 — в поставке, включая ядро) и три
  настоящих BACKSPACE в документах на месте границы слова регулярного выражения — команда `Repro` урока
  `EXPERIENCE.md:414` была неисполнима, в `HOUSE_RULES.md:35` между ёлочками стояла пустота. Три места в документах
  восстановлены; 39 мест кода — отдельной задачей (ядро принимает ветку эпика CB, контур требует живого браузера).
- **Собственное ложное утверждение в чате, поправлено в чате:** «находка глубже, чем думала ревизия» — сказано после
  чтения двух баг-документов семейства из четырёх; третий (`bugs/119` №3) описывал BOM с теми же байтами. В файлы
  репозитория утверждение не попадало.
- **Наложение прогонов:** мои одиночные прогоны `s14` и мутантов 12:12–12:13 шли одновременно с послекоммитным полигоном
  субагента эпика CB (старт 12:10:52), который дал необъяснённый красный `s09` (в одиночку и повтором зелёный, вывод не
  сохранён). Причинная связь не доказана; названа как первая лошадь — параллельная нагрузка. Перед своим полигоном
  процессы проверены пробой, прогон шёл в одиночку.
- Дефектов, уехавших в дерево, — **ноль** по счёту до коммита; **судья сессии (вердикт 14:37, VERIFIED WITH CAVEATS)
  нашёл четыре в этой работе, все починены до пуша:** F1 — комментарий свода утверждал, что строка README, потерявшая
  пустой stdin, «краснеет», а закрытый stdin отдаёт EOF мгновенно, и мутант судьи проходил 87/87 → статический ассерт
  по тексту строк и мутант М5; F9 — «путь — проверено на реальном» шире наблюдения, «до/после» в разных режимах
  запуска → прогоны 14–15 и поправка § 2 и § 4; F10 — «было 68» при счёте 67 → клетка прогона 4; F11 — метка хука-таймера
