# Отчёт прогона — эпик SC 2.8, шаг SC2: заявление о версии судится парой, а не формой строки

**Создан:** 2026-09-26 02:52 +03:00 · **Прогон вёл:** Claude Opus 5.5 (1M context), сессия 74 (ночной цикл) · **Версия/сборка:** HEAD `4cd6543` + рабочее дерево

## 1. Работа

Критерий 17 `plans/117` (тикеты origin #75 · #91; находки N3 · N4), шаг SC2 `plans/123`. Скан устаревших заявлений решал «что такое
заявление» формой строки: любая строка с датой пропускалась целиком (строка версии в записи о развёртывании врала четыре интервала,
#75), пин версии в скрипте без слова KAIF в 16 знаках был невидим (#91), версия продукта рядом со словом KAIF называлась (N3), скобка
атрибуции, перенесённая на вторую строку, не снималась (N4 · K-R4). Сделано в `scanStaleClaims` ядра:

- **Пара.** Заявление — слово фреймворка и версия, которая ему ПРИНАДЛЕЖИТ: в промежутке (до 16 знаков, как прежде) нет союза, а в прямом
  порядке («KAIF … 2.7») — и другого имени (заглавное слово, не слово версии); в обратном («2.7 «Audited KAIF»») заглавное слово перед
  KAIF — кодовое имя выпуска. Пара ищется от КАЖДОГО вхождения слова и версии отдельно.
- **Дата — только вне скобок.** Строка — датированная запись журнала, когда дата стоит вне скобок; «Версия KAIF 2.1 (релиз от
  2026-07-31)» — заявление.
- **Пин скрипта — словарём кода.** Кавычкой взятая старая версия, присвоенная идентификатору, который называет пин (`EXPECTED_VERSION`,
  `kaifVersion`, `required…version`), в скрипте, который называет фреймворк.
- **Перенесённая скобка** снимается на обеих строках: голова строки до непарной `)` и хвост от непарной `(`.
- **Новая команда ядра `stale-claims`** — перепрогон скана только чтением (`--from`/`--to`, по умолчанию — квитанция обновления; код 1
  только при провале обхода): задание говорит «исправь и перепрогони», а перепрогон был только внутри чекпоинта. Записка §10.7.

## 5. Найдено

Функциональный прогон на настоящих деревьях нашёл три дефекта ПЕРВОЙ редакции, которых свод не видел:
1. **Перекрытие:** одно регулярное выражение по строке брало первое вхождение слова фреймворка (`/kaif-go`) с промежутком, в котором
   стояло второе («— с KAIF »), — настоящая пара «KAIF 2.2» терялась. Пара теперь ищется от каждого вхождения; случай C6, мутант M11.
2. **Пин по голому `version`:** `'<?xml version="1.0" encoding="UTF-8"?>'` в скрипте дерева A назван «(asserts 1.0)». Пин теперь —
   только идентификатор, который называет пин; случай C7, мутант M12.
3. **Кодовое имя как чужое имя:** правило «заглавное слово в промежутке — другое имя» в обратном порядке теряло «версия **2.7 «Audited
   KAIF»**» — настоящее заявление README дерева B. В обратном порядке заглавное слово перед KAIF — кодовое имя; случай C5, мутант M10.
4. Ноль дефектов вне этого.
