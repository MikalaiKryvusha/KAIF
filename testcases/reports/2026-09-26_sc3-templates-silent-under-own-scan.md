# Отчёт прогона — эпик SC 2.8, шаг SC3: шаблоны поставки не краснят свой сканер

**Создан:** 2026-09-26 03:12 +03:00 · **Прогон вёл:** Claude Opus 5.5 (1M context), сессия 74 (ночной цикл) · **Версия/сборка:** HEAD `193bff1` + рабочее дерево

## 1. Работа

Критерий 18 `plans/117` (находки K-R4 · K-R5), шаг SC3 `plans/123`. Строка шаблона одинакова во всех развёртываниях, поэтому строка
поставки, которую называет скан устаревших заявлений, встанет в задание обновления КАЖДОГО поля; разведка насчитала для перехода
2.7 → 2.8 одиннадцать таких строк в семи файлах, а маркер «версия в порядке» не был описан для строки таблицы. Сделано:

- **Гард сборки 5m** (`tools/check-framework.mjs`, функция `tools/lib/templates-own-scan.mjs` — одна на сборку и пробу): файлы
  поставки из бандла пишутся во временный каталог так, как их несёт английское развёртывание, и собственная команда ядра
  `stale-claims` гоняет по ним скан с целью «следующая версия»; каждая названная строка — отказ сборки с подсказкой; `--selftest` —
  четыре ответа (строка со старой версией названа; перенесённая атрибуция, строка таблицы с маркером внутри и исходник языкового
  пакета — молчат).
- **Шаблоны.** Для 2.7 → 2.8 гард молчит уже после правила перенесённой скобки SC2 (из одиннадцати строк разведки осталось две);
  под целью выпуска (2.8 → 2.9) он называл четыре исторические строки — переписаны в обоих слоях («Since KAIF 2.8 …» → «Since 2.8 …»,
  «Since KAIF 1.5 …» → «Since 1.5 …», «**KAIF 2.6 — the contract…**» → «**Since 2.6 the contract…**»), одна получила маркер
  (`<!-- KAIF-VERSION-OK: … -->` — «REVISED in 2.8 by the KAIF owner's word»).
- **Маркер для строки таблицы описан:** пункт задания `stale-claims`, итог команды `stale-claims` и записка §10: строка таблицы несёт
  маркер ВНУТРИ строки, в любой ячейке — строка над строкой таблицы — другая строка.
- Попутно — близнец F14 суда UP в гарде 5f (новейший тег мог оказаться тегом самого коммита).
