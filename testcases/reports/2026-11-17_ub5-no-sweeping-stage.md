# Отчёт прогона — шаг UB5 версии KAIF 2.10: закрытие и коммит по умолчанию ставят набор по именам, без `git add -A`

## 1. Работа

Шаг UB5 `plans/139` (критерий 15 `plans/136`; `ideas/32` п. 5; поле — `bugs/79`: подметающий `git add -A` увёз в origin два файла владельца).
Подметание жило в трёх местах поставки (разведка `researches/44` §1 п. 15) и, как нашёл судья, в четвёртом — шаг 6 `/release`
(`git commit -am "release: X.Y"`). Теперь `/end-chat-soft`, `/end-chat-force`, значение по умолчанию `<COMMIT_COMMAND>` машинерии и пример
документации слота `framework/_intro.md` говорят «git add each path you mean to ship by name — new, changed, deleted, and both names of a move
(git status --short lists them; never -A) — check the staged set with git diff --cached --stat», шаг 6 `/release` обоих слоёв — `git add`
по именам и `git diff --cached --stat` перед `git commit -m`. Форма подметающей инструкции — в одном месте, `tools/lib/sweep-stage.mjs`; её
читают гард сборки 5y и свод `s01`. Судья нашёл, что смена текста слота даёт полю ложное «not found» по строке соавтора навыка закрытия:
ядро (`update-verify`) теперь сверяет обещанную строку с оставшейся канонической заглушкой как образец ВСЕЙ строки диска, где место заглушки —
значение до шести слов без запятой, точки с запятой и отрицания (первая форма — без якоря, `\S.*?` — опровергнута повторным судом).
